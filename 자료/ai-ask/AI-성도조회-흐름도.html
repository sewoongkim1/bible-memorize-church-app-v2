AI 성도 조회 흐름도

목사님이 말로 물으면 AI는 질문을 「조건」으로 바꾸기만 합니다. 명단은 서버가 DB에서 직접 꺼내 화면에 그리고, 이름은 AI에게 가지 않습니다.

  • 지금 성경암송 앱과 같은 Supabase 프로젝트
  • 같은 Claude 키
  • 아직 만들기 전 · 예시 자료

한눈에 보기

질문 하나 따라가기

예: 「10년 동안 사역하신 분들 중에 올해는 안 하고 계신 분」

  1. ①
    목사님 화면 → 서버

    질문을 보낸다

    교회 어드민 「성도 묻기」 칸에 적은 글이 카카오 로그인 표와 함께 서버로 갑니다. 서버는 누가 물었는지 압니다.

  2. ②
    서버

    역할을 확인한다

    담임목사 역할이 있는 분인지 봅니다. 교회 어드민의 다른 메뉴가 지금 쓰는 방식(역할 표 admin_roles) 그대로이고, 없으면 여기서 끝납니다.

  3. ③
    서버 → Claude

    AI에게 질문과 필드 목록을 보낸다

    보내는 것은 셋입니다. 지시문, 물을 수 있는 것을 적은 필드 목록, 그리고 질문 글.

    필드뜻비교
    served_years_count섬긴 해 수 (서로 다른 해만 셈)≥ · ≤ · =
    served_years섬긴 해 목록들어 있음
    served_streak_max가장 길게 잇따라 섬긴 해 수≥ · ≤
    position직분 (집사 · 권사 · 장로 …)= · 여럿 중
    gu교구 (믿음 · 사랑 · 소망 …)=
    edu_done받은 교육들어 있음

    지시문은 짧습니다. 이 필드로만 조건을 만들 것. 날짜는 숫자로 셈하지 말고 {"rel":"this_year"}처럼 둘 것. 못 하는 조건은 unsupported에 적을 것. 이름이나 명단은 보내지 않고, AI는 DB의 표 이름도 모릅니다.

  4. ④
    Claude → 서버

    AI는 조건 트리 한 덩이만 돌려준다

    {
  "and": [
    { "field": "served_years_count", "op": ">=", "value": 10 },
    { "not": { "field": "served_years", "op": "has",
               "value": { "rel": "this_year" } } }
  ],
  "alternatives": [ "잇따라 10해 (served_streak_max >= 10)" ],
  "unsupported": []
}

    AI가 할 일은 여기서 끝납니다. 글이 아니라 정해진 꼴의 JSON이라 서버가 한 칸씩 검사할 수 있습니다. 「10년 동안」처럼 뜻이 갈리는 말은 다른 읽기(alternatives)를 함께 냅니다.

  5. ⑤
    서버

    검사하고 SQL로 번역한다

    • ✓served_years_count 필드 목록에 있음 · ≥ 쓸 수 있음 · 10은 1~17 안
    • ✓served_years 필드 목록에 있음 · 「들어 있음」 쓸 수 있음
    • ✓this_year → 2026 (서버가 오늘 날짜로 바꿈)
    where served_years_count >= $1
  and not (served_years @> array[$2])
-- $1 = 10, $2 = 2026

    필드 목록에 없는 칸이나 비교가 오면 여기서 막고, 까닭을 붙여 AI에게 한 번 다시 묻습니다. 값은 언제나 $1 · $2 자리로만 들어가 SQL 글에 섞이지 않습니다.

  6. ⑥
    서버 → DB

    읽기 전용 역할로 한 번 묻는다

    begin;
set local role ai_reader;             -- 요약 표만 읽을 수 있는 역할
set local statement_timeout = '3s';
select name, position, gu, served_years_count, last_served
  from person_facts                   -- 교인 한 분 한 줄
 where served_years_count >= $1
   and not (served_years @> array[$2])
 order by served_years_count desc
 limit 200;
commit;

    person_facts는 교인명부 · 사역 이력 · 교육 · 성경필사를 교인 한 분에 한 줄로 모은 요약 표입니다. 「섬긴 해 수」 같은 셈은 여기서 미리, 서로 다른 해만 세는 식으로 해 둡니다. 밤마다, 그리고 명단을 새로 올린 뒤 다시 만듭니다.

  7. ⑦
    DB → 서버

    찾은 분들이 돌아온다

    이름직분교구섬긴 해마지막 사역
    김○○권사화평14해2025
    박○○장로소망12해2024
    이○○집사믿음10해2025

    예시 자료입니다(이름은 가림). 이 결과는 Claude에게 가지 않습니다.

  8. ⑧
    서버 → 목사님 화면

    조건 칩과 명단을 보여 준다

    섬긴 해10해 이상 2026년 섬김없음

    이렇게도 읽을 수 있어요: 잇따라 10해

    12분예시

    이 질문은 기록에 남습니다 — 누가 · 언제 · 무엇을 물었는지

    칩은 AI가 쓴 글이 아니라 ⑤에서 검사를 통과한 조건으로 서버가 만듭니다. 그래서 화면에 보이는 조건이 실제로 돈 조건입니다. 목사님이 칩을 고치면 ③④를 건너뛰고 ⑤부터 다시 돕니다.

    덧붙이기(선택): 명단 위에 두세 줄 정리를 붙이고 싶으면, 서버가 숫자만(「12분 · 그중 8분은 작년까지 사역」) 다시 Claude에 보내 문장을 받습니다. 이름은 이때도 보내지 않습니다.

지금 앱의 「내게 주시는 말씀」과 비교

성경암송 앱은 지금도 같은 Claude 키로 설교 질문에 답합니다. 다른 점은 DB에서 나온 자료가 어디로 가는가입니다.

지금 있는 것 · 새로 만들 것

지금 있음
  • Supabase 프로젝트 하나 — DB와 서버 함수가 한곳에
  • 교회 어드민 화면 · 카카오 로그인 · 역할 표 admin_roles
  • 서버 함수 church-admin(교회 어드민) · api(성경암송)
  • Claude 키 ANTHROPIC_API_KEY — 「내게 주시는 말씀」과 영어 본문이 이미 씀
  • 표: 교인명부 church_people · 사역 이력 ministry_history · 성경필사 event_signups · 잇기 people_links · 교육 · 봉사
새로 만듦
  • 화면 「성도 묻기」 · 역할 「담임목사」
  • 서버 액션 askPeople — Claude 부르기 · 검사 · 번역 · 실행
  • 필드 목록 — 물을 수 있는 것을 한곳에 (AI 양식 · 검사 · 칩 이름이 모두 여기서)
  • 요약 표 person_facts — 교인 한 분 한 줄
  • 읽기 전용 DB 역할 ai_reader와 그 역할로 SQL을 돌리는 길
  • 물은 기록 ai_ask_log

두 가지 원칙

AI가 보지 않는 것

  • 이름 · 연락처 · 주소 · 사진
  • 찾은 명단
  • 심방 메모
  • DB 표 구조 — AI는 필드 목록의 설명만 압니다

AI에게 SQL을 맡기지 않는 까닭

  • 무엇을 돌렸는지 사람이 확인하기 어렵습니다. 여기서는 칩이 검사를 통과한 조건에서 나오니, 보이는 것이 곧 돈 것입니다.
  • 「섬긴 해」를 그때그때 세면 한 해에 두 팀을 섬긴 분이 2해로 셀 수 있습니다. 요약 표에서 한 번, 사람이 정한 뜻으로 셉니다.
  • 연락처 칸을 고를 길이 처음부터 없습니다. 필드 목록과 읽기 전용 역할, 두 겹으로 막습니다.
