## 2. 화면 지도

`app.js`에 `render*` 함수 36개가 있다. 화면 전환은 라우터가 아니라 **함수 호출**이다 — `app.innerHTML`을 갈아끼운다.

```
[스플래시] → [인트로 슬라이드]* → [로그인] → [첫 화면 renderSummary]
                                                  │
   ┌──────────────┬──────────────┬────────────────┼──────────────┬──────────────┐
   │              │              │                │              │              │
 말씀 목록      말씀 도전      나의 말씀 앨범   도전 순위     응원·기도·공감   성경필사 노트
renderVerseList renderChallenge renderAlbum   renderRanking  renderBoard     renderPilsaApply
   │              │              │                │
 암송 화면      완료 화면      이어 듣기       내 순위·응원
renderTestScreen renderChallengeDone           renderMyRecord
   │                                            renderGuRanking
 복습 renderReview                              renderCalendar
```

**곁가지** — `renderSettings`(설정) · `renderManual`(사용 설명서 13항목) · `renderHelp`(자세한 안내) · `renderPrivacyInfo`(개인정보) · `renderInstallGuide`(홈 화면에 앱 만들기) · `renderIntro`(인트로) · `renderBlessing`(축복) · `renderEvent*`(말씀 이벤트 4단계) · `renderPassage*`(긴 본문 암송 4단계) · `renderSermonChat`(설교 챗봇, 관리자 베타)

**첫 화면 단추는 일부러 늘리지 않는다.** 지금 다섯이다 — 나의 말씀 앨범 · 도전 순위 · 응원·기도·공감 · 성경필사 노트 · 고척교회 찬양. 새 기능은 대개 **설명서나 설정 안으로** 들어간다.

## 3. 핵심 흐름 — 한 구절을 외우는 길

### 3단계 암송 (`renderTestScreen`)

| 단계 | 빈칸 | |
|---|---|---|
| 1단계 | **25%** | 보면서 채운다 |
| 2단계 | **65%** | 절반 넘게 가린다 |
| 3단계 | **100%** | 전부 빈칸 |

단계를 마치면 **가운데 창**(`showStageDoneModal`)이 뜬다. 그전에는 문장 아래에 작은 단추가 생겼는데, 긴 구절에 큰 글씨면 화면 밖이고 키보드까지 올라와 **다 외우고도 끝난 줄 모르고** 앉아 계셨다.

### 입력 두 가지

- **⌨️ 쓰기** — 자판으로 친다
- **👆 카드** — 낱말 쟁반에서 눌러 채운다. 자판이 어려운 분을 위한 길이고, 설정에서 **늘 카드로 시작**하게 둘 수 있다

기록은 `learn-typing` · `learn-typing-card` · `learn-voice`로 남는다.
⚠️ **카드 이름에 `typing`이 들어가야** 순위·통계의 `%typing%` 집계가 지금까지와 똑같이 유지된다.

### 복습 (간격반복)

3단계를 마치면 자동으로 예약된다. Leitner 상자 5칸 — **3 · 7 · 14 · 30 · 60일**. 맞히면 다음 칸, 틀리면 1칸으로.

### 도전 (`renderChallenge`)

외운 구절을 무작위로 낸다. 다섯 번에 한 번은 **🔥 어려운 도전** — 빈칸 밑줄을 지운다(3단계까지 마친 구절에서만 고른다).

### 암송 도우미 — 네 탭

```
💡 풀이     쉬운 말로 (AI가 미리 만들어 둔 것)
🧠 기억법   끊어읽기·대구·첫글자
🌐 영어     NIV 본문 (있는 구절만)
🖼️ 그림     말씀 연상 그림 34장 — 2026-08-28 추가
```

**🖼️ 그림**은 글자가 없어 언어와 무관하다. `img/verse/<번호>.webp`가 있는 구절만 탭이 뜨고, 어느 구절에 그림이 있는지는 `VERSE_IMG` 한 곳에서 관리한다.

| `reviews` | 간격반복 예약 (`box`, `due_at`) |
| `push_subscriptions` · `push_log` | 알림 구독과 발송 이력 |
| `board_posts` · `board_replies` · `board_reactions` | 게시판 |

| `pilsa_orders` | 필사 신청 |
| `event_entries` | 이벤트 응모 |
| `passages` · `passage_progress` | 긴 본문 암송 |
| `app_config` | 배포 없이 고치는 값 (마음에 둠 문구, 인트로 슬라이드, 필사 담당자…) |

**형제 앱 것** — `sermon_chunks` · `sermon_ai_cache` · `sermon_chat_log`. 같은 프로젝트를 세 앱이 나눠 쓴다. `sermons` 표도 말씀 아카이브 것인데 **이 앱이 읽는다**(오늘의 묵상 · 쉬운 풀이 · 기억법).

### 집계표가 핵심이다

`daily_activity(day, user_id, mode, cnt)`에 **`challenge_log`의 INSERT·DELETE 트리거**가 걸려 있다. **앱이 아니라 DB가 지킨다.**

```
로그 20,809행  =  집계 952행
전체 기간 순위 조회  2,903ms → 516ms
```

로그는 총 횟수만큼 늘지만 집계표는 **참여자 × 활동일수**만큼만 는다. 순위·mydays가 로그 대신 이걸 읽고, 실패하면 옛 경로로 조용히 되돌아간다.

`monitor`가 매일 **로그 행수와 집계 합계를 대조**해 어긋나면 경보한다.

## 8. 지켜야 할 규칙과 그 이유

여기가 이 문서의 값어치다. **코드만 읽어서는 알 수 없고, 어기면 조용히 깨지는 것들**이다.

### 🔴 `user_id`는 어떤 응답에도 실리면 안 된다

이 API는 JWT가 없어 **클라이언트가 준 `user_id`를 그대로 믿는다.** 남의 `user_id` 하나면 그 사람 행세로 글쓰기·진도 저장·순위 응원·필사 신청이 된다. 공개 키는 앱 코드 안에 있어 누구나 가진 것이나 같다.

- `boardList`는 `isMine` 참/거짓만 내려준다 (2026-08-24에 `select("*")`를 통째로 펼쳐 유출된 적 있음)
- 순위 응원 대상은 **화면에 보이는 신원 네 조각**으로 지목하고 서버가 `identity_key`로 되짚는다
- `rankCheerers`는 **부른 사람 본인 것만** 돌려준다 — 남의 명단을 물어볼 길이 없다

### 🔴 뷰(view)는 RLS 대상이 아니다

RLS는 테이블에 걸린다. 뷰는 만든 사람 권한으로 실행되어 **밑 테이블의 RLS를 지나간다.** `anon`에게 SELECT가 남아 있으면 PostgREST가 그대로 내보낸다.

**표를 새로 만들면 그 자리에서 `enable row level security`. 뷰를 만들면 `revoke all from anon, authenticated` + `security_invoker = on`.**

점검: 공개 키로 `GET /rest/v1/{이름}?select=*&limit=1` — 행이 오면 열려 있는 것이다.

### 🟠 `challenge_log.mode`는 CHECK 제약이 있다

새 값을 그냥 보내면 **기록이 통째로 막힌다.** 예전에 `learn-typing-stage3`로 그런 적이 있다. 제약을 넓히는 SQL을 먼저 돌리고, **서버에는 폴백**을 둔다 — 거부되면 조용히 옛 값으로 되돌린다. **구분보다 기록이 먼저다.**

### 🟠 배포는 `python tools/bump.py` 한 번

`?v=` 캐시태그(app.js·style.css·js/\*.js) · 스플래시 판 번호 · `APP_BUILD`가 함께 올라간다. **손으로 고치면 하나를 빠뜨리고, 그 파일만 옛것이 남는다.**

`?v=`는 브라우저 캐시만 무력화할 뿐 **파일 내용을 고르지 않는다.** 배포 직후 CDN이 옛 파일을 내보내면 브라우저가 그 옛 내용을 새 주소 아래 캐시한다 — 그래서 app.js가 자기 `APP_BUILD`와 index.html의 `?v=`를 비교해 다르면 한 번만 새로고침한다(마지막 안전장치).

### 🟠 배포 확인은 「이번 판에만 있는 표식」으로

이전 판에도 있던 함수명·클래스명으로 검사하면 **CDN이 옛 파일을 줘도 통과해** 「배포 완료」로 오인한다(2026-08-25에 두 번).

### 🟡 글꼴 CSS를 `rel="stylesheet"`로 두지 말 것

한글 웹폰트 넷을 부르면 구글이 돌려주는 CSS 하나가 **765KB**다(app.js보다 크다). 그대로 두면 **다 받을 때까지 스플래시조차 안 뜬다.** `media="print" onload="this.media='all'"`로 미룬다.

### 🟡 큰 글씨 설정을 잊고 `em`으로 폭을 고정하지 말 것

글씨 크기 설정이 있어 `em`이 함께 커진다. `xl`이면 `.word-input` 27px → 7.5em = **202px** — 한 줄에 한 칸씩만 들어가 화면이 무너진다.

### 🟡 게시판 사진은 반드시 캔버스로 다시 그려 보낸다

두 가지 이유다.

1. **크기** — 1280px·품질 0.8은 한 장이 1MB를 넘겨 폰에서 「Failed to fetch」가 났다. 1080px·품질 0.7(300KB 근처)로 낮추니 됐다. 서버·CORS·서비스워커·배포는 모두 무죄였다
2. **EXIF의 GPS** — 그대로 올리면 집에서 찍은 사진에 집 주소가 붙어 공개 게시판에 올라간다. 캔버스로 다시 그리면 화소만 남는다

### 🟡 사용자가 켜 둔 설정을 새 기능이 조건부로 무시하지 말 것

「반복해서 쓰기」·「자동으로 계속 도전」 같은 토글은 **그분이 그렇게 하기로 정한 것**이다. 예외를 둘 때는 그 자리에 이유를 적는다.

## 9. 운영과 개발 (2026-08-27 분리)

```
gocheok.onlybible.kr  →  xnomlgydifiqiybervtf   운영
그 밖의 모든 주소      →  ktpwthwqzgcqcrmsafdo   개발
```

`js/config.js`가 **주소를 보고 저절로 고른다.** 사람이 손으로 바꾸지 않는다. **기본값이 개발 쪽인 것이 핵심** — 모르는 주소가 생겨도 운영에 붙지 않는다.
