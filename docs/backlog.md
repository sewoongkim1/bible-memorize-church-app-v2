## 3. 굳혀 둔 일하는 방식 (다시 사고 내지 않으려고 만든 것)

| 무엇 | 왜 생겼나 |
|---|---|
| `python tools/bump.py` 한 번으로 판 올리기 | 캐시태그를 손으로 고치다 하나를 빠뜨리면 옛 파일이 남는다 |
| `tools/preflight.py` 가 배포 앞을 막음 | 문법 오류·태그 불일치 판이 성도님께 나가는 것을 원천 차단 |
| 주소로 운영/개발 DB 자동 선택, 「개발 DB」 띠 | 시험하다 성도님 기록을 건드리는 것 방지 |
| SQL·Edge Function 은 **개발 먼저** | 운영 마이그레이션은 되돌릴 수 없다 |
| 새 기능은 **노출 게이트**를 달고 시작 | 푸시가 곧 배포라 미완성이 그대로 나간 적이 있다(9/10) |
| 배포 확인은 **이번 판에만 있는 표식**으로 | CDN 이 옛 파일을 줘도 통과해 「배포 완료」로 오인한 적 두 번(8/25) |
| `user_id` 는 어떤 응답에도 싣지 않음 · 새 표는 RLS 즉시 | JWT 없는 API라 `user_id` 하나로 남 행세가 된다 |
| 여러 세션이 같은 체크아웃 → 내 헝크만 커밋 | 남의 미완성 작업이 딸려 나간 사고가 여러 번(마지막 9/24) |
| 「사실이 아닌 말을 화면에 쓰지 않는다」 | 개인정보 도움말 세 곳이 틀렸던 일(8/24), 저녁 알림 문구(0판) |

## 5. 앞으로의 계획 (제안)

분석이 말하는 것은 하나다 — **새 기능보다 이미 온 분을 붙잡는 것.** 그래서 순서를 이렇게 제안한다.

### 이번 주 (9/24 ~ 9/30) — 약속한 날짜부터
1. 저녁 알림 **1판**을 개발 → 운영으로 배포하고 **아이폰 푸시 부활**을 실기기로 확인 (13대가 알림을 못 받고 있다)

3. 9/30 이벤트 마감 공지와 함께 **가을 말씀 동행 예고**

### 10월 상순 (10/1 ~ 10/11) — 첫날 붙잡기
1. **첫날 둘째 구절까지** 구현 (분석 1순위, 가장 싸고 효과 큼)
2. 저녁 알림 2판 → 3판(실제 발송 시작) → 4판(첫 구절 완료 뒤 알림 초대)
3. 10/7 숫자 보기: 쉴만한 물가 전환율 · 복습 카드 효과
4. 10/11 가을 말씀 동행 측정 시작

1. 우리 교구 순위 · 복습 카드 · 저녁 알림을 **숫자로 판정**하고 효과 없는 것은 되돌린다
2. 가을 이벤트 신청 창(10/27~11/28) 운영
