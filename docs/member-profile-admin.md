# 관리자 이름·소속 변경

관리자 허브 → **성도 정보 관리** → 현재 이름 검색 → 성도 선택 → 이름·소속 및 변경 사유 입력 → 변경 전후 확인 → 저장.

## 동작

- `users.id`를 그대로 유지하고 이름·구분·교구·목장·부서·학년과 `identity_key`만 변경한다. 암송 진도·로그·복습·신청·응원·알림 구독의 사용자 연결은 유지된다.
- 이전 `identity_key`는 `user_identity_aliases`에 예약한다. 기존 기기와 구버전 앱이 옛 정보로 `login`해도 같은 사용자와 현재 프로필을 반환하며, 옛 프로필을 다시 저장하지 않는다. 여러 번 변경하거나 원래 정보로 되돌려도 같은 사용자다.
- 최신 클라이언트는 동기화 때 서버의 이름·소속을 저장하고 이름 기반 로컬 한글·영어 진도도 이전한다. 변경 전 로컬 기록을 삭제하지 않는다. 사용자 번호가 다른 응답에는 로컬 진도를 이전하지 않는다.
- 변경 내용이 다른 사용자의 현재 정보 또는 예약된 이전 정보와 겹치면 저장하지 않는다. 같은 이름만으로 합치지 않는다. 이미 나뉜 두 사용자 기록의 병합은 이 기능에 포함하지 않는다.
- 변경 전 식별자가 다른 관리자의 수정으로 달라졌으면 재검색을 요구한다. 저장·별칭·이력·필사 담당자 설정 변경은 한 트랜잭션이다. 실패하면 전부 롤백된다.
- `pilsaAdmins`의 기존 식별자도 새 식별자로 교체하므로 필사 신청 담당자 알림이 끊기지 않는다.
- 과거 게시물·신청서에 별도로 저장된 작성 당시 이름·소속 문자열은 역사적 표기로 남는다. 사용자 번호가 있는 게시물은 이름 변경 후에도 본인 글 조회·삭제가 가능하다. 번호가 없는 오래된 게시물의 소유권 이전은 포함하지 않는다.
- 교구·목장 통계는 현재 `users`를 조인하는 기존 방식이다. 소속 변경 시 과거 활동도 새 소속으로 집계된다. 활동 당시 소속별 통계를 유지하는 기능은 별도다.
- 이력은 관리자 인증 후 최근 20건을 표시한다. 비밀번호를 이력에 기록하지 않는다. 공유 관리자 비밀번호 방식이므로 개별 관리자의 실명은 구분하지 못한다.

## 적용 순서

개발에서 먼저 확인한 뒤 운영에도 같은 순서로 적용한다.

1. `supabase/member_profile.sql` 실행 (`schema.sql`과 `app_config.sql`이 먼저 필요).
2. `supabase/functions/api/index.ts`를 `api` Edge Function으로 배포.
3. `admin-members.html`, `js/admin-members.js`, `admin.html`, `app.js`, `index.html` 프론트 변경 배포.
4. 가상 성도로 이름·목장 변경 후 옛 정보/새 정보 양쪽의 로그인과 기록 유지 확인. 운영에서 가상 성도를 만들지 않는다.

새 API의 로그인은 `member_login` RPC가 필요하므로 **SQL보다 먼저 API를 배포하면 안 된다.** 이력 테이블과 별칭에는 RLS를 켜고 공개 역할의 권한을 거두며 RPC도 `service_role`에만 허용한다. 관리자 API는 기존 `adminError` 검증 후 호출한다.

로그인과 변경은 동일한 트랜잭션 잠금으로 순서를 보장한다. `users`의 삽입/식별자 변경 트리거도 별칭 충돌을 막아 구버전 API·일괄 가져오기가 옛 식별자로 새 사용자를 만드는 일을 방지한다. 변경 기능을 사용한 뒤에는 기존 upsert 방식의 로그인 API로 되돌리지 않는다(옛 정보 로그인 시 충돌로 실패할 수 있음).

기존 이름·소속만으로 로그인하는 접근 모델을 유지한다. 별칭은 본인 인증 수단이 아니며, 기존 정보를 아는 사람이 로그인할 수 있다는 기존 한계를 개선하는 기능은 아니다. 기기 토큰·본인 확인·복구 코드는 별도 작업이다.

## 로컬 검증

실제 DB에 연결하지 않고 PGlite의 PostgreSQL과 jsdom으로 테스트한다. 의존성은 저장소 밖에 설치한다.

```powershell
$memberTestDir = Join-Path $env:TEMP 'codex-member-profile-tests'
npm install --prefix $memberTestDir --no-package-lock --no-audit --no-fund @electric-sql/pglite@0.3.14 typescript@5.9.3 jsdom@26.1.0
$env:NODE_PATH = Join-Path $memberTestDir 'node_modules'
node --test tests/member-profile.test.cjs
```

검증 범위: 이관 전후 기록·번호 유지, 이전/새 식별자 로그인, 중복·경합 방지 조건, 교회학교 이동, 반복 변경, 원복, 트랜잭션 실패 롤백, 공개 역할 접근 차단, 관리자 인증·입력 검증, 로컬 진도 이전, 검색·확인·저장·이력 화면 동작.
