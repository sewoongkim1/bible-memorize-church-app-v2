- **시편 말씀 액자 = 「쉴만한 물가」(2026-09-10 개발 · **2026-09-12 개시** · 게이트 켬 2026-09-11):** 시편·잠언·전도서 180구절을 **하루에 한 편씩** 열어 액자 그림 안에서 **0단계(읽고 듣기) → 1(25%) → 2(65%) → 3(전체 빈칸)** 으로 외운다. **2026-09-12(토) 1일차 → 2027-03-10(수) 180일차**(처음 계획은 9/21). 화면은 `js/psalm.js` 한 파일, 설계는 `docs/superpowers/specs/2026-09-10-psalm-frame-design.html`(14장), 계획은 `docs/superpowers/plans/2026-09-10-psalm-frame.md`.
  - **같은 표, 번호대만 나눈다** — `verses` 에 `track`·`day_no`·`frame_art` 를 더하고 시편은 **`no = 1000 + day_no`**(1001~1180). `progress`·`challenge_log`·`reviews` 가 이미 `verse_no` 로 묶여 있어 **순위와 복습이 저절로 함께 돈다.** 서버는 `getVerses` 만 갈래를 타고 나머지는 한 줄도 안 고쳤다.
  - ⚠️ **`challenge_log.mode` 를 새로 만들지 않았다** — 시편은 `verse_no ≥ 1001` 로 이미 갈린다. 클라이언트는 주간 화면과 똑같이 `"typing"`/`"card"` 를 보내고 서버가 `learn-*` 로 옮긴다. **`learn-` 을 직접 보내면 안 된다.** 새 값을 만들었다면 CHECK 제약에 걸려 기록이 통째로 막혔을 자리다.
  - ⚠️ **잠금은 「안 열린 구절을 응답에 아예 안 싣는 것」이다** — 화면에서 가리는 게 아니다. 폰 시계를 바꿔도 못 연다. 그래서 **180편이 든 정적 JSON 폴백을 만들지 않는다.**
  - ⚠️ **노출 게이트 `psalmVisible()`**(`app_config('psalmPublic')`, 기본 꺼짐, `?psalm=1` 미리보기). **처음부터 달았어야 했다** — 아래 「여러 세션」 절 참고.
  - ⚠️ **배포 순서는 함수가 먼저, SQL이 나중이다.** 시드가 `verses` 표에 행을 더하는데, 옛 함수는 track 필터가 없어 `is_active` 인 것을 전부 돌려준다 → 성도님 말씀 목록이 「전체 45구절」이 된다. 그래서 시드를 **`is_active=false`** 로 넣고 활성화 한 줄을 주석으로 분리했다. **새 표에 새 액션만 얹는 기능은 반대다**(표가 먼저).
  - ⚠️ **다섯 줄 규칙은 3단계(전체 빈칸) 기준으로 잰다** — 빈칸이 낱말마다 1em 넓어져, 0단계 기준으로 맞추면 3단계에서 6~7줄이 된다. 잣대는 **`글자수 + 낱말수 ≤ 76`**. 다만 **320px 폰의 실질 상한은 70 근처**라 76은 그보다 낙관적이다. `python tools/psalm-measure.py --fake --stage 3 --width 320` 으로 잰다.
  - ⚠️ **글씨는 화면 폭을 봐야 한다** — 고정값(1370px)으로 두었더니 320px 폰에서 상한 안쪽 구절까지 넘쳤다. `psalmUsablePx()` 가 실제 폭으로 계산한다. 그리고 `html[data-fs]` 규칙이 특이도로 이겨 **큰 글씨 설정을 켠 분에게 빈칸만 다른 크기**가 되던 것을 `html[data-fs] .ps-fr-body .word-input` 로 막았다.
  - ⚠️ **어두운 모드는 `.dark` 하나다.** `data-theme` 도 `prefers-color-scheme` 도 이 앱은 안 쓴다(`.dark` 규칙 453개 vs `data-theme` 0개). 그걸 모르고 쓴 CSS 는 **절반이 죽고 절반이 엉뚱할 때 켜졌다.** 새 화면을 지을 때 `.pr-frame` 의 어두운 모드 규칙을 보고 따라 쓸 것.
  - ⚠️ **`no` 는 진도의 키다.** 한 번 열린 번호를 다른 구절에 재배정하면 이미 마친 분의 기록이 엉뚱한 구절에 붙는다. 추가는 뒤에만. **`verses` 에서 `delete` 금지** — `on delete cascade` 가 성도님 기록을 함께 지운다. `tools/psalm-fit.py` 가 번호 재배정을 감지하면 생성을 거부한다.
  - **자료 흐름**: 담당자 엑셀(`psalm/시편말씀액자_구절입력_180.xlsx`, 길이 판정이 수식으로 들어 있어 붙여 넣는 즉시 빨간불) → `python tools/psalm-fit.py [--fix] [--sql]` → `supabase/psalm_frames.sql`. **본문은 사람이 붙여 넣는다** — 성경은 AI 가 지어내면 안 되는 자리다. 도구는 길이·꼴·중복·절 번호 딸림은 잡지만 **출처↔본문 일치는 못 본다.**
