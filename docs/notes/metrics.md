## 열람 기록 (`feature_log`) — 2026-09-23 배포

그때까지 **시편 액자·매일 묵상·말씀 앨범·사용 설명서·푸시 열람**은 서버에 흔적을 하나도 안
남겼다. 「쓰임이 적다」가 아니라 **「쓰임을 알 수가 없다」**였다 — 카드 모드를 여덟 달 동안
못 쟀던 것과 같은 일이 다섯 군데에서 벌어지고 있었다. 그래서 `blessing_log` 가 이미 검증한
모양(하루 × 사람 × 항목 = 1행, 다시 봐도 `cnt` 만 오름)을 **통합 표 하나**로 일반화했다.

- **표** `public.feature_log` — 기본키 `(user_id, day, feature, item)`, `day` 는 **한국 시간** 기준
- **액션** `featureLog` — 허용 목록은 `supabase/functions/api/index.ts` 의 `FEATURES` **한 곳**
- **설계** `docs/superpowers/specs/2026-09-23-feature-log-design.md`

`feature` 값(2026-09-23 배포 시점. **늘어난다** — 지금 값은
`select distinct feature from public.feature_log` 로 본다):

| `feature` | 언제 | `item` |
|---|---|---|
| `psalm` | 시편 액자 한 편을 펼침 | 구절 번호(`1000 + day_no`) |
| `meditation` | 첫 화면 **「오늘의 묵상」 단추** | 그 주 구절 번호 |
| `meditation-widget` | **위젯**을 눌러 열림(`?w=meditation`) | 그 주 구절 번호 |
| `meditation-auto` | 하루 한 번 **저절로** 뜸 | 그 주 구절 번호 |
| `album` / `album-play` | 앨범을 엶 / 듣기를 시작함 | 0 |
| `guide` | 사용 설명서를 엶 | 0 |
| `push` | 알림을 눌러 앱이 열림(`?from=push`) | 0 |
| `ranking-scope` | 순위 범위 칩 | **깃발**이다 — 1=우리 교구 · 0=전체 |
| `event` | 이벤트 화면을 엶 | 0 |
| `song` | 오늘의 찬양을 엶 | 0 — ⚠️ **서버 안쪽 호출**이라 `FEATURES` 관문을 안 거친다(`index.ts` 의 `logSongClick`) |

**보는 법은 손으로 짜지 말 것** — 질의는 두 파일에 박아 두었다.
`supabase/feature_log.sql`(기능별 한눈에 · 날짜별 추이 · 능동 대 수동 · 앨범 새는 자리 ·
사람별 본 날수 · 소속별)과 `supabase/psalm_metrics.sql`(시편 닿는 범위 · **전환율** ·
이어 보는 정도 · 어느 편이 읽히나 · 묵상과의 겹침).

### ⚠️ 이 숫자를 읽을 때 (전부 한 번씩 틀릴 뻔한 자리다)

1. **배포(2026-09-23) 전 열람은 영영 없다.** 시편은 9/12 개시, 묵상·앨범·설명서는 그보다 훨씬
   오래됐지만 **이 표에는 9/23부터만 쌓인다.** 「9월 초에 아무도 안 봤네」는 사실이 아니라
   기록이 없는 것이다. **그래서 시편 전환율을 뜻있게 보는 시점은 개시일이 아니라
   배포일 + 2주 = 2026-10-07 이다.**
2. **시편 전환율은 `min(day)` 로 바닥을 깐다.** `seen`(액자를 본 분)은 9/23부터만 쌓이는데
   `memo`(암송한 분, `challenge_log`)는 **처음부터 다 있다** — 9/23 이전에 이미 14명·248회가
   들어가 있었다. 바닥을 안 깔면 「9/15에 외운 분이 9/25에야 액자를 처음 폈다」까지 전환으로
   세어져 **전환율이 위로 부푼다.** `psalm_metrics.sql` ②가 `created_at >= (select min(day) …)`
   로 양쪽을 다 볼 수 있는 기간만 놓고 잰다.
3. **여기서는 `daily_activity` 가 아니라 `challenge_log` 를 읽는 것이 맞다.** 평소 규칙은
   「순위·`mydays` 는 집계표를 읽는다」인데, **집계표에는 `verse_no` 가 없어** 「시편 구절인지」를
   가릴 수가 없다. 이건 순위가 아니라 시편만 골라 세는 질의다 — 집계표로 바꿔 짜면 숫자가
   오류 없이 조용히 틀어진다.
4. **⚠️ `meditation` 은 2026-09-23 하루치에 관리자 미리보기가 섞여 있다.** `?preview=daily` 가
   그날 오후까지 `meditation` 으로 남았다. 같은 날 고쳐 **그 이후로는 안 섞인다**(미리보기는
   아예 기록하지 않는다). 9/23 하루만 `meditation` 이 실제보다 높게 보인다 — 첫 주 숫자를
   인용할 때 이 하루를 빼거나, 최소한 그렇다고 밝힐 것.
5. **`meditation` ÷ `meditation-auto` 로 나누지 말 것.** 세 갈래는 서로 겹쳐서 100% 를 넘는다.
   분모는 **합집합**이다 — 「묵상을 본 분」 = 셋의 합집합, 「스스로 찾아 연 분」 =
   `meditation` ∪ `meditation-widget`(위젯 탭도 일부러 누른 능동이다).
6. **`guide` 는 「설명서를 본 사람」이 아니다.** `guide/` 는 일부러 로그인 없이 열리는 페이지라,
   로비 QR·주보로 들어온 분은 안 세어진다 — **「앱에 로그인한 채 설명서를 누른 사람」**이다.
7. **`feature` 값을 늘리면 `supabase/feature_log.sql` 머리의 「item 의 뜻」 표도 그 자리에서
   함께 고친다.** 이 표는 **여러 세션·여러 기능이 함께 쓰는 공용 표**라, 배포 하루 만에 다른
   두 세션이 이미 값을 더 쓰고 있었다(`song`·`ranking-scope`). 안 고치면 다음에 보는 사람이
   목록에 없는 값을 「데이터가 오염됐나」로 오해한다.
