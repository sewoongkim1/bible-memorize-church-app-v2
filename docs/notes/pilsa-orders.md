## 성경필사 노트 신청 (2026-08-11)
A5/A4 · 아래쪽/오른쪽 필사형 · 번역본 5종 · 성경 31단위 부수(한 분 총 **5부**까지) · 휴대폰(필수) · 요청사항.
**A5**와 **한영·영한**은 한 부가 **2권**으로 나온다 — 상한은 고른 부수(5부) 기준이라 A5로도 5부(=10권) 신청할 수 있고, 권수·금액만 2배로 계산한다(`pilsaMult` / 서버 `pilsaMultOf`, 저장되는 `total`은 실제 권수).
상태 흐름 **신청완료 → 준비중 → 준비완료 → 배부완료** — 성도는 신청완료에서만 고치거나 취소할 수 있고, 배부완료면 새로 신청.
수령은 4층 새가족실 방문, 권당 3,000원(찾을 때 지불). **배부완료로 바꾸면 서버가 휴대폰 번호를 비운다**(`pilsaSetStatus`, 2026-08-24 — 개인정보 안내가 약속한 것을 사람 기억에 맡기지 않는다). 되돌릴 수 없어 관리자 화면이 한 번 묻고, 지운 뒤 카드에서 번호가 바로 사라진다. 「번호 없음」은 처음부터 없는 것과 구분해 **「번호 없음 · 배부 후 삭제」**로 쓴다. **준비완료로 바꾸면 앱 알림을 켜 둔 분께 Web Push 1회**(notified_at), 켜지 않았으면 관리자 화면이 휴대폰 번호로 연락하라고 알려 준다. 관리자 화면은 **보냄 / 안 켜심 / ⚠️ 발송 실패** 셋을 구분해 보여 준다 — 실패를 '안 켜심'으로 뭉뚱그리면 푸시가 고장 나도 아무도 모른다(`pushError`). **반대로 성도가 신청·수정하면 담당자에게 Web Push**가 간다(`pilsaNotifyAdmins`). 받는 사람은 `app_config.pilsaAdmins`(identity_key 배열)에 두고 `supabase/pilsa_admin_notify.sql`로 등록한다 — 저장소가 공개라 이름·user_id를 코드에 박지 않고, 담당자가 바뀌어도 배포가 필요 없다. **등록하지 않으면 아무에게도 가지 않는다.**

## 단추를 화면 아래에 못 박았다 (2026-09-23)
신청·확인·「내 신청」 세 화면의 단추(`.pl-acts.sticky`)를 **`position:fixed`** 로 바꿨다. 성경 31단위를 훑다 보면 화면이 길어져, 끝까지 내리기 전에는 「신청」이 보이지 않았다.
⚠️ **`position:sticky` 로는 안 붙는다** — 클래스 이름이 `sticky` 이고 CSS 도 `position:sticky` 였는데 **실제로는 거의 붙지 않았다.** `body` 에 `overflow-x:hidden` 이 걸려 있어 `body` 가 스크롤 상자가 되는데 정작 스크롤은 문서(`html`)가 한다 — sticky 는 그 body 를 기준으로 계산해 움직일 일이 없다. 게다가 `.pilsa-screen` 의 아래 여백이 72px 뿐이라, 붙는 구간도 그 72px 뿐이었다. **사역신청 `.min-acts` 가 2026-09-18 에 성도님 제보로 이미 겪은 것과 같은 자리다**(`style.css` 그 자리의 ⚠️ 를 그대로 옮겨 적어 두었다).
- 모양·수치는 `.min-acts` 를 그대로 따랐다: `bottom: calc(10px + env(safe-area-inset-bottom))` · `width: min(560px, 100% - 40px)` · 둥근 반투명 막대 · `#update-banner` 가 뜬 동안만 68px 올림.
- **여백은 `.pilsa-screen` 이 진다** — `calc(96px + env(safe-area-inset-bottom, 0px))`(`.min-screen` 과 같은 값). ⚠️ env() 를 여백에도 넣어야 한다(단추가 안전영역만큼 올라가므로).
- 단추가 셋(수정하기·취소·뒤로)이면 좁은 폰에서 글자가 두 줄로 접힌다 — `pl-acts-3`(app.js 가 `btns.length >= 3` 일 때 붙인다)으로 글씨·여백을 줄여 한 줄로 고정. 사역신청의 `min-acts-3` 과 같은 처리다.
- 잰 값: 390px 폭에서 맨 아래까지 내렸을 때 마지막 입력칸(요청사항)이 막대보다 **55px 위**에서 끝난다(막대 높이 64px). `python tools/screen-sweep.py --steps 14-pilsa` 8조건 모두 통과(가로 넘침·홈 막대 걸림 0).

## A5는 지금 신청받지 않는다 (2026-09-23)
화면에서 **A5 단추를 못 누르게** 막았다(`PILSA_SIZE_OFF` — 값이 곧 단추에 적히는 이유다). 다시 받으려면 그 줄에서 빼면 되고, 다른 곳은 손댈 것이 없다.
⚠️ **목록(`PILSA_SIZE`)에서 지우지는 않았다** — 이미 A5로 신청하신 분이 「수정」을 누르면 그분의 크기를 그대로 보여 주어야 하고, 2권 계산(`pilsaMult`)도 살아 있어야 한다. 그 화면에서 A5는 **고른 상태 그대로 흐리게** 뜬다(고를 수는 없다).
⚠️ **서버는 그대로 A5를 받는다**(`pilsaApply`·`pilsaMultOf`). 옛 신청을 고쳐 저장하는 길이 막히면 안 되기 때문이다 — 화면만 막은 것이고, 막는 곳을 서버까지 넓히면 그분들이 수정도 취소도 못 하게 된다.
- 문구도 함께 맞췄다: 부수 안내의 「A5와 한영·영한은 2권」은 **A5를 고른 상태일 때만** 그렇게 쓰고, 그 밖에는 한영·영한만 말한다. 설명서 단계의 「노트 크기(A5·A4)」도 「노트 크기」로 줄였다.

- 첫화면(renderSummary)의 「✍️ 성경필사 노트 신청」 버튼으로 들어간다(응원·기도·공감 게시판과 찬양 아카이브 사이). `index.html?preview=pilsa`로도 같은 화면.
- 관리자: admin-stats.html → 신청자 카드 목록. 상태 체크박스(신청·준비·완료·배부, 기본 신청)로 추리고, 카드의 「✉️ 문자」가 담당자 폰의 문자 앱을 문구까지 채워 연다(문자 API 미연동).
