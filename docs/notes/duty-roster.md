# 봉사 당번 (2026-10-06 ~)

식당 설거지처럼 **「날짜 × 예배(조) × 일 × 정원」 자리에 성도님이 지원**하고 담당자가 관리하는 틀. 김장 같은 한 번짜리 모집도 같은 틀로 받는다.
설계 `docs/superpowers/specs/2026-10-06-duty-roster-design.md` · 계획 `docs/superpowers/plans/2026-10-06-duty-roster.md`.

> **지금 어디까지(2026-10-07):** **1·2·3단계 운영 반영** — 표·SQL 함수 · 교회 어드민 담당자 화면(🧰 당번 관리 · 📅 당번 명단) · 성도님 앱 화면(날짜가 많으면 달력)과 `api` 성도님 액션 여섯(2단계) + **지난 봉사**(일곱째 액션 · 2026-10-07) · **앱 알림**(3단계 — 확정 · 전날 저녁 · 담당자가 바꾼 것 · 잠긴 날 지원).
> 공개(4단계)는 아직이다. **문 `dutyOpen` 이 없어 성도님께는 보이지 않는다** — 🧪 시험 참여자만 첫 화면 「교회」 묶음의 🙋 봉사 당번을 본다(웹·아이폰 · 플레이스토어 앱은 심사 동안 숨김).

## 뼈대

**당번(`duty_boards`) → 자리 틀(`duty_lines`) → 날짜(`duty_days`) → 자리(`duty_slots`) → 지원(`duty_signups`)**

- **자리 틀** = 「매주 주일 · 2부 · 설거지 · 11:30~12:30 · 2명」. 요일이 있는 틀은 **자리가 저절로 생긴다**(`duty_ensure_slots` — 읽는 함수들이 먼저 부른다 · 오늘 ~ 오늘+보이는 기간 · 끝 날짜까지). 요일이 없는 틀은 「날짜 더하기」(`duty_date_add` · 자리에 `manual = true`)로만 — 한 번짜리 모집·특별 예배.
- **날짜 줄**은 쉼(`off`)과 확정(`confirmed_at`)을 **따로** 가진다(쉼을 풀어도 확정 여부는 그대로). 날짜 줄을 지우는 길은 없다 — 그래서 만드는 날짜는 모두 **오늘 + 400일 안**(날짜 더하기 · 쉬는 기간 · 메모).
- **지원 줄은 자리·사람에 한 줄**(다시 지원하면 그 줄을 되살린다). 계정 없는 분(담당자가 넣은 새가족·명부의 분)은 `ident_key` 로.
- 당번 상태: `draft` 준비(앱에 안 보임) · `open` 받는 중 · `closed` 지원 멈춤(앱에 명단은 보이고 새 지원만 막음 — **담당자가 넣는 당번**도 이 상태) · `archived` 보관(안 보임 · 쓰기 거절 · 지우는 길은 없다).

## 규칙 (전부 SQL 함수 — 코드에서 표에 직접 쓰지 않는다)

- **잠금은 표에 쓰는 값이 아니다.** `duty_locked` = 담당자가 확정했거나 지금이 그날 **전날 19:00(한국)**을 지났다. 크론이 잠그지 않는다. 「19시」는 `duty_cutoff` 한 곳.
  잠긴 날: 본인은 취소·변경 못 함 · 빈 자리 지원은 받되 `ack_locked` 를 보내야 들어간다(아니면 `locked-day` — 화면을 열어 둔 사이 잠긴 경우도 서버가 잡는다).
  확정은 **자리가 있는 날에만**(`no-slots`) · 풀 것·지울 메모가 없으면 날짜 줄을 만들지 않고 `already`.
- **쉬는 날은 스위치**다 — 지원 줄을 건드리지 않는다. 쉬는 동안 찬 수·겹침·전날 알림에서 빠지고, 다시 열면 그대로 살아난다.
- **끝 날짜(`until_date`)** 뒤의 자리는 앱에 안 보이고 지원도 안 받는다(`after-until`). 자리·줄은 지우지 않는다(늦추면 살아난다). 그 뒤에 선 분 수는 `duty_after_count`.
- **남은 자리**(`duty_leftover` — 뺀 틀의 자리 · 요일을 바꾼 틀의 옛 요일 자리)는 성도님 지원을 받지 않는다(`closed`). 담당자는 넣고 옮길 수 있다.
  요일을 바꾼 틀의 남은 자리는 「날짜 더하기」로 **다시 살린다**(`reopened` — `manual = true` 가 되어 그날만 받는다). `manual` 자리는 요일을 바꿔도 지우지 않는다.
- 담당자가 **뺀** 줄은 본인이 스스로 되살리지 못한다(`removed-by-staff`) · 담당자가 **넣은** 줄은 본인이 스스로 빼지 못한다(`staff-row`) → 「못 가게 됐어요」(`duty_ask`)로 알린다.
  담당자가 잘못 뺀 줄은 `duty_restore` 로 **그 줄 그대로** 되살린다(정원·겹침은 넣기와 같은 규칙 · `p_force`).
- **같은 분**(`duty_same_person`) = 계정이 같다 · 또는 **명부 키(`person|교인ID`)가 같다** · 또는 둘 다 계정이 없고 키가 같다. 명부에서 넣은 줄과 그분의 앱 계정 줄이 따로 놀지 않게 —
  계정 없는 줄로 서 있는 분을 담당자가 계정까지 찾아 다시 넣으면 그 줄에 계정을 잇고 `linked` 로 알린다(「이미 서 계세요」지만 쓴 것이 있다 → 교회 어드민이 기록을 남긴다).
- 겹침 = 같은 분이 같은 날 **시각이 겹치는**(맞닿은 자리는 안 겹침) 다른 자리에 살아 있다. 당번이 달라도 본다. 담당자는 확인 뒤 `force`. 정원 거절(`full`)에도 겹친 자리(`with`)가 함께 온다.
- 정원·겹침·`max_ahead` 는 동시에 눌러도 넘지 않는다(잠금 차례 — 아래).
- 주별 명단(`duty_roster`)의 기간: 끝을 안 주면(담당자 화면) 앞날은 `오늘+보이는 기간` 과 **가장 먼 날짜 줄** 가운데 늦은 쪽(오늘+400일까지), 지난 날은 오늘−400일까지 — **따로 자른다**. 끝을 주면(엑셀) 기간 400일까지(넘으면 앞을 당긴다). 보이는 기간 밖의 날은 `notYet`.

## 성도님 앱 (2단계)

첫 화면 「교회 생활」 묶음 **🙋 봉사 당번 신청**(2026-10-07 친구 요청으로 이름을 바꿨다 — 묶음은 「교회」였고 단추·화면 제목은 「봉사 당번」이었다) → 당번 목록 + 내 당번(당번이 하나뿐이고 내 당번이 없으면 목록을 건너뛴다) → 당번 자세히(날짜가 넷 이상이면 **달력**에서 날짜를 골라 그날의 자리 · 그보다 적으면 날짜마다 자리 · 선 분 이름) → 지원 · 취소 · 「못 가게 됐어요」.
액션은 `dutyList`·`dutyBoard`·`dutyMine`·`dutyPast`(지난 봉사 · 2026-10-07 — 아래 절)·`dutyApply`·`dutyCancel`·`dutyAsk` — 모두 `duty.sql` 의 함수를 부르기만 한다(`p_staff`·`p_force` 는 늘 `false`).

- **문은 두 겹이다.** 화면의 `dutyVisible()`(계정 번호가 있고 · `dutyOpen` 캐시 또는 🧪 시험 참여자 · 플레이스토어 앱은 `ministryHiddenOnPlay()`)은 **단추를 숨길 뿐**이고, 막는 것은 서버 `dutyGate` 다 —
  `users` 에 그 줄이 **실제로 있고**(꼴만 맞는 UUID 는 닫힘) `app_config.dutyOpen` 이 `true` 이거나 시험 참여자.
  ⚠️ **읽기도 막는다**(교육과 다르다 — 당번표에 선 분 이름이 나간다): 닫혔으면 읽기는 `{ok:true, open:false}` 하나(당번·이름·수 없음), 쓰기는 `not-open`.
  설정(`dutyOpen`)을 못 읽은 것은 닫힘이 아니라 오류로 던진다(닫힘이라고 답하면 화면이 「아직 열지 않았어요」라고 말한다).
- **신원은 화면이 보낸 값을 쓰지 않는다** — `user_id` 로 `users` 줄을 꺼내 이름·소속·신원 키를 만든다. 지원하지 못하는 계정은 `dutyMeWhy` 한 곳: 어린이·청소년 부서(`needsGuardian`) → `guardian` ·
  당번표에 실을 수 없는 이름(20자 넘음 · 꺾쇠·따옴표·제어·방향 바꿈 글자 · 한글 채움 글자 같은 보이지 않는 글자 · 숫자가 네 자리 넘게 이어짐) → `bad-name`.
  `dutyApply` 가 SQL 앞에서 막고, 읽기 응답의 `me.why` 로도 실어 화면이 그런 계정에 「지원하기」 단추를 두지 않는다(까닭은 자세히 맨 위 한 줄).
  겹침 거절의 `with` 는 준비 중(draft) 당번이면 이름을 싣지 않는다(`dutyOverlapOut`) · 보관한 당번의 `archived` 는 `not-found` 로 내보낸다(`dutyErrOut` — 없는 당번과 같은 답).
- **화면은 판정을 다시 하지 않는다** — 서버가 준 `why`(지원 못 하는 까닭)·`locked`·`lockAt`·`staffAdded`·`me.why` 를 보여 주기만 한다(「저녁 7시」도 `lockAt` 에서 읽는다 — 그 숫자를 화면에 적지 않는다).
  찬 자리·쉬는 자리·시작한 자리·담당자가 넣는 자리에는 단추를 두지 않는다. 잠긴 날 지원은 「취소할 수 없는 날」 창을 거쳐 `ack_locked:true` 로 —
  화면을 열어 둔 사이 잠겼으면 서버가 `locked-day`(아무것도 안 씀)로 알려 그 창을 띄운다.
- **날짜가 많으면 달력(2026-10-06 친구 요청 — 보이는 기간이 1년이면 날짜 카드가 52장이 된다)** — 날짜가 `DUTY_CAL_MIN`(4) 이상이면 한 달 달력 + **고른 날 하나의 자리**만 그린다(`dutyCalUse`).
  그보다 적으면(한두 번짜리 모집) 날짜 카드를 그대로 늘어놓는다. 매주 도는 당번은 보이는 기간 4주부터 늘 달력이라 주마다 모양이 뒤바뀌지 않는다.
  · 칸에는 날짜 아래 **「채워진 인원/필요 인원」**(`dutyCalCell` — 친구 요청). 쉬는 자리는 세지 않고, 담당자가 정원을 넘겨 넣은 자리는 정원까지만 센다(「3/3」인데 손이 필요한 날이 되지 않게).
    손이 필요한 날은 초록 · 내 당번은 남색 · 쉬는 날 「쉼」 · 고른 날은 겹테두리 · 오늘은 숫자 위 금색 줄(자리가 없는 날은 숫자 밑줄 — 밑줄이 인원 글 「3/4」에 얹히면 분수 줄처럼 보인다). 아래 풀이는 그 당번표에 실제로 있는 표시만 싣는다.
    쉬는 날 칸과 쉬는 날 카드의 줄은 `#5a6273`(순위 범위의 잠긴 단추 · 필사 「마감」 칩과 같은 값 · 5.38:1) — `--gray` 는 그 바탕(`--light`)에서 4.25:1 이다. ⚠️ **새 색을 만들지 않는다**(이 CSS 머리의 규칙): 10-07 에 대비를 맞추며 `#565c67` 을 새로 넣었다가 검토 확인에서 잡혀 이미 쓰는 값으로 바꿨다 — 색을 고칠 때는 `style.css` 에서 그 값을 쓰는 곳이 있는지부터 찾는다.
    받는 중 당번의 「담당자가 넣는 자리」(뺀 틀·요일을 바꾼 틀의 남은 자리)는 서 있는 분만 세고 **빈 칸은 필요 인원으로 치지 않는다**(서버의 「손이 필요한 수」와 같게 · 달력 함수의 `me.staffOnly` 가 지원 멈춤 당번과 가른다).
    ⚠️ 다만 **보는 분 자신의 줄이 있는** 남은 자리(서 있거나 담당자가 뺀 줄)는 줄이지 못한다 — 판정이 `mine` 이라 남은 자리인지 알 수 없어 정원을 모두 센다(정원 2 인 남은 자리에 혼자 선 분의 앱은 「1/2」 · 다른 분의 앱과 교회 어드민은 「1/1」).
    수까지 맞추려면 `duty_board_view` 가 자리마다 남은 자리인지 싣고 `dutyCalCell` 이 판정이 아니라 그 값으로 줄여야 한다(SQL·앱·시험을 함께 고치는 일 — 아직 안 했다).
    인원 글은 `「/」` 뒤에서 줄을 바꿀 수 있다(`<wbr>` — `nowrap` 을 걸지 않는다): 「100/120」처럼 긴 수가 좁은 폰의 칸을 넘쳐 이웃 칸에 묻히지 않게(내 당번 칸에서는 「00/12」로 읽힌다). 칸에 드는 수는 그대로 한 줄이다.
    ⚠️ 줄을 바꾸는 문턱이 **칸 폭**이 되도록 `style.css` 가 인원 글에 좌우 여백 −2px 을 준다(칸의 투명 테두리 2px 자리까지 쓴다 — 시험이 두 값이 같은지 본다). 그것이 없으면 문턱이 칸의 안쪽 폭이라
    폭 329px 이하에서 「10/12」처럼 칸에 드는 두 자리/두 자리 수까지 두 줄이 된다(올리기 전 확인 — 처음 고친 판이 그랬다). 달력 상자·격자·칸에 `nowrap` 을 걸지도 않는다(인원 글이 물려받는다 —
    크롬은 그래도 `<wbr>` 에서 줄을 바꾸지만 사파리·파이어폭스는 바꾸지 않아 다시 넘친다 · 크롬 탐침만으로는 못 본다).
    ⚠️ 칸의 뜻은 `dutySlotView`(= 서버가 준 `why`)에서 나온다 — **달력용 규칙을 따로 짜지 않는다.** 「지원 인원」이라고 적지 않는다(담당자가 넣어 드린 분도 세므로 「채워진 인원」).
  · 고른 날(`dutyState.calSel`)은 화면 상태일 뿐이다 — 날짜·앞뒤 달 단추는 **서버를 다시 부르지 않고** 가진 자료로 다시 그린다(화면 번호도 그대로 — 받는 중인 응답을 버리지 않는다).
    고르는 차례(`dutyCalPick`): 내 당번 카드로 온 날·방금 지원·취소한 날 → 전에 고른 날 → 내가 서거나 손이 필요한 가장 이른 날. 당번을 새로 열면 잊는다(`dutyResetState` 도 비운다).
    「내 당번」 카드로 온 날짜는 첫 그리기까지 `dutyState.first` 에 품는다 — 첫 읽기가 조용한 다시 받기(화면이 다시 보임 · 앞 일의 답)에 밀려나도 뒤 읽기가 그 날짜·안내 줄·굴리기를 이어받는다.
  · ⚠️ **보내는 동안 자리 단추를 모두 끈다**(`dutySendStart` → `dutyButtons` · 달력에서 날짜를 바꿔 다시 그려도 꺼진 모습 — 그리는 쪽이 `dutyBusy()` 를 본다). 켜진 모습인데 눌러도 말없이 버려지는 단추가 있었다.
    20초가 넘도록 답이 없으면 막음과 함께 **꺼 둔 단추도 다시 켠다**(`dutySendStart` 의 20.1초 시계) — 막음만 풀리고 눌렀던 단추가 꺼진 채 남으면, 다시 눌러도 아무 일이 없다(검토가 진짜 크롬에서 본 옛 모습 · 고친 뒤 가짜 시계로 21초를 건너뛰어 확인). 가짜 화면의 `tap` 은 매번 새 단추를 만들어 이것을 못 본다 — 흐름 시험은 `acts()`(화면의 단추들)와 `fireLong()`(20초 시계)으로 본다.
    답이 왔을 때 **다른 날을 보고 있으면 그날로 끌고 가지 않는다** — 보던 날에 머문 채 맨 위 한 줄(「10월 18일(일) 2부 설거지 — 지원했어요.」 · `opt.topNote`)로 알린다(보던 날의 단추 자리에 앞 일의 결과가 그려졌다).
  · 앞뒤 달 단추는 **날짜가 있는 달로만**(「◀ 10월」·「12월 ▶」 — 그쪽에 달이 없으면 단추도 없다 · `dutyCalStep`). 자리 단추의 차례 번호(`data-d`)는 달력에서도 `days` 의 자리 그대로다.
  · 날짜를 고른 뒤(「내 당번」 카드로 들어온 뒤에도) 그날 카드에서 **해야 할 것**(내 줄이 있으면 그 자리 · 없으면 첫 단추가 든 자리 · 단추가 없는 날은 카드 머리 쪽 240px)이 🏠 단추에 가리면 화면을 굴린다(`dutyCalReveal` — 얼마나 굴릴지는 순수 함수 `dutyRevealBy`): 달력을 맨 위에 붙이고, 그래도 가리면 **모자란 만큼만** 더 올린다(그날 카드가 맨 위를 넘지는 않게). 이미 다 보이면 움직이지 않는다.
    ⚠️ **🏠 단추(`.home-fab`)가 덮는 곳은 보이는 곳이 아니다** — 화면 높이가 아니라 그 단추의 위끝으로 잰다. 「달력을 맨 위로」만 하면 높이 640~740px 화면(아이폰 사파리는 주소창 때문에 664 · 흔한 안드로이드 — **가장 흔한 크기다**)에서
    날짜를 고를 때마다 「지원하기」가 🏠 단추 밑에 깔린다. 2026-10-07 에 화면 크기 일곱 × 경우 다섯(+안전 영역 둘) 37가지를 진짜 브라우저로 재니 21가지가 그랬다 — 처음 고침은 검토가 든 320×568 만 봤다(**숫자 하나가 아니라 크기를 훑어서 잴 것**).
    화면 전수 점검의 49 단계(`_DUTY_SEEN`)가 작은 화면 조건(app-se · web-320-xl)에서 이것을 본다. 달력 ↔ 날짜 카드로 모양이 바뀐 그리기(날짜 수가 4 를 넘나듦)에서는 방금 한 날로 굴린다. 좁은 폭(379px 이하)에서는 앞뒤 달 단추가 화살표만이다(달 이름은 `aria-label` — 둘 다 있는 달에서 카드 밖으로 넘쳤다). ⚠️ `.duty-cal`·`.duty-day` 의 `scroll-margin-top` 에는 `var(--app-safe-top, env(safe-area-inset-top))` 를 더해 둔다 —
    빼면 홈 화면 웹앱에서 달 이름과 앞뒤 달 단추가 상태바 밑에 깔린다(라이브 샘플 자료 시험에서 잡힘).
- ⚠️ **성도님께 하는 말은 어느 경우에도 참인 말만**(검토에서 한꺼번에 나온 자리들 — `tests/duty-front.test.cjs` 가 글자로 지킨다):
  · 「못 가게 됐어요」는 **담당자 휴대폰으로 가는 알림이 아니다**(담당자 당번표에 표시가 뜬다) → 「알렸어요」가 아니라 「담당자 당번표에 표시했어요 · 급하시면 직접 연락」, 스스로 못 빼는 줄(잠김 · 담당자가 넣음 · 담당자가 뺌)의 「내 당번」 카드에는 문의처를 함께.
  · 취소는 **「확정 전까지」**다 — 전날 저녁은 「늦어도」(담당자가 먼저 확정할 수 있다). 「○일 저녁 7시까지 취소할 수 있어요」라고 못 박지 않는다(`dutyUntilText`).
  · 담당자가 넣는 당번(`closed`)의 날짜 줄에는 지원·취소 말을 쓰지 않는다 · 빈 자리가 없는 당번은 「다 찼어요」가 아니라 「지금은 지원할 수 있는 자리가 없어요」(쉬는 날뿐·날짜가 아직 없음일 수 있다).
  · 자리만 쉬면 「이 자리는 쉬어요」, 그날이 쉬면 「이날은 쉬어요」(`duty_mine` 의 `dayOff` — 자리만 쉬는데 「이날은」이라고 하면 같은 날 다른 당번까지 빠지신다).
    지원 거절 `off` 는 둘을 가르지 않고 온다 → 「쉬는 날이거나 쉬는 자리예요」.
  · 빈 당번표는 **「지금은 당번표에 보이는 날짜가 없어요 — 궁금하신 점은 담당자께 문의해 주세요」**. 화면은 날짜가 비는 까닭(틀 없음 · 더한 날짜가 보이는 기간 밖 · 끝 날짜 지남)을 모른다 —
    「담당자가 날짜를 넣으면 보여요」(이미 넣었을 수 있다 — 10-06 낮에 올렸다가 그날 밤 검증에서 잡힘) · 「날짜가 가까워지면 보여요」(끝 날짜가 지났으면 오지 않는다 — 10-07 검토에서 잡힘)처럼 **까닭을 넘겨짚지 않는다.**
    까닭을 말하는 것은 담당자 화면이다(교회 어드민 `emptyKind`).
  · `guardian` 은 「어린이·청소년 부서」라고 넘겨짚지 않는다(사랑부 · 중등부 1·2학년도 든다 — 중3·고등부는 지원한다) → 「이 계정은 앱에서 바로 지원할 수 없어요(보호자 확인이 필요한 부서·학년이에요)」.
  · 서버에 계정이 없다는 답(`no-user` — 기록을 합쳐 옛 계정이 사라진 기기)은 로그인돼 있는 분께 온다 → 「로그인한 뒤에」가 아니라 닫힘과 같은 말 · 목록으로.
  · 준비 중 당번에 담당자가 넣어 둔 줄과 겹치면 이름 없이 온다(`with` 없음) — 그 당번은 「내 당번」에도 없으므로 「보이지 않으면 지금 앱에 열려 있지 않은 당번이에요 — 담당자께」(「아직」이 아니다 — 받는 중이던 당번을 준비로 되돌린 것일 수 있다).
- ⚠️ 이름·담당자가 적은 글은 모두 `dutyEsc` 로 넣는다. **`appModal`(`appAlert`·`appConfirm`)의 글은 HTML 그대로 들어간다** — 거기 넣는 글도 모두 `dutyEsc`.
  자리·지원 번호는 화면 글자(`data-*`)에 싣지 않는다(차례 번호만 — `dutyState` 의 배열에서 꺼낸다).
- ⚠️ **늦게 온 응답이 다른 화면을 덮지 않게**(`tests/duty-flow.test.cjs` — `js/duty.js` 전체를 가짜 DOM 위에서 돌린다): 받는 쪽은 화면 번호(`dutyState.screen`)와 `.duty-wrap` 이 아직 있는지를 함께 본다 ·
  🏠 첫 화면으로는 `dutyLeave()` · 일(지원·취소·표시)을 끝낸 뒤 다시 그리기는 `dutyRedraw` 로만(당번 화면을 떠났으면 아무것도 하지 않는다) · `soft`(화면을 비우지 않고 다시 받기)는 당번 화면이 떠 있을 때만.
  이것이 없으면 첫 화면으로 간 분이 응답 한 번에 당번 화면으로 도로 끌려온다(당번이 하나뿐일 때의 「목록 건너뛰기」가 특히).
  다시 받기가 실패하면: 「불러오는 중」만 떠 있었으면 실패를 알리고 · 방금 한 일이 있었으면 「지원은 됐어요 — 화면을 새로 받지 못했어요」(`failNote`) · 당번이 내려갔으면(`not-found`) 낡은 당번표를 남기지 않는다.
- ⚠️ **일(지원·취소·표시)의 답은 셋이다 — 됐다 · 서버가 거절했다 · 됐는지 알 수 없다**(2026-10-06 검증). 표에 없는 코드(통신 끊김 · `HTTP 5xx` · `server`)는
  요청이 안 나간 것과 답만 잃은 것을 가를 수 없다 — **서버에는 이미 쓰였을 수 있다.** 「잠시 뒤 다시 해 주세요」가 아니라 「됐는지 확인하지 못했어요」라고 말하고 화면을 다시 받는다(`dutyErrKnown`).
  · 알림은 `dutyTell` 로만 — 떠 있는 창(읽던 확인 창)을 지우지 않고 닫힌 뒤에 띄우고(`appModal` 은 떠 있는 창을 답 없이 지운다), 그 일을 보낸 뒤 로그아웃·신원 바꿈이 있었으면(`dutyState.gen`) 버린다.
    기다리는 것들은 한 줄(`dutyWait`)에 서서 **온 차례대로** 뜬다. ⚠️ 응답이 띄우는 **확인 창**(`locked-day` 의 「취소할 수 없는 날」 다시 묻기)도 같은 길(`dutyWhenClear`)로 — 그 창이 떠 있던 알림을 지우면 「거절을 듣지 못함」이 된다.
    거절 알림과 「일은 됐어요」(`failNote`)에는 어느 자리인지(날짜·자리)를 붙인다 — 늦게 온 말이 지금 누른 다른 자리 일로 읽히지 않게.
    「화면을 새로 받지 못했어요」 꼴은 뜨는 때에 다시 본다 — 기다리는 사이 새 화면을 받았으면(`dutyState.reads`) 버린다.
  · 막음은 제 번호(`dutyState.tok`)일 때만 푼다 — 20초가 넘어 늦게 온 답이 그 뒤에 보낸 일의 막음을 풀지 않는다.
  · 「일은 됐는데 화면을 못 받았다」는 말(`failNote`)은 `dutyState.owe` 에도 품는다 — 다시 받기가 다른 다시 받기(화면이 다시 보일 때)에 밀려나도 남고, 다음 읽기가 성공하면 지우고 실패하면 그때 알린다. 당번 화면을 떠나면 버린다.
  · 떠난 뒤에 온 `locked-day`(아무것도 안 쓰임)는 창을 띄우지 않되 **안 됐다고 알린다**(확인 창에서 「지원하기」를 누르신 분이 지원한 줄 아신다) — 같은 당번을 그대로 보고 있으면(화면만 다시 받았어도) 「취소할 수 없는 날」 창을 띄운다.

  당번표(달력) 화면의 달력 위 한 줄 「지난 봉사 N번 ›」(당번이 하나뿐이고 내 당번이 없으면 목록을 **건너뛰고** 곧바로 당번표로 들어온다 — 지난 봉사만 있는 분이 바로 그 경우다) ·

  문의가 적힌 당번마다 한 번 · 번호는 눌러서 걸린다: 「담당자께」라고 말하는 자리에 닿을 길을 함께 둔다 — 보관한 당번은 당번표가 열리지 않아 여기가 유일한 길이다)). 한 번도 없으면 묶음도 줄도 없다.
  ⚠️ 당번표의 「지난 봉사 N번」 한 줄은 **당번표 응답의 `past`(두 수)** 로 고친다(`dutyPastCounts`) — 화면이 다시 보일 때는 당번표만 다시 받으므로, 목록이 준 수만 쓰면 날이 바뀐 뒤(또는 담당자가 바로잡은 뒤) 낡은 수가 남는다.
  옛 서버는 그 칸을 주지 않는다 → 가진 수 그대로(0 으로 덮으면 한 줄이 사라진다).
- **세는 기준은 SQL `duty_past` 한 곳**(친구 결정 「당번표에 이름이 남아 있던 날」 — 앱에는 **출석 확인이 없다**): 날짜가 오늘보다 앞 · 살아 있는 줄(스스로 취소·담당자가 뺌·기록 합치기로 정리된 줄은 세지 않는다) ·
  그날과 그 자리가 쉬지 않았다 · 앱 계정(`user_id`)에 이어진 줄. 한 **자리**가 한 번이다(같은 날 두 자리면 두 번). 당번의 상태마다:
  **앱에 보이는 당번**(받는 중·지원 멈춤)은 지난 줄 모두 · **보관한 당번은 앱에 보이던 동안 끝난 자리만**(자리의 끝 시각 <= `duty_boards.hidden_at` — 끝난 한 번짜리 모집의 기록은 남는다) · **준비 중 당번은 세지 않는다** ·
  한 번도 앱에 보인 적 없이 보관한 당번도 세지 않는다.
  ⚠️ **`hidden_at`(앱에서 숨긴 때)은 트리거 `duty_board_hidden_stamp` 한 곳이 적는다** — 보이다가(받는 중·지원 멈춤) 숨기면(준비 중·보관) 지금 · 숨긴 채 준비 중 ↔ 보관을 오가도 처음 숨긴 때 그대로 · 다시 열면 비운다 ·
  코드에서 써도 되돌린다. 처음에는 보관한 당번을 통째로 셌다 — **앞날에 선 분이 있는 채 접은 당번**(교회 어드민이 확인 한 번으로 받는다 · 지원 줄은 그대로 남는다)의 그 뒤 날짜가 지나면 서지 않은 날이 지난 봉사로 들어왔고,
  보관한 당번의 줄은 담당자도 못 빼 고칠 길이 없었다(독립 확인이 잡은 것 — 아래 「지난 봉사의 독립 확인 반영」).
  ⚠️ 보관을 풀었다가 다시 보관하면 그 사이 지나간 날짜의 줄이 돌아온다(보이는 동안에는 담당자가 뺄 수 있다 — 다시 숨기기 전에 뺀다).
  ⚠️ **안 오신 분은 담당자가 지난 날 명단에서 빼야 그분의 이력에서도 빠진다** — 교회 어드민의 빼기 확인 글이 그렇게 말한다(`REMOVE_PAST_NOTE`). 「내 당번」(오늘부터)과 「지난 봉사」(오늘보다 앞)는 겹치지 않는다.
- ⚠️ **말: 「봉사했어요」·「섬겼어요」라고 단정하지 않는다** — 출석을 확인한 것이 아니다(안 오신 분을 담당자가 아직 안 뺐을 수 있다). 묶음의 이름은 「지난 봉사」, 목록은 「당번표에 남아 있는 기록」이라고 적는다(시험이 그 낱말들을 본다).
  「함께해 주셔서 고맙습니다」는 친구가 고른 화면 그림에 있던 말이다.
- 응답: `dutyList` 에 `past`(두 수와 가까운 세 줄) · `dutyBoard` 에 `past`(두 수 · 줄 없이 — SQL 이 줄 때만) · 새 액션 `dutyPast {user_id}` → `{ok, open, today, past: {total, year, rows: [{date, board, service, task, start, end, contact}]}}`.
  `contact` = 그 당번의 문의처 한 줄(당번표·내 당번에 이미 보이는 글).
  ⚠️ `api` 는 SQL 이 준 것을 **그대로 돌려주지 않는다**(`dutyPastOut` — 아는 일곱 칸의 글자만 옮긴다: 뒷날 SQL 에 칸이 늘어도 이름·계정 번호가 새지 않게). 내 것만 — 다른 분의 이름·수 없음.
- 옛 서버·옛 `js/api.js` 와 섞여도 조용하다: `past` 가 없는 답이면 묶음을 그리지 않고, `api.dutyPast` 가 없으면 서버를 부르지 않고 「새 화면을 받는 중이에요」라고 말한다.
- 「지난 봉사」 화면은 화면이 다시 보여도 다시 받지 않는다(지난 기록은 자정과 담당자의 바로잡기에만 바뀐다) · 단추는 `data-past`(일을 보내는 `data-act` 가 아니다 — 보내는 동안 꺼지지 않고 자리 단추의 갈래에 들어가지 않는다).
- ⏰ 4단계(공개) 방침 글에 **「지난 봉사 기록을 본인에게 보여 준다」** 한 줄을 함께(새로 모으는 것은 없다 — 이미 있는 지원 기록을 본인에게 보여 줄 뿐). 지금은 문이 닫혀 시험 참여자만 본다.
- ⏰ **4단계 앞에 운영 시험 당번의 줄을 정리한다** — 시험 참여자가 지원해 둔 줄은 날짜가 지나면 그분들의 「지난 봉사」로 센다. 시험 당번을 치울 때는 **보관하기 전에 지난 날·앞날의 시험 줄을 빼거나**(📅 당번 명단의 빼기 —
  보관한 뒤에는 못 뺀다), 보관 대신 **준비 중**으로 둔다(준비 중은 세지 않는다). 그냥 보관하면 그때까지 끝난 시험 줄이 공개 뒤에도 그분들 횟수에 섞인다.
- 담당자가 바로잡는 길(교회 어드민): 안 오신 분 = 지난 날 명단에서 **빼기** · 잘못 걸린 쉬는 날 = 지난 쉬는 날의 **「다시 열기」**(`duty_days_off` 가 다시 열기는 오늘 − 400일까지 받는다 — 전에는 그날이 지나면 풀 길이 없었다 ·
  지난 날을 쉬는 날로 거는 것은 여전히 안 된다) · 지난 자리의 「이 자리만 쉬기」는 그 자리를 지난 봉사에서 뺀다(확인 글이 그렇게 말한다).
- ⚠️ **지난 봉사의 당번 이름·자리 이름·시각은 그때 것이 아니라 지금 값이다**(자리는 틀을 가리키고 틀을 고치면 그 틀의 모든 날짜에 보인다 — 표의 원래 뼈대). 시각·이름을 손보는 고침은 해가 작지만,
  틀을 **다른 일로 바꿔 쓰면** 지난 기록이 서지 않은 일·시각으로 보인다 — 교회 어드민 자리 틀 안내가 「일이 아예 바뀐 것이면 고치지 말고 틀을 빼고 새로」라고 말한다(그때 값을 굳히려면 지원 줄에 칸이 더 필요하다 — 하지 않았다).
- 하지 않은 것: 첫 화면의 길 · 출석 확인(담당자가 「오셨어요」를 표시) · 순위·배지 · 담당자 화면의 「이분의 지난 봉사」.

## 공휴일 (달력의 빨간 날짜 · 2026-10-07 친구 요청)

성도님 앱의 당번 달력과 교회 어드민 📅 당번 명단의 달력(아래 「교회 어드민 달력」)은 **공휴일과 일요일의 날짜 숫자를 빨갛게** 적는다(당번이 없는 날도 · 요일 줄의 「일」도). 칸의 바탕과 인원 글은 뜻 색 그대로다.
그 달에 공휴일이 있으면 달력 아래 풀이에 이름을 적고(「빨간 날짜는 일요일과 공휴일이에요(3일 개천절 · 5일 대체공휴일 · 9일 한글날)」 — 색만으로 말하지 않는다), 성도님 앱은 그날 카드의 날짜 옆에도 이름을 붙인다
(`dutyHolChip` — 날짜가 적어 달력이 없는 당번에서는 이것이 유일한 표시다). 화면 낭독에는 「공휴일(한글날)」.

- **일요일도 빨갛다**(친구 결정 2026-10-07 「네 빨갛게」). 처음에는 칠하지 않았다 — 당번이 대부분 주일이라 그 칸의 색은 뜻(초록 = 손이 필요 · 남색 = 내 당번 · 담당자 화면은 금색·붉은 바탕)이 먼저라고 보았다.
  여쭈었더니 빨갛게 하자고 하셨다. 그래서 공휴일과 **같은 방식**으로: 빨간 것은 날짜 숫자와 요일 줄의 「일」뿐이고 칸의 바탕·인원 글은 뜻 색 그대로다(대비는 공휴일에서 잰 값과 같다 — 칸의 종류마다 4.5:1 이상).
  일요일은 표에 적지 않고 **요일로 본다**(`dutyIsSunday` · 교회 어드민 `isSunday` — 날짜만 있는 값이라 UTC 로 읽는다): 표식은 `sun`, 공휴일은 `hol`(이름이 붙는다 — 풀이·낭독·그날 카드). 일요일이면서 공휴일이면 둘 다.
  풀이는 공휴일이 있는 달에만 나온다(일요일뿐인 달은 요일 줄의 빨간 「일」과 낭독의 「(일)」이 말한다). 표에는 여전히 「일요일이 아닌 까닭으로 쉬는 날」만 적는다
  (일요일과 겹친 공휴일도 그날은 넣는다 — 2027-02-07 설날 · 06-06 현충일). 토요일인 공휴일도 빨갛다(관보: 「일요일을 비롯한 관공서의 공휴일은 적색으로 표기」) · 공휴일이 아닌 토요일은 칠하지 않는다.
- **색은 새로 만들지 않았다** — 밝은 바탕은 `--error`(내 달력의 일요일과 같은 값), 성도님 앱의 남색 칸·어두운 모드는 이미 쓰는 `#ffaaa2`, 교회 어드민의 고른 날(남색) 위는 `--danger-bd`. 모두 대비 4.5:1 이상을 진짜 브라우저에서 쟀다.
- ⚠️ **표는 두 곳에 있다** — 성도님 앱 `js/duty.js` 의 `DUTY_HOLIDAYS`·`DUTY_HOL_FROM`·`DUTY_HOL_UNTIL` 과 교회 어드민 `js/menus/duty/holidays.js` 의 `HOLIDAYS`·`HOL_FROM`·`HOL_UNTIL`. 한쪽만 고치면 성도님과 담당자가 다른 달력을 본다.
  두 저장소의 시험(`tests/duty-front.test.cjs` · 교회 어드민 `tests/duty-cal.test.mjs`)이 **같은 지문**(범위 「처음~끝」 한 줄 + 「날짜=이름」을 줄바꿈으로 이은 글의 sha256 앞 12자)을 본다 — 표나 범위를 고치면 시험이 떨어지며 새 지문을 보여 준다. 두 곳을 같은 값으로.
- ⚠️ **셈하지 않고 표로 적는다.** 시험이 표의 꼴 · 해마다 있어야 하는 날 · 대체공휴일(규정 제3조를 다시 셈한다)을 맞대지만, 날짜 자체는 아래 근거에서 옮긴다.

### 교회 어드민 달력 (📅 당번 명단 · 2026-10-07 친구 요청 「어드민에서도 달력으로 확인」)

날짜가 넷 이상인 당번은 날짜 칩 줄 대신 **달력**으로 날짜를 고른다(성도님 앱과 같은 수 — 한두 번짜리 모집은 칩 그대로). 칸 = 날짜 + 「채워진 인원/필요 인원」 · 칸의 뜻은 칩과 같은 판정(빈 자리 · ⚠ 못 온다는 분 · 다 참 · 쉼 · 지난 날) ·
🔒 = 확정된 날 · 고른 날 남색 · 오늘 남색 테두리. PC 는 달력 옆에 그날 판, 폰은 달력 아래(날짜를 누르면 그날 판이 보일 만큼만 굴린다). 「◀ 지난 날」은 앞 달을 통째로 더 불러온다(4주씩 — 달이 넘어갈 때까지 · 52주까지).
- 수는 서버가 준 「빈 자리」와 맞는다(필요 − 채워진 = `need` — 쉬는 자리는 세지 않고 · 남은 자리는 서 있는 분만 · 정원을 넘겨 넣은 자리는 정원까지). 성도님 앱 달력과도 같은 수다 — **남은 자리 둘만 빼고**:
  ① 지원 멈춤 당번의 남은 자리 ② 받는 중 당번에서 **보는 분 자신의 줄이 있는** 남은 자리(그분의 앱에서만). 앱은 그 자리가 남은 자리인지 받지 못해 정원을 모두 센다(위 「성도님 앱」 절).
- **명단은 달을 통째로 읽는다**(「오늘 − 14일」이 든 달의 1일부터 — `rosterFrom`). 처음에는 오늘 − 14일부터 읽어, 매달 중순 뒤에는 그 달의 첫 주일들이 「당번 없는 날」과 같은 칸으로 보였다
  (10월 25일에 열면 4일의 「1/2」이 맨 숫자였고 「◀ 지난 날」을 눌러야 나타났다 — 검토에서 가장 무겁게 본 것).
  **읽은 범위는 줄이지 않는다**(`rosterFromKeep`·`readFrom`): 달 단위로 뛰는 셈이라, 화면을 연 채 날이 바뀌면(처음 화면은 매달 14 → 15일) 읽던 지난달이 통째로 빠져 그 달의 날을 보던 판이 저장 뒤 다른 날짜의 판으로 바뀌었다
  (다음 넣기·빼기가 그 날에 적힌다 — 올리기 전 확인). 같은 뿌리의 옛 꼴(하루씩 미끄러지며 보던 날이 창 밖으로 나가던 것)도 함께 사라졌다.
- **다시 그려도 달력은 제자리다**(`settleView`·`calSettle`): 그날 판이 짧아지면 문서가 줄어 달력이 손끝에서 달아나고 같은 자리에 다른 단추가 왔다(붙은 달력의 「▶」를 이어 누르다 「쉬는 기간」 창이 열렸다).
  굴린 자리를 지키고(모자라면 묶음을 늘린다) · 달력이 붙어 있었으면 그날 판을 맨 위부터 · 자판으로 눌렀으면 초점이 가려지지 않게만 본다.
  ⚠️ **지키지 않는 때**(올리기 전 확인이 잡은 것 — 처음 고친 판은 모든 그리기에서 지켰다): 달력을 누르지 않았는데 **보이는 날이 바뀐 그리기**(「옮기기」로 다른 날에 · 서버가 거절해 다시 읽은 때 · 날짜 더하기 ·
  맡은 당번에서 빠져 남은 당번이 저절로 열림). 옛 판에서 굴려 둔 자리를 지키면 짧은 새 판이 화면 위로 사라지고 「…로 옮겼어요」와 **빈 화면만 남았다**(자리 셋~다섯인 당번의 아래쪽 자리에서 · 운영하던 판은 괜찮던 것) →
  새 판의 위가 가려 있을 때만 머리줄 아래까지 올리고 문서는 늘리지 않는다(같은 날의 빼기·메모는 여전히 굴린 자리 그대로). 붙은 달력에서 자판으로 누른 때에는 초점을 보정하지 않고(달력 안의 초점은 굴려도 제자리다),
  맨 위에서는 묶음을 늘리지 않는다(큰 화면의 짧은 명단에 없던 굴림줄이 생겼다).
  ⚠️ **방금 옮긴 분의 줄은 보이게 한다**(마지막 확인이 잡은 것 — 위 규칙만으로는 같은 자리의 다음 주일로 옮길 때 판의 맨 위로 튀어 그 줄이 화면 밖으로 나갔다): 옮긴 줄이 그 자리에서 다 보이면 그대로 두고,
  아니면 새 판의 위로 간 뒤 줄이 화면 아래일 때만 보일 만큼 내린다(「보인다」의 위쪽 끝 = 머리줄 + 붙는 날짜 줄 아래). 거절돼 다시 읽은 때·날짜 더하기·남은 당번이 열릴 때는 줄이 없으니 판의 위부터다.
  ⚠️ 메뉴를 옮겨 **떼어진 화면**에서는 화면 자리를 건드리지 않는다 — 명단을 불러오는 사이 다른 메뉴로 옮기면 늦게 온 답이 떼어진 화면에 그리고, 떼어진 요소의 상자는 모두 0 이라 지금 보이는 다른 메뉴를 64px 올렸다(마지막 확인).
- 함께 고친 것: 날짜가 하나도 없는 당번(끝난 한 번짜리 모집)에도 「◀ 지난 날 더 보기」가 뜬다 — 전에는 지난 명단을 화면에서 볼 길이 없었다. 더 불러와도 새 날짜가 없으면 그렇다고 말한다.

  (겹친 줄을 정리한 것 — 그분은 남은 줄로 서 있다 · 동명이인이면 담당자가 따로 알린다: 빼기 확인 창이 그렇게 말한다).
  ⚠️ **옮김만은 떠난 자리로도 가른다**(고침 검토 반영 2026-10-07): 아직 안 끝난 자리(앞날 · 오늘 끝 시각 전)에 서 있던 줄을 오늘 끝난 자리로 옮기면 그분의 남은 당번이 사라진다 →
  「옮겨 드렸어요 — 옛 자리 → 새 자리」를 보낸다(`duty_move` 가 옮기는 순간 `moved_from.live` 를 적는다 · 끝난 자리끼리·지난 날 줄의 바로잡기는 `false` 라 조용 · 옛 SQL 은 그 칸이 없어 그대로 거른다).

  ⚠️ **한 번만**: 확정·전날은 `duty_notify_claim` 이 **보내기 전에** 잡는다(잡힌 줄에만 보낸다 · 보내다 실패해도 다시 안 보낸다 — 많아야 한 번). 그 밖은 저장 한 번에 한 번 부탁하므로 잡지 않는다. 종류 목록은 SQL `duty_notify_log` 의 CHECK 와 같아야 한다(`DUTY_NOTE_CLAIM`).

  새 날짜의 전날 알림은 이미 잡힌 줄이라 영영 안 간다(크론이 두 번 돌아 그 틈도 두 번이 됐다). 인자를 더했으므로 **SQL 이 `api` 보다 먼저**다 — 새 `api` 는 옛 SQL 에서 「그런 함수가 없다」(`PGRST202`·`42883` — `dutyNoFn`)일 때만 인자 둘로 물러선다.
- ⚠️ **돌려주는 수는 둘이다** — `sent`(**자기 기기 가운데 하나라도 받아들여진 분**) · `missed`(가지 않은 분: 받는 기기가 없다 · 자기 기기가 모두 실패). 담당자 화면은 「N분께 앱 알림을 보냈어요 · M분께는 앱 알림이 가지 않았어요 — 따로 알려 주세요」라고 말한다.

  잡기(확정·전날)는 그대로다 — 받는 기기가 없어도 잡힌 줄은 남는다(개발 시험의 증거 · 많아야 한 번).
  ⚠️ **받는 분마다 센다**(`dutyNoteTally` · 고침 검토 반영 2026-10-07) — `eduPushDevices` 가 받아들여진 기기 줄(`okWeb`·`okIos` — 두 표의 번호가 섞이지 않게 따로 · 응답·기록에 싣지 않는다)을 함께 돌려준다.
  처음 고칠 때는 **글 묶음마다** 셌다(묶음에서 한 대라도 받아들여지면 기기 있는 분 모두 `sent`) — 같은 자리의 확정·전날·쉼은 여러 분이 한 글이라, 죽은 구독뿐인 분이 「보냈어요」에 들고 그 줄은 잡혀 다시 가지도 않았다.

  ⚠️ 문장 꼴이 180자를 넘으면 **뜻을 앞에 둔 꼴**로 바꾸고 목록을 「외 N일」로 줄인다(`dutyNoteFit`) — 끝에서 자르기만 하면 여러 주를 한 번에 쉬게 하거나 다시 열 때 「쉬어요」·「다시 서요」가 잘려 날짜 목록만 갔다(쉰다는 말 뒤에 오면 뜻이 거꾸로 읽힌다).
  자리만 쉬면 그 자리를 말한다(「10월 18일(일) 식당 봉사 2부 설거지 당번은 쉬어요」 — 그날 다른 당번까지 빠지시지 않게). 응답·`push_log`·알림 글에 `user_id` 를 싣지 않는다.

  모레 분들께 「내일」이 가고 그분들의 제 시각 알림이 사라진다: 시각 문이 막으려던 바로 그 사고다 · 고침 검토 반영 2026-10-07).

  `monitor`(매일 07:12)가 26시간 넘게 멈췄으면 알린다(흔적이 한 번이라도 생긴 뒤부터만 — 크론을 안 건 곳에서는 헛경보가 없다 · 크론을 걷을 때는 그 줄도 지운다). **끄는 스위치(`dutyNotifyOff`)가 켜진 채면 아침마다 한 줄**(「봉사 당번 앱 알림이 꺼져 있습니다」 — 전날 알림에는 「꺼 두었어요」를 말해 줄 화면이 없어, 잊으면 며칠째 안 가는 것을 아무도 모른다 · 판정은 순수 함수 `dutyRemindProblems`). ⚠️ 흔적이 **아직 없는 곳**은 monitor 가 못 본다 — 크론을 처음 걸거나 다시 건 날은 같은 길로 한 번 불러 응답을 본다(아래 5). 교육 크론 파일의 「키도 치우려면」은 **두 작업을 모두 걷을 때만**이다(같은 비밀을 읽는다).
- **알림 주소 `?duty=1`** — 누르면 당번 목록(내 당번이 맨 위). `app.js` `routeAfterLoad` 가 교육 줄 뒤에서 본다: 로그인했고 🙋 가 보이는 분(`dutyVisible`)만 연다 · 아니면 평소 길 · 주소에서 `duty` 는 늘 지운다(`dutyTakeDeepLink`). 이미 열린 창은 서비스워커 「from-push」 메시지. 아이폰 앱은 주소를 안 읽어 앱만 열린다 — 그래서 글에 날짜·자리·시각·장소를 싣는다.
  알림을 눌렀는데 화면이 안 열리던 세 경우를 막았다(검토 반영 2026-10-07 — `tests/duty-front.test.cjs` 가 가짜 환경에서 돌린다):
  ① **문 캐시가 뒤처진 기기**(문을 연 뒤·명단에 오른 뒤 앱을 아직 안 연 분 — 서버는 그분께 보냈다): 평소 길로 가되 품어 두었다가(`dutyWantOpen`), 문 확인(`refreshDutyOpen`·`refreshMinistryTester`)이 끝나 🙋 가 보이면 그때 연다
  (`dutyOpenIfWanted` — 한 번 · 10초 안 · 첫 화면이 떠 있고 다른 창이 없을 때만 · 서버도 닫힘이면 평소 그대로). ⚠️ **4단계에서 문을 여는 날** 이 길이 쓰인다.
  ② **같은 주소의 다른 쪽이 떠 있을 때**(퀴즈·설명서·개인정보 안내·관리자 화면 — 앱 탭이 그리로 옮겨 가 있어도): 서비스워커가 첫 창을 앞으로 올리기만 해 화면이 안 열렸다 → `sw.js` 가 **앱 창**(범위의 뿌리 · `index.html`)만 고르고, 없으면 그 주소를 새로 연다(`isAppWindow`).
  ③ **배포 직후의 새로고침**(`ensureFreshBuild`): 앱이 알림 주소를 읽어 주소에서 지운 뒤에 `location.reload()` 가 오면 첫 화면으로 떨어졌다 → 처음 주소(`#` 는 빼고)로 다시 연다 — 교육 `?edu=` · 구절 `?v=` 도 같은 덕을 본다.
  ⚠️ 알림 표식(`from=push`)은 **앱이 이미 읽었을 때만** 뺀다(고침 검토 반영 2026-10-07): 다시 받기가 앱의 주소 읽기보다 먼저 끝나면(배포 직후의 보통 차례) 표식이 아직 주소에 있다 → 그대로 `reload` 해 새로 뜬 실행이 한 번 센다.
  처음 고칠 때는 늘 표식을 뺀 주소로 갈아 끼워, 그 차례의 알림 누름(매일 알림 포함)이 열람 기록에 한 번도 안 남았다(예전의 `reload` 는 한 번 남겼다).
- ⚠️ **받는 기기는 「지금 그 기기를 쓰는 계정」이어야 한다** — 알림은 지원 줄의 계정(`user_id`)으로 기기를 찾는다(`eduDevicesOf`). 매일 알림은 모두 같은 글이라 드러나지 않았지만, 당번·교육 알림은 사람마다 글이 다르다.
  · 웹 푸시: 구독 줄의 주인은 알림을 켤 때와 알림 시각을 바꿀 때만 쓰였다 — 「로그인 정보변경」으로 신원이 바뀌면(= 다른 계정) 새 계정은 알림을 못 받고 앞 계정의 알림이 그 기기에 떴다. 이제 동기화 뒤 `syncPushOwner`(js/push.js)가
    이 기기의 구독을 지금 계정으로 한 번 다시 저장한다(기기에 `push-owner` 표식 · **구독이 있을 때만** — 권한을 묻지도 구독을 만들지도 않는다 · 시각은 이 기기의 것 그대로).
  · 아이폰 앱: 껍데기가 앞에 올 때마다 지금 계정으로 토큰을 다시 등록한다. 「내 정보 지우기」는 웹 구독만 지우고 아이폰 토큰을 남겼다(화면은 「이 기기의 알림도 함께 꺼집니다」) → `api` `removeIosPush`(그 계정의 토큰을 지운다 —
    토큰은 껍데기만 알아 기기를 가려 보낼 수 없다 · 그분의 다른 아이폰은 앱을 다시 열 때 다시 등록된다).
    ⚠️ 그래서 **같은 이름으로 쓰는 다른 아이폰의 매일 알림·당번 알림도 그 폰에서 앱을 다시 열 때까지 멈춘다**(껍데기는 앱이 앞에 올 때만 토큰을 저장한다 · 로그인만으로는 깨지 않는다) — 아이폰 앱의 확인 창이 그렇게 말한다
    (웹·안드로이드에 보이는 문장은 그대로). **실패를 삼키지 않는다**: 아이폰은 서버 줄을 지우는 것이 알림을 끄는 유일한 길이라, `disablePush(true)` 가 못 지웠으면(`false` · 한 번 더 해 본 뒤) 정보를 지우기 **전에**
    「알림을 끄지 못했어요 — 그래도 지우기 / 취소」를 묻고 끝낸 말에도 「아이폰 설정에서 꺼 주세요」를 붙인다(고침 검토 반영 2026-10-07 — 삼키면 「이 기기의 알림도 함께 꺼집니다」가 거짓으로 남았다).
    한 기기의 토큰만 지우려면 껍데기가 토큰을 웹에 실어 줘야 한다(다음 껍데기 판의 일 — 아래 「넣지 않은 것」). `tests/smoke-readonly.sh` 15번이 그 액션이 살아 있는지 본다(계정 없이 부른다 — 거절만 본다).
- 교회 어드민: 저장·기록 **뒤에** 부탁만 한다(`index.ts` `notifyDuty` → `duty-db.ts` `withNotify` — 지원 번호만 보낸다 · 실패해도 저장은 성공 · 응답 `notified`(실제로 나간 분)·`missed`(가지 않은 분 — 0 이면 없다)·`notifyError`(`notify-failed`·`notify-off`)).
  앱 계정이 없는 줄뿐이면 부탁하지 않는다(응답에 그 칸이 없다). 「＋ 넣기」의 알림은 **그 줄의 앱 계정**(`duty_apply` 의 `hadUser`)으로 정한다 — 이번 명부 찾기가 맞춘 계정과 다를 수 있다. 알림을 보내지 못한 저장은 토스트가 아니라 창으로 알린다(`sayDone`).
  고침 검토 반영(2026-10-07): **꺼 둔 동안**에는 `api` 가 `held`(꺼 두지 않았으면 보냈을 분 수 — 확정·전날은 이미 받은 줄을 뺀다: `dutyNotifyUnclaimed`)를 주고, 0 이면 평소처럼 조용히 끝낸다 — 지난 날 바로잡기·준비 중 당번·앱 계정 없는 줄의 저장에까지
  「앱 알림을 보내지 못했어요 — 따로 알려 주세요」 창이 뜨지 않게(모르면 — 옛 `api`·읽기 실패 — 알리는 쪽). **겹친 줄 안내**는 서버가 「빼 드렸어요」를 거르는 범위(같은 자리 · 같은 이름)에서만 뜬다(`slotTwins` —
  다른 자리의 같은 이름에 「이 줄은 두고 앱 없음 줄을 빼 주세요」라고 하면 다른 당번의 줄을 빼게 된다 · 남는 줄이 모두 앱 줄이면 「따로 알려 주세요」만). **확정 알림을 부르지 못했을 때**의 「다시 확정」 안내는 약속하지 않는다
  (`CONFIRM_RETRY` — 다시 가는 것은 아직 잡히지 않은 줄뿐 · 준비 중·보관 당번에서는 말하지 않는다). **넣기 창**은 그 자리의 「빠진 분」에 앱 줄이 있으면 「빠진 분 → 다시 넣기」를 권한다(`addEndedNote` —
  「＋ 넣기」가 앱 계정을 못 맞추면 앱에 안 이어진 새 줄이 되어 그분의 마지막 알림이 「빼 드렸어요」로 남는다). 확인 창의 「N분」은 줄 수였다 → 「지원 N건」(저장 뒤의 「N분께 보냈어요」는 사람 수다).

### 3단계에서 밟은 길 (SQL → `api` → 교회 어드민 → 화면 → 크론)

1. `duty.sql` 다시(`duty_notify_rows` 에 `dayOff`·`past`·`pastCutoff`·`movedFrom` — create or replace · 옛 api 는 그 칸을 읽지 않는다) → 확인 질의.
2. 운영 `api` 를 빈 폴더에 내려받아 **origin/main 과 같은지** → `--workdir <그 가지 폴더>` 로 배포(커밋된 그대로) → 다시 내려받아 차이 0 → 스모크 넷이 올리기 전과 같은 수(봉사 당번 14 · 교육 13 · 이벤트 · 공통 읽기 14) + 내부 액션 둘이 키 없이 `unauthorized`.
3. 교회 어드민 함수(`notifyDuty`) — 같은 방법(내려받아 대조 → 배포 → 다시 대조) → 화면 푸시(`NOTIFY_LIVE = true`). ⚠️ **`api` 가 먼저**다 — 함수가 먼저면 저장마다 「앱 알림은 보내지 못했어요」가 뜬다(저장은 된다).
4. `python tools/bump.py` → 푸시(알림 주소).
5. **크론은 맨 마지막** — 사본(주소를 바꾼 것)으로 걸고, `cron.job` 에서 `schedule`·`active`·명령이 Vault 를 읽는지(키가 명령에 없어야 한다)를 본다.
   내일 당번인 줄이 0 인 것을 읽기로 확인한 뒤(`duty_remind_ids(내일)`) 크론과 같은 길(`net.http_post` + Vault 의 키)로 한 번 불러 `net._http_response` 에서 응답을 본다 — 한국 19시 뒤면 `{ok:true, rows:0, sent:0}`, 그 전이면 `{ok:false, error:"too-early"}`(이것도 키·주소·액션 이름이 맞다는 증거다 — 틀리면 `unauthorized`·`unknown action` 이 온다 · 아무에게도 가지 않는다).
   ⚠️ 크론을 **처음 걸거나 다시 건 날은 이 확인을 꼭** 한다 — 흔적(`dutyRemindRun`)이 생기기 전에는 monitor 가 못 본다(처음부터 틀리게 건 크론은 경보가 없다).
**끄기(되돌리기)는 스위치 한 줄**: `insert into app_config(key,value) values('dutyNotifyOff','true'::jsonb) on conflict (key) do update set value='true'::jsonb;` — 배포 없이 곧바로, 아무것도 잡지도 보내지도 않는다
(값은 `true` 하나일 때만 꺼진다 — 글자 `'"true"'` 는 아니다 · 담당자 화면은 알릴 분이 있던 저장마다 「앱 알림은 지금 꺼 두었어요 — 그분께 따로 알려 주세요」를 창으로 말한다 · 크론은 그대로 두어도 된다 — 흔적에 `off`·`held` 를 남긴다 ·
**꺼 둔 채면 monitor 가 아침마다 한 줄**을 보낸다: 잊지 않게다 — 오래 끌 것이면 아래 「통째로 걷는 차례」로). 다시 켜기: `delete from app_config where key='dutyNotifyOff';`
⚠️ **켠 뒤 저절로 다시 가는 것은 없다**(잡힌 줄이 없을 뿐이다 · 고침 검토 반영 2026-10-07 — 처음에는 「다시 부르면 간다」고만 적었다): 크론은 늘 「부른 순간의 내일」만 고르고, 교회 어드민은 이미 끝난 저장을 다시 부탁하지 않는다.

### 그 고침의 올리기 전 확인 · 「일요일도 빨갛게」의 확인 반영 (2026-10-07 · 올리기 전 확인 네 갈래 아홉 가지 — 참 여덟(중간 1 · 낮음 7) · 반박 1 / 일요일 두 갈래 다섯 가지 — 모두 참 · 낮음)

### 지난 봉사의 독립 확인 반영 (2026-10-07 저녁 · 두 갈래 열세 가지 — 참 열둘(높음 1 · 중간 1 · 낮음 10) · 반박 1 · 올린 뒤의 확인)

「지난 봉사」를 올린 뒤(18:25) 올라간 그대로를 두 갈래(서버 · 화면과 담당자 글)로 따로 읽히고 발견마다 다시 반박해 보게 했다. 운영에는 지난 봉사로 잡힐 줄이 아직 0건이라(첫 당번 날짜 10/11) 성도님께 보인 것은 없다.
- (높음) **앞날에 선 분이 있는 채 「보관」한 당번의 줄이, 날짜가 지나면 지난 봉사로 셌다** — 당번을 접은 뒤의 날(서지 않은 날)이 횟수·목록에 들어온다. 보관한 당번의 줄은 내 당번·전날 알림에서 빠지고 담당자도 못 빼
  고칠 길도 없었다. 「보관 = 끝난 한 번짜리 모집의 기록」은 보관할 때 앞날 줄이 없다고 본 설계였다. → **숨긴 때(`duty_boards.hidden_at`)를 트리거가 적고, 보관한 당번은 그때까지 끝난 자리만 센다**(위 「지난 봉사」 절).
  ⚠️ 검토가 권한 줄(보관한 날 = `updated_at` 까지만)은 두 길을 놓쳤다(반박 쪽이 잡았다): 보관을 풀었다 다시 보관하면 그날로 밀리고, 받는 중 → 준비 중 → (날짜가 지남) → 보관이면 준비 중이던 날이 센다. 그래서 「처음 숨긴 때」를 따로 적는다.
- (중간) 담당자 화면·문서가 보관을 「앱에 안 보인다」고만 말했다(시험 당번을 치우는 길로 적힌 것도 보관뿐) → 교회 어드민의 상태 풀이·숨기는 확인 글·명단의 보관 안내·준비 중 안내를 사실대로 ·
  **4단계 앞에 시험 줄 정리**(위 ⏰). 지난 자리의 「이 자리만 쉬기」 확인 글이 「쉬어요로 보여요」라고 했다(지난 자리에는 보이는 곳이 없고, 그 줄이 지난 봉사에서 빠진다) → 지난 날 갈래.
- 지난 날의 「쉬는 날」은 풀 길이 없었다 — 쉬는 날의 줄을 세지 않게 되면서, 잘못 걸었거나 실제로는 섬긴 날의 봉사가 그날 선 모든 분에게서 영영 빠졌다 → `duty_days_off` 가 **다시 열기는 지난 날도** 받고(오늘 − 400일까지),
  교회 어드민 날 판이 지난 쉬는 날에 「다시 열기」를 둔다. 지난 날을 쉬는 날로 거는 것은 여전히 안 된다.
- 당번표의 「지난 봉사 N번」 한 줄이 당번표만 다시 받는 길(화면이 다시 보일 때)에서 낡았다(주일에 5번 → 월요일에 다시 보여도 5번 · 눌러 본 화면은 6번) → 당번표 응답에 두 수를 함께 싣는다.

- 시험의 빈 곳: 「올해」 셈과 「가까운 N줄」 고르기를 값으로 보는 시험이 없어 틀린 SQL 다섯이 모두 통과했다 → 규칙 시험에 줄을 둘 더(29일 전 · 지난 해 12월 31일 — 한도보다 많게 · 365일 안의 지난 해) + 글자 검사.

## ⚠️ 함정

- **잠금 차례는 모든 함수가 같다**(교착 막기): ⓪ 전역 advisory `(7240910, 1)` — **지원 줄을 쓰는 함수 모두**(지원·취소·옮기기·되살리기·못 가요·표시 거두기·담당자 메모) → ① 사람 advisory `(7240911, …)`(계정 → 명부 키 차례 · `duty_person_lock`) → ② 날짜 줄 `for update` → ③ 자리 줄 → ④ 지원 줄.
  ⓪ 은 `member_merge.sql` 의 쓰기 연결 트리거가 지원 줄을 쓸 때 어차피 쥐는 잠금이다 — 맨 먼저 잡아 기록 합치기와 같은 차례로 선다.
  ⚠️ **`duty_signups` 에 직접 update 하지 말 것**(메모 한 칸도 `duty_note_set`) — 직접 쓰면 트리거가 「줄 → 전역」 차례로 잠가 위 차례와 뒤집힌다(두 번째 검토에서 잡았다).
- **날짜 줄·자리를 만드는 일은 당번 advisory `(7240912, 당번)` 을 맨 먼저** — `duty_ensure_slots`(만들 것이 있을 때만) · 틀 고치기·빼기 · 날짜 더하기 · 쉬는 기간 · 날짜 메모. 틀·날짜 줄의 `for update` 와 새 자리의 FK 검사가 서로를 기다리지 않게 당번마다 한 줄로 세운다. 여러 당번을 도는 읽기(`duty_list_view`·`duty_board_counts`)는 당번 id 차례로 돈다.
  `tests/duty-sql.test.cjs` 가 두 규칙을 글자로 본다(지원 줄을 쓰는 함수 = 전역 잠금 먼저 · 날짜 줄·자리를 만드는 함수 = 당번 잠금 먼저).
- **`duty.sql` 뒤에 `member_merge.sql` 을 다시 돌린다** — 표가 먼저 있어야 쓰기 연결 트리거가 `duty_signups` 에 붙는다(`member_merge_duty.dev.sql` ⓪ 이 본다). FK 가 `on delete cascade` 라 합치기가 이 표를 모르면 원본 계정을 지울 때 지원 줄이 **조용히** 함께 지워진다.
  ⚠️ `member_merge.sql` 은 **통째로 갈아 끼우는** 파일이다 — 옛 사본(교육·봉사 당번을 모르는 판)을 운영에 돌리면 그 기록이 있는 계정의 합치기가 `merge-unsupported-records` 로 멈춘다(오류·경보 없음). **운영에 돌리기 전에 origin/main 의 것과 같은지** 볼 것.
- **읽는 함수는 jsonb 하나를 돌려준다**(표로 돌려주면 PostgREST 가 1,000줄에서 자른다). `user_id`·`ident_key`·`confirmed_by` 를 싣지 않는다 — `duty_notify_rows` 만 받는 분(`uid`)을 싣고, 그것은 api 안에서만 쓴다(`duty_remind_ids` 는 지원 번호만 준다).
- `pk`(주별 명단의 「같은 분 표식」)는 부를 때마다 바뀌는 소금을 섞은 해시다 — 저장하거나 응답에 그대로 싣지 말 것(교회 어드민이 `maybeDup` 으로 바꾼 뒤 버린다).
- 함수를 더하면 **권한 두 줄**(revoke public·anon·authenticated · grant service_role)과 파일 끝 확인 질의의 기대 수(지금 34 — 트리거 함수 `duty_board_hidden_stamp` 도 센다)를 함께 — `tests/duty-sql.test.cjs` 가 글자로 본다. **인자 목록을 바꾸면 옛 꼴을 `drop function` 으로 지울 것**(안 지우면 옛 꼴이 권한째 남는다).
- 이름이 **앱을 쓰는 누구에게나** 보인다(친구 결정 「로그인한 분께 보인다」 — 이 앱의 로그인은 본인 확인이 아니다). 그래서 응답에는 이름 글자만(소속·시각 없음 · `duty_name_out` 이 제어·방향 바꿈 글자를 뺀다) · 방침 글은 공개(4단계) 전에.
- 「임명된 분만 지원하는 당번」은 만들지 않았다 — 그런 당번은 `closed`(지원 멈춤)로 두고 담당자가 넣는다(친구께 여쭌 채 진행 · 설계 §0-1 ①).
- ⚠️ **`api` 는 origin/main 을 합친 나무에서만 배포한다** — 낡은 나무로 올리면 성도님 액션 일곱(`dutyList`·`dutyBoard`·`dutyApply`·`dutyCancel`·`dutyMine`·`dutyAsk`·`dutyPast`)이 **조용히 빠지고**, 시험 참여자의 🙋 단추가 「지금 불러올 수 없어요」가 된다(교육·이벤트와 같은 함정). 올린 뒤 `EVT_ENV=prod bash tests/duty-smoke.sh`.
- **담당자 화면의 「앱에 날짜가 안 보여요」는 `duty_board_counts` 의 `shown` 을 본다**(2026-10-06 검증) — 성도님 앱 당번표(`duty_board_view`)와 **같은 범위**(오늘 ~ 오늘+보이는 기간 · 끝 날짜까지)의 자리 수다.
  `slots` 는 보이는 기간으로 자르지 않아(「날짜 더하기」로 먼 날에 만든 자리도 센다) 김장처럼 더한 날짜가 보이는 기간 밖뿐인 당번을 가리지 못했다(카드는 「앞날 자리 1 · 빈 자리 30」인데 앱에는 날짜가 없었다).
  ⚠️ `duty_board_view` 의 날짜 범위를 고치면 `shown` 도 함께 — `tests/duty-sql.test.cjs` 가 두 범위를 글자로 견준다. 교회 어드민 `emptyKind` 가 까닭 다섯(틀 없음 · 남은 자리만 · 끝 날짜 지남 · 보이는 기간 밖 · 날짜 없음)을 가른다.
- ⏰ **플레이스토어 심사가 통과한 날** `app.js` 의 `MINISTRY_HIDE_ON_PLAY = false` 와 함께 **교회 어드민 `js/menus/duty/duty-logic.js` 의 `PLAY_HIDDEN = false`**(시험 한 줄도) —
  그동안 담당자 화면은 「플레이스토어 앱에서는 심사가 끝날 때까지 🙋 단추가 보이지 않아요 — 안드로이드는 크롬으로 열어 확인」이라고 말한다(그 앱을 쓰는 시험 참여자에게는 단추가 없다).

## 운영 반영 차례 (1단계에서 밟은 길 — 다음에 SQL 을 고칠 때도 같다)

단계마다 **같은 link 로** 확인 질의를 돌려 운영임(users 400 넘음)과 들어간 것(표·함수·역할 수 · 합치기가 당번을 아는가 · 쓰기 연결 트리거)을 본다 — 확인 없이 다음으로 가지 않는다.

1. 이 저장소 `supabase/duty.sql`(끝의 확인 질의가 **그 파일 끝 주석의 기대 수와 같은지** — 수를 여기에 적지 않는다: 함수가 늘 때마다 이 줄이 낡았다 · 공개 권한 0) → 2. `supabase/member_merge.sql` 다시(운영 정의가 origin/main 판과 같은지 먼저) → **이 저장소 main 푸시**(당번을 아는 `member_merge.sql` 이 일찍 main 에 서게)
→ 3. 교회 어드민 SQL 015 → 4. 노출 점검: 공개 키·로그인 토큰으로 `duty_signups`·`duty_board_staff`·`rpc/duty_apply`(인자 이름을 맞춰)가 **401/403**(404 는 「없다」일 수 있어 통과가 아니다) · 교회 어드민 `check-authenticated-exposure.sql` 0줄
→ 5. 교회 어드민 함수: 빈 폴더에 내려받아 대조(차이가 내 것뿐인지) → `--workdir <그 가지 폴더>` 로 배포 → **다시 내려받아 내 나무와 차이 0**
→ 6. 교회 어드민 main 푸시(화면) — 그 앞에 rebase 가 있었으면 5 를 다시.

### 2단계에서 밟은 길 (SQL 한 칸 · `api` · 교회 어드민 · 화면)

0. **운영에 「받는 중·지원 멈춤」 당번이 시험 당번뿐인지** 읽기로 확인(수만 센다 — 올리는 순간 그 명단이 시험 참여자에게 보인다) · origin/main 이 움직였으면 rebase(`index.html` 의 `?v=` 가 부딪히면 모두 같은 값으로 — `bump.py` 가 하나로 모아 준다)
→ 1. SQL 이 바뀌었으면 `duty.sql` 다시(이번에는 `duty_mine` 의 `dayOff` 한 칸 — create or replace) → 확인 질의
→ 2. 운영 `api` 를 빈 폴더에 내려받아 **origin/main 과 같은지**(다르면 누가 무엇을 올렸는지 먼저) → `--workdir <그 가지 폴더>` 로 배포(나무 = origin/main + 내 것 · 커밋된 그대로) → **다시 내려받아 내 나무와 차이 0**
→ 3. 스모크: `EVT_ENV=prod bash tests/duty-smoke.sh`(올리기 전에는 0/14 — 액션이 없어서 · 올린 뒤 14/14) + 교육·이벤트·공통 읽기 스모크가 올리기 전과 같은 수인지
→ 4. 교회 어드민 `duty-logic.js` 의 `APP_LIVE = true`(시험 한 줄도) → preflight → 푸시 — **화면보다 먼저**(먼저 나가도 「시험 참여자만 볼 수 있어요」로 바뀔 뿐이고, 늦으면 담당자 화면이 「성도님께 보이지 않아요」라는 틀린 말을 한다)
→ 5. `python tools/bump.py` → preflight → 푸시 → 라이브 `APP_BUILD` = `?v=` · 이번 판에만 있는 표식(`renderDutyList`).
⚠️ **`api` 가 화면보다 먼저**다 — 화면이 먼저 나가면 시험 참여자의 단추가 「지금 불러올 수 없어요」가 된다.
2단계 되돌리기: 화면은 `git revert` + bump 푸시 · 교회 어드민 `APP_LIVE` 를 다시 `false` 로 · `api` 는 main 에 되돌림 커밋을 넣고 **origin/main 나무로** 배포(내려받아 둔 옛 묶음을 올리지 말 것 — 그 뒤에 얹힌 3단계와 남의 배포분이 말없이 빠진다 · 문이 닫혀 있어 급하지 않다) · SQL(`dayOff` 한 칸)은 둔다(옛 화면·옛 api 가 그 칸을 읽지 않는다).

**되돌리기**(1단계 — 반영의 거꾸로): 화면 `git revert` 푸시 → 함수는 되돌림 커밋을 넣고 origin/main 나무로 다시 배포(내려받아 둔 옛 묶음을 올리지 말 것) → 015(담당 줄·역할 줄 — 역할을 받은 분이 있으면 그 줄 먼저) → `member_merge.sql` 은 origin/main 옛 판을 다시 → `duty.sql` 은 표를 지워야 하는데 **담당자가 명단을 넣은 뒤에는 지우지 않는다**(앞으로 고치는 것만). 운영 확인은 읽기로만 — 시험 당번을 만들면 보관 상태로 남는다(지우는 길이 없다).
