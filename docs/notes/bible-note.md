# 성경 필사노트 가로형 (bible-note/)

> **언제 읽나:** `bible-note/` 의 파이썬(parse · paginate · render · generate · verify)을 고치거나,
> 필사노트를 새로 뽑다가 멈췄을 때. 사용법은 성도님용 가이드 **`bible-note/필사노트_만들기.md`**(같은 내용의
> `.html` 도 있다), 설계는 `docs/superpowers/specs/2026-09-22-bible-landscape-note-design.md`,
> 계획(Task 1~9)은 `docs/superpowers/plans/2026-09-22-bible-landscape-note.md`.

## 무엇인가 (2026-09-22)
`bible/*.txt`(개역개정) 한 권 또는 한 장을 **A4 가로 · 왼쪽 원문 / 오른쪽 필사줄** HTML 로 만들어 크롬에서 바로
인쇄한다. 세로 노트는 왼쪽 쪽의 와이어가 손에 닿아 쓰기 어렵다는 말씀이 있어 가로로 바꿨다(제본은 왼쪽 긴 변 그대로).

```
cd bible-note
python generate.py 시편 --chapter 1      # → 시편_1편.html
python generate.py 요한복음 --chapter 1  # → 요한복음_1장.html
python generate.py 유다서                # → 유다서.html (5쪽)
python verify.py 유다서.html             # 「모두 통과했습니다.」
```

성도님이 정한 것: 원문:필사 **50:50** · 절 번호와 본문을 나눠 내어쓰기 · 머리글 날짜 칸은 밑줄 없이 빈 공간 ·
바닥글 세 칸(God is Love · 표어, 짝수 쪽은 영어 · `1 / 5`) · 장마다 왼쪽 「1장」(시편 「1편」) · 권 제목 가운데 ·
머리글/바닥글 서체·크기와 원문 자간은 `render.py` 맨 위 설정.

## ⚠️ 손대기 전에
- ⚠️ **줄 수는 눈대중이 아니라 헤드리스 크롬 실측이다.** 1차(원문만 있는 초안)를 찍어 줄 수를 재고(요소 높이 ÷
  줄 높이 — `getClientRects` 상자 수를 세면 틀린다), 그 수로 쪽을 나눈 뒤 2차(인쇄본)를 만든다.
  **1차와 2차는 반드시 같은 CSS 규칙(`base_css()`)을 써야 한다** — 열 폭·안쪽 여백·자간·번호 칸·권 제목·장 표시
  중 하나라도 한쪽에만 주면 줄바꿈이 달라져 필사줄 수가 조용히 어긋난다.
- ⚠️ **틀린 채 인쇄하느니 멈춘다**(성도님 결정). 원문의 세 꼴 — 권 제목(`시1:제일권`) · 끊긴 절(`요12:예수께서 <…> …`)
  · 합쳐진 절(`롬9:1-2`) — 만 인쇄 성경처럼 찍고(66권에 5 · 45 · 11곳), 그 밖의 절 번호 없는 줄 · 한 쪽보다 긴 절 ·
  잘못된 줄 수는 멈춘다. 끊긴 절은 원문이 소제목을 **본문 첫 낱말 뒤**에 두므로(`예수께서 <소제목> 이 말씀을`)
  「소제목 → 예수께서 이 말씀을」로 되돌려 찍는다.
- ⚠️ `CONT_RE`(끊긴 줄)는 콜론 뒤 첫 글자가 숫자가 아닌 줄을 모두 끊긴 줄로 읽는다. 개역개정에는 다른 꼴이 없음을
  확인했지만, **다른 번역본을 넣으면 다시 볼 자리**다.
- ⚠️ **저작권 — 만든 HTML 과 원문은 절대 커밋하지 않는다.** 이 저장소는 공개이고 푸시가 곧 배포다. `.gitignore` 가
  `bible-note/**/*.html` · `**/fonts/` · `**/_*`(실측 임시 파일 · `_샘플/` 원문 본보기)를 막고, `generate.py` 의
  `ensure_out_path_safe()` 가 저장소 안의 무시되지 않는 `--out` 을 거부한다. **예외는 가이드
  `필사노트_만들기.html` 하나**(`!` 줄) — 본문이 아니라 설명서라서다.
- ⚠️ 최종 HTML 은 `fonts/` 를 상대 경로로 부른다. HTML 만 옮기면 서체가 대체되어 줄이 어긋난다 — 그래서 붉은 띠
  (`FONT_WARN_HTML`)를 띄우고 verify 가 `FONT_NOT_LOADED` 를 낸다. 머리글·바닥글 서체(`HEADER_FONT_URL` ·
  `FOOTER_FONT_URL`)는 내 PC 파일도 된다(`{'fonts/파일.ttf': ''}` — 주소가 비면 받지 않는다, `.ttc` 는 멈춘다).
- ⚠️ `verify.py` 는 인쇄 확인 PDF 를 HTML 옆에 고정 이름(`_verify_print.pdf`)으로 만든다 — **같은 폴더에서 verify 를
  둘 동시에 돌리면 서로의 PDF 를 읽어** `PRINT_PAGES` 가 틀리게 나온다(2026-09-22 시편 `5!=1` 로 재현). 하나씩 돌린다.
- 크롬이 가끔 한 번 헛돌아 `PRINT_FAILED` 를 낸다 — 파일을 바꾸지 말고 다시 돌려 본다.
- 테스트: `cd bible-note && python -m pytest tests -q`. 한글 출력은 Git Bash 에서 `PYTHONIOENCODING=utf-8`.

## 남은 것 — 2026-09-22 최종 검토(Task 1~9 · Ready: Yes)의 Minor
성도님이 「나중에 다시 요청하겠다」고 하셔서 고치지 않고 적어 둔다. 보통 쓰는 방법(만들기 → 확인 → 인쇄)에는 영향이 없다.
1. **임시 파일 이름이 고정이다** — verify(`_verify.html` · `_verify_print.pdf`)와 generate(`_draft.html` · `_measure.html`).
   같은 폴더에서 둘을 동시에 돌리면 서로의 파일을 읽는다. 일부러 망친 HTML 이 3번 중 2번 「모두 통과」로 나왔다(재현).
   → `tempfile.mkstemp(dir=…, prefix='_verify_')` 처럼 실행마다 다른 이름.
2. **서체 설정 오류가 트레이스백으로 뜬다**(`.ttc` · 모르는 확장자 · 한 벌 초과 · 한 파일에 주소 둘) — 다른 멈춤은 모두
   `!! …`. → `main()` 에서 ValueError 를 잡아 `SystemExit('!! ' + msg)`.
3. **주소가 빈 내 PC 서체 키가 `fonts/` 밖이면**(`'C:/…/x.ttf': ''`) 멈추지 않고 붉은 띠·verify 에서야 드러난다.
   붉은 띠 문구도 Noto Serif KR 이라고 적어 원인을 잘못 가리킨다. → 그런 키는 거부, 띠 문구는 일반적으로.
4. **`FOOTER_FONT_URL` 을 두고 바닥글 글을 모두 `''` 로 비우면** 안 쓰는 서체가 unloaded 로 남아 붉은 띠와
   `FONT_NOT_LOADED:NSKF` 가 난다(재현). → 글이 없는 자리의 서체는 넣지 않거나, status 'error' 만 실패로.
5. `CONT_RE` 의 첫 낱말 `(\S*)` 가 콜론 바로 뒤 `<` 도 먹는다 — `요5:<소제목> 이 날은` 이 본문 `<소제목> 이 날은` 으로
   읽혀 「모르는 꼴은 멈춘다」가 이 꼴에서 안 지켜진다(개역개정에는 0곳). → `([^\s<]*)`, 본문에 `<` `>` 가 남으면 멈춤.
6. 다듬기: 서체 자리 목록이 `_slot_fonts()` 와 `page_css()` 두 곳 · `render.py` 오류 메시지에 조각 번호가 없음 ·
   `parse.py` 의 안 쓰는 `ch_s` · `paginate.py` 머리 주석과 계획·설계의 낡은 설명(절 → 조각, 번호 칸 폭은 가장 긴 번호 글자).
7. 전부터 남은 것: git 이 PATH 에 없으면 `--out` 검사를 건너뜀 · `PRINT_FAILED` 에 크롬 stderr 가 빠짐 ·
   1차·2차 공용 규칙 테스트가 문자열이 있는지만 봄.
