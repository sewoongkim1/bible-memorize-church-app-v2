# 말씀 도전 순위 — 서로 응원하기

## 배경 및 목적

「🏆 말씀 도전 순위」는 지금 읽기 전용이다. 이름과 횟수가 나열될 뿐, 성도끼리 아무 말도 주고받을 수 없다. 순위표를 **서로 격려하는 자리**로 바꾼다.

방금 이름을 바꾼 「응원·기도·공감」 게시판이 긴 나눔을 받는다면, 순위표의 응원은 **한 번의 탭**이다. 글을 쓸 만큼은 아니지만 "잘하고 계세요"를 전하고 싶을 때의 통로다.

- **대상**: 로그인한 성도 (딥링크로 들어온 비로그인 사용자는 응원 버튼을 보지 않는다)
- **범위**: 개인 순위 화면(`renderRanking`)만. 교구별 순위·내 참여는 건드리지 않는다.

## 핵심 결정 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| 응원 모양 | `👏` 칩 하나, 한 탭 | 순위 줄이 좁다. 5종 픽커는 과하다 |
| 자격 | 오늘(KST) 내 도전 기록 1건 이상 | 자기도 달리고 나서 남을 응원한다 |
| 빈도 | 하루 한 사람당 한 번, 다시 누르면 취소 | 게시판 공감과 같은 결 |
| 대상 식별 | `구분\|소속\|세부\|이름` 조합 | 화면에 이미 다 보이는 값 — 새로 새는 정보가 없다 |
| 알림 | 없음 (앱 안에서만) | 상위권이 하루에 알림을 여러 번 받게 된다 |
| 숫자 기준 | 조회 기간(from~to) | 화면 전체가 "이 기간의 순위"다 |
| 켬 기준 | 오늘 | 버튼이 하는 일이 "오늘 주기/취소"다 |
| 소속 표기 | `사랑교구 3목장` → `사랑-3` | 칩이 들어갈 자리를 만든다. 폰에서 **절대 두 줄로 넘어가지 않아야** 한다 |

## 화면과 상호작용

### 칩이 뜻하는 것

한 줄에 손댈 곳이 둘이다. **뜻을 서로 다른 요소에 갈라 둔다.**

| 누르는 곳 | 하는 일 |
|---|---|
| `👏` 칩 | 응원 주기 / 취소 (남의 줄만) |
| `42회` 통계 숫자 | 그 사람을 응원한 사람 명단 펼치기 / 접기 |

- **취소만 한 번 묻는다** — 주는 건 한 번에 되고, 무르는 것만 확인을 거친다. 칩이 작아 잘못 눌러 지워지면 되돌릴 길이 없다.
- **내 줄의 칩은 버튼이 아니다** — 자기 자신은 응원할 수 없으니 받은 수를 보여주는 표식이다. 명단은 내 줄에서도 `42회`로 연다.
- **자격이 없을 때 칩을 누르면** 왜 안 되는지 알려 준다("오늘 말씀을 한 번이라도 암송하면…").
- **명단 보기는 자격·기간과 무관하다.** 잠기는 것은 주는 일뿐이다.

> **두 번 갈아엎은 자리다.** ① 처음엔 "남의 줄 칩 = 주기/취소, 내 줄 칩 = 명단"이었다. 한 시간 앞서 만든 게시판 공감 칩이 **똑같이 생겼는데 탭하면 명단**이라, 그 습관대로 누른 사람의 응원이 지워졌다. ② 그래서 "칩 = 명단, 주기·취소는 펼친 패널 안 버튼"으로 바꿨더니 패널이 늘 열려 거슬렸고 주는 데 두 탭이 들었다. ③ 지금 형태로 정착 — **칩은 오직 +/−, 명단은 이미 넉넉한 「42회」가 연다.** 칩 안을 둘로 쪼개는 안도 검토했지만 탭 영역이 30px도 안 돼 버렸다.

명단은 게시판에서 쓰는 `.rx-names` 패턴을 그대로 재사용한다(줄 아래로 펼쳐지고, 다시 누르면 접힌다).

**명단 보기는 응원 자격·조회 기간과 무관하다.** 오늘 도전을 안 했어도, 과거 기간을 보고 있어도 내가 받은 응원은 언제나 펼쳐 볼 수 있다. 잠기는 것은 "주는 일"뿐이다. 받은 응원이 0이면 펼칠 것이 없으므로 칩을 누를 수 없게 둔다.

「내 순위」 바에도 같은 칩을 한 칸 붙인다 — `👏 받은 응원 5`. 순위에 아직 못 든 성도도 자기가 받은 응원은 여기서 본다.

### 자격이 있을 때

```
🥇 김사랑  사랑-3     42회  👏5   ← 남색 채움 = 내가 오늘 응원함
🥈 이은혜  믿음-12    38회  👏3   ← 흰 바탕 = 아직 안 함
🥉 박민수  소망-남성  31회  👏    ← 0이면 숫자를 감춘다
```

받은 응원이 0일 때 `👏0`을 노출하지 않는다. 0이 줄줄이 드러나면 격려하려다 되레 상처가 된다. 같은 이유로 상위권만이 아니라 **모든 줄에** 버튼을 단다.

### 자격이 없을 때

목록 위에 안내를 한 줄 띄우고, 칩은 옅게 비활성으로 남긴다. 줄마다 자물쇠를 달면 화면이 시끄러워진다.

```
🔒 오늘 말씀을 한 번이라도 암송하면 서로 응원할 수 있어요 · 도전하러 가기 ›

🥇 김사랑  사랑-3   42회  👏5   ← 눌러도 같은 안내만 뜬다
```

오늘 한 번이라도 도전하면 안내가 사라지고 칩이 살아난다.

### 켬/끔 표시

`.rx-chip.on`과 같다 — **남색(`--navy`)으로 꽉 채우고 숫자를 흰색으로 뒤집는다**. 2026-08-15에 확인한 대로, 색조만 바꾸는 옅은 틴트는 대낮 폰 화면에서 흰 배경과 구분되지 않는다. 켬/끔은 색조가 아니라 밝기로 갈라야 한다.

## 응원 자격 규칙

**오늘(KST) `challenge_log`에 내 기록이 1건 이상 있으면 응원할 수 있다.** 순위표 자체가 이 기록으로 만들어지므로 기준이 한 결이다.

- `ranking` 응답이 최상위에 `canCheer`를 실어 보낸다 — 클라이언트가 따로 물어볼 필요가 없다.
- **`rankCheer`도 같은 검사를 다시 한다.** 클라이언트만 막으면 우회된다.
- 자정 경계는 KST. 서버는 `kstDateOnly`(index.ts), 클라이언트는 `kstDateParts`(app.js)를 쓴다 — 새로 만들지 않는다.
- 자기 자신에게는 응원할 수 없다.

## 기간과 켬/끔

숫자와 켬은 서로 다른 시계를 쓴다. 버튼의 겉모습은 **버튼이 하는 일**과 일치해야 하므로, 켬은 언제나 오늘 기준이다.

| 상황 (이번주 탭) | 칩 | 누르면 |
|---|---|---|
| 아무도 안 누름 | `👏` 흰 바탕 | `👏1` 채움 |
| 남들만 눌렀음 | `👏7` 흰 바탕 | `👏8` 채움 |
| 내가 오늘 눌렀음 | `👏8` **채움** | `👏7` 흰 바탕 (취소) |
| 내가 월요일에 눌렀고 오늘은 안 누름 | `👏7` 흰 바탕 | `👏8` 채움 |

마지막 줄에서 7 안에는 내 월요일 응원이 들어 있지만 칩은 꺼져 있다. "오늘은 아직 안 보냈으니 또 보낼 수 있다"는 뜻이라 버튼 동작과 어긋나지 않는다. 반대로 켬을 "이 기간에 눌렀나"로 잡으면, 월요일에 누른 사람이 칩을 눌렀을 때 오늘 것을 더할지 월요일 것을 취소할지 정할 수 없어 더 헷갈린다.

**과거 기간 조회 시 읽기 전용.** 날짜를 직접 넣어 오늘이 포함되지 않는 기간(예: 8/1~8/7)을 보면, 응원은 오늘로 기록되는데 화면은 그 기간만 세므로 눌러도 숫자가 변하지 않는다. 그래서 조회 기간이 오늘을 포함하지 않으면 **주는 버튼만** 감추고 숫자는 그대로 보여준다. 내 줄의 명단 보기는 이때도 살아 있다.

## 데이터 모델

```sql
create table if not exists rank_cheers (
  id           bigserial primary key,
  target_key   text not null,   -- '구분|소속|세부|이름' 정규화 결과
  from_user_id uuid not null references users(id) on delete cascade,
  from_name    text,            -- 명단 표시용(소속+이름) — users를 조인하지 않아도 되게
  cheer_date   date not null,   -- KST 기준 날짜
  created_at   timestamptz not null default now(),
  unique (target_key, from_user_id, cheer_date)
);
create index if not exists rank_cheers_target_date on rank_cheers (target_key, cheer_date);
```

기간 집계는 `created_at`이 아니라 **`cheer_date`로 거른다.** 시간대 환산 없이 정확하고, 순위 조회의 `from`~`to`(KST 날짜)와 단위가 같다.

`target_key`는 `[gubun, sosok, sebu, name]`을 각각 `norm()`으로 다듬어 `|`로 잇는다. **서버가 조합한다** — 클라이언트가 만든 문자열을 그대로 믿으면 공백·표기 차이로 같은 사람이 여러 키로 갈린다.

## API

| 액션 | 요청 | 응답 |
|---|---|---|
| `ranking` (기존, 확장) | `+ me`(내 user_id, 선택) | 각 항목에 `cheers`·`iCheered`, 최상위에 `canCheer` |
| `rankCheer` (신규) | `{gubun, sosok, sebu, name, user_id, who, on}` | `{ok, on}` 또는 `{ok:false, error}` |
| `rankCheerers` (신규) | `{gubun, sosok, sebu, name, from, to}` | `{ok, list:[이름…]}` |

`rankCheer`의 검사 순서 — ① `user_id` 있음 ② 오늘 KST 내 `challenge_log` 기록 있음 ③ 대상이 나 자신이 아님 ④ 대상이 실제 `users`에 있음. 하나라도 어긋나면 사람이 읽을 수 있는 한국어 `error`를 돌려준다.

`me`가 없으면(관리자 도전현황 등) `cheers`만 집계하고 `iCheered`는 전부 `false`, `canCheer`는 `false`로 둔다. 기존 호출부가 깨지지 않는다.

## 레이아웃 — 폰에서 한 줄을 지킨다

**두 줄로 넘어가면 안 된다.** 줄바꿈을 허용하면(`flex-wrap: wrap`) 넘침은 막히지만 순위표가 들쭉날쭉해져 훑어보기 어렵다. 그래서 실제로 폭을 맞춘다.

`.rank-row`는 360px 폰에서 290px을 쓸 수 있는데 지금 내용이 이미 약 256px이다. 칩(약 44px)을 붙이면 모자란다. 두 가지로 자리를 만든다.

1. **소속 표기 축약** — `사랑교구 3목장` → `사랑-3`. 9자가 4자로 줄어 약 64px을 번다. 목장은 입력 단계에서 이미 **숫자 또는 "남성"**으로 강제돼 있어(app.js의 검사) 축약이 안전하다.

   | 원래 값 | 표기 |
   |---|---|
   | 교구=사랑, 목장=3 | `사랑-3` |
   | 교구=믿음, 목장=12 | `믿음-12` |
   | 교구=소망, 목장=남성 | `소망-남성` |
   | 교구=새가족, 목장=99 (없음) | `새가족` |
   | 부서=중등부, 학년=2학년 | `중등부-2` |
   | 부서=청년부, 학년 없음 | `청년부` |

2. **소속을 신축 칸으로** — `.rk-so`에 `flex: 1 1 auto; min-width: 0; white-space: nowrap; overflow: hidden; text-overflow: ellipsis`. 나머지(`rk-no`·`rk-name`·`rk-cnt`·칩)는 `flex: 0 0 auto`로 고정한다. 이러면 이름이 길든 소속이 길든 **소속만 `…`로 줄어들고 줄은 절대 안 늘어난다.** 이 저장소가 이미 쓰는 방식이다(style.css의 `.pg-card-main` 등).

   `.rank-row`의 `gap`은 12 → 8로 좁힌다.

**검증 결과** — 320·360·390·430px에서 최악 케이스(4글자 이름 + `새가족-남성` + 두 자리 응원 수)까지 넣어 렌더한 결과 **전부 한 줄**이었다. 320px에서 그 최악 케이스만 소속이 `새가족…`으로 줄고, 나머지는 온전히 보였다. 판정은 눈대중이 아니라 자식 요소들의 위/아래 좌표를 비교해서 했다.

명단 줄은 `.rank-row` 바깥의 형제 요소로 두어 한 줄 규칙에 끼어들지 않게 한다. 이름은 `word-break: keep-all`로 어절 단위로 끊는다.

## 보안 — user_id를 내보내지 않는 이유

이 API는 JWT 없이(`--no-verify-jwt`) 클라이언트가 보낸 `user_id`를 그대로 믿는다. 순위 응답에 전 교인의 `user_id`를 실으면 누구나 남의 이름으로 기록을 쓰거나 지울 수 있다.

그래서 대상은 **화면에 이미 보이는 네 조각**으로만 지정한다. 새로 새는 정보가 없다. 클라이언트가 서버로 보내는 `user_id`는 언제나 **자기 것뿐**이고, 이는 게시판 공감이 이미 하는 방식과 같다.

## 하지 않는 것

- **푸시 알림** — 상위권이 하루에 알림을 여러 번 받게 된다. 앱 안에서만 본다.
- **이모지 여러 종** — 순위 줄이 좁다. `👏` 하나로 시작한다.
- **관리자 화면의 응원 현황** — 앱 안에서 보면 충분하다(2026-08-15 확인).
- **교구별 순위·내 참여 화면의 응원** — 개인 순위에서만 시작한다.
- **응원 랭킹(누가 많이 응원했나)** — 격려가 또 하나의 경쟁이 된다.

## 검증

- **레이아웃**: 320·360·390·430px 폭을 한 화면에 늘어놓은 하네스를 헤드리스 크롬 `--screenshot`으로 찍어, 칩과 명단 줄이 카드 밖으로 나가지 않는지 눈으로 확인한다(`--dump-dom`은 이 PC에서 출력이 비어 쓸 수 없다).
- **자격 규칙**: 오늘 기록이 없는 계정으로 `rankCheer`를 직접 호출해 거부되는지 확인한다 — 클라이언트를 거치지 않는 경로가 진짜 관문이다.
- **기간 집계**: 어제 날짜의 `rank_cheers` 행을 하나 넣고, "오늘" 탭에서는 안 세고 "이번주"·"전체" 탭에서는 세는지 확인한다.
- **스모크**: `tests/smoke-readonly.sh`에 `rankCheerers` 읽기 호출을 한 줄 더한다.
