# 성경 필사노트 — 가로형 (A4 landscape) 설계

> 종이 인쇄물이다. 앱 기능이 아니다. 브라우저에서 직접 `Ctrl+P`로 인쇄하는 HTML 파일을 만든다.

## 1. 왜 만드는가

담당자가 그동안 성경 각 권을 A4 세로 · 왼쪽 원문 / 오른쪽 필사 2단 구조로 만들어
와이어링(스프링) 제본해 왔다(참조: `tmp/65.유다서.pdf`). 세로 A4는 폭이 210mm뿐이라
왼쪽·오른쪽 두 칸으로 나누면 필사 칸이 좁고, 필사할 때 손이 왼쪽의 스프링 제본
가까이 있게 되어 쓰기 불편하다는 성도님 지적이 있었다.

**해결책**: 용지를 가로(297×210mm)로 눕힌다. 제본은 그대로 **왼쪽 긴 변**에 하지만,
전체 폭이 297mm로 넓어지므로 오른쪽 필사 칸을 스프링에서 더 멀리, 더 넓게 뗄 수 있다.

## 2. 범위 (이번 견본)

- 유다서 1장 전체(25절)
- 요한복음 1장(51절, 긴 본문으로 한 번 더 검증)

이후 성경 전체로 넓힐지는 이 견본을 보고 결정한다. 지금은 확장을 전제로 코드를
짜되, 66권 전체를 자동으로 도는 기능까지는 만들지 않는다(YAGNI).

## 3. 전체 흐름

```
bible/2-26유다서.txt (CP949, 절 텍스트)
      ↓ 파싱
절 목록 (권·장·절 번호·소제목·본문, 파이썬 안의 리스트/딕셔너리 — 별도 JSON 불필요할 만큼 작다)
      ↓ generate.py 1차 그리기
초안 HTML (원문 열만, 필사줄 없음 — 페이지도 아직 안 나눈다)
      ↓ 헤드리스 크롬 실측: 절마다 원문이 몇 줄로 찍혔는지
줄 수 데이터
      ↓ generate.py 2차 그리기: 절을 페이지에 배분 + 필사줄 개수 확정
최종 HTML (인쇄용)
      ↓ 헤드리스 크롬 검증
통과 확인
```

「기독교 고전 소책자」(`booklet/generate_classics.py`)가 쓴 2단계 방식을 그대로 옮긴다.
손으로 "이 절은 몇 자니까 몇 줄"이라고 계산하지 않는다 — 실측이 원칙이다.
⚠️ 폰트·폭을 나중에 조금만 바꿔도 1차 그리기부터 다시 돌리면 된다(캐시하지 않는다).

## 4. 페이지 레이아웃

- 크기: 297×210mm(A4 landscape), 여백 상하좌우 각 13mm
- 위쪽: 「유다서 1:1~1:5」처럼 **그 쪽에 실제로 담긴 절 범위**(참조 PDF와 같은 방식 —
  페이지마다 값이 다르다. 책 제목만 고정이 아니다) + 「  년   월   일」 쓰는 칸 — 밑줄 없이 빈 공간만
  (연 20mm · 월 12mm · 일 12mm, 2026-09-22 성도님 요청)
- 아래쪽: 쪽번호 위에 머리글 밑줄과 같은 선을 긋고, 그 아래 세 칸 — 왼쪽 `God is Love` ·
  가운데 표어 `주의 말씀은 내 발에 등이요 내 길에 빛이니이다`(짝수 쪽은 영어
  `Your word is a lamp to my feet and a light for my path.`) · 오른쪽 `쪽 / 전체`.
  `render.py` 맨 위 설정(FOOTER_*)으로 바꾼다. 로고·자유메모 페이지는 넣지 않는다.
  (처음엔 「간결하게」로 쪽번호만이었다 — 2026-09-22 견본을 본 성도님이 참조 PDF 처럼 바꿨다)
- 좌우 폭: 여백 뺀 가용폭 기준 **원문 50% : 필사 50%**(각 135.5mm). 사이에 가는 세로선 하나.
  처음엔 「필사 칸을 더 넓게」로 38:62였는데, 견본을 본 성도님이 50:50으로 바꿨다(2026-09-22).
- 서체: 원문·필사 모두 **Noto Serif KR**(SIL OFL, 소책자에서 이미 검증·재사용).
  머리글의 서체·글씨 크기와 바닥글의 글씨 크기는 따로 정한다(`render.py` 맨 위 HEADER_PT · HEADER_FONT_URL ·
  FOOTER_PT, 2026-09-22 성도님 요청). 원문 자간도 LETTER_SPACING_EM 한 줄로 정한다 — 실측·인쇄가 함께 쓰는 규칙에 넣는다.
  바닥글 서체도 따로 정한다(FOOTER_FONT_URL, Task 9). 머리글·바닥글 서체로 내 PC 의 서체 파일(fonts/ 에 복사, 주소 '')도 쓸 수 있다.
  `bible-note/fonts/`는 커밋하지 않는다 — 없으면 생성기가 받아온다(소책자와 같은 이유).
- 줄 높이: **9.5mm** 고정(소책자에서 실측으로 검증된, 손 글씨 쓰기 좋은 값).
  원문 폰트 크기는 이 줄 높이에 맞춰 정하고, 원문 열 폭 안에서 한 줄에 몇 자가
  들어가는지는 실측으로 정한다.

## 5. 절 표기 규칙

- 「1. 예수 그리스도의 종이요…」처럼 번호+본문을 쓴다. (앱 딥링크 같은 "장:절" 표기는 쓰지 않는다.)
- **번호와 본문은 나눈다(내어쓰기)** — 본문이 다음 줄로 넘어가면 번호 칸만큼 비우고 본문 첫 글자 아래에서
  시작한다(2026-09-22 성도님 요청). 번호 칸 폭은 뽑은 범위에서 가장 긴 표시 번호(label — 합쳐진 절은 「1-2」처럼 찍힌다)의 글자 수에 맞춘다(시편 119편은 세 자리, 예레미야 33장의 「10-11」은 다섯).
  ⚠️ 실측(1차)과 인쇄(2차)가 같은 폭을 써야 줄바꿈이 같다.
- 장이 시작하는 자리마다 **왼쪽 정렬로 「1장」**(시편은 「1편」)을 원문·필사 양쪽에 굵게 찍는다(참조 PDF 처럼,
  2026-09-22 성도님 요청). 시편 권 제목이 있으면 「제일권」(가운데) → 「1편」(왼쪽) → 소제목 → 1절 순서다.
- 소제목(원본의 `<인사>` 같은 표시, 다른 책 인용까지 포함하는 경우도 있다 —
  예 `<세례 요한의 증언(마 3:1-12; 막 1:7-8; 눅 3:15-17)>`)은 **원문·필사 양쪽에 굵은 글씨로**
  한 줄씩 그대로 찍는다. 필사 대상이 아니라 어디를 읽는지 알려주는 이정표이기 때문이다.
- 원본 텍스트의 문단 시작 기호(참조 PDF의 "○")는 `bible/*.txt` 원본에 없다
  (PDF 제작 당시 따로 붙인 것으로 보인다) — 이번 판에는 넣지 않는다.

## 6. 필사줄 대응 방식

원문 절이 N줄로 찍히면, 오른쪽 같은 절 자리에 **정확히 N개의 빈 줄**(9.5mm 간격)을 둔다.
줄 수는 1차 그리기의 실측 결과를 그대로 쓴다 — 2차 그리기에서 원문 열의 폭·폰트가
같으므로 다시 그려도 같은 줄 수가 나온다(이 전제가 깨지면, 즉 실측 폭과 최종 폭이
다르면 어긋난다 — 코드에서 두 값이 반드시 같은 상수를 쓰게 한다).

## 7. 페이지 나누는 규칙

- **절 중간에서 페이지를 자르지 않는다.** 한 절이 통째로 다음 페이지로 넘어간다.
- 소제목은 바로 다음 절과 한 묶음으로 취급해, 소제목만 페이지 맨 아래 혼자
  남지 않게 한다(고아 방지).
- 페이지당 가용 줄 수 = (페이지 높이 − 여백 − 헤더 − 푸터) ÷ 9.5mm.
- 절(과 앞에 붙은 소제목)을 순서대로 쌓다가, 다음 절이 남은 줄 수보다 크면
  새 페이지로 넘긴다.
- 장이 바뀌면 새 페이지에서 시작한다(이번 견본은 각 권 1장뿐이라 실제로 발동하지
  않지만, 나중에 여러 장을 붙일 때를 위해 규칙만 정해 둔다).

## 8. 파일 구조

```
bible-note/
  generate.py          # 2단계 생성기 (CLI: python generate.py 유다서 [--chapter N] [--out 경로])
  parse.py · paginate.py · render.py · verify.py · tests/
  fonts/                # Noto Serif KR (gitignore, 없으면 자동 다운로드)
  유다서.html
  요한복음_1장.html
```

**파싱 규칙** (`bible/*.txt` — 개역개정은 CP949. UTF-8(BOM 포함)도 읽는다, 2026-09-22):
- 한 줄이 대개 `약자N:M <소제목>? 본문` 꼴이다. 정규식 `^\D+(\d+):(\d+)\s*(?:<([^>]*)>)?\s*(.*)$`
  으로 장·절·소제목·본문을 가른다(`bible-note/parse.py`의 `VERSE_RE`와 같다).
- 파일명에서 책 전체 이름을 얻는다(`2-26유다서.txt` → 유다서). 줄 속 약자 자체는
  쓰지 않는다(장·절 숫자와 순서만 쓰면 되므로).
- 요한복음은 "1장만"이 이번 요청이므로 파싱 뒤 1장 절만 추린다(`chapter == 1`).
- 원문에는 절 번호로 딱 나뉘지 않는 꼴이 셋 있다(66권을 훑어 확인, 2026-09-22). 처음엔 발견하면 멈추게 했다가,
  같은 날 성도님이 **멈추지 말고 인쇄 성경처럼 찍기**로 정했다.
  - **권 제목** `시1:제일권`(시편 1·42·73·90·107편, 5곳) — 그 편 첫 절 위에 **가운데 정렬**로 찍는다.
  - **끊긴 절** `요5:이 날은 안식일이니`(45곳) — 소제목 자리에서 한 절이 둘로 나뉜 것. 그 자리에서 나누어, 앞부분은 절 번호와 함께,
    (소제목이 있으면 그 줄), 뒷부분은 번호 없이 이어 찍는다. ⚠️ 원문은 이런 줄의 소제목을 **본문 첫 낱말 뒤**에 둔다
    (`요12:예수께서 <그들이 …> 이 말씀을`) — 뜻은 「소제목 → 예수께서 이 말씀을」이다.
  - **합쳐진 절** `롬9:1-2 …`(11곳) — 번호를 「1-2.」로 찍고 한 절처럼 다룬다.
  - 이 셋에도 안 맞는 절 번호 없는 줄은 여전히 멈춘다(지금 원문에는 없다).

## 9. 검증

「기독교 고전 소책자」때와 같은 방식으로, 최종 HTML을 헤드리스 크롬으로 열어:
1. 원문 글자가 페이지 밖으로 넘치지 않았는지
2. 필사줄 개수가 그 절의 실제 렌더링 줄 수와 같은지
3. 절이 페이지 중간에서 끊기지 않았는지(마지막 줄이 페이지 하단보다 안쪽인지)

세 가지를 자동으로 대조한다. 실패하면 어느 절·어느 페이지인지 짚어 알려준다
(손으로 한 쪽씩 눈으로 세지 않는다 — 소책자 때 그 방식이 두 번 틀렸던 전례가 있다).

## 10. 이번 범위에서 하지 않는 것

- 성경 전체 66권 자동 생성 (범위 밖 — 견본 승인 뒤 별도 요청 시)
- PDF 변환 (HTML을 브라우저로 직접 인쇄하는 것이 이번 요청이다)
- 로고·자유메모 페이지 (성도님이 "간결하게 핵심만"으로 결정. 표어는 뒤에 바닥글 가운데로 들어왔다)
- 원문 문단 기호(○) 재현 (원본 데이터에 없음)
