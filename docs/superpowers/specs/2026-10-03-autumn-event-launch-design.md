### 측정 시작일 SQL — `supabase/event_autumn_2026_move.sql`
- `update public.events set needs = jsonb_set(needs, '{eligibility,start}', '"2026-10-18"') where id = 'autumn-2026' and status = 'draft'`
- **막는 조건 둘을 SQL 안에 넣는다:** `status = 'draft'` 일 때만 · `event_signups` 에 이 회차 행이 **0건**일 때만(규칙을 바꾸면 과거 판정이 소급해 바뀐다 — 9/23 설계 §13 「규칙을 나중에 바꾸지 않는다」).
- 확인 질의를 같이 둔다: `needs->'eligibility'` · `opens_on > eligibility.start` (앞서면 화면이 「곧 시작」이라 하면서 신청 단추가 열린다 — 9/23 설계 SQL 주석).
- 개발 먼저 돌리고 확인 → 운영. `db query --linked` 를 쓸 때는 **어느 쪽에 이어져 있는지 먼저**(메모 `supabase-sql-needs-user`).

### 순서
날짜 칸끼리 서로를 검사한다 — 교회 어드민 `checkEvent` 는 `opens_on < eligibility.start` 면 `before-eligibility` 로 막는다.
새 값(신청 11/3 > 시작 10/18)은 어느 순서로 넣어도 걸리지 않는다. 그래도 **SQL(시작일) 먼저 → 어드민(이름·날짜)** 으로 한다.

## 5. 다른 세션과 겹치는 곳

- **교회 어드민 가지 `autumn-excuse`**(자격 인정·미신청 목록 · 2026-10-03 작업 중) — 화면 문구에 「가을 말씀 동행」이 박혀 있다(`js/menus/bibleevent/*`). **이름 바꿈과 새 날짜를 그 세션에 알린다.** 그쪽 코드는 이 작업에서 건드리지 않는다. 날짜는 회차 행(`needs.eligibility`)에서 읽으므로 따로 고칠 필요가 없어야 한다 — 박힌 날짜가 있으면 그쪽이 고친다.
- `app.js`·`index.html` 은 공용 파일 — 내 헝크만 담아 커밋(CLAUDE.md 「여러 세션」).

## 6. 안 하는 것

- 회차 id 를 새로 만들지 않는다(신청 0건 · draft 라 그대로 옮겨도 된다).
- `event_stamp_2026.sql` 을 다시 돌리지 않는다.
- 규칙(주 3일 · 6주 · 3주 · 처음 오신 분 `max(2, floor(남은 주/2))`)은 바꾸지 않는다.
- 전화번호·선물 품목 칸을 만들지 않는다.
- 「가입은 되는데 첫 활동이 없다」(backlog 4-4)는 이 작업 밖이다 — 첫날 흐름 효과는 10/8 이후 `first_day_metrics.sql` 로 따로 잰다.

## 8. 바뀜 (2026-10-03 같은 날 · 친구 결정) — 「하루 3번」 규칙 + 시험 참여자 시험

### 8-1. 규칙
| 항목 | 값 |
|---|---|
| 하루 한 칸 | 그날 활동 **`perDay`(=3) 번 이상**이면 한 칸 — 예전 「하루 한 번이라도」(9/23 설계 §3 「하루 ●」)를 바꾼다 |
| 「한 번」 | 앱 첫 화면 **「오늘 N회」와 같은 수** = `daily_activity.cnt` 를 모드 구분 없이 더한 값(암송 단계 하나 · 도전 한 구절 · 복습 한 구절마다 1) |
| 숫자의 자리 | `needs.eligibility.perDay` 하나. 없으면 1(다른 회차·옛 판과 맞춘다) |
| 바꿀 수 있는 때 | **10/18 개시 전까지만**(3 ↔ 5). 연 뒤에는 바꾸지 않는다(지난 날 도장이 소급해 사라진다). **인쇄물 때문에 실제 마감은 10/14** |
| 나머지 | 주 3일 · 6주 가운데 3주 · 처음 오신 분 완화 · ✨ 그대로 |
| `first_day` | 처음 오신 분 판정은 **여전히 「아무 활동이든 처음 한 날」**(문턱과 무관) |

**화면:** 도장판의 날 칸은 `n ≥ perDay` 일 때만 찍히고, 모자란 날은 「n/3」, 오늘 칸은 「오늘 n/3」으로 그 자리에서 오른다(`bumpStampToday` 는 칸을 뒤집지 않고 오늘 수를 하나 올린다). 앱 안 문구는 숫자를 박지 않고 `perDay` 를 따른다.
**바뀌는 자리:** `v2_event_weeks`(새 인자 `p_per_day` · 기본 1) · api `evtRule`·`evtStampsFor`·`eventSignup`·명단 집계 · `js/events.js`·`app.js`(알약·오늘 칸) · `events.copy.intro` · `event_streak_metrics.sql` · 포스터·공지(「하루 한 번」 → 「하루 3번」).
⚠️ **교회 어드민 가지 `autumn-excuse`(다른 세션 · 아직 main 에 안 합침)** 의 `events-elig.ts`·`index.ts` 도 `v2_event_weeks` 를 부르고 `perWeek` 로 주를 센다 — **`perDay` 를 넘겨야 명단 자격이 앱과 같아진다.** 그 세션에 알린다.

### 8-2. 시험 — 운영에서 「🧪 시험 참여자」만
- 시험 회차 **`autumn-2026-test`**: `status draft` · `needs.testOnly = true` · 제목 「[시험] 가을 말씀암송 동행」 · 측정 **2026-09-27(일)부터 6주** · `perDay 3` · **`perWeek 1` · `need 1` · `minNeed 1`**(며칠 안에 신청까지 해 보려고) · 신청 **10/4 ~ 10/17** · 목록 끝 10/17.
- 보이는 사람: 교회 어드민 ⚙️ 시스템 → 🧪 시험 참여자(app_config `ministryTesters` · api `ministryIsTester`)에 든 계정만. 다른 성도님께는 목록·도장·신청·명단 어디에도 안 나온다.
- ⚠️ `testOnly` 가 없는 draft(진짜 `autumn-2026`)는 시험 참여자에게도 **안** 보인다 — 개시 전에 진짜 회차가 새면 안 된다.
- **10/17 에 시험 회차를 지운다**(`event_signups` 는 cascade 로 함께 지워진다) → 10/18 진짜 회차 개시.

### 8-3. 일정
시험 준비 ~10/6 → 친구 시험 10/7~10/13 → **3 이냐 5 냐 확정 10/14**(주보·포스터) → 10/17 시험 회차 삭제 → 10/18 개시.
