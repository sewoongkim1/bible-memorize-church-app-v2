# 담임목사 AI 성도 조회 — 설계 초안 (2026-10-15)

> **상태: 아이디어 · 설계 초안.** 친구와 이야기한 것을 적어 둔 것이다 — 아직 아무것도 만들지 않았다.
> 담임목사님 · 교회의 결정(아래 「정할 것」)이 먼저다.
> 화면 시안(캔버스 · 예시 자료 · 비공개): https://claude.ai/artifact/LpNKB372jaCEE5nei6fY8t
> — ① 성도 묻기(PC) · ② 심방 준비 한 장(휴대폰)

## 왜

담임목사님이 「3교구 권사님 중 작년까지 섬기시다 올해는 쉬시는 분」처럼 **말로 물어 명단을 얻고**,
심방 전에 한 분의 기록을 **한 장으로** 보시게 하려는 것. 교회 어드민에는 이미 재료가 있다 —
교인명부(`church_people` · 가족 · 직분 · 소속) · 사역 이력(`ministry_history` 2022~) · 교육 · 봉사 당번 · 새가족 ·
성경필사(암송) 명단(`event_signups`) · 잇기 표(`people_links`).

## 원칙 — AI 는 통역만 한다

- **AI 는 「질문 → 조건」만 만든다. 명단은 서버가 DB 에서 꺼내 화면에 그린다.** 명단은 AI 를 거치지 않는다.
- **AI 가 SQL 을 짜지 않는다.** 정해진 양식(도구)의 칸만 채운다. 질문 글에 「전화번호 다 보여줘」가 들어와도
  양식에 그런 칸이 없으니 나갈 길이 없다(프롬프트 주입을 구조로 막는다).
- **AI 에 보내지 않는 것:** 이름 · 연락처 · 주소 · 사진 · 생년월일 · 심방 메모. 정리 글에는 숫자만, 심방 카드에는 이름 없는 사실 목록만.
- **판단은 사람 몫.** 점수 · 딱지(「멀어진 분」 등) · 이유 짐작(「건강 때문에」)은 쓰지 않는다 — 근거만 나열한다.

## 구조

```
목사님 브라우저 (admin.onlybible.kr · 카카오 로그인)
  │ ① 질문 글
  ▼
Edge Function church-admin · 새 액션 askPeople
  │ ② 역할 확인 — ACTION_ROLES: askPeople = "pastor"
  │ ③ Claude API ── 질문 + 조건 양식(도구 하나 · 꼭 부르게) ──▶ Claude
  │                ◀── 채운 조건 JSON ─────────────────────────┘
  │ ④ 조건 검사 — 값이 명부에 있는 것인가 · 연도 범위 · 인원 상한
  │ ⑤ DB — 미리 짜 둔 RPC ai_search_people(조건) 한 번
  │ ⑥ (선택) 결과의 숫자만 Claude 에 → 「AI 정리」 두세 줄
  │ ⑦ 기록 — ai_ask_log (누가 · 언제 · 질문 · 조건 · 몇 명 · 이름 없음)
  ▼
화면: 조건 칩 + 명단(DB 그대로) + AI 정리
```

조건 칩을 목사님이 고치면 AI 를 다시 부르지 않고 ⑤ 부터 돈다(액션 `searchPeople` · 조건을 직접 받음).
한 번 묻는 데 Claude 1~2번 · DB 1번.

## 1. AI 에 묻기 — 조건 양식

- 서버가 보내는 것: 지시문 · 질문 · 도구 `search_people` 하나 · `tool_choice` 로 그 도구를 꼭 부르게.
- 양식의 고르는 값(`enum`)은 **명부에서 뽑아 넣는다**(교구 · 직분 · 사역팀 · 교육 과정 · 행사 회차). 하드코딩하면 명부가 바뀔 때 어긋난다.

```json
{ "name": "search_people",
  "input_schema": { "type": "object", "properties": {
    "gu":         { "type": "string", "enum": ["…명부의 교구 값…"] },
    "mok":        { "type": "string" },
    "title":      { "type": "array", "items": { "enum": ["…명부의 직분 값…"] } },
    "served":     { "type": "array", "items": { "type": "integer" } },
    "not_served": { "type": "array", "items": { "type": "integer" } },
    "team":       { "type": "string", "enum": ["…사역팀…"] },
    "edu_done":   { "type": "string", "enum": ["…교육 과정…"] },
    "event":      { "type": "string", "enum": ["…성경필사 회차…"] },
    "registered_after": { "type": "string", "format": "date" },
    "unknown":    { "type": "string", "description": "양식에 없는 조건은 여기에 그대로 — 화면이 「이건 못 찾아요」로 보인다" }
  } } }
```

- 질문 「3교구 권사님 중 작년까지 섬기시다 올해는 쉬시는 분」 → `{"gu":"3교구","title":["권사"],"served":[2025],"not_served":[2026]}`
- `unknown` 칸: 출석처럼 **자료가 없는 조건**을 AI 가 다른 칸에 억지로 끼워 넣지 않게 한다(모름을 「없음」으로 뭉개지 않기).
### 여러 조건 · 셈이 든 조건 — 조건 트리 + 필드 목록 + 사람별 요약 표 (2026-10-15 친구 질문)

칸이 고정된 양식(위)은 「그리고」만 된다. 「10년 동안 사역하신 분 중 올해는 안 하시는 분」처럼 셈 · 「또는」 · 「아님」이 섞이면
AI 와 DB 사이에 **조건 트리**라는 중간 언어를 둔다. AI 는 DB 의 표 · 칸 이름을 모르고, 필드 목록의 한글 설명만 안다.

```
질문 → ① 해석(Claude · 도구 입력 = 조건 트리 JSON)
     → ② 검사(서버 · 필드 목록에 있는 칸 · 연산자 · 값만 · 깊이 3 · 조건 10개)
     → ③ 번역(서버 · 트리 → 매개변수 SQL)
     → ④ 실행(요약 표만 읽는 DB 역할 · 시간 제한 · 200명)
     → ⑤ 화면(트리를 서버가 사람 말로 되돌린 칩 + 명단)
```

- **필드 목록(의미 층)** — 「물을 수 있는 것」을 한 곳에 정의한다: 이름 · 한글 라벨 · 형(수 · 해 목록 · 고르기) · 쓸 수 있는 연산자 · SQL 자리 · AI 에게 줄 설명.
  도구 양식 · 검사 · 번역 · 칩 라벨이 모두 이 목록 하나에서 나온다. 물을 수 있는 것을 늘리는 일 = 한 줄 더하기.
- **사람별 요약 표 `person_facts`**(교인 한 분 한 줄 · 구체화 뷰 · 밤마다와 명단을 올린 뒤 다시 만듦) — 섬긴 해 수 · 섬긴 해 목록 · 처음/마지막 섬긴 해 ·
  가장 길게 잇따른 해 · 받은 교육 · 성경필사 완주 수 · 소속 · 직분 · 등록일. 셈은 여기서 한 번, **사람이 정한 뜻으로**
  (「섬긴 해」 = 서로 다른 해 — 한 해에 두 팀이어도 1). 그래서 질문은 한 표의 거르기가 되고 AI 는 GROUP BY 를 쓸 일이 없다.
  ⚠️ 구체화 뷰에는 RLS 가 없다 — `revoke all … from anon, authenticated` 필수(스킬 `new-table`).
- **조건 트리** — `and` · `or` · `not` + 잎 `{field, op, value}`. 재귀 스키마 없이 깊이 3까지 펼쳐 둔다.
  「올해」 · 「작년」은 AI 가 숫자로 셈하지 않고 `{"rel":"this_year"}` 로 두면 서버가 오늘 날짜로 푼다.
  예: `{"and":[{"field":"served_years_count","op":">=","value":10},{"not":{"field":"served_years","op":"has","value":{"rel":"this_year"}}}]}`
  → `where served_years_count >= $1 and not (served_years @> array[$2])` · 값 `[10, 2026]`
- **되돌려 말하기** — 칩 · 문장은 AI 글이 아니라 **검사를 통과한 트리에서 서버가** 만든다 — 보이는 것 = 실제로 돈 것.
- **다르게 읽기** — 뜻이 갈리면 AI 가 `alternatives`(다른 트리)를 함께 낸다 → 「이렇게도 읽을 수 있어요: 잇따라 10해」.
- **못 하는 조건** — `unsupported: ["출석"]` → 「이 조건은 아직 찾을 수 없어요」. 검사에서 걸리면 까닭을 붙여 AI 에 한 번 다시 묻고, 또 걸리면 「이해하지 못했어요」.
- **요약 표로 안 되는 조건**(「2015년엔 찬양대, 지금은 교사」처럼 해와 팀을 함께) — 필드 목록에 매개변수 필드 `served_team_in_year(team, year)` → `exists (select 1 from ministry_history …)` 틀로.
- **실행** — 번역기는 서버 코드(TypeScript). SQL 은 트랜잭션 안에서 `set local role` 로 요약 표(와 매개변수 필드가 쓰는 표의 안전한 칸)만 SELECT 할 수 있는 역할로 돌린다
  — 번역기에 실수가 있어도 연락처 칸에 닿지 못한다. `set local statement_timeout` · `limit`. 값은 언제나 매개변수(`$1`)로만.
- **시험** — 번역기는 순수 함수(트리 → SQL · 트리 → 한글)라 `node --test` 로. 해석은 질문 30~50개 시험표(바라는 트리)를 모델 · 지시문을 바꿀 때마다.

**자료 범위**
- ⚠️ **자료 범위 밖이면 「없음」이 아니라 「모름」.** 서버가 사역 이력이 운영에 몇 해부터 있는지(`min(year)`) 알고,
  조건이 그보다 길면 0명을 보이지 말고 「사역 이력이 20XX년부터라 10해를 셀 수 없어요 — N해로 찾을까요?」를 보인다.
  **2026-10-15 운영 확인: 2010~2026 열일곱 해 · 17,848줄 · 교인과 이어짐 15,769(88%).** 그래서 「10해」는 셀 수 있고, 「20해」부터 「모름」이다.
- ⚠️ **옛 해일수록 덜 이어져 있다** — 이어짐 2010 76% · 2014 85% · 2018 92% · 2022~ 97~100%.
  이어지지 않은 줄은 그분의 섬긴 해에 안 들어가 **적게 센다**(10해 섬긴 분이 8해로 보여 빠진다).
  2021년까지 줄은 느슨한 규칙으로 이은 것이라 **다른 분에게 붙었을 수도** 있다 — 옛 해가 섞인 셈에는 「옛 기록은 덜 이어져 있고 틀릴 수 있어요」 한 줄.
- ⚠️ **2021 이 459줄**로 앞뒤 해(1,000~1,300 · 2022 601)보다 훨씬 적다 — 코로나로 사역이 줄었는지 명단이 빠졌는지 확인 전.
  빠진 것이면 「잇따라 N해」가 2021 에서 끊겨 오래 섬긴 분이 빠진다 → 확인 전에는 「잇따라」 칸을 열지 않거나 2021 을 건너뛰고 센다고 칩에 적는다.

- 모델: 조건 뽑기는 작은 모델로 충분 — 환경변수 `ASK_MODEL`(기본 `claude-haiku-5-5`). 정리 글은 `ASK_SUMMARY_MODEL`.
- 키: **같은 Supabase 프로젝트에 `ANTHROPIC_API_KEY` 가 이미 있다**(성경암송 `api` 가 말씀 질문 · NIV 등에 씀 · 시크릿은 프로젝트 공용). 브라우저에는 절대 안 간다.

## 2. DB 에 묻기 — RPC 하나

- `ai_search_people(p jsonb)` — 조건은 **매개변수로만**. 글을 이어 붙여 SQL 을 만들지 않는다.
  조건 트리(1절 「여러 조건」)로 넓히면 이 함수 대신 서버 번역기 + 요약 표만 읽는 역할로 돈다 — 어느 쪽이든 값은 매개변수로만.
- 읽는 표: `church_people`(소속 · 직분 · 가족 · 등록일) + `ministry_history`(섬김 · `person_id`) + 교육 신청 · `event_signups`(`people_links` kind `signup` 으로 이은 것만).
- 돌려주는 칸: 교인ID · 이름 · 직분 · 소속 · 섬긴 해 · 받은 교육. **연락처 · 주소 · 생년월일은 꺼내지 않는다**(전화하기는 누를 때 따로).
- 인원 상한(예 200) · 넘으면 「조건을 좁혀 주세요」.
- 새 함수 규칙 그대로(스킬 `new-table`): `revoke execute … from anon, authenticated` · `service_role` 만 · `TO authenticated` 금지 · 노출 점검 0행.

## 3. AI 정리 · 심방 이야깃거리

- **AI 정리(①):** 서버가 결과에서 숫자만 뽑아 보낸다 — `{"total":12,"served3plus":8,"weekly":5}`. 이름 없음.
- **심방 카드(②):** 서버가 그분 기록을 이름 없는 사실 목록으로 만든다 — `이분: 권사 · 2011 등록 · 2023~2025 찬양대 · 2026 쉼 · 2025 제자훈련 · 가을 말씀 동행 3주째`.
  지시문: 「이 사실만 쓴다 · 이유를 짐작하지 않는다 · 평가하는 말을 쓰지 않는다 · 세 줄」. 이름 · 사진 · 가족은 화면이 DB 에서 붙인다.
- 화면에 늘 「AI 는 위 기록만 보고 썼어요 · 판단은 목사님 몫」 한 줄.

## 4. 역할 · 기록

- 새 역할 `pastor`(라벨 「담임목사」) — `admin_roles` 한 줄(SQL `020_pastor_role.sql`) + `ACTION_ROLES`. 역할 목록을 코드 · CHECK 에 박지 않는다(church-admin 함정).
- `ai_ask_log`(RLS 켬 · anon/authenticated revoke): `member_id` · `at` · `question` · `conditions` · `result_count`. 결과 이름은 안 남긴다.
  ⚠️ 질문 글 자체에 이름이 들어갈 수 있다(「김○○ 권사 가족」) — 보관 기간을 정한다(예 1년 뒤 지움 · cron).
- 화면에 「이 질문은 기록에 남습니다」를 늘 보인다.

## 5. 개인정보

- 교회 소속 · 직분 · 신앙 활동은 **민감정보(사상 · 신념)** 로 다룬다.
- Claude API(Anthropic · 국외)로 가는 것은 조건 · 숫자 · 이름 없는 사실 목록뿐이지만, 그래도 **국외 이전 · 처리 위탁**이다 → 교회 개인정보 안내(church-admin `privacy.html` · 교적 동의 범위)에 적어야 한다. **교회 결정.**
- API 로 보낸 자료는 학습에 쓰이지 않는다. 목사님 개인 Claude 앱(MCP)에 명단을 바로 잇는 방식은 대화 기록에 명단이 남으므로 시험용으로만.
- 성경암송 앱 방침(`privacy/`)은 건드리지 않는다 — 이 기능은 교회 어드민 것이다. (플레이 심사 중 방침 문장 추가 금지도 그대로.)

- [ ] 심방 메모 칸을 새로 둘 것인가 — 건강 · 가정사가 들어가기 쉬운 가장 민감한 자료. 둔다면 목사님만 · AI 에 안 보냄 · 지우기 쉬움
- [ ] 명단 내려받기(엑셀)를 허용할 것인가 — 교인명부처럼 「기록 남기고 허용」인지
- [ ] **출석 자료가 없다** — 「돌봄 신호」는 사역 · 교육 · 성경필사 · 봉사 기록으로만 판단하게 된다
- [ ] **성경암송 앱 활동(`users` · `daily_activity`)을 교인 한 분과 잇는 줄이 없다** — 이으려면 교회 생활 확인 번호(스위치 off)나 계정 잇기를 거쳐야 한다. 그 전까지 심방 카드의 「말씀」은 성경필사 명단만
- [ ] 교회 개인정보 안내 문구(5절)

## 7. 차례 — 위험이 작은 것부터

1. **숫자 질문 → 그래프**(「교구별 사역 참여 비율」) — 집계만 · 이름이 오가지 않는다. 구조(양식 · RPC · 기록)를 여기서 먼저 세운다.
2. **심방 준비 한 장** — 한 분씩 · 이름은 화면이 그린다.
3. **말로 찾기(①)** — 조건 칩 · 명단.
4. **돌봄 신호** — 주 1회 「마음 써야 할 분」 목록을 메일로(교회 어드민 알림 길).

## 하지 않는 것

- AI 가 SQL 을 짜거나 표를 직접 읽는 것(text-to-SQL · DB 를 통째로 여는 MCP)
- 명단 · 연락처를 AI 응답에 싣는 것
- 사람에게 점수를 매기거나 딱지를 붙이는 것
- 성경암송 앱(이 저장소)에 관리 화면을 더하는 것 — 관리 기능은 교회 어드민에만(2026-10-08 결정)
