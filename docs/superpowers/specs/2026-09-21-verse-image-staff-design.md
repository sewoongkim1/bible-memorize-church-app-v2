# 설교·찬양 담당자가 말씀 연상 그림을 만든다 — 설계 (2026-09-21)

> **왜:** 설교 올리기(`2026-09-21-sermon-staff-upload-design.md`)를 담당자께 맡기면서, 그 주 암송구절의
> **연상 그림**도 맡기기로 했다(성도님). 지금은 친구가 AI(Claude + Higgsfield)에게 시켜 만들고, 그림 목록을
> `app.js` 코드(`VERSE_IMG`)에 적은 뒤 `bump.py` 로 배포해야 앱에 뜬다. 담당자는 AI 프롬프트도, 코드도 못 쓴다.
>
> **범위:** 설교 올리기와 같은 가지(`feat/sermon-staff`)에서 **개발 DB 로 만들고 시험**한다. 운영 반영은
> 2026-09-27 안드로이드 심사가 끝난 뒤, 설교 올리기와 함께.

## 1. 지금 (조사한 사실)

- 그림은 구절마다 **대표 1장**(`<번호>.webp`, 수채·먹선) + **짝 0~2장**(`<번호>b`·`<번호>c`, 구아슈·색연필). 1~38번이 다 있다(116장).
- 앱: 암송 화면 도우미 줄의 **「🖼️ 그림」 탭을 누를 때만** `img/verse/<file>.webp?v=APP_BUILD` 를 받는다. 짝이 있으면
  「🔄 보기 (1/3)」. 목록은 `app.js` 의 `VERSE_IMG`(번호 → 설명) · `VERSE_IMG_MORE`(번호 → 짝 목록).
  **설명이 곧 `alt`** — 낭독기가 읽고, 그림이 안 뜰 때 보인다. **실제 그림을 보고** 적는다(프롬프트를 옮기지 않는다).
- 만드는 법: `img/verse/암송말씀_그림_만들기.md` — 심상 한 문장(영어) + **고정 화풍 문구**(한 글자도 바꾸지 않는다),
  4:3, 사람 눈 검수(글자·사람·액자화·사진처럼 찍힘·그림 도구·뜻 왜곡 — 「열에 한둘은 걸린다」 실측), 1080px WebP 품질 78.
- 모델: 지금 그림체는 nano banana pro. 구글 Gemini API 에 **`gemini-3-pro-image`**(Nano Banana Pro, 정식)로 있다
  (2026-09-21 친구 키로 모델 목록 확인). `api` 함수는 이미 Anthropic(Claude) 키를 쓴다.

## 2. 성도님이 정한 것

| 물음 | 정한 것 |
|---|---|
| 공개 시점 | **담당자가 저장하면 바로** 앱에 뜬다. 친구·담당자는 나중에 「내리기」 |
| 장수 | **대표 1장은 꼭, 짝 둘은 골라서**(「짝 그림도 만들기」를 누를 때만) |
| 방식 | **A — 관리자 화면에서 바로 만들고, 고른 것만 저장**(배포 없이 뜬다) |
| 그림 모델 | 구글 Gemini `gemini-3-pro-image` · 키는 Supabase 시크릿 `GEMINI_API_KEY` 에만(파일·커밋·메모리에 적지 않는다) |
| 비용 안전장치 | 한 구절에 **하루(24시간) 15장**까지 |

## 3. 담당자가 보는 화면 — 「③ 연상 그림」

「설교·찬양 관리」 메뉴의 ①·② 다음 카드. ② 에서 「✅ 다 올렸어요」가 뜨고 그 설교가 암송구절에 이어져 있으면
**「③ 연상 그림 만들기 →」**(그 구절 번호를 들고 간다).

1. **구절 고르기** — 최신 구절부터, 구절마다 「🖼️ 그림 있음 / 없음」. 처음엔 **그림이 없는 가장 최근 구절**.
   구절 본문과(이어진 설교가 있으면) 설교 한 줄 요약을 보인다.
   - 「있음」 판정: DB 그림(`verse_images`)이 있거나, 옛 그림 파일 `img/verse/<번호>.webp` 가 있으면(화면이 HEAD 로 본다).
   - 1~38번 옛 그림은 **보이기만** 하고 여기서 고치지 않는다(바꾸려면 DB 그림을 새로 만들면 그것이 앞선다 — 7장).
2. **장면 고르기** — **「🤖 장면 제안 받기」** → 우리말 장면 **세 가지**(라디오). 고르면 아래 칸에 들어가고 고쳐 쓸 수 있다(300자까지).
   영어 문장·화풍 문구는 서버가 붙인다 — **담당자는 영어를 보지 않는다.**
3. **대표 그림(수채)** — **「🎨 그림 만들기」** → 「그리는 중… 30초쯤」 → 그림을 크게 보인다.
   - **확인표 여섯 칸**(모두 체크해야 「✅ 이 그림 쓰기」가 켜진다):
     글자가 없다 · 사람(손·발·뒷모습 포함)이 없다 · 액자·카드처럼 잘리지 않았다 · 종이를 찍은 사진처럼 보이지 않는다 ·
     이젤·스케치북·책이 없다 · 구절의 뜻과 맞다(다른 종교 상징이 없다)
   - 하나라도 걸리면 **「🔁 다시 뽑기」**(같은 장면으로 다시, 또는 장면을 고친 뒤).
   - 「쓰기」 → AI 가 **그림을 보고** 우리말 설명 한 줄을 제안(40자 안팎) → 담당자가 고친다 → **「💾 저장」** → 「✅ 앱에 바로 떠요」.
4. **짝 그림(골라서)** — **「짝 그림도 만들기」** → 「넓은 장면」·「가까이 본 장면」 두 칸. 순서는 3과 같다.
   설명 칸은 기존 관례대로 **「구아슈·색연필 화풍 — 」**을 앞에 채워 둔다.
5. **이미 만든 DB 그림** — 칸마다 **「바꾸기」**(다시 만들어 덮어쓰기)·**「내리기」**(숨김, 되돌리기 가능).
6. **남은 수** — 「오늘 이 구절에 12장 더 뽑을 수 있어요」.

화면 표준 v1(`docs/notes/ministry-admin-ui.md`)을 따른다 — 주 동작 48px, 보조 44px, 제목 줄 `.rep-head.mn-top`, 결과는 `mnNote`, 놓치면 안 되는 것은 `mnDialog`.

## 4. 뒤에서 도는 구조

```
③ 화면 ──verseImgScenes───▶ api ──Claude──▶ 우리말 장면 3개
       ──verseImgGenerate─▶ api ──Claude(우리말 → 영어 한 줄)──▶ 영어 장면
                                 ──Gemini gemini-3-pro-image(4:3, 영어 장면 + 고정 화풍)──▶ PNG
                                 ◀── 그림(base64) — 화면 미리보기(저장하지 않는다)
       [쓰기] 브라우저가 긴 변 1080px WebP(품질 0.78)로 줄인다 — WebP 를 못 만드는 브라우저면 JPEG(0.85)
       ──verseImgAlt──────▶ api ──Claude(그림을 보고)──▶ 우리말 설명 제안
       ──verseImgSave─────▶ api ──▶ Supabase 저장소 verse-img/<번호><칸>-<시각>.webp + 표 verse_images
성도님 앱 ── getVerses ──▶ 구절마다 images:[{slot,url,alt}] (숨김 제외) → 있으면 그것, 없으면 옛 img/verse/
```

- **쓰지 않은 그림은 어디에도 남지 않는다** — 생성 결과는 화면으로만 가고, 「저장」한 것만 저장소에 올라간다.
- **프롬프트 = 영어 장면 한 줄 + 칸별 꼬리말 + 고정 화풍 문구.** 화풍 문구는 `img/verse/암송말씀_그림_만들기.md` 2장의
  두 덩이를 **글자 그대로** 서버 코드에 둔다(대표 = 수채·먹선, 짝 = 구아슈·색연필). 칸별 꼬리말: `b` → ` Wide open scene with distant space around it.`
  · `c` → ` Close-up view of the subject filling the frame.`(안내서 그대로).
- **장면 제안(Claude)** 은 안내서 3장의 규칙을 시스템 지시로 준다: 한 가지만 · 빛으로 맺기(at dawn 등) · 뜻이 아니라 사물 ·
  **사람이 나오는 구절은 그 일의 흔적으로**(35번 다림줄 예) · 다른 종교 상징 금지. 우리말 장면만 돌려준다.
- **우리말 → 영어(Claude)** 는 같은 규칙으로 **영어 한 문장**(줄바꿈·따옴표 제거, 300자까지)만 받는다 — 화풍 문구를 흔들 수 없게.
- **그림 크기:** `imageConfig.aspectRatio = "4:3"`. `imageSize` 는 **`1K` 로 시작해 실제 크기를 재고**(긴 변이 1080 보다 작으면 `2K`)
  정한다 — 원본이 크면 기다림과 응답 크기가 는다. Gemini 호출은 110초에서 끊는다(함수 한도 150초).
- **새 표 두 개**(`supabase/verse_images.sql`):
  - `verse_images(verse_no int, slot text check (slot in ('a','b','c')), path text, alt text not null, scene_ko text, scene_en text,
    hidden boolean default false, created_by text, created_at, updated_at, primary key (verse_no, slot))`
  - `verse_image_gens(id identity, verse_no int, slot text, created_by text, created_at)` — 성공한 생성만 적는다(하루 15장 세기)
  - 둘 다 그 자리에서 RLS + `revoke all … from anon, authenticated`.
- **저장소:** 공개 읽기 칸 `verse-img`(같은 SQL 파일에서 `storage.buckets` 에 한 줄). 올리기·지우기는 서비스 키(함수)만.
  바꿀 때마다 **새 이름**으로 올리고 옛 파일은 지운다(캐시에 옛 그림이 남지 않게).
- **`api` 액션(모두 `contentError` — 설교·찬양 담당자 또는 관리자):**

| 액션 | 하는 일 |
|---|---|
| `verseImgList` | DB 그림 목록(구절·칸·url·설명·숨김) + 구절마다 오늘 남은 수 |
| `verseImgScenes {verseNo}` | 구절 본문(+이어진 설교 요약)으로 우리말 장면 3개 |
| `verseImgGenerate {verseNo, slot, sceneKo}` | 하루 제한 확인 → 우리말→영어 → Gemini → `{ok, image(base64), mime, sceneEn, left}` |
| `verseImgAlt {verseNo, slot, image}` | 줄인 그림을 보고 우리말 설명 한 줄 제안 |
| `verseImgSave {verseNo, slot, image, mime, alt, sceneKo, sceneEn}` | 파일 앞머리 검사(WebP `RIFF…WEBP` · JPEG `FFD8`) · 500KB 까지 · 설명 필수 → 저장소 + 표(덮어쓰기) |
| `verseImgHide {verseNo, slot, hidden}` | 내리기·되올리기 |

- **`getVerses`(공개):** 구절마다 `images: [{slot, url, alt}]`(숨김 제외, a→b→c 순)를 **더한다** — 옛 앱은 이 칸을 모르고 지나가니 깨지지 않는다.
- **`app.js`(성도님 앱, 한 군데):** 🖼️ 탭을 띄울지와 그림 목록을 `verse.images` 가 있으면 그것으로, 없으면 지금 `VERSE_IMG`/`VERSE_IMG_MORE`.
  DB 그림의 주소는 저장소 공개 주소 그대로(`?v=APP_BUILD` 를 붙이지 않는다 — 이름이 바뀔 때마다 새 주소다).
  ⚠️ 이 줄이 바뀌므로 **`bump.py` 가 필요한 배포**다(9/27 뒤).

## 5. 실패할 때

| 무엇이 | 화면 |
|---|---|
| Gemini 오류·110초 넘김 | 「그림을 만들지 못했어요 — 다시 눌러 주세요」(뽑은 수에 세지 않는다) |
| 안전 기준에 걸려 그림이 없음 | 「이 장면으로는 그림이 안 나왔어요 — 장면을 조금 바꿔 주세요」 |
| 하루 15장을 다 씀 | 「오늘은 이 구절에 더 뽑을 수 없어요 — 내일 다시」 |
| 브라우저가 WebP 를 못 만듦 | 저절로 JPEG — 담당자는 모른다 |
| 저장 실패 | 그림을 화면에 그대로 두고 「💾 다시 저장」 |
| 설명 제안 실패 | 칸을 비워 두고 직접 쓰게 한다 — **설명이 비면 저장이 안 된다** |

## 6. 시험 (개발 DB)

1. **권한 스모크**(`tests/sermon-staff-smoke.py` 에 더한다): 새 액션 여섯 — 담당자 통과 · 틀린 암호 `unauthorized` ·
   가짜 파일(앞머리 틀림)·500KB 넘는 파일·빈 설명 거절 · 잘못된 칸(`d`) 거절. 하루 제한은 표에 기록 15줄을 넣어 본다(개발만).
2. **실제로 한 구절**: 개발 1번 구절 — 장면 제안 → 대표 그림(원본 크기를 재 `1K/2K` 확정) → 설명 제안 → 저장 → `getVerses` 에 `images`
   → 짝 둘. 4~6장.
3. **성도님 앱(localhost)**: DB 그림 구절은 🖼️ 탭에 새 그림 · 옛 그림 구절(1~38)은 그대로 · 내리기 하면 옛 그림으로(없으면 탭이 사라진다).
4. **화면 점검**: 390px — 오류·가로 넘침·36px 미만 단추.

## 7. 정해 두는 것

- **DB 그림이 옛 그림 파일보다 앞선다** — 같은 번호에 둘 다 있으면 DB 것. 내리면 옛 파일로 돌아간다.
- **짝만 있고 대표가 없는 DB 그림은 보이지 않는다**(대표 `a` 가 있어야 탭이 뜬다 — 지금 규칙과 같다).
- 프롬프트 기록(`img/verse/prompts.md`)은 DB 의 `scene_ko`·`scene_en` 이 대신한다 — 파일은 친구가 만든 1~38번 기록으로 남긴다.

## 8. 안 하는 것

- 옛 그림(1~38) 옮기기 · 한꺼번에 여러 구절 만들기 · 화풍 고르기(화풍은 고정) · 액자화만 난 그림 잘라 쓰기(다시 뽑는다).

## 9. 운영 반영 (9/27 뒤, 설교 올리기와 함께)

`supabase/verse_images.sql`(표 둘 + 저장소 칸) 개발 → 운영 · 운영 시크릿 `GEMINI_API_KEY` → `api` 배포 →
관리자 화면 + `app.js` 합치기 → `python tools/bump.py` → 배포 확인(이번 판에만 있는 표식).
