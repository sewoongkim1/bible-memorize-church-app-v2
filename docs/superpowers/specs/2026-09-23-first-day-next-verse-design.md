**요청**: 친구 — 2026-09-23 사용률 분석의 **1순위**(첫날 「둘째 구절」까지 데려가기)를 진행
**대상 저장소**: `bible-memorize-church-app-v2` (gocheok.onlybible.kr)

## ① 왜 — 첫 구절을 끝낸 분에게 갈 곳이 없다

### 실측 (2026-09-23 운영 DB)

| 항목 | 값 |
|---|---:|
| 로그인을 통과한 사람 | 416명 |
| 한 번이라도 암송한 사람 | 225명 (54.1%) |
| **하루만 쓰고 안 돌아온 사람** | **82명 (활동자의 36.4%)** |
| 하루만 쓴 분 — 첫날 만진 구절 | **1.38개** |
| 5일 이상 쓴 분 — 첫날 만진 구절 | **4.73개** |

### ⚠️ 분석의 가설이 틀렸다 — 「첫 구절을 못 끝낸다」가 아니다

사용률 분석(`docs/analysis/2026-09-23-usage-analysis.md` 3.4)은 「떠난 분은 첫 구절을
끝까지 못 간다」로 읽힐 여지를 남겼다. **실제로는 끝까지 간다.**

| 집단 | 첫날 암송기록 | 첫날 만진 구절 | **구절당 기록** |
|---|---:|---:|---:|
| 하루만 (82명) | 4.3 | 1.38 | **3.1** |
| 2~4일 (57명) | 5.9 | 1.84 | 3.2 |
| 5일 이상 (86명) | 17.6 | 4.73 | 3.7 |

한 구절을 마치려면 1·2·3단계를 저장해야 하므로 **구절당 3개**가 「한 구절 완주」다.
하루만 쓴 분도 **3.1개** — 끝까지 간다. 차이는 완주율이 아니라 **몇 구절을 하느냐**다.

⚠️ **`progress.updated_at` 으로 「첫날 완주」를 재려 했지만 못 쓴다.** 나중 저장에 덮여서
5일 이상 쓴 분이 오히려 「못 끝냈다」로 나온다(65.1% vs 58.5%). 그래서 구절당 기록 수로 봤다.

### 진짜 원인 — 앱으로 재현해 확인했다

신규 성도님이 밟는 길:

```
첫 화면 → 주간 구절 카드 「암송하기」  ← 가장 눈에 띄는 자연스러운 입구
        → startTest(이번 주 구절)
        → 1단계 → 2단계 → 3단계 완료
        → showStageDoneModal(verse, 3, wasFirst=true)
        → 주 단추 = 「↺ 처음 말씀으로」     ← ★ 여기
```

`showStageDoneModal` 이 「다음」을 **번호순 +1** 로 찾는다:

```js
const idx  = verses.findIndex((v) => v.no === verse.no);
const next = (idx >= 0 && idx < verses.length - 1) ? verses[idx + 1] : null;
const first = (!next && idx >= 0 && verses.length > 1) ? verses[0] : null;
const mainLabel = stage < 3 ? `${stage + 1}단계로 계속하기`
  : next ? "다음 말씀 ▶" : (first ? "↺ 처음 말씀으로" : "목록으로");
```

그런데 **이번 주 말씀은 목록의 맨 마지막**이다:
- `verses` 는 서버 `.order("no")` 로 **오름차순**(no=1…38)
- `getWeeklyVerseInfo()` 는 **날짜가 오늘 이하인 것 중 가장 최근** = no=38
- 따라서 `idx = 37`, `verses.length - 1 = 37` → `37 < 37` 은 **false** → `next = null`
- → `first = verses[0]`(no=1) → 주 단추가 **「↺ 처음 말씀으로」**

**첫 구절을 막 마친 분이 보는 주 단추가 9개월 전 구절로 돌려보내는 것이다.**
「다음 말씀 ▶」은 **아예 뜨지 않는다.**

재현 확인(Playwright, no=1~38 · 이번 주 38):
```
주간구절: 38 · 배열에서 몇번째: 37 · 전체: 38 · 주단추문구: ↺ 처음 말씀으로
```

⚠️ 분석에서 「다음이 눈에 덜 띈다」고 짐작했던 것도 틀렸다 — **다음이 없다.**

## ② 정한 것 — 두 가지 결정

| # | 질문 | 정한 것 | 왜 |
|---|---|---|---|
| 1 | 「다음」은 어느 구절인가 | **안 외운 것 중 가장 최근**(`no` 가 가장 큰 것) | 38 → 37 → 36 으로 시간을 거슬러 오른다. 설교를 들으신 기억이 가장 가까운 구절부터라 떠올리기 쉽고, 신규·기존 모두에게 말이 된다 |
| 2 | 첫 화면 「말씀 암송하기」 큰 단추도 고치나 | **아니다 — 완료 창만** | 재어 보고 재본 그 한 자리라 효과를 깨끗하게 읽을 수 있다. 목록도 맨 위가 이번 주 구절이라 첫 진입은 멀쩡하다 |

## ③ 설계

### 3.1 「다음」 계산을 바꾼다 (`app.js` · `showStageDoneModal`)

```js
// 지금: 번호순 다음. 이번 주 말씀은 목록의 끝이라 언제나 null 이 된다.
const next = (idx >= 0 && idx < verses.length - 1) ? verses[idx + 1] : null;
```

를 다음으로 바꾼다:

```js
// ⚠️ 번호순 +1 이 아니라 **아직 안 외운 것 중 가장 최근**을 고른다.
//    이번 주 말씀은 목록의 **맨 마지막**이라(verses 는 no 오름차순, 주간 구절은 최신 = 최대 no)
//    번호순으로 찾으면 언제나 다음이 없어, 첫 구절을 막 마친 분이 「↺ 처음 말씀으로」를 보고
//    9개월 전 구절로 돌아가게 된다. 2026-09-23 실측 — 하루만 쓰고 떠난 82명은 첫날 1.38구절,
//    5일 이상 쓴 분은 4.73구절. 완주는 둘 다 하지만(구절당 기록 3.1 vs 3.7) 갈 곳이 없었다.
//    38(이번 주) → 37(지난주) → 36 … 시간을 거슬러 오르므로 설교 기억과도 이어진다.
const next = verses
  .filter((v) => v.no !== verse.no && getPassedStage(v.no) < 3)
  .reduce((best, v) => (!best || v.no > best.no ? v : best), null);
```

- `getPassedStage(no)` 는 `loadProgress(...)[no]?.stage || 0` 이고, **3단계를 마친 것만** 제외한다.
- **다 외우셨으면** `next` 가 `null` → 기존 `first` 갈래(「↺ 처음 말씀으로」)가 그대로 받는다.
  그 자리엔 「🔥 외운 N구절로 도전해 보기」 권유도 이미 함께 뜬다.
- **`stage < 3` 갈래는 손대지 않는다** — 「N+1단계로 계속하기」 그대로.
- `main` 핸들러(`next ? () => startTest(next) : …`)는 **한 글자도 안 바꾼다** — `next` 가 무엇을
  가리키느냐만 달라진다.

### 3.2 문구 — 첫 구절을 막 마친 분에게만 다르게

```js
const mainLabel = stage < 3 ? `${stage + 1}단계로 계속하기`
  : next ? (wasFirst ? "이어서 한 구절 더 ▶" : "다음 말씀 ▶")
  : (first ? "↺ 처음 말씀으로" : "목록으로");
```

「37구절 중 다음」이 아니라 「한 구절 더」로 들리게 하려는 것이다.
⚠️ **남은 개수를 보여주지 않는다** — 적체를 벽으로 만들지 않는다(복습 묶음 때와 같은 이유,
`docs/notes/home-screen.md` 의 「단위를 두 번 쓰지 말 것」과도 같은 결).

`wasFirst` 는 이미 이 함수의 인자이고 `FIRST_DONE_HTML`(🎉 첫 말씀을 마음에 새기셨어요!)을
띄우는 데 쓰이고 있다 — 새로 계산할 것이 없다.

## ④ 안 하는 것 — 그리고 왜

| 안 하는 것 | 왜 |
|---|---|
| 첫 화면 「말씀 암송하기」 큰 단추를 바로 진입으로 | 친구 결정(②-2). 효과를 한 자리에서 깨끗하게 읽기 위해 |
| **신규에게 카드 모드 기본 켜기** | 첫날 카드 사용률 차이(떠난 분 17.1% · 남은 분 23.3%)는 **상관일 뿐**이고, 「켜 둔 설정을 새 기능이 조건부로 무시하지 말 것」(2026 v3.181→182 되돌림) 교훈에 걸린다 |
| 「둘째 구절」 이정표 추가 | 첫 구절 이정표(`FIRST_DONE_HTML`)가 이미 있다. 이 변경의 효과를 재기 전에 늘리지 않는다 |
| 「다음」을 짧은 구절부터 고르기 | 순서가 무작위로 보이고 설교 흐름과 끊어진다(②-1에서 검토 후 배제) |
| 목록 화면(`renderVerseList`) 정렬·추천 | 범위 밖 |

## ⑤ 함정

1. **`stage < 3` 갈래를 건드리지 말 것.** 1·2단계 완료 창은 같은 함수가 그린다 —
   「N+1단계로 계속하기」가 바뀌면 단계 진행이 통째로 어색해진다.
2. **`main` 핸들러의 `go(fn)` 을 `setTimeout` 으로 미루지 말 것.**
   같은 동기 흐름(탭 이벤트 안)에서 불러야 다음 화면의 `focus()` 가 사용자 탭과 이어져
   사파리가 자판을 띄운다(2026-09-18 실기기 확인). 이번 변경은 그 자리를 안 건드리지만,
   근처를 고치다 함께 손대기 쉬운 자리다.
3. **`verses` 가 비어 있거나 현재 구절이 목록에 없을 수 있다.** `reduce` 의 초기값이 `null` 이라
   그 경우 `next = null` 이 되고 기존 `first` 갈래로 안전하게 떨어진다 — 별도 방어가 필요 없다.
4. **시편(`no > 1000`)은 `verses` 에 없다** — 서버 `getVerses` 가 `track='weekly'` 만 준다.
   따라서 이 계산에 섞이지 않는다. ⚠️ 다만 옛-DB 폴백 경로에는 `track` 필터가 없어
   시편이 섞일 수 있다(`index.ts` 의 `getVerses` 폴백) — 지금 쓰이지 않는 길이지만 알아 둘 것.
5. **영어(NIV) 모드.** `getPassedStage(no)` 는 `verseLang(no)` 로 **지금 언어의 진도**를 본다.
   영어로 보시는 분에게는 「영어로 아직 안 외운 것」이 다음이 된다 — 의도대로다
   (진도는 언어별로 따로 센다, `docs/notes/english-niv.md`).

## ⑥ 검증

**새 시험 `tests/stage-done.py`** (Playwright, 기존 `tests/review-card.py` 의 하네스를 본뜬다):

| 갈래 | 못 박는 것 |
|---|---|
| ① 이번 주 구절(맨 마지막)을 3단계로 마치면 주 단추가 **「↺ 처음 말씀으로」가 아니다** | 지금 버그를 그대로 잡는다 |
| ② 다음이 **안 외운 것 중 `no` 가 가장 큰 것**이다 | 중간을 일부러 외운 것으로 만들어 두고 확인 |
| ③ 첫 구절이면 문구가 **「이어서 한 구절 더 ▶」** | 3.2 |
| ④ 첫 구절이 아니면 **「다음 말씀 ▶」** | 3.2 |
| ⑤ 전부 외웠으면 **「↺ 처음 말씀으로」** | 폴백이 살아 있다 |
| ⑥ `stage < 3` 이면 **「N+1단계로 계속하기」** | 안 건드렸다 |

**돌연변이 검증(필수):** `next` 계산을 옛 `verses[idx + 1]` 로 되돌려 **①②가 FAIL 하는지**
확인하고 원복한다. 이 시험이 실제로 회귀를 잡는다는 증거다.

**기존 시험도 함께:** `tests/review-card.py` · `tests/review-batch.py` ·
`tests/event-input.py` · `tools/preflight.py`.

**화면:** `tools/screen-sweep.py` 에 완료 창이 없다 — 이번에 한 줄 더한다
(`showStageDoneModal(verses[verses.length-1], 3, true)`). ⚠️ 찍기 전에 `docs/notes/capture-tools.md`.

## ⑧ 배포와 되돌리기

**프런트만이다.** DB·Edge Function 변경이 없다 → `bump` → 커밋 → push 한 번.
⚠️ 다른 세션이 같은 체크아웃에서 `app.js` 를 고치고 있다 — 커밋은 `git apply --cached` 로
내 헝크만 담고 **경로 없이** 한다. 커밋 뒤 `git show HEAD -- app.js | grep '^@@'` 로 확인.

**되돌리기:** `next` 계산 한 줄을 옛 `verses[idx + 1]` 로 되돌리면 끝이다(문구도 함께).
데이터는 아무것도 안 바뀌므로 되돌려도 숫자가 틀어지지 않는다.
