## 3. 본인 찾기 — 로그인 교구·목장·이름 / 부서·이름

서버가 `users` 표에서 그분의 `type`·`gu`·`mok`·`bu`·`name` 을 꺼낸다(**화면이 보낸 이름·소속은 쓰지 않는다** — `user_id` 만 받는다).
교회 어드민 `people-match.ts` 에 순수 함수 **`matchLoginPerson(cands, applicant) → { personId } | { personId: null, why }`** 를 더한다.

- 신청자 모양은 성경필사 줄과 같다 — `applicantFromSignup({ who_type: type, group_name: gu 또는 bu, sub_name: mok, name })` 을 그대로 쓴다.
- 「같은 소속」은 **기존 `sameAffiliation`** 그대로(교적 표시 「맞음」과 같은 기준):
  - 교구: 교적 교구(`mok1`) = 로그인 교구, 교적 목장 번호 = 로그인 목장. 「남성」은 교적 남성 목장과. 새가족은 교구만.
  - 교회학교: 교적 부서(`school_dept`) 또는 목장 첫 칸(`mok1` — 청년부) = 로그인 부서.
- 같은 소속 후보가 **딱 한 분이면** 그분의 교인ID. 0명·여러 명이면 `personId: null`.
- 로그인 목장이 99(모름)·빈칸이면 `mokUnknown` → 같은 소속이 없다 → 「찾지 못함」.
- `why` 는 서버 안에서만 쓴다(「없음」·「여럿」) — 화면에는 「찾지 못했어요」 한 가지로만 말한다(여럿인지 알려 주면 동명이인이 있다는 것이 드러난다).
- ⚠️ 교인명부 세션이 `sameAffiliation`·`mokNumber` 를 고치면 이 함수도 함께 바뀐다 — 그래서 규칙을 이 파일에 둔다(§0 「A」의 까닭).

- **보이는 칸:** 연도 · 부서 · 팀 · 직책(있을 때) · 그때 직분. 연도 내림차순, 같은 해는 부서·팀 차례. 빼 둔 줄(`deleted_at`)은 없다.
- **[정정]** → 앱 안 창(사역신청의 `minAlert`·`minConfirm` 과 같은 모양 · 브라우저 `alert`·`confirm`·`prompt` 금지):
  「내 것이 아니에요 / 팀·부서가 틀려요 / 그 밖에」 중 하나 + 한 줄 설명(200자 · 「그 밖에」는 설명 필수).
- **[＋ 빠진 사역 추가하기]**(2026-10-02 이름 바꿈 · 친구 요청) → 연도(숫자) + 「부서」·「팀」 두 칸(2026-10-02 · 교회 어드민 SQL 009 `committee_text` · 둘 중 하나는 꼭) + 한 줄 설명.
- **찾지 못했을 때:** 「교적의 교구·목장·이름과 맞는 기록을 찾지 못했어요. 그사이 목장이 바뀌셨거나 같은 이름이 계시면 그럴 수 있어요.」 + **[내 기록 찾아 주세요]** 신청 하나(한 줄 설명). 기록·[정정]·[빠진 사역]은 그리지 않는다.
- **찾았는데 기록이 0줄:** 「아직 올라온 사역 기록이 없어요」 + [＋ 빠진 사역 알리기].
- **현황:** `신청 → 확인 중 → 반영` / `반영 안 함`(끝 칸만 바뀐다). 담당자가 적은 말(`반영 안 함`의 사유 등)이 있으면 그 아래 한 줄로(공유 문서 ⑤). 단계 줄은 사역신청 `minStepsHtml` 의 `pl-steps` 모양.
  - 화면 이름: `신청`·`확인 중`·`반영`·`반영 안 함`. 값과 같다(값을 바꾸면 DB CHECK·서버·화면 세 곳 — `allowlist-lives-in-three-places`).
- **막는 것(서버가 막고 화면은 미리 알린다):** 같은 기록 줄에 끝나지 않은(신청·확인 중) 신청이 있으면 그 줄 [정정] 대신 「신청함」 딱지 · 한 분의 끝나지 않은 신청 **20건**까지 · 「내 기록 찾아 주세요」는 끝나지 않은 것 하나만.
- **불러오는 중 · 통신 실패 · 열리지 않음**(서버가 문을 닫음): 사역신청 화면처럼 문구 + [나가기] 단추(빠져나갈 길을 늘 둔다).
- 첫 화면 「사역현황」에서 들어오고 [나가기]는 `renderSummary`.

### 5.1 표 `ministry_history_requests` — 교회 어드민 SQL `008_ministry_history_requests.sql`

번호: b6 가 005, 교인명부 세션이 006·007 을 잡아 두었다 — 만들 때 비어 있는 다음 번호를 다시 본다.

| 칸 | 뜻 |
|---|---|
| `id` bigserial PK | |
| `user_id` uuid not null | 앱 계정(`users.id`) · FK 없음(계정이 합쳐지거나 지워져도 신청은 남는다) — **서버만 읽는다, 어떤 응답에도 싣지 않는다** |
| `person_id` int | 신청 때 찾은 교인ID(찾지 못했으면 null) · FK 없음(명부가 바뀌어도 남는다) |
| `history_id` bigint | 정정할 줄(`ministry_history.id`) · 빠진 사역·찾아 주세요는 null · FK 없음(빼 둔 줄이어도 신청은 남는다) |
| `kind` text CHECK | `not_mine` · `wrong_team` · `other` · `missing` · `find_me` |
| `detail` text | 한 줄 설명(200자 · NFC · 줄바꿈은 공백으로) |
| `year` int | `missing` 일 때 연도(1950~2100) |
| `team_text` text | `missing` 일 때 「부서·팀」 글(100자) |
| `who_type`·`who_group`·`who_sub`·`who_name` text | 신청 때 로그인 소속·이름 사본(담당자가 찾을 때 · 나중에 이름을 바꿔도 그때 값) |
| `status` text CHECK | `신청` · `확인 중` · `반영` · `반영 안 함` (기본 `신청`) |
| `answer` text | 담당자가 적은 사유(`반영 안 함` 때 화면에 보인다) |
| `handled_by` uuid → `admin_members` on delete set null · `handled_at` | 처리한 담당자·때(§7 메뉴가 쓴다) |
| `created_at` · `updated_at` | |

- 색인: `(user_id)` · `(status, created_at)` · `(history_id) where status in ('신청','확인 중')`.
- **RLS 를 켜고 정책을 두지 않는다 · `anon`·`authenticated` 권한을 모두 뺀다**(시퀀스도). 운영에 카카오 로그인이 켜져 있다 — `TO authenticated` 로 열지 않는다. 적용 뒤 `check-authenticated-exposure.sql` 0행.

### 5.2 교회 어드민 함수 — 내부 액션 둘

- **들어오는 길이 새로 생긴다:** 지금은 모든 요청이 카카오 토큰부터 검사한다. 내부 액션은 **토큰 검사 앞에서** `x-internal-key` 가 서비스 키와 같은지(시간 일정 비교 — 성경암송 `api` 의 `sameSecret` 과 같은 방식 · 교회 어드민에는 아직 없어 새로 둔다)만 보고, 맞으면 그 둘만 처리한다. 그 머리가 있으면 내부 갈래로만 간다 — 키가 다르면 401 `unauthorized`(토큰 검사로 넘어가지 않는다). 내부 액션 이름을 토큰으로 부르면 `unknown-action`. `authz.ts` `ACTION_ROLES` 에는 넣지 않는다 — 역할로 부르는 액션이 아니다(시험이 이를 확인).
- 성경암송 `api` 의 `internalMinistryNotify`(교회 어드민 → `api`) 와 같은 방식을 **반대 방향**으로 쓴다.
- `internalMyHistory { who: {type, gu, mok, bu, name}, user_id }` →
  `{ ok, found: boolean, rows: [{ id, year, committee, team, role_title, position }], requests: [{ id, history_id, kind, detail, year, team_text, status, answer, created_at }] }`
  - 후보는 `church_people` 에서 `name_key` 로(이름 NFC·띄어쓰기 없음).
  - `rows` 는 그 교인ID 의 `ministry_history`(`deleted_at is null`, `person_id` = 찾은 분). 찾지 못하면 빈 배열.
  - `requests` 는 그 `user_id` 의 신청(찾았든 못 찾았든).
- `internalHistoryRequest { who, user_id, history_id?, kind, detail, year?, team_text? }` → `{ ok }` 또는 `{ ok:false, error }`
  - `history_id` 가 있으면 **그 줄이 이분 것(찾은 교인ID)인지** 확인한다 — 남의 줄 id 로 신청을 넣지 못하게.
  - §4 의 막는 것(같은 줄 열린 신청 · 20건 · 찾아 주세요 하나) · 글자 수 · `kind` 허용 목록을 여기서 검사한다.
  - 신청은 「바꾼 기록」(audit)에 남기지 않는다 — 담당자의 처리(§7)만 남긴다.
- **응답에 싣지 않는 칸:** `user_id` · `person_id` · 교인ID · `match_basis`·`match_reason`·`link_how` · `mok`(그때 목장) · `src_note` · 담당자 정보(`handled_by`). 시험이 응답 키 집합을 정확히 대조한다.

### 5.3 앱 `api` — 액션 둘 (`supabase/functions/api/index.ts` · `js/api.js`)

- `ministryHistoryMine { user_id }` → 교회 어드민 `internalMyHistory` 결과에 `who`(화면 머리줄 「기쁨-12 홍길동」용 — `users` 값)를 붙여 돌려준다.
- `ministryHistoryRequest { user_id, history_id?, kind, detail, year?, team_text? }` → `internalHistoryRequest`.
- **문 검사는 둘 다:** `cfg.isOpen`(사역신청 기간) **또는** `ministryIsTester(user_id)` **또는** 관리자 비번(`adminError(b)` 통과). 아니면 `{ ok:false, error:"closed" }`.
  - ⚠️ **`b.preview` 깃발은 받지 않는다** — 서버가 확인할 수 없는 값이다(`ministryApply` 의 ⚠️⚠️). 미리보기 화면은 관리자 비번(`minPw()`)으로 통과한다. 비번 없이 `?preview=ministry` 로 연 분께는 단추는 보이지만 화면이 「아직 열리지 않았어요」를 말한다.
- `users` 줄이 없으면 `{ ok:false, error:"no-user" }` → 화면은 다시 로그인 안내.
- 교회 어드민 함수가 응답하지 않으면 `{ ok:false, error:"upstream" }` → 화면 「잠시 뒤 다시 열어 주세요」.

### 5.4 배포 순서

- **개발 먼저:** 개발 SQL 008 → 개발 교회 어드민 함수 → 개발 `api` → localhost 화면 확인.
- **운영은 b6 의 `ministry_history` 가 운영에 올라간 뒤.** 운영 SQL 008(빈 새 표 — 아무도 안 읽는다) → 운영 교회 어드민 함수 → 운영 `api` → 화면(bump·푸시).
- 교회 어드민 함수는 다른 세션(b6·교인명부·성경필사)과 **한 벌**이다 — 배포 전 `git merge main`, 운영 배포 전 `git status --short supabase/functions` 가 비어 있어야 한다.
- 화면이 먼저 나가도 문이 닫혀 있으면(시험 참여자 아님) 성도님께는 안 보인다 — 그래도 순서는 위대로.

## 6. 개인정보 안내

- 앱 `privacy/index.html` 1항(모으는 것)·3항(보관)·4항(누가 보나) + 앱 안 화면 두 곳(`app.js` 개인정보 화면 · 도움말 수집 항목): 「**사역 이력 확인** — 로그인하신 교구·목장(교회학교는 부서)·이름으로 교인명부에서 같은 분을 찾아, 교회 홈페이지에 해마다 올리던 사역 임명 기록(연도·부서·팀·직책·직분)을 보여 드립니다. **정정 신청**을 하시면 그 내용(고를 것·설명 글·빠진 사역이면 연도와 부서·팀 글)을 받아 담당자가 확인합니다.」
- 교회 어드민 `privacy.html`: 「앱에서 성도님이 낸 사역 이력 정정 신청(로그인 소속·이름·설명 글)을 사역신청 담당자가 본다」.
- ⚠️ 로그인은 본인 확인이 아니다 — 다른 분 이름·소속으로 들어오면 그분 기록이 보인다(친구 확인 2026-10-01). 그래서 보이는 칸을 홈페이지 명단에 오르던 칸으로만 좁히고, **신청만으로는 기록이 바뀌지 않는다**(담당자 확인 뒤 반영).
- 같은 이름·소속으로 들어오면 **같은 앱 계정**이 된다 — 그분이 낸 정정 신청 글과 담당자 답도 보인다. 그래서 정정 창에 「사적인 사정은 적지 말 것」 안내를 두고, 담당자 답(§7)에도 다른 분 이름·사적인 사정을 적지 않는다.
