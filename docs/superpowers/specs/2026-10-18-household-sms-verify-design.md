# 가구 단위 문자 인증 — 확인 번호(4자리)를 문자로 바꾸기 (설계 · 2026-10-18)

상태: **설계만.** 코드·표·방침은 아직 아무것도 바꾸지 않았다.
나온 곳: 2026-10-16~18 친구와 「ID 에 본인인증이 필요해지면」 논의. 바탕은 `2026-10-08-church-life-pin-design.md`(확인 번호 4자리) —
**문(`lifeError`)·기기 표(`life_devices`)·담당자 풀기는 그대로 쓰고, 「무엇으로 확인하나」만 4자리 → 문자로 바꾼다.**

## 1. 왜

- 4자리의 약점: **먼저 정한 사람이 주인**이고, 휴대폰 뒷자리는 아는 사람이면 아는 숫자다(4자리 설계 §10).
- 문자 인증만으로도 모자란다. 문자가 증명하는 것은 「이 사람이 그 폰을 지금 들고 있다」까지다 — **그 폰이 누구 것인지는 모른다.**
  남의 이름으로 들어와 **자기 폰 번호**를 넣으면, 문자를 받는 것도 자기라서 통과한다.
- 그래서 「이 이름에는 이 번호가 맞다」를 문자 밖에서 알려 줄 명단이 필요하다 → **교인명부의 가족(신앙세대) 연락처.**
  `church_people.household_id`(신앙세대주의 교인ID) · `phone_digits`(연락처1·2) — 2026-09-29 명단 8,672명 · 5,387가구.
- PASS(통신사 본인확인)보다 교적이 낫다: 아이 폰은 부모 명의, 어르신 폰은 자녀 명의가 많아 PASS 는 진짜 본인도 막힌다.
  PASS 는 법이나 교회가 실명을 요구할 때만 따로 본다(이 설계 밖).

## 2. 친구 결정

1. (2026-10-17) **가구 안에서는 서로 대신 확인해도 된다.** 남편이 아내 이름으로, 부모가 아이 이름으로 확인할 수 있다.
   교적상 같은 신앙세대에 남은 다 큰 자녀도 여기에 든다.
2. (2026-10-17) **문자가 4자리를 대신한다.** 처음 쓰는 폰에서 「휴대폰 번호(본인 또는 가족)」 → 문자 6자리 → 통과.
   번호를 정하는 단계도, 잊어버리는 일도 없다. 4자리 코드는 지우지 않고 설정 하나(`lifeMethod`)로 되돌릴 수 있게 남긴다.
3. (2026-10-17) 문자 업체는 **교회 명의** 계정 · 발신번호는 **교회 대표번호**. 준비물은 §7.

## 3. 성도님이 겪는 흐름

문이 걸린 단추(사역 · 교육 · 봉사 당번 · 필사 노트 신청 — `lifeEnter`)를 누르면:

| 상태 | 화면 |
|---|---|
| 이 폰에서 이미 확인했다 | 묻지 않는다 |
| 이 폰이 처음이다 | 「본인 또는 가족의 휴대폰 번호를 넣어 주세요」 → 「문자 받기」 → 「문자로 온 6자리」 → 통과 |
| 어린 부서(`needsGuardian`) | 문구만 「보호자(가족) 휴대폰 번호」 |

- 아이 태블릿에서 아이 이름으로 → 엄마 번호를 넣음 → 엄마 폰에 문자 → 엄마가 숫자를 불러 줌 → 통과.
- 확인은 **기기마다 한 번**이다(기기 표 · 10대 · 180일 — 4자리 때와 같다). 한 사람이 확인했다고 가족 전부가 통과하지 않는다 —
  가족은 각자 자기 기기에서 한 번씩 한다(같은 가족 번호로).
- 다시 받기는 60초 뒤. 코드는 3분 · 5번까지.

### 화면 문구의 원칙
- ⚠️ **「어느 번호로 보낼까요?」처럼 가구 번호 목록을 보여 주지 않는다** — 가린 꼴(`010-****-5678`)도 안 된다.
  남의 이름으로 들어온 사람에게 그 가족의 번호를 알려 주는 셈이다. 번호는 성도님이 직접 넣는다.
- ⚠️ **가족 이름을 화면에 보여 주지 않는다**(「홍길동 님 가족 번호로 확인됐어요」도 뺀다).
- ⚠️ 「교적과 달라요」라고 쓰지 않는다(4자리 설계 §3 과 같은 이유 — 교적 번호의 힌트가 된다).
- 문구는 쓸 때 스킬 `copy-truth` 로 「어느 경우에도 참인 말인가」를 본다.

## 4. 판정 — 교적 가구 맞대기

### 번호 다듬기 (순수 함수 `lifePhoneNorm`)
- 숫자만 남긴다 · `+82 10…`/`8210…` → `010…` · **휴대폰만**(`/^01[016789][0-9]{7,8}$/`). 그 밖(02-… 집 전화 등)은 `bad-phone`.
- 교인명부 쪽도 같은 규칙으로 다듬어 **휴대폰 번호만** 맞댄다(집 전화는 문자를 못 받는다).

### 해시 — 번호를 주고받지 않는다
- `phone_hash = HMAC(LIFE_PIN_SECRET, "life-phone|" + 다듬은 번호)` — **계정과 상관없는 값**(한 번호를 몇 계정이 쓰는지 세려고).
- 성경암송 `api` 는 이 해시만 교회 어드민에 넘기고, 교회 어드민은 교인명부 번호로 같은 해시를 만들어 본다(`internalPinMatch` 와 같은 방식).
  성경암송 쪽은 교적 번호도, 가족 이름도 보지 않는다.
- ⚠️ 해시 공식은 두 함수에서 **글자까지 같아야** 한다(시험이 본다).

### 교회 어드민 내부 갈래 `internalPhoneMatch` — 두 꼴
| 꼴 | 받는 것 | 하는 일 · 답 |
|---|---|---|
| ① 찾기 | `user_id` · `who`(구분·소속·이름) · `phone_hash` | 이름(NFC)이 같은 교인마다 **그분 가구**(같은 `household_id` · 없으면 그분 혼자)의 휴대폰 번호에 이 해시가 있는지 본다. 맞는 분이 둘 이상이면 소속(교구·목장/부서)으로 한 번 좁힌다.<br>답: `one`(+ `person_id` · `rel: self/family`) / `none` / `many` / `null`(명부를 못 읽었다 — 「없다」가 아니다) |
| ② 이 분 맞나 | `person_id` · `phone_hash` | 이 번호가 그분 가구의 번호인가 → `yes` / `no` / `null` |

- 응답에 번호·가족 이름·다른 교인ID 를 싣지 않는다.
- 내부 키(`INTERNAL_FN_OK` 꼴)로만 부른다. 역할이 있는 사람 화면에서는 부를 수 없다.

## 5. 확인할 때의 규칙 — 코드가 맞은 **뒤에** 정한다

⚠️ **보내기 전에는 아무것도 판정하지 않는다.** 보내기 단계에서 「이 번호는 가족 번호가 아니에요」라고 답하면,
문자를 받지 못하는 사람도 번호를 바꿔 가며 「이 번호가 김OO 님 가족 번호인가」를 알아낼 수 있다.
코드가 맞은 뒤에는 그 사람이 **자기가 가진 번호**에 대해서만 답을 듣는다.

용어: **P** = 이 계정에 이어진 교인(`life_links.person_id` · 없으면 4자리 때 이어진 `life_pins.person_id`).
**B** = 이 계정의 「번호만 확인」 묶음 번호(`life_links.bound_hash`).

| 계정 | 맞대기 | 처리 |
|---|---|---|
| P 있음 | ② `yes` | 통과(교적 확인) |
| P 있음 | ② `no` | 거절 `not-family` — 「이 번호로는 확인할 수 없어요. 가족 번호로 해 보시거나 담당자에게 풀어 달라고 해 주세요」 |
| P 있음 | ② `null` | 거절 `try-later` — 「잠시 뒤 다시 해 주세요」(명부를 못 읽었다 · 막힌 게 아니다) |
| P 없음 | ① `one`(Q) | **Q 와 잇는다**(`auto`) · 통과. B 가 있었으면 지우고 **그 계정의 다른 기기도 모두 지운다**(교적 쪽이 이긴다 — 남이 먼저 자기 폰을 묶어 둔 경우를 끊는다) |
| P 없음 | ① `one` 인데 Q 가 이미 **다른 계정**과 이어져 있다 | 잇지 않는다 → 아래 「번호만 확인」 + 담당자에게 보인다(같은 분의 두 계정일 수 있다 — 합치기는 담당자가) |
| P 없음 | ① `none` / `many` / `null` | **「번호만 확인」** — B 가 없으면: 이 번호로 묶인 계정이 3 미만이면 묶는다(B = 이 번호 · 3이면 거절 `phone-full`) · 연락처 저장(§6) · 통과 · 알림(아래). B 가 이 번호면 통과. B 가 **다른 번호**면 거절 `bound-other` → 담당자 |

- 담당자가 「이분 아님」으로 정한 계정(`how = 'no'`)은 ① 이 `one` 이어도 잇지 않는다(사람이 정한 것은 자동이 덮지 않는다).
- `null` 로 「번호만 확인」이 된 계정은 나중에 다시 맞대 본다(§9 다시 맞대기).
- **알림:** 「번호만 확인」 묶음이 새로 생기면 그 계정의 **다른 알림 기기**에 「이 이름이 새 폰에서 확인됐어요」를 보낸다 —
  남이 먼저 묶었을 때 진짜 본인이 알게 하려는 것. 문구는 `copy-truth` 로(본인이 아니면 담당자에게 — 연락처는 방침의 것).
  (2026-10-08 `login-new-device-alert-design.md` 와 같은 자리에 붙인다.)

## 6. 저장

| 표 | 칸 | 뜻 |
|---|---|---|
| `life_links`(새) | `user_id`(PK) · `person_id` · `how`(`auto`/`staff`/`no`) · `rel`(`self`/`family`) · `matched_at` · `bound_hash` · `bound_at` | 계정 ↔ 교인 이음과 「번호만 확인」 묶음. **번호는 해시만** |
| `life_otps`(새) | `id` · `user_id` · `phone_hash` · `code_hash` · `created_at` · `expires_at` · `tries` · `used_at` | 보낸 문자 코드. `code_hash = HMAC(LIFE_PIN_SECRET, "life-otp|"+id+"|"+코드)` · 보낼 때마다 이틀 지난 줄을 지운다(크론 없이) |
| `life_devices`(있음) | 그대로 | 확인을 마친 기기 |
| `life_contacts`(있음) | 그대로 | 「번호만 확인」 분은 **확인된 번호를 여기에 넣는다**(180일 규칙 그대로) — 연락처 창(`openLifeContact`)을 다시 띄우지 않아도 된다 |
| `life_pins`(있음) | 그대로 | 4자리 때의 것. 지우지 않는다(되돌리기 · 그 때 이어진 `person_id`) |

- 모든 새 표: RLS 켬 · `anon`·`authenticated` 둘 다 revoke · service_role 만 · `TO authenticated` 금지 — 스킬 `new-table`.
- ⚠️ **`user_id` 칸이 있는 새 표 둘은 기록 합치기(`member_merge.sql`)가 알아야 한다** — 본체·허용 목록 둘·counts·쓰기 트리거 넷.
  규칙: 남는 계정에 이음이 있으면 그것 · 없으면 옮긴다 · 기기는 모두 지운다(다시 확인) · 코드 줄은 지운다.
- 4자리 때 이어진 분(`life_pins.person_id`)은 0단계 SQL 에서 `life_links` 로 **한 번 복사**한다. 그 뒤로 읽는 곳은 `life_links` 를 먼저 본다 —
  `api` `lifePersonLinked` · 교회 어드민 교인 「자세히」 배지 · `lifeRematchAll` · `lifeResetDo`.
- 번호 원문은 `life_contacts`(「번호만 확인」 분만)에만 남는다. 문자를 보낼 때는 함수 안에서만 쓰고 기록(로그)에 찍지 않는다.

## 7. 문자 보내기

### 횟수 — 순수 함수 `lifeSmsAllowed`
- 한 번호에 하루(한국 날짜) **3통** · 한 계정에 하루 **5통** · 다시 받기 60초 뒤.
- **하루 전체 상한** `app_config.smsDailyCap`(관리자만 · `ADMIN_CONFIG_KEYS` · 처음 200 제안) — 넘으면 그날은 멈추고
  「오늘은 문자를 더 보낼 수 없어요. 내일 다시 해 주세요」 · `app_config.smsCapHit` 에 날짜를 남겨 다음 날 07:12 매일 점검(`monitor`)이 텔레그램으로 알린다(`api` 에는 텔레그램 비밀값이 없다).
  남의 번호로 문자를 계속 보내 비용을 쓰게 하는 장난을 막는 것 — 업체를 **선불 충전**으로 쓰면 최대 손실이 충전액으로 한 번 더 묶인다.
- 접속 주소(IP)로 세지 않는다(2026-10-08 친구 결정 — 교회 와이파이·카페에서 죄 없는 분이 막힌다).

### 문자 내용 — 단문(90바이트) 안
```
[고척교회] 확인번호 123456

@gocheok.onlybible.kr #123456
```
- 마지막 줄은 안드로이드 크롬(플레이 앱 TWA 포함)의 자동 채움(WebOTP) 꼴이다. 아이폰은 칸에 `autocomplete="one-time-code"` 로
  메시지 앱의 코드를 띄운다 — **둘 다 실기기로 확인할 것**(아이폰 앱 WKWebView 에서 뜨는지).
- 광고가 아니라 `(광고)` 표시·수신 거부 문구는 넣지 않는다.

### 업체 · 준비물 (교회 명의 · 발신번호는 교회 대표번호)
**업체 고르기**
- 국내 문자 API 업체(예: 솔라피 · NHN Cloud · 네이버 클라우드 SENS 등). 해외 업체(Twilio)는 비싸고 국내 발신번호 규정이 맞지 않는다.
- 방송미디어통신위원회 **전송자격인증**을 받은 업체인지(대량문자 업체에 2025년 법정 의무화 · 2026-04-28 시행령 강화 — 업계 자료 기준, 계약 때 업체에 확인).
- **고유번호증(비영리·종교단체)으로 가입되는지 먼저 묻는다** — 안내 페이지에는 「개인 · 사업자」만 있어 확인되지 않았다.
- 선불 충전이 되는지 · 단문 단가(대략 건당 10~20원 · 견적으로 확인).

**업체 가입(교회 명의 계정)**
- 고유번호증 사본 · 대표자(담임목사님) 정보 — 업체가 요구하는 대로.
- 계정을 맡을 담당자의 이름·휴대폰·이메일(업체 로그인 · 충전 · 알림 받기).
- 결제 수단(교회 카드·계좌 — 선불 충전).
- ⚠️ 계정 명의와 번호 명의를 **둘 다 교회로** 맞춘다. 다르면(예: 친구 개인 계정 + 교회 번호) 위임 서류에 재직증명서까지 요구된다.

**발신번호 등록(교회 대표번호 02-2686-5871 — 방침에 적힌 사무실 번호 · 확정은 친구)**
- **통신서비스 이용증명원** — 그 번호를 개통한 통신사에서 교회 명의로 발급. 사업자명·전화번호·발급일이 **가린 곳 없이** 보여야 한다.
  유효 기간은 업체마다 다르다(최근 1개월 · 6개월 이내 등 — 그 업체 기준으로). KT 기업 고객은 고객센터(1588-0114)에서 팩스로 받는다.
- **ARS 인증** — 등록할 번호로 걸려 오는 전화를 받거나, 그 번호에서 직접 건다. **사무실 전화기 앞에서** 해야 한다.
  대표번호가 교환기·안내 방송으로 이어져 있으면 받기가 안 될 수 있다 — 그때는 업체에 수신·발신 환경을 알려 다른 길을 묻는다.
- 심사는 영업일 1~3일 안팎. 등록에 유효 기간이 있다(솔라피 기준 2026-09-09 이후 신규 24개월) → **2년마다 다시** 등록.

**우리 쪽**
- API 키·비밀값은 Supabase 시크릿(`SMS_API_KEY`·`SMS_API_SECRET`·`SMS_FROM`)에만 — 저장소·문서에 값을 적지 않는다.
- 개발 DB 에서는 문자를 보내지 않는다: 시크릿 `SMS_FAKE=1`(개발에만) 이면 보내지 않고 응답에 코드를 실어 스모크가 쓴다.
  ⚠️ **운영 주소(`xnomlgydifiqiybervtf`)에서는 `SMS_FAKE` 를 코드가 무시한다** — 시크릿을 잘못 넣어도 코드가 새지 않게.

## 8. 서버 (`api`)

### 스위치
- 문을 거는지: 지금의 `app_config.lifePin`(`off`/`test`/`on`) 그대로.
- 무엇으로 확인하나: 새 `app_config.lifeMethod` — 없음·`pin`(지금과 같다) / `sms`. 관리자만(`ADMIN_CONFIG_KEYS`).
  **되돌리기 = `lifeMethod` 를 지운다**(배포 없이). 4자리 때 확인한 기기도, 문자로 확인한 기기도 그대로 통과한다(기기 표는 하나).

### 액션
| 액션 | 받는 것 | 하는 일 |
|---|---|---|
| `lifeGate`(있음) | `user_id` · `device` | `sms` 일 때 `{ state: "off" \| "ok" \| "phone" }` — 「phone」 = 이 기기가 아직 확인 안 됨 |
| `lifePhoneSend`(새) | `user_id` · `phone` | 다듬기 → 횟수 → 코드 만들어 보냄 → `{ ok, otp_id, wait }` · 오류 `bad-phone`/`too-many-today`/`sms-paused`/`sms-fail` |
| `lifePhoneVerify`(새) | `user_id` · `otp_id` · `code` · `phone` | 코드 확인(해시·3분·5번) → §5 표 → 통과면 기기 표를 돌려준다 · 오류 `wrong`(`left`)/`expired`/`not-family`/`bound-other`/`phone-full`/`try-later` |
| `lifeResetRequest`(있음) | 그대로 | 담당자에게 풀어 달라고 |

- `lifeError`(교회 생활 17개 액션의 첫 줄)는 `sms` 일 때 **기기 표만** 본다(번호 줄이 없어도 된다) → 없으면 지금처럼 `pin-needed`.
- `lifePhoneVerify` 의 `phone` 은 `hash(phone) == otp.phone_hash` 일 때만 쓴다(연락처 저장용).

## 9. 화면 · 교회 어드민

### 앱
- 새 창 하나: 번호 칸(`inputmode="tel"`) → 「문자 받기」 → 코드 칸 여섯(`autocomplete="one-time-code"` · 안드로이드 WebOTP) · 다시 받기(60초) · 「아주 큼」 글씨 · 어두운 모드.
- `lifeEnter` 가 `state: "phone"` 이면 이 창을 연다.
- ⚠️ **옛 판 앱은 모르는 상태를 4자리 창으로 연다**(`lifeEnter` 의 `openLifePin(state === "new" ? "set" : "check")`).
  그래서 **새 화면이 나가 라이브 확인된 뒤에** `lifeMethod = sms` 를 켠다(4자리 설계 §5 「화면이 먼저, 스위치는 그 뒤에」와 같다).
  옛 판은 `APP_BUILD` 다시 받기로 몇 분 안에 사라진다. 아이폰·안드로이드 껍데기는 같은 웹이라 새 빌드가 필요 없다.

### 교회 어드민
- 「🔑 확인 번호 풀기」(있음) — 풀면 `life_links`(이음 · 묶음)와 기기를 지운다 → 다음에 새로 확인. 이음을 다시 맺는 것은 교인명부 「자세히」에서.
  ⚠️ 풀기 요청은 **남도 낼 수 있다** — 담당자가 그분께 전화로 확인한 뒤에 푼다(풀기 화면에 한 줄로 적는다).
- 줄 표시: 「교적 확인(본인 / 가족 번호)」 · 「번호만 확인」 · 「같은 교인에 계정 둘」 — 신청 현황·당번 명단·교육 신청 현황.
- **다시 맞대기:** 새 명부를 올린 뒤(`lifeRematchAll`) 이음이 없고 `how ≠ 'no'` 이고 B 가 있는 계정을 ① 꼴로 다시 맞대 본다 —
  교적이 늦게 고쳐진 분이 이때 이어진다(그 번호는 이미 손에 든 것이 확인된 번호다).

## 10. 개인정보

새로 생기는 것: **문자 업체에 휴대폰 번호를 맡긴다**(처리 위탁 — 업체 이름을 적는다) · **교적의 가족(신앙세대) 연락처로 본인을 확인한다** ·
확인한 번호를 바꾼 값으로 보관 · (「번호만 확인」 분만) 확인된 번호를 연락처로 180일.
줄어드는 것: 4자리 확인 번호(문자로 바꾼 뒤 새로 정하는 분이 없다).

- 고칠 곳: `privacy/` · 앱 안 개인정보 화면 둘(`renderPrivacyInfo`·`renderHelp`) · 교회 어드민 방침 · 스토어 데이터 양식(플레이·앱스토어).
- ⚠️ 교적 연락처를 본인 확인에 쓰는 것은 **교회가 교적을 모은 목적과 맞는지 교회(사무실·담당 목사님)에 먼저 묻는다** — 친구 혼자 정할 일이 아니다.
- ⏸ **플레이 심사 중에는 방침에 새 문장을 넣지 않는다.** 그 전에는 `lifePin = test`(🧪 시험 참여자)까지만.

## 12. 막지 못하는 것

- **가족끼리는 서로 대신 한다**(친구 결정 1 — 일부러 열어 둔 것).
- **교적의 신앙세대는 실제 사는 집과 다를 수 있다.** 분가·결혼이 늦게 반영되면 따로 사는 자녀가 부모 가구에 남아 있다.
- **교적에 없는 분**(새가족 · 번호 없음 · 옛 번호)은 「번호만 확인」이다 — 먼저 묶은 사람이 주인이 될 수 있다.
  울타리는 알림 · 한 번호 3계정 · 교적 쪽이 이김 · 담당자 풀기.
- **남의 폰을 잠깐 손에 넣은 사람**은 그 폰 번호로 통과한다.
- **비용 장난**은 상한에서 멈추지만, 멈춘 날은 진짜 분들도 문자를 못 받는다(다음 날 풀린다).
- **암송·순위·게시판은 그대로다**(4자리 설계 §10 과 같다).
