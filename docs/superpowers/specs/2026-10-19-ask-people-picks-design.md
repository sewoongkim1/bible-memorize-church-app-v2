# 성도 묻기 — 직분 · 교구 고르기 칸 (설계 · 2026-10-19)

## 1. 친구 결정 (2026-10-19)

1. **직분 목록 = 큰 묶음 + 세부.** 위에 「장로 전체 · 안수집사 전체 · 권사 전체 · 집사 전체」, 아래에 교인명부의 세부 직분(직분상세 칸 그대로 —
   시무장로 · 은퇴장로 · 시무안수집사 · 시무권사 · 명예권사 · 서리집사 …). 여러 개 · 옆에 인원 수.
2. **고르기 칸은 서버가 바로 거르는 조건이다(길 A).** 질문 조건과 「그리고」로 묶는다. **질문 없이 고르기만 하면 AI 를 부르지 않는다**(빠르고 비용 0 — AI 한도와 무관).
3. **「모두 고르기」를 둔다.** 모두 = 「아무것도 안 고름」과 같은 뜻(조건 없음).
4. **세부 직분은 AI 에 보내지 않는다.** 지시문 · 스키마는 그대로 → 견주기(`tools/ask-eval` 32문항)를 다시 돌리지 않는다.

견준 길(버린 것): B 고른 값을 질문 글에 붙여 AI 로(매번 AI · 세부 직분은 지금 AI 가 못 읽음) · C AI 에 세부 직분 필드를 가르침(지시문 변경 → 견주기 다시).

## 2. 화면

```
무엇이 궁금하세요?
[ 직분 ▾ ]  [ 교구 ▾ ]                 ← 공용 고르개 pickMany(폰은 아래에서 올라오는 판)
┌──────────────────────────────────┐
│ 예: 10년 동안 사역하신 분들 중에 …   │   (직분·교구만 골라도 찾아요)
└──────────────────────────────────┘
[            묻기            ]
```

- 단추 글(교인 찾기 거르기 단추 `.pp-pick-b` 와 같은 꼴 — 작은 이름 「직분」 아래 값): 안 고름 「전체」 · 하나 「시무장로」 · 여럿 「시무장로 외 2」 · 모두 「모두」(교구도 같은 꼴).
  안 고름 · 모두는 둘 다 조건이 없는 것이라 켜진(on) 모양이 아니다.
- **모두 고른 상태는 조건이 없는 것**이다 — 보낼 때 빈 배열. 모두 고른 뒤 몇 개만 빼면 뺀 나머지가 조건이 된다(예: 교구 모두 → 「임시교구」만 빼기).
- 「묻기」: 질문이 있으면 지금처럼 AI(「조건을 만드는 중이에요…」), 질문이 비고 고른 것이 있으면 AI 없이(「찾는 중이에요…」).
  둘 다 비면 지금처럼 「질문을 적어 주세요」 → 글을 「질문을 적거나 직분·교구를 골라 주세요」로.
- 고른 조건도 「이렇게 알아들었어요」 칩(「그리고」 묶음 맨 앞)에 보인다. **칩 ×로 고른 조건을 빼면 그 고르기 칸도 비운다** — 보이는 것 = 걸린 것.
- 고른 값은 **이 화면 안에서만** 남는다(메뉴를 옮기면 비워짐 · 질문 칸과 같다).
- 머리 안내(INTRO)는 그대로다 — 고른 값도 AI 에 가지 않으므로 「AI 에는 질문과 「물을 수 있는 것」 목록만」이 여전히 참이다.

## 3. 목록 — 새 액션 `askPeopleOptions`

서버가 10분 담아 둔 재료(`askData`)에서 센다. 이름 · 교인ID 는 싣지 않는다(값과 인원 수만).

```
{ ok, people: 8672,
  positions: [ { value: "장로 전체", label: "장로 전체", count: 54, kind: "group" }, …,
               { value: "시무장로", label: "시무장로", count: 19, kind: "detail" }, … ],
  gu: [ { value: "믿음", count: … }, … ] }
```

- **세부 값 규칙(순수 함수 `posDetailOf`):** 직분상세(`position_detail`) → 비었으면 직분(`position`) → 둘 다 비면 「직분 없음」. 모든 분이 한 값에 든다.
- **큰 묶음:** 이미 있는 `positionBucket(position)` 의 장로 · 안수집사 · 권사 · 집사 넷(「그 밖」·「직분 없음」 묶음은 큰 묶음 칸에 두지 않는다 — 「직분 없음」은 세부 쪽 한 줄).
- **세부 차례:** 큰 묶음 차례(장로 → 안수집사 → 권사 → 집사 → 그 밖) 안에서 인원 많은 순 · 「직분 없음」은 맨 끝.
- **교구 차례:** 교회 정한 차례 `BE_GU`(믿음 · 소망 · 사랑 · 섬김 · 은혜 · 화평 · 기쁨 · 새가족 — `events-rules.ts`) 가운데 명부에 있는 것 → 그 밖(청년공동체 · 임시교구 … 인원 순).
- 권한: `askPeople` 과 같은 역할(`directory` · 총괄). 기록은 남기지 않는다(목록만 · 사람 자료 없음).

## 4. 서버 조건

### 새 잎 `pos_pick` — AI 밖에 둔다
- `FIELDS`(AI 스키마의 field 값 · 지시문의 필드 표가 여기서 나온다)에 **넣지 않는다.** 따로 `PICK_FIELDS = [{ id: "pos_pick", label: "직분", ops: ["in"], value: "list" }]`.
- `checkLeaf` 는 `FIELDS` + `PICK_FIELDS` 를 함께 본다 — 칩 × 길(`askPeopleRun`)의 트리에 이 잎이 있어도 통과해야 한다.
  AI 는 스키마의 field 값이 `FIELD_IDS` 뿐이라 이 잎을 낼 수 없다.
- 검사: 토큰마다 「X 전체」(X ∈ 장로 · 안수집사 · 권사 · 집사) 또는 `vocab.posDetail` 안의 값. 목록 밖 토큰은 notice 로 빼고, 남는 것이 없으면 `unsupported`(no_data).
- 셈: **토큰 하나라도 맞으면 참**(같은 칸 안은 「또는」) — 「X 전체」는 `p.pos === X`, 세부는 `p.posDetail === 값`.
- 칩 글: 「직분 장로 전체·시무안수집사」 · `from_text` 「고른 직분」.

### 교구는 이미 있는 `gu` 잎
- `gu` 잎(in · list)을 그대로 쓴다. 칩 「교구 기쁨·화평」 · `from_text` 「고른 교구」.

### 재료
- `askData` 의 교인명부 읽기에 `position_detail` 한 칸을 더한다(이미 교인명부 「자세히」가 보이는 칸 · 새로 모으는 것 아님).
- `AskPerson.posDetail` · `AskVocab.posDetail`(세부 값 목록). ⚠️ `vocab` 은 지시문에도 쓰이지만 **지시문은 `posDetail` 을 읽지 않는다**(시험이 지킨다).

## 5. 흐름

`askPeople { question, picks: { pos: string[], gu: string[] } }`
1. 질문 · 고르기가 **둘 다 비면** `no-question` — 재료도 안 읽고 AI 도 안 부른다(지금 PROBE 그대로).
2. 고른 값은 **서버가 잎으로 만든다**(`picksToLeaves` — 화면이 잎을 만들지 않는다) · 칸마다 문자열 30개까지.
3. 질문이 있으면 AI 트리를 받고 **고른 잎을 `all` 맨 앞에** 둔 뒤 `askOut(…, fromAi=true)`. 잎 상한 10(`ASK_MAX_LEAVES`) 안에서 고른 잎이 먼저 자리를 차지한다.
4. 질문이 없으면 AI 를 부르지 않고 `askOut({ all: 고른 잎 }, …, fromAi=false)` — 응답의 `model` ""· `raw` null.
5. 기록 `people.ask` 에 `picks: { pos, gu }`(직분 · 교구 이름 — 사람 자료 아님) · AI 를 안 불렀으면 `ai: false`.

`askPeopleRun` 은 그대로다(트리에 `pos_pick` 잎이 있어도 같은 검사를 거친다).

## 6. 공용 고르개 — 「모두 고르기」

- `pickMany` 에 `allBtn`(기본 꺼짐)을 더한다 — 켜면 바닥에 「모두 해제 · **모두 고르기** · 확인」. 교인 찾기 등 다른 화면은 그대로.
- 「모두 고르기」는 목록의 모든 줄을 체크한다(직분이면 큰 묶음 줄까지). 화면은 고른 수 = 목록 수이면 「모두」로 보고 빈 배열을 보낸다(순수 함수 `picksToSend`).

## 8. 배포 차례

1. **서버(함수) — 개발 → 운영.** 새 액션 하나 · `picks` 는 없어도 되는 칸이라 **옛 화면은 그대로 돈다.**
2. **화면 — 개발 확인 → 운영(Pages).** 함수가 먼저 나가 있어야 새 화면의 목록이 뜬다.
- 새 SQL 없음 · 개인정보 방침 변화 없음(새로 모으는 것 없음 · AI 에 가는 것 그대로).
- church-admin `CLAUDE.md` 의 배포 규칙대로.

## 9. 범위 밖 (YAGNI)

- AI 가 질문의 「시무장로님」을 세부 직분으로 알아듣기 — 지시문 변경 · 견주기가 필요하다. 쓰다가 필요하면 그때.
- 목장 · 나이 · 성별 고르기 칸 — 지금은 말로 충분하다.
- 고른 값을 메뉴를 옮겨도 남기기.
