## 1. 데이터

### 표 — 고치지 않는다

`events`(회차) · `event_signups`(명단) 둘 다 성경암송 앱의 것이다. **칸·제약·RLS 를 바꾸지 않는다.**
새로 만드는 것은 `admin_roles` 한 줄뿐이다(`supabase/sql/004_bibleevent_role.sql`, 개발 먼저).

```sql
insert into admin_roles (id, label, description)
values ('bibleevent', '성경필사(암송)', '성경필사·암송 이벤트 명단 보기 · 고치기 · 올리기 · 통계')
on conflict (id) do nothing;
```

### 줄의 모양 — 앱과 한 글자도 다르지 않게

- `who_type`: `'교구'` 또는 `'교회학교'` 둘만(표에 CHECK 가 없으니 서버가 막는다).
- `group_name`: 교구는 `믿음·소망·사랑·섬김·은혜·화평·기쁨·새가족`(「화평교구」가 아니다). 교회학교는 부서 이름 그대로(청년부·중등부·소년2부…).
- `sub_name`: 교구는 목장 **숫자 문자열**(「20」 · 「20목장」 아님 · 「07」은 「7」로) 또는 `남성`. 교회학교는 학년(대개 빈칸).
- `ident_key`: 성경암송 `identityKey()`(index.ts:153)와 **바이트까지 같게** — 교회 어드민 `paper.ts` 의 `appIdentityKey` 를 쓴다(NFC 를 하지 않는다). `authz.ts` 의 `identityKey`(NFC)를 쓰면 앱 계정과 영영 안 맞는다.
- 이름·소속에 `" \ , ( ) |` 는 받지 않는다(`|` 는 신원 키 구분자 · postgrest `.in()` 이 이스케이프하지 않는다). 한 칸 40자.
- `note`(담당자 메모)와 `memo`(성도님이 쓴 한 줄)는 **다른 칸**이다. 이 메뉴는 `memo` 를 쓰지 않는다.
- `answers`(자격 스냅샷·인정 사유)·`phone` 은 **쓰지 않는다.** 전화는 새로 받지 않는다.
- `updated_at` 은 코드가 넣는다(트리거가 없다). `created_at` 은 새 줄이면 DB 기본값.

### 메모에 남기는 표기 — 운영에 이미 쓰인 것을 그대로

| 언제 | `note` 에 |
|---|---|
| 담당자가 한 분 더함 | `담당자가 더함` |
| 명단 올리기로 더함 | `명단 올리기` |
| 빈칸을 교인명부로 채움 | `소속: 교인명부로 채움` |
| 교인명부로 고침(2026-09-29 일괄) | `원래: 화평 30 · 집사` — 이미 1,032줄에 있다. 고치기 창은 지금 메모를 그대로 채워 보여 줘 이 기록이 지워지지 않게 한다 |

여러 표기가 겹치면 ` / ` 로 잇는다.

### 같은 분 판정과 앱 계정 잇기 — 한 규칙, 순수 함수 하나

한 분 더하기(`evRowAdd`)·고치기(`evRowSave`)·올리기(`evUploadCheck`/`Save`)가 **같은 함수**를 쓴다(시험을 붙인다).

1. **후보 키 집합** = (목장 원문 · 「N목장」 · 앞자리 0 뗀 꼴) × (이름 원문 · NFC) 로 만든 `ident_key` 들.
   앱 로그인은 「07」도 받고 줄의 `sub_name` 은 users 값 그대로라(api index.ts:5416-5419), 담당자 줄을 「7」로 다듬으면 같은 분이 두 줄이 될 수 있어서다.
2. **계정 찾기**: `users.identity_key` 와 `user_identity_aliases`(교회 어드민이 이미 읽는 표) 에서 후보 키로 찾는다. `users` 는 **쪽을 나눠 전부** 읽는다(`allRows`, 지금 421행). **계정이 둘 이상 나오면 잇지 않고** 화면에 알린다. 계정을 새로 만들지 않는다.
3. **이미 있음(`already`)**: 그 회차에 ① `ident_key` 가 후보 키 집합에 드는 줄이 있거나, ② 찾은 계정의 `user_id` 줄이 있으면(앱에서 낸 줄 포함) 넣지 않는다. `user_id` 가 없는 줄은 DB unique 가 막지 않으므로(NULLS DISTINCT) 이 판정이 유일한 막이다.
4. **올리기 안의 중복**: 한 파일 안의 줄끼리도 같은 규칙으로 접는다(먼저 나온 줄이 남는다).
5. 교회학교 줄은 앱 계정과 사실상 이어지지 않는다(앱 로그인의 학년 표기가 제각각) — 그대로 둔다.
6. 이어진 줄의 부작용(화면 안내에 적는다): 성도님 앱 「📋 이미 내신 것」에 보이고, **등록 기간 중인 회차면** 성도님이 앱에서 고치거나 취소할 수 있다.

⚠️ 동시에 두 담당자가 같은 분을 더하면 둘 다 판정을 통과할 수 있다(계정 없는 줄) — 드문 일이라 막지 않고, 명단 화면이 같은 이름·같은 소속 줄에 「중복일 수 있음」 표시를 한다.

### 줄 모양 검사 — 「모양 틀림」 판정표

| 칸 | 받는 것 | 틀리면 |
|---|---|---|
| 이름 | 1~40자 · `" \ , ( ) |` 없음 | `no-name` · `bad-char` · `too-long` |
| 구분 | `교구` / `교회학교` | `bad-type` |
| 교구(교구 줄) | 8교구 중 하나(다듬은 뒤) | `bad-group` |
| 부서(교회학교 줄) | 비지 않은 40자 이하 | `no-group` |
| 목장(교구 줄) | 숫자 · `남성` · 빈칸 | `bad-sub` |
| 직분 | 40자 이하(목록 밖이면 경고만) | `too-long` |
| 메모(`note`) | 500자 이하 | `note-too-long` |

`evRowSave` 는 **실제로 바뀐 칸만** 검사한다(옛 값 때문에 저장이 막히지 않게).

### 1,000행

PostgREST 는 한 번에 1,000행까지만 주고 넘어도 **오류 없이** 자른다(2026-09-29 관리자 칩 숫자가 이것으로 틀렸다 — 성경암송 커밋 `576acfc`).
명단·이력·통계·계정 읽기는 모두 `allRows`(쪽 나누기 + `order(id)`), 회차 인원은 `head: true` 개수로 센다.

## 2. 서버 (`supabase/functions/church-admin`)

### 역할

`bibleevent`. 액션마다 `authz.ts` `ACTION_ROLES` + `index.ts` switch case + `tests/server.dev.test.mjs` PROBE 세 곳에 한 줄씩.
`tests/authz.test.mjs` 의 역할 목록(`knownRoles`)과 server.dev 의 사람 목록·`want()` 에도 새 역할을 더한다.

### 액션 (모두 `bibleevent`)

| 액션 | 받는 것 | 돌려주는 것 · 규칙 |
|---|---|---|
| `evEvents` | — | 회차 목록: id·title·short_title·subtitle·season·kind·status·opens_on·closes_on·list_until·updated_at · **인원**(head 개수) · **listedNow**(지금 성도님께 보이는가, KST · `evtListable` 규칙) · hasEligibility(자격 회차인가) |
| `evRoster` | event_id | 그 회차의 모든 줄: id·who_type·group·sub·name·position·note·source·hasUser·at·updated_at · 줄마다 **교적 표시** `church:{state,reason}`(교인명부가 없으면 `null`). **`user_id`·`ident_key`·`answers`·`phone`·`memo` 는 싣지 않는다** |
| `evEventCreate` | event(id·title·short_title·subtitle·season·opens_on·closes_on·list_until) | **insert 만**(있으면 `exists`). id `/^[a-z0-9][a-z0-9-]{1,40}$/`, 만든 뒤 못 바꾼다. **status 는 `draft` 로 고정**(공개는 만든 뒤 설정에서 — 아래 공개 확인을 거친다). 검사는 `evEventSave` 와 같은 함수(DB CHECK 에 걸려 500 이 나지 않게). `needs` 는 서버가 `{"position":true,"phone":false,"memo":false,"extra":[]}` 로 채운다(앱 등록 폼에 직분 칸이 생기게). `kind='signup'` |
| `evEventSave` | event_id·expect(updated_at)·바꿀 칸·confirmListed | **보낸 칸만** 바꾼다. `needs`·`copy`·`kind` 는 받지 않는다(자격 규칙·문구가 조용히 지워지지 않게). 검사: title 필수(`no-title`) · 날짜 꼴(`bad-period`) · closes_on ≥ opens_on(`period-reversed`) · status ∈ draft/open/closed/archived(`bad-status`) · list_until 은 비우면 null, 날짜 꼴(`bad-list-until`), ≥ closes_on(`list-until-before-close`) · 자격 회차면 opens_on ≥ `needs.eligibility.start`(`before-eligibility`). **공개 확인은 쓰기 전에**: 바뀐 뒤의 listedNow 를 먼저 계산해, 지금 안 보이는 회차가 보이게 되는데 `confirmListed:true` 가 없으면 **아무것도 쓰지 않고** `needs-confirm` 을 돌려준다 |

### 교인명부 → 이벤트 줄로 옮겨 적는 규칙(순수 함수 · 시험을 붙인다)

2026-09-29 일괄 맞추기에서 **한 번 틀리고 바로잡은 규칙**을 그대로 쓴다.

1. `kind2` 가 `교회학교`·`학생`이면 → 교회학교 · `school_dept`(없으면 소속을 정하지 않는다). ⚠️ 교인명부에는 **아이도 가족의 교구·목장(`mok1`·`mok3`)이 있다** — 이것을 먼저 보면 아이가 부모 목장으로 간다(그날 135줄이 그랬다).
2. `mok1` 이 7교구면 → 교구 · `mok1` · 목장 = `mok3` 끝 숫자(「소망-남성1」처럼 `남성` 이 들어 있으면 `남성`). `mok3` 에 숫자도 `남성` 도 없으면 **교구만 채우고 목장은 비운다**.
3. `mok1` 이 청년부·청년공동체·청년새가족이면 → 교회학교 · 청년부.
4. 그 밖에 `school_dept` 가 있으면 → 교회학교 · 그 부서. 없으면 소속을 정하지 않는다(새가족·임시교구 등).
5. 직분 = `position`(대분류) 앞에 `position_detail` 의 **명예·은퇴·원로**를 붙인다(은퇴협동권사→은퇴권사, 서리집사은퇴→은퇴집사). `position` 이 비면 채우지 않는다.

**빈칸 채우기**(올리기의 `fill`)는 교인명부 전체에서 이름이 **한 분뿐**일 때만 하고, **빈 칸만 채운다**(명단에 이미 적힌 교구·목장·직분은 덮지 않는다). 다음은 다른 사람으로 보고 채우지 않는다:
명단 줄은 아이(어린이·학생)인데 명부는 어른 / 명단은 청년부인데 명부는 교구(가족 교구일 수 있다 — 청년부를 둔다) / 명단의 교구 줄인데 명부는 교회학교 아이.

### 교적 표시 — 사역신청과 같은 모양

줄마다 `church:{state:'맞음'|'확인 필요'|'없음', reason}` 만 싣는다. 새 순수 함수 `applicantFromSignup(row)` 가 줄을 `people-match.ts` 의 `Applicant` 로 바꾸고,
`churchLookup`·`churchFor`·`matchChurch` 를 그대로 쓴다(새 규칙을 만들지 않는다). 교적 값 자체는 싣지 않는다.

### 사람 묶음(이력·통계) — 근삿값임을 화면에 적는다

줄끼리 **`user_id` 가 같거나, 다듬은 신원(구분·소속·목장 숫자·이름 NFC·띄어쓰기 없음)이 같으면** 같은 사람으로 이어 붙인다(합집합 — 계정이 있는 해와 없는 해가 한 묶음이 되게).
같은 분이 해마다 목장을 옮겼으면 둘로 셀 수 있다 — 통계 옆에 「같은 이름·같은 소속 기준(근삿값)」이라고 적는다.
응답의 묶음 이름표는 **순번**만 쓴다(`user_id` 를 이름표로 쓰면 새어 나간다). 교인ID(`person_id`)로 묶는 것은 이번에 하지 않는다.

통계의 빠른 고르기: id 가 `lent-booklet-` 로 시작하면 「소책자」, 그 밖의 `lent-` 는 「사순절」, `summer-` 는 「썸머」. 셋에 안 드는 회차(가을 말씀 동행 등)는 개별로만 고른다.

### 팝업 — 전부 직접 만든 창(친구 결정)

- **브라우저·시스템 팝업을 한 번도 띄우지 않는다**: `alert`·`confirm`·`prompt` 금지, 저장 안 한 채 나갈 때의 `beforeunload` 경고도 쓰지 않는다(대신 창 안에서 「저장하지 않은 내용이 있어요」).
- 확인·알림은 `ui.js` 의 `dialog`/`toast`. 입력이 있는 창(회차 설정·새 회차·한 분 더하기·줄 고치기·빼기 두 단계 확인)은 **같은 모양의 전용 창**을 만든다 — `dialog` 와 같은 배경·모서리·단추 크기(표준 v1), 폰에서는 아래에서 올라오는 판, PC 에서는 가운데 창.
- 창의 공통 동작: 바깥 누르기·Esc 로 닫기(입력이 바뀌었으면 창 안에서 한 번 더 묻기) · 열리면 첫 칸에 초점 · 저장 중에는 창의 단추를 스스로 잠근다(`busy()` 는 `document.body` 에 붙은 창을 잠그지 않는다) · 서버 오류는 창 안 빨간 줄로(창을 닫지 않는다).
- **뒤로 가기**: 창을 열 때 `history.pushState` 로 한 칸을 쌓고 `popstate` 를 「창 닫기」로 받는다(입력이 바뀌었으면 창 안에서 한 번 더 묻기). 메뉴를 옮기면(`route()`) 열린 `be-` 창을 닫는다 — 안 그러면 다음 메뉴 위에 창이 남는다.
- 입력 창은 `dialog` 의 본문 모양(`.dlg .body` — `white-space:pre-line`)을 다시 쓰지 않는다(폼 줄바꿈이 깨진다). `dialog` 에 넘기는 글에는 줄바꿈 문자를 넣지 않는다.
- **날짜·고르기 칸도 직접 만든 고르개**: `<select>`·`<input type=date|time>`·`datalist` 를 쓰지 않고 `js/core/picker.js` 의 `pickDate`·`pickOne`·`pickMany`(폰은 아래 판, PC 는 작은 판)로 고른다. ⚠️ **선행 조건** — 이 파일은 아직 가지 `native-pickers`(5108df3, 다른 세션 작업)에만 있다. 구현 계획의 첫 단계에서 그 가지가 main 에 합쳐졌는지 확인하고, 안 합쳐졌으면 그 세션과 순서를 맞춘다. 입력 창 안에서 고르개를 열었을 때 Esc 한 번에 두 창이 함께 닫히지 않는지 시험한다(고르개는 keydown 을 capture 단계에서 받아 멈춘다).
- 피할 수 없는 것 하나: 엑셀 **파일 고르기**는 운영체제 창이다. 그래서 붙여넣기 칸과 끌어다 놓기 칸을 함께 두어 파일 창 없이도 올릴 수 있게 한다.

1. **옛 동작 원문**을 먼저 커밋한다: `church-admin/docs/port/event-roster-legacy.md` — `admin-event.html`, 성경암송 `api` 의 `eventRoster`·`eventSave`·`eventSetNote`·`eventImport`·`eventRosterPublic`·`identityKey`·`evtListable`·`evtShown`·`EVT_ID_RE`·`evtImportPosition`, `events.sql`, 줄 번호와 함께 · 동작 목록 · 「찾지 못한 것」.

   - **남기는 것**: `eventRoster`(읽기) · `eventExcuse`(자격 인정) · 자격 회차의 미신청 목록 — 가을 말씀 동행(측정 10/11 · 신청 10/27~11/28)에 필요하고 이번에 옮기지 않는다.

## 5. 안전장치와 시험

- **순수 모듈 시험**(preflight 가 배포 전에 돈다):
  신원 키가 성경암송 `identityKey` 와 같은지(같은 입력 여러 개로 고정) · **같은 분 판정**(07/7·N목장·NFC·계정 둘) · 교인명부 옮겨 적기 5규칙(아이·청년·남성·새가족·목장 숫자 없음·직분 접두) · 빈칸만 채우기 · 올리기 다듬기(화평교구·20목장·07·남성목장·유년·청년부·교회학교·이름 끝 숫자·제목 줄) · 줄 모양 판정표 · 사람 묶음(합집합) · 통계 빠른 고르기 · 명단 묶음 차례 · CSV.
- **개발 서버 시험**(`server.dev.test.mjs`): 새 액션 PROBE(아무것도 바꾸지 않는 입력 — 만들기는 틀린 id 로 검사에서 떨어지게) · 역할 행렬 · **누출 시험**(응답 JSON 전체에 UUID 꼴 값이 없고 `user_id`·`ident_key`·`answers`·`phone` 칸이 없으며, `evPeopleLookup` 은 다섯 칸만) · **공개 확인**(`confirmListed` 없이 보이게 바꾸면 `needs-confirm` 이고 회차가 **그대로**) · 자격 회차에 더하기·올리기 = `eligibility-event` · app 줄 note 외 거절 · 중복 `already`(07/7 포함) · 같은 올리기 두 번 = 두 번째 0건 · 1,000행 넘는 회차 읽기 · `people.lookup`/`people.fill` 기록이 남는지. 시험 회차는 `draft` 로 만들고 `after()` 에서 지운다(줄은 CASCADE).
- **화면 확인**(localhost): 어느 동작에서도 브라우저·시스템 창이 뜨지 않는지(날짜·고르기 포함 · 파일 고르기만 예외) · 입력 창 안 고르개에서 Esc 한 번에 고르개만 닫히는지 · 창을 연 채 뒤로 가기·메뉴 옮기기.
- 개발 DB 에는 가짜 명단만. 진짜 명단은 저장소에 한 줄도 넣지 않는다(leak-scan·pre-commit 그대로).
- **배포 순서** — 표를 안 고치고 새 역할·새 액션만 얹으므로 **역할 SQL 이 먼저**:
  개발 SQL(004) → 개발 함수 → 개발 시험 → localhost:8000 친구 확인 → 운영 SQL → `check-authenticated-exposure.sql` 0행 →
  **같은 날 차례로**: 성경암송 `api` 얼리기(개발 → 운영, 4-3) → 교회 어드민 운영 함수(`git status` 깨끗) → 푸시(= 운영 화면) → 이번 판에만 있는 표식으로 확인.
  얼리기를 뒤로 미루면 그 사이 두 곳이 함께 쓴다 — 그래서 한 날에 묶는다.

## 6. 오류 처리

업무 오류는 `200 {ok:false,error}` 로, 화면은 `ui.js` `MESSAGES` 로 한국말로 보인다.

| 코드 | 언제 |
|---|---|
| `not-found` | 줄·회차가 없음(다른 사람이 지웠거나, id 가 바뀜) → 화면이 다시 불러온다 |
| `conflict` | expect(updated_at)가 다름 — 그사이 누가 고침 → 다시 불러와 보여 준다 |
| `already` | 같은 회차에 같은 분이 이미 있음(신원 키·계정) |
| `app-row-note-only` / `app-row` | 앱에서 낸 줄(또는 자격 회차의 줄)의 메모 밖 칸을 고치거나 빼려 함 |
| `eligibility-event` | 자격 회차에 한 분 더하기·올리기를 하려 함 |
| `needs-confirm` | 저장하면 성도님 첫 화면에 보이게 되는데 확인을 받지 않음 — **아무것도 쓰지 않은 상태** |
| `exists` / `bad-event-id` | 새 회차 id 가 이미 있음 / 모양이 틀림 |
| `no-title` / `bad-period` / `period-reversed` / `bad-status` / `bad-list-until` / `list-until-before-close` / `before-eligibility` | 회차 설정 검사 |
| `bad-char` / `too-long` / `bad-type` / `no-name` / `bad-group` / `no-group` / `bad-sub` / `note-too-long` | 줄 모양 검사(1절 판정표) |
| `too-many` | 올리기 600줄 넘음 |
| `moved-to-church-admin` | (성경암송 쪽) 얼린 액션을 부름 |

`23505`(unique 위반)는 줄마다 잡아 `already` 로 돌린다(500 이 되지 않게).
