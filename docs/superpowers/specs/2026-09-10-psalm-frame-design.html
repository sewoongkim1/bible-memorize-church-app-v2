시편 말씀 액자

시편 180구절을 하루에 한 편씩 열어, 액자 안에서 0단계부터 3단계까지 외우는 새 코너.

2026-09-10 · 기획 확정 · 개발 착수 전 · gocheok.onlybible.kr

한 줄로 — 시편에서 고른 180구절을 온 교회가 같은 날 같은 한 편씩 만나고, 액자 그림 안에서 0단계(읽고 듣기) → 1단계(25%) → 2단계(65%) → 3단계(전체)로 외운다. 180일이면 한 바퀴다.

01 왜 만드는가

지금 앱의 본진은 주간 암송 35구절이다. 주보·설교와 묶여 있어 한 주에 한 구절이 정석이고, 그래서 매일 열어 볼 이유가 약하다. 「오늘 뭘 하면 되나요」에 대한 답이 주중에는 「복습」 하나뿐인 날이 많다.

시편 말씀 액자는 그 빈자리를 채운다. 매일 새 말씀 하나가 열리고, 그 한 편은 액자 한 장에 담기는 길이다. 짧아서 하루에 끝난다. 종이 말씀카드가 하던 일 — 한 장을 받아 들여다보고 마음에 새기는 일 — 을 화면에서 한다.

「하루에 하나씩」이 단순한 장식이 아니다. 180구절을 한꺼번에 목록으로 내놓으면 어르신께는 「180개 중에 고르세요」가 그 자체로 벽이다 (가정 축복 기도문 104편에서 이미 배운 자리). 하루 한 편만 열리면 고를 것이 없다 — 열려 있는 것이 곧 오늘 할 일이다.

02 무엇이 아닌가

  • 주간 암송 35구절을 대체하지 않는다. 별도 코너다. 첫 화면의 「오늘 할 일」 큰 단추, 진행 막대 「전체 35」, 말씀 목록·앨범·어려운 도전은 한 글자도 안 바뀐다.
  • 「내 안에 거하는 말씀」(긴 본문 암송)과 다르다. 그건 한 본문을 마디로 쪼개 며칠에 걸쳐 외우는 것이고, 이건 하루에 한 편이 열려 하루에 끝나는 것이다.
  • 「매일 묵상」과 다르다. 묵상은 읽는 것이고 이건 외우는 것이다 — 진도가 쌓이고 순위에 들어간다.

03 정해진 것

항목결정이유 · 대가
이름시편 말씀 액자 종이 「말씀카드」와 헷갈리지 않게 「액자」로. 내용이 전부 시편이라는 것도 이름이 말해 준다.
자리별도 코너 합치면 첫 화면 진행 막대가 「전체 215」가 되어, 35구절을 다 마치신 분이 갑자기 16%로 보인다.
분량시편 180구절 · 180일 반년에 한 바퀴.
열리는 방식하루에 한 편 · 교회가 같은 날 시작 로비에서 「오늘 몇 편 보셨어요?」가 통하고 게시판도 같은 말씀으로 돈다. 대가 — 50일째 들어오신 분은 50편이 한꺼번에 열려 「매일 하나」의 기대감이 없다(→ 09장에서 달램).
0단계읽고 들어보는 칸 액자 안에 말씀 전체 + 🔊 들어보기 + [다음]. 횟수를 세지 않는다 — 준비되셨다 싶을 때 누르시면 된다. 이미 외우신 분께 걸림돌을 두지 않는다.
액자 범위0~3단계 끝까지 액자 안 「암송카드 한 장을 받아 채워 간다」는 느낌이 산다. 대가 — 빈칸이 들어가도 5줄이 지켜지도록 크기를 다시 재야 한다(06장).
액자 그림구절마다 고정 · 종류를 늘린다 무작위가 아니다. 같은 그림이 기억의 고리가 된다 — 매번 바뀌면 그 고리가 끊긴다.
길이액자에 5줄을 넘지 않는다 상한을 두어 목록을 짜고, 넘칠 때를 대비해 자동 축소를 바닥까지만 둔다.
순위함께 센다 안 세면 「그건 안 해도 되는 것」이 된다.
복습함께 예약된다 3단계를 마치면 간격반복에 들어간다. 복습도 액자로 한다.
앨범들어가되 골라서 「주간 말씀 / 시편 액자 / 전부」 칩. 기본은 주간 말씀이라 지금 쓰시던 분께는 아무것도 안 바뀐다.
본문담당자가 개역개정을 붙여 넣는다 성경 본문은 AI가 지어내면 안 되는 자리다. 그럴듯하게 틀린 성경이 올라가면 되돌릴 방법이 없다.

06 5줄 규칙 — 3단계 기준으로 잰다

여기가 이 기획에서 가장 틀리기 쉬운 자리다.

빈칸(.word-input)은 폭이 글자수 + 1em이다. 즉 단어 하나가 빈칸이 될 때마다 1em씩 넓어진다. 15단어짜리 구절이 3단계(전체 빈칸)가 되면 15em ≈ 한 줄 반이 더 는다.

0단계 기준으로 5줄을 맞추면 3단계에서 6~7줄이 된다. 길이 상한은 반드시 「전체 빈칸 상태에서 5줄」로 정한다.

잣대 한 줄

3단계에서 한 구절이 차지하는 가로 길이는 글자수(공백 제외) + 단어수 em이다. 액자 안쪽 폭 322px(폰 390px − 좌우 여백 34px×2)에 5줄, 줄바꿈 낭비를 15%로 잡으면 쓸 수 있는 길이는 약 1,370px이므로 — 

필요한 글씨 크기(px) = 1370 ÷ (글자수 + 단어수)

바닥을 18px로 두면   →   글자수 + 단어수 ≤ 76

실제 시편 구절로 재 보면(2026-09-10 계산):

시 119:10526자19+8 = 27em50px위와 같음

(가상)90자68+23 = 91em15px 넘침 — 목록에서 뺀다

공백 포함 75자 언저리가 상한이다. 시편 1편은 1절도 3절도 들어간다. 아래쪽도 막는다 — 26자짜리를 5줄에 채우려 들면 글씨가 50px이 되어 액자를 뚫는다. 글씨는 20~34px 사이로 가두고, 짧은 구절은 액자가 조금 비어 있는 채로 둔다.

python tools/psalm-fit.py를 만들어 드린다 — 엑셀을 읽어 3단계 기준으로 재고, 「너무 긴 것」과 「너무 짧은 것」을 각각 골라 준다. 담당자는 그 두 목록만 보시면 된다 — 긴 것은 짧은 절로 바꾸거나 빼고, 짧은 것은 앞뒤 절을 붙여 한 편으로 묶으면 액자가 알맞게 찬다.

em으로 폭을 고정하지 말 것. 글씨 크기 설정(보통/크게/아주 크게)이 있어 em이 함께 커진다 — 「어려운 도전」에서 7.5em이 202px이 되어 한 줄에 한 칸씩만 들어가 화면이 무너진 적이 있다(2026-08-25). 액자 안 글씨는 설정과 별개인 --frame-fs로 따로 잰다.

헤드리스 크롬으로 재면 뷰포트가 526px로 고정된다 — --window-size와 무관하다. 폰 폭 390px로 재려면 컨테이너 폭을 CSS로 못 박고 재야 한다. 넓은 창에서 재면 여백 손해를 절반으로 과소평가한다(기도문 액자에서 실제로 그랬다).

07 자료 — 같은 표, 번호대만 나눈다

progress·challenge_log·reviews가 전부 verse_no 하나로 묶여 있다. 「순위 함께 · 복습 함께」를 골랐으니, 시편 구절도 같은 verses 표에 두는 것이 압도적으로 싸다. 

-- supabase/psalm_frames.sql  (개발 DB 먼저 → 운영)
alter table public.verses
  add column if not exists track     text not null default 'weekly',  -- 'weekly' | 'psalm'

  add column if not exists frame_art smallint;   -- 1~12 · 액자 그림(구절마다 고정)

create index if not exists idx_verses_track on public.verses(track, day_no);

서버가 바뀌는 곳 — 딱 하나

안 열린 구절은 아예 안 내려보낸다. 화면에서 가리는 것이 아니다 — 클라이언트에 없으면 폰 시계를 바꿔도 열 수 없다. 「하루에 하나」를 지키는 가장 확실한 방법이고, 서버 코드도 한 줄이면 된다.

지금 앨범에 담기는 것은 두 가지다.

항목소리비고
주간 말씀 (35)브라우저 TTS3단계까지 마친 것만 앨범에 올라온다
📻 3분요약아카이브 MP3(Azure 뉴럴)설교가 있는 구절만. 화면이 꺼져도 잘 안 끊긴다
시편 액자 (180) ← 새로브라우저 TTS 3분요약이 없다 — 설교와 묶인 구절이 아니다

고르는 방법은 지금 있는 장치를 그대로 쓴다.

  • 새로 목록 위에 칩 하나 — 「주간 말씀 / 시편 액자 / 전부」. 기본은 주간 말씀.
  • 그대로 ☑️ 고르기 — 카드마다 말씀·📻 3분요약을 따로 담는다.
  • 그대로 ▶️ 전부 듣기는 화면에 보이는 순서 그대로. 섞기·미확인·칩이 걸린 그 목록이 곧 재생 목록이다 — 따로 배울 규칙을 만들지 않는다.
  • 그대로 📄 요약 함께·예상 시간 표시·2초 쉼·화면 깨우기.

기본을 「주간 말씀」으로 두면 지금 앨범을 쓰시던 분께는 아무것도 안 바뀐 화면이다. 시편 180개가 갑자기 섞여 「전부 듣기」가 몇 시간이 되는 일이 없다. 시편을 듣고 싶은 분만 칩을 한 번 누르시면 된다.

09 하루에 하나씩 — 세부 규칙

시작일app_config.psalmStart에 둔다. 코드에 박지 않는다 — 날짜가 밀려도 배포가 필요 없다.
열린 수openCount = min(180, 오늘 − 시작일 + 1). 서버가 계산한다.
오늘의 말씀day_no === openCount인 한 편. 크게 내놓는다.
지난 말씀day_no < openCount. 접힌 아코디언 안에 최근 것부터.
시작 전코너를 숨긴다. 또는 「10월 1일에 시작해요」 한 줄.
오늘 것을 안 하면그냥 열린 채 남는다. 독촉하지 않는다 — 못 한 날이 빚으로 쌓이면 돌아오기 어려워진다.
180일 뒤전부 열린 채로 둔다. 다시 잠그지 않는다. 두 바퀴째는 이번 범위 밖.

늦게 오신 분을 달랜다. 50일째 들어오시면 50편이 한꺼번에 열려 「매일 하나」의 기대감이 없다. 첫 화면에 「오늘은 50일차예요 · 지난 말씀 49편이 기다리고 있어요 · 서두르지 않으셔도 돼요」 한 줄을 둔다. 「49편이나 밀렸다」로 읽히지 않게 하는 것이 이 한 줄이 하는 일 전부다.

10 만들지 않는 것

  • 영어(NIV) 모드 — 180개 영문을 성경과 대조해 검수할 사람이 없다. 틀린 성경보다 없는 편이 낫다.
  • 🎤 음성 암송 — 도전에서 2회·2명으로 사실상 죽었다(2026-09-02 측정). 단 🔊 듣기(TTS)는 넣는다 — 0단계의 핵심이다.
  • 설교 연결 · 💡 쉬운 풀이 · 🧠 기억법 · 🖼️ 연상 그림 — 180개분의 AI 생성·검수 비용. 필요하면 나중에 자주 열리는 구절부터.
  • 어려운 도전(밑줄 지우기) 합류 — 「말씀 도전」 쪽 장치다.
  • 액자 「크게 보기」 회전(⟳) — 암송 중에는 자판이 올라와 있어 쓸 자리가 없다.
  • 두 바퀴째 · 개인별 시작일 — 180일 뒤에 다시 이야기한다.
  • 주제별 찾기 — 하루에 하나씩 열리므로 고를 것이 없다. 목록이 다 열린 뒤(180일 뒤)에 필요하면 그때.

11 함정 — 이미 값을 치른 것들

이 저장소가 지난 두 달 동안 실제로 걸려 넘어졌던 자리다. 구현할 때 이 표를 옆에 둔다.

자리무슨 일이 나는가
em으로 폭 고정 글씨 크기 설정(xl)과 곱해져 한 칸이 202px이 된다 → 화면이 무너진다. 액자는 --frame-fs로 따로 잰다.
norm은 전역이 아니다 setupAutoCheck 안의 지역 함수. 그냥 부르면 카드 모드일 때만 화면이 통째로 멈춘다 — 자판 쓰는 분은 멀쩡해서 못 알아챈다.
setupChallengeTyping은 공용(4곳) 그 안에서 mode를 바꾸면 복습·긴 본문 기록이 제약에 걸려 사라진다. 깃발은 부르는 쪽에서만 읽는다.
새 함수 이름 renderBlessing이 이미 로그인 축복 인사에 쓰이고 있었다 — 그대로 지었으면 로그인할 때마다 기도문이 떴다. psalm*은 지금 비어 있음을 확인했다(2026-09-10). 짓기 전에 다시 grep.
[hidden]display:grid를 못 이긴다. [hidden]{display:none}을 따로 둔다.
잎가지 폭 %로 두면 액자의 가로를 따라 돌려보기에서 두 배로 부푼다. 「화면의 짧은 쪽」 기준 픽셀로 넣는다.
금색 글씨 잎가지 위에서 대비가 1.86:1까지 떨어진다 → 바탕색 text-shadow 테를 두른다. 잎을 옅게 하면 액자가 사라진다.
.pr-frame에 z-index 주면 겹침 맥락이 생겨 어두운 모드의 filter가 덮개 바탕과 안 섞인다.
어두운 모드 수채화 그대로 두면 「때 묻은 얼룩」이 된다. grayscale(1) brightness(2.6) + 옅기 0.28. 색을 살리려 하지 말 것.
화면 아래 고정 단추 .home-fab를 쓰면 목록 아래 여백을 calc(96px + env(safe-area-inset-bottom,0px))로 준다.
헤드리스 캡처 뷰포트 526px 고정 · ?go= 스크립트에 + < # % ` 금지 · --virtual-time-budget은 트랜지션을 안 돌린다(아코디언을 「안 열린다」로 오진) · 스크롤 뒤에는 position:fixed가 안 찍힌다.
배포 python tools/bump.py 한 번(새 이미지·js/psalm.js도 포함되게 확인) · 확인은 「이번 판에만 있는 표식」으로.

12 만드는 차례

담당자

  1. 엑셀 한 장 — 열은 순번(1~180) · 출처(시편 1편 1절) · 개역개정 본문 · 액자(선택). 본문은 성경 프로그램·사이트에서 복사해 붙여 넣는다.
  2. 내가 tools/psalm-fit.py로 재서 「너무 긴 것」·「너무 짧은 것」 두 목록을 드린다 → 긴 것은 바꾸거나 빼고, 짧은 것은 앞뒤 절과 묶는다.
  3. 시작일을 정한다(예: 2026-10-01). 180일이면 2027-03-29에 한 바퀴가 끝난다.
  4. 액자 그림 열두 장을 함께 고른다(꽃·열매를 어느 구절에 붙일지는 기계가 먼저 배정하고 손보시면 된다).

개발

  1. 액자 소재 늘리기 — 원본 폴더 확인 → 모자라면 AI 생성 → tools/frame-art.py
  2. tools/psalm-fit.py — 3단계 기준 줄수 측정
  3. supabase/psalm_frames.sql — 컬럼 세 개 + 180행 시드 → 개발 DB 먼저 → 운영
  4. Edge Function getVerses의 track 갈래 → 개발 먼저 → 운영
  5. js/psalm.js — 첫 화면 · 0단계 · 1~3단계 · 완료
  6. app.js 세 군데 — 첫 화면 한 줄 · 복습 큐(필수) · 앨범 칩
  7. style.css — 액자 안 빈칸·카드 쟁반(액자 밖 아래에 둔다)
  8. localhost(개발 DB)에서 확인 → bump.py → 커밋 → 배포 확인
  9. 게시판 공지(작성자 「제자양육부」) · ❓ 사용 설명서에 항목 하나 추가

13 잘 되었는지 재는 법

무엇을어떻게보는 것
들어오시는가challenge_log에서 verse_no ≥ 1001인 분 수 ÷ 전체 활동자 2주 안에 30%면 성공. 카드 모드가 8일 만에 32%였다.
매일 오시는가날짜별 시편 활동자 · 어제도 오신 분의 비율 이 코너의 존재 이유가 이 숫자다.
끝까지 가시는가progress에서 시편 구절의 단계 분포 0단계만 열고 나간 분 vs 3단계까지 간 분
본진을 잠식하는가 supabase/challenge_funnel.sql에 verse_no < 1001 조건을 더한 질의를 따로 고정 주간 35구절의 도전 전환율이 떨어지면 신호다. 개편 전 기준선은 08-31주 37.3%.

전환율 질의를 손으로 다시 쓰지 말 것 — 파일로 고정해 두었기에 앞뒤를 나란히 놓을 수 있다. 그리고 2026-09-02부터 복습이 review-로 빠졌으므로 그 이전 주와 나란히 놓지 않는다.

14 아직 안 정한 것

  1. 180구절이 전부 시편인지 — 이름으로 보아 그렇게 이해했다. 시편 밖 구절이 섞이면 이름을 다시 본다.
  2. 시작일 — 새벽기도회·절기와 맞물리면 좋다.
  3. 첫 화면 단추 자리 — 「함께」 묶음 위를 제안했다. 실제로 놓아 보고 정한다.
  4. 액자 그림 열두 장의 구성 — 원본 폴더를 열어 본 뒤 몇 장을 새로 만들지 정해진다.
  5. 개역개정 사용 범위 — 35구절과 달리 180구절은 규모가 다르다. 플레이스토어에 올라가는 앱이므로, 대한성서공회 표기·허락 절차를 한 번 확인해 두는 편이 안전하다.
