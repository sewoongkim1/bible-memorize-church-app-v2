# 로그인 「처음 보는 기기」 알림 — 접속 주소 없이 (설계 · 2026-10-08)

상태: **설계 · 친구 승인(2026-10-08).** 코드 전. 접속 주소(IP)로 세는 로그인 횟수 제한(login_seen · app_config loginLimit)을 **대신한다** — 그쪽은 카페·모임 장소에서 죄 없는 분을 막아 접었다.

## 1. 왜 · 무엇
JWT 없는 API라 순위·게시판이 이름·소속을 보여 주어 **순위 명단이 곧 로그인 명단**이다. 명단을 통째로 login 에 넣으면 모든 분의 user_id 를 한 번에 긁는다.
- **막지는 않는다.** 정상적인 새 폰·재설치·아이폰 네이티브 로그인은 명단 긁기와 **같은 서명**이라(아래 §3) 막으면 죄 없는 분이 막힌다.
- **센다.** 서비스 전체에서 「기존 계정 + 처음 보는 기기」 로그인이 짧은 시간에 몰리면 텔레그램으로 알린다. 사람이 보고 판단한다(지금 monitor 와 같은 길).

## 2. 판정 — login 반환값에 이미 다 있다 (질의 안 늘림 · 2026-10-08 코드 확인)
login(member_login)이 돌려주는 값만으로 세 가지가 갈린다:
- **새 계정** = `user.created_at === user.last_seen_at`(방금 만들어진 계정 — 모르는 이름으로 로그인하면 만들어진다)
- **쓰던 기기** = `previous_user_id === user_id` **또는** `merged_from === previous_user_id`(그 폰 localStorage 에 있던 user_id 를 함께 보낸다)
- **셀 대상** = 새 계정도 아니고 쓰던 기기도 아닌 로그인 = **기존 계정 + 처음 보는 기기**

## 3. 한계(막지 못하는 까닭) — 설계의 전제
previous_user_id 는 **첫 로그인·아이폰 네이티브·새 폰·재설치·브라우저 자료 삭제**에서 안 나간다(flows 확인). 그래서 그런 정상 로그인이 모두 「기존 계정 + 처음 보는 기기」로 잡힌다 — 명단 긁기와 구별이 안 된다. **그래서 알림만.** 임계값은 「한 사람이 폰 바꾸는 정상 빈도」보다 충분히 높게 둔다(여럿이 동시에 긁을 때만 울리게).

## 4. 서버
- login 끝에서, 위 「셀 대상」이면 집계표에 한 칸 올린다. **접속 주소·이름·user_id 를 적지 않는다** — 창(예: 10분) 단위 **수만** 센다.
  표 `login_probe_counts`(window_start timestamptz · n int · primary key window_start) 또는 더 가볍게 메모리 없이 app_config 한 칸에 「현재 창 시작·수」. ⚠️ user_id 칸 없음(member_merge 가 멈추지 않게).
- 세다 임계값(예: 10분에 30건)을 넘는 **첫 순간**에 텔레그램으로 한 번(창마다 한 번 · 폭주해도 도배 안 함). 발송은 monitor 와 같은 방식 — 단, login 은 자주 불리니 **발송은 크론/모니터가 집계표를 읽어** 하고 login 은 세기만 하는 쪽이 안전하다(login 응답을 느리게 하지 않게).
- 세지 못하면(표 없음·오류) 조용히 넘어간다 — 로그인을 막지 않는다. 관리자 비번이 든 요청은 안 센다.
- ⚠️ login 은 자주 불린다(앱 열 때마다 기록 맞추기) — **쓰기를 가볍게.** 창 한 칸을 `update … set n=n+1` 로. 새 창이면 insert. 집계 질의를 login 경로에 넣지 말 것.

## 5. 임계값
`app_config.loginProbe` = `{ windowMin: 10, alertAt: 30 }`(없으면 끈 것). 배포 없이 숫자만 바꾼다. 켜기 전에 **운영의 평소 「기존 계정 + 처음 보는 기기」 분포**를 며칠 재서(주일 아침에 몰리는지) alertAt 을 정한다 — 안 그러면 주일마다 울린다.

## 6. 만드는 차례
① 집계표/칸 + login 의 세기 한 줄(개발 → 운영 · 꺼진 채) → ② 며칠 분포 재기(알림 없이 수만 쌓기) → ③ alertAt 정하고 크론/모니터에 발송 붙이기 → ④ 켜기.

## 7. 개인정보
세는 것은 **수뿐**(주소·이름·user_id 없음)이라 개인정보 안내에 새 수집 문장이 필요 없을 가능성이 높다 — 다만 「부정 사용 징후를 수로만 관찰한다」 한 줄은 두는 게 정직하다. ⏸ 플레이 심사 중 방침 새 문장 금지라, **방침 문장이 필요하면 심사 뒤.** 수만 세는 ①②는 그 전에 해도 된다(개인정보가 아님).

## 8. 함께 치울 것
접속 주소 방식(login_seen 표 · loginLimitError · app_config loginLimit)은 이 방식으로 갈아탄 뒤 걷는다. login_seen 표는 지금 비어 있고 꺼져 있다.
