## 0. 한눈에

종이 등록카드와 엑셀 한 파일로 하던 새가족 등록을 교회 어드민에 옮긴다.
새가족 한 분이 여덟 걸음 가운데 어디 계신지 보이고, 맡은 분은 자기 차례의 일만 본다.

```
카드 접수 → (사진) → 섬김이 배정 → 섬김이 교육 네 번 → 목사님 교육 → 섬김이 보고서 → 교구 배정 → 등록식
 영접팀                정착팀 총무     섬김이(정착팀)       목사님        섬김이          목사님      운영팀
```

**지키는 것 넷**
1. **성도님 앱(성경암송)에는 아무것도 넣지 않는다** — 메뉴·알림·방침 모두. 내부 담당자만 쓴다.
2. **기존 표는 읽기만** — `church_people`(인도자·섬김이 찾기 · 교구 목록). 고치지 않는다.
3. **옛 엑셀은 옮기지 않는다** — 쓰기 시작한 날부터의 카드만. 수료번호는 `26-201` 부터.
4. **새가족은 아직 교인이 아닌 분이다** — 응답에 싣는 칸을 역할마다 줄이고, 진짜 명단·사진은 저장소 밖에만.

## 1. 정해진 것 (기획서 8-1 요약)

| 무엇 | 정한 것 |
|---|---|
| 카드 입력 | 주일 현장에서 영접팀이 **휴대폰으로**. 종이 카드는 그대로 쓰고, 사진을 찍으면 글씨를 읽어 칸을 채운다(읽은 것은 초안 — 사람이 고쳐 저장) |
| 수료 대상 | 카드를 넣을 때 **사람마다 예/아니오**. 아이는 아님 · 청년·장년은 본인 뜻. 대상이 아닌 분은 단계 없이 「정보만」 |
| 섬김이 배정 | **정착팀 총무**가 한다. 교육은 1:1 — 새가족 한 분에 섬김이 한 분 |
| 섬김이 교육 | **네 번**(주가 아니라 횟수 · 한 주에 두 번도 됨 · 같은 날 두 번은 안 됨). **교육한 그날** 휴대폰에 「오늘 만났어요」 → 일자·내용·비고 |
| 섬김이 보고서 | 따로 쓰지 않는다 — **교육한 날마다 적은 줄이 모인 것**이 보고서. 덧붙일 말은 「＋ 한 줄 더」 |
| 목사님 교육 | 한 번 · 참석 여부만 |
| 교구 배정 | 새가족 목사님이 보고서를 보고. **여기까지가 등록 절차** |
| 등록식 | 운영팀이 **교구 배정까지 끝난 분** 가운데 골라 명단을 만든다(저절로 채우지 않는다). 확정할 때 수료번호 |
| 수료번호 | `연도-일련번호` · 2026년은 `26-201` 부터 · 2027년부터 `27-001` |
| 통계 | 세는 기준 날짜를 고른다 — 카드 쓴 날 · 교구 배정된 날 · 등록식 날 |
| 정보 보관 | 수료하지 않은 분·대상이 아닌 분도 지우지 않는다(지워 달라 하시면 지움) |
| 사진 | 카드 사진(판독·대조) · 환영 사진(선택) — **보관만**, 운영팀·목사님만 봄 |
| 섬김이 보고서의 종이 사진 | **처음엔 만들지 않는다** — 섬김이분들과 이야기해 보고 온라인이 어렵다 하시면 넣는다 |
| 인쇄물 여섯 가지 | 나중(1~4단계가 자리 잡은 뒤) |

## 2. 사람과 역할

부르는 이름: **영접팀**(카드) · **정착팀**(구성원 = 섬김이 · 총무 = 배정) · **새가족 목사님** · **운영팀**.

### 2-1. 어드민 역할(`admin_roles`) 둘

| 역할 id | 라벨 | 누구 |
|---|---|---|
| `newfamily` | 새가족 운영팀 | 운영팀 — 새가족 묶음의 모든 것 |
| `nfteam` | 새가족 섬김 | 영접팀 · 정착팀 총무 · 섬김이 · 새가족 목사님 — **무엇을 하는지는 아래 `nf_staff.kind` 가 정한다** |

교육(`education`/`educourse`)·봉사 당번(`duty`/`dutylead`)과 같은 모양이다 — 문(`ACTION_ROLES`)은 역할로 열고,
「자기 것만」은 서버가 줄마다 본다(`nf-db.ts` `mayTouch` → 아니면 `not-assigned`).

### 2-2. 하는 일(`nf_staff.kind`) 넷

| kind | 하는 일 | 볼 수 있는 것 |
|---|---|---|
| `greeter` 영접팀 | 카드 입력 · 사진 붙이기 · 판독 | **모든 카드**(누가 넣었든 · 기한 없음 — 친구 2026-10-07) · 카드 사진·환영 사진. 교육 줄·보고서 없음 |
| `lead` 정착팀 총무 | 섬김이 배정·바꾸기 | **카드의 모든 칸과 사진**(전화·주소·가족 포함 — 친구 2026-10-07) · 섬김이마다 맡은 수 · 교육이 몇 번째인지. 교육 줄의 내용·보고서는 없음 |
| `helper` 섬김이 | 교육 줄 적기(= 출석·보고서) · 목사님께 보내기 | **자기에게 배정된 분만** — 이름·전화·인도자 이름·자기가 적은 줄 |
| `pastor` 새가족 목사님 | 교육 진행 현황 · 목사님 교육 참석 · 보고서 읽기·돌려보내기 · **교구 배정** | 모든 새가족 · 보고서 |

한 분이 여러 kind 를 가질 수 있다(총무이면서 섬김이). 운영팀(`newfamily`)은 kind 없이 전부.

### 2-3. 「함께 쓰는 분 넣기」 — 운영팀이 직접

기획서 4-8. 운영팀이 총괄(super)에게 부탁하지 않고 새가족 담당을 넣고 뺀다.

- **섬김이는 이름만으로 먼저 넣는다**(`nf_helpers` 줄 · 교인명부에서 찾아 고름). 로그인한 적이 없어도 배정은 된다.
- 그분이 카카오로 들어와 「등록」(지금 있는 `register` — `admin_members` 대기 줄)하면 운영팀 화면 「들어오신 분」에 뜬다.
- 운영팀이 **그 대기 줄을 승인하면서 `nfteam` 역할을 주고**, kind 를 고르고, 섬김이면 `nf_helpers` 줄과 잇는다.

⚠️ **판단 A(친구가 정함 2026-10-07 — 운영팀이 승인을 가져간다).** 지금은 승인·역할 주기가 총괄만의 일이다(`membersApprove`·`membersSetRoles` = `super`).
`nfStaffApprove` 는 이것을 새가족에 한해 운영팀에 연다. 그래서 좁게 묶는다:
- 줄 수 있는 역할은 **`nfteam` 하나뿐**(다른 역할을 주거나 빼지 못한다 — 서버가 몸통의 역할 이름을 받지 않는다).
- 건드릴 수 있는 분은 **대기 중인 분**과 **이미 `nfteam` 인 분**뿐. 다른 역할을 가진 분의 상태(정지·승인)는 못 바꾼다.
- 뺄 때는 `nf_staff` 줄과 `nfteam` 역할만 뺀다(그분의 다른 역할·승인 상태는 그대로).
- 승인·빼기는 「바꾼 기록」 `nf.staff` 에 남는다.

## 3. 단계 — 저장하지 않고 사실에서 읽는다

단계 칸을 따로 두면 사실과 어긋난다. `nf-rules.ts` 의 순수 함수 `stageOf(person, lessonCount)` 하나가 정한다(시험이 같은 파일을 읽는다).

| 단계 | 조건(위에서부터 먼저 맞는 것) | 다음 차례 |
|---|---|---|
| `info` 정보만 | `target = false` | — |
| `stopped` 멈춤 | `stopped_at` 있음 | 운영팀(다시 오시면 풂) |
| `done` 등록식 마침 | `cert_no` 있음 | — |
| `registered` 등록 완료 | `parish` 있음 | 운영팀(등록식 명단) |
| `wait_parish` 교구 배정 기다림 | `report_sent_at` 있음 | 목사님 |
| `wait_report` 보고서 기다림 | `pastor_class_on` 있음 | 섬김이 |
| `wait_class` 목사님 교육 기다림 | 섬김이 교육 줄 4개 | 목사님 |
| `learning` 교육 중(N/4) | `helper_id` 있음 | 섬김이 |
| `wait_helper` 배정 기다림 | 그 밖 | 정착팀 총무 |

**넘어가는 규칙(서버가 지킨다)**
- 교육 줄은 `helper_id` 가 있어야, 그리고 **그 섬김이 본인**(또는 운영팀)만 적는다. 5번째 줄은 `kind='extra'`(횟수에 안 든다).
- 같은 분에게 같은 날 `lesson` 줄 둘은 안 된다(`same-day`). 앞날 날짜는 안 된다.
- 목사님 교육 참석은 교육 줄 4개가 찬 분만(`not-ready`). 풀 수 있다(보고서를 보내기 전까지).
- 보고서 보내기는 목사님 교육을 마친 분만. **보낸 뒤에는 섬김이가 줄을 못 고친다**(`sent`). 목사님이 돌려보내면(`report_sent_at` 비움 + 한마디) 다시 고칠 수 있다.
- 교구 배정은 보고서가 온 분만. 등록식 명단을 확정하기 전까지 바꿀 수 있다.
- 섬김이를 바꾸면 적어 둔 줄은 **그대로 남는다**(줄마다 쓴 사람이 있다). 새 섬김이는 앞 줄을 읽기만.
- 수료 대상을 「아니오」로 바꾸는 것은 운영팀만, 교육 줄이 하나라도 있으면 확인을 한 번 더(`has-lessons` → `force`). 줄은 지우지 않는다.

「3주 넘게 소식 없는 분」 = `learning` 인데 마지막 줄(없으면 배정한 날)이 21일보다 앞. 화면에서 따로 모아 보일 뿐 단계는 아니다.

## 4. 표 — church-admin `supabase/sql/016_newfamily.sql`

관리 화면에만 있는 개념이라 성경암송 저장소가 아니라 여기 둔다. **모두 서버(service role)만 읽고 쓴다** —
RLS 켜고 정책 없음, `public`·`anon`·`authenticated` revoke. 여러 번 돌려도 안전하게(`if not exists`·`on conflict`).

| 표 | 한 줄 | 주요 칸 |
|---|---|---|
| `nf_cards` | 종이 카드 한 장(한 가정) | `id` · `reg_date` · `service`(1부·2부·3부·찬양·수요·그 밖) · `pastor`(담당 교역자 글자) · `address` · `car_no` · `note` · `consent`(true 여야 저장) · `card_photo` · `welcome_photo`(저장소 경로) · `draft`(마저 채울 카드) · `created_by`(`admin_members.id`) · `created_at` · `updated_at` |
| `nf_people` | 사람 한 분 | `id` · `card_id` · `relation`(본인·배우자·자녀…) · `name` · `gender` · `birth`(date) · `birth_lunar`(bool) · `phone` · `tel` · `baptized`(yes·no·unknown) · **`target`**(bool not null) · `helper_id`(→`nf_helpers`) · `assigned_at` · `pastor_class_on` · `report_sent_at` · `report_return`(목사님 한마디) · `parish`(편성 교구 글자) · `parish_at` · `ceremony_id` · `attended`(bool) · `cert_no`(unique) · `stopped_at` · `stop_reason` · `wait_note`(등록식을 미루는 사정) · `updated_at` |

| `nf_helpers` | 섬김이 한 분 | `id` · `name` · `person_id`(교인명부) · `services`(섬기는 예배) · `member_id`(→`admin_members` · 이어지기 전엔 null) · `resting`(쉬는 중) |

| `nf_ceremonies` | 등록식 한 번 | `id` · `held_on` · `confirmed_at` · `first_no` · `last_no` |
| `nf_settings` | 해마다 한 줄 | `year` · `next_no` — 2026 은 201 로 넣어 둔다 |

- **수료번호는 SQL 함수 `nf_ceremony_confirm(p_ceremony)` 한 곳에서만 매긴다** — `nf_settings` 그해 줄을 잠그고(`for update`), 참석으로 표시한 분에게 이름순으로 차례로. 그해 줄이 없으면 1 부터 만든다. 두 번 부르면 `already`.
  확정을 되돌리는 길은 두지 않는다(번호를 이미 드렸다). 확정 뒤 한 분을 더하려면 다음 등록식으로.
- 이름·전화에는 `" \ , ( ) |` 금지(이 저장소의 규칙 — postgrest `.in()`).
- 같은 분이 또 들어오는지: 저장 전에 `nf_people` 에서 **이름 + 전화 뒷자리 4** 가 같은 줄을 찾아 알린다(막지는 않는다 — `dup` → `force`).
- 편성 교구는 **목장까지**(예 `믿음-35` — 친구 2026-10-07). 고르기 목록은 `church_people` 의 목장 값을 묶어 읽고, 목록에 없는 글자는 받지 않는다.

### 사진 — 비공개 저장소 칸 `newfamily`

- 경로 `cards/<card_id>/card.jpg` · `cards/<card_id>/welcome.jpg`. **공개 주소 없음** — 볼 때마다 서버가 5분짜리 서명 주소를 만들어 준다.
- 올리기: 화면이 줄이고(긴 변 1600px · JPEG) **다시 그려서 위치 정보(EXIF)를 떼고** 서버 액션으로 보낸다. 서버는 크기(1.5MB)와 JPEG 머리만 본다.
- 볼 수 있는 분: 운영팀·목사님·영접팀·정착팀 총무. **섬김이는 못 본다.**
- storage 정책을 `TO authenticated` 로 열지 않는다 — 정책을 아예 두지 않고 service role 로만.

## 5. 서버 — `supabase/functions/church-admin`

파일: `nf-rules.ts`(순수 — 단계·칸 지도·검사) · `nf-db.ts`(액션) · `nf-read.ts`(판독). `index.ts` `switch` 와 `authz.ts` `ACTION_ROLES` · `tests/server.dev.test.mjs` `PROBE` 에 한 줄씩.

| 1 | `nfPeopleFind` | 운영팀 · greeter · lead | 교인명부에서 이름으로(인도자·섬김이 고르기) — 이름·목장·직분만, 교인ID 없음 · 기록 `people.lookup` `from:"newfamily"` |
| 1 | `nfCardSave` · `nfCardGet` | 운영팀 · greeter(쓰기·읽기) · lead·pastor(읽기) | 카드 + 사람들 + 인도자를 한 번에. `updated_at` 잠금(`changed`) |
| 1 | `nfPhotoPut` · `nfPhotoUrl` | 운영팀 · greeter(올리기·보기) · lead·pastor(보기) | 사진 올리기 · 서명 주소 |
| 1 | `nfList` | 둘 다 | 명단 — **kind 마다 다른 칸**(§2-2). helper 는 자기 분만 |
| 1 | `nfPersonSet` | 운영팀 | 수료 대상 바꾸기 · 멈춤/풀기 · 등록식 미루는 사정 |
| 1 | `nfAssign` | 운영팀 · lead | 섬김이 배정·바꾸기 · 응답에 섬김이마다 맡은 수 |
| 1-나 | `nfCardRead` | 운영팀 · greeter | 카드 사진 → 읽은 칸(초안). **아무것도 저장하지 않는다** |
| 2 | `nfLessonSave` · `nfLessonDelete` | 운영팀 · helper(자기 분) | 교육 줄 |
| 2 | `nfPastorClass` | 운영팀 · pastor | 목사님 교육 참석 표시·풀기 |
| 2 | `nfReportSend` | 운영팀 · helper(자기 분) | 보고서 보내기 |
| 2 | `nfReportGet` · `nfReportReturn` · `nfParishSet` | 운영팀 · pastor | 보고서 읽기 · 돌려보내기 · 교구 배정 |
| 3 | `nfCeremonyList` · `nfCeremonySave` · `nfCeremonyConfirm` · `nfExport` | 운영팀 | 등록식 명단 · 확정(수료번호) · 엑셀 |
| 4 | `nfStats` | 운영팀 · pastor | 통계 — 숫자만 |

**응답 규칙**
- `auth_user_id` · `member_id` · 교인ID 를 싣지 않는다. 섬김이는 `nf_helpers.id` 와 이름으로만.
- helper 에게 가는 응답에는 주소·차량·생일·가족·사진·다른 섬김이의 줄이 없다. greeter·lead 에게는 교육 줄의 내용·보고서가 없다.
- 「바꾼 기록」 `nf.*` 의 detail 에는 **이름·전화를 싣지 않는다** — 줄 id 와 수만(`nf.card` `nf.assign` `nf.lesson` `nf.class` `nf.report` `nf.parish` `nf.ceremony` `nf.staff` `nf.person`). 보고서·카드 사진을 연 것은 `nf.view` 로 남긴다.

### 판독(`nfCardRead`) — 1단계-나

- 서버가 사진을 **Gemini** 로 보내 정해진 칸(JSON)으로 받는다. 칸마다 `sure`(자신 있음/없음)를 함께 받아 화면이 색으로 보인다.
- 이름·전화·생일은 `sure` 와 상관없이 **늘 「확인하세요」** 표시. 읽은 것은 화면의 초안일 뿐 — 사람이 저장을 눌러야 기록이 된다.
- 키는 함수 시크릿 `GEMINI_API_KEY`(성경암송 `api` 의 것과 따로 넣는다). 키가 없으면 `no-reader` → 화면은 손 입력으로만.
- 환영 사진(얼굴)은 보내지 않는다. 카드 사진만.
- ⚠️ **만들기 전에 잰다** — 실제 카드 열 장쯤으로 칸마다 맞은 비율을 재고(저장소 밖에서), 이름·전화가 기대에 못 미치면 「읽어서 채우기」를 숫자·○표 칸으로 줄인다. 일요일(10-11)에 받을 카드로.

## 6. 화면 — `js/menus/newfamily/`

묶음 **「새가족」**(`GROUP_ICON` 🌱) · CSS 접두사 `nf-` · 고르기·날짜는 `picker.js` 만(`<select>`·`type="date"` 금지) · 확인·알림은 `ui.js`.
**휴대폰 세로 화면이 기준**이다 — 영접팀·섬김이·목사님이 모두 폰에서 쓴다. PC 배치는 `@media (min-width:1024px)` 안에만.

| 메뉴 | 역할 | 누가 무엇을 보나 |
|---|---|---|
| 🌱 **새가족 카드** `nf-card` | `newfamily`·`nfteam` | 영접팀·운영팀: 「＋ 새 카드」 · 모든 카드 · 「마저 채울 카드」 — 정착팀 총무·목사님은 읽기 · 섬김이에게는 이 메뉴가 비어 있다 |
| 👣 **새가족 현황** `nf-board` | `newfamily`·`nfteam` | kind 에 따라 — 섬김이: 내 새가족 · 총무: 배정 기다림 + 섬김이별 맡은 수 · 목사님: 교육 진행 현황 · 교육받으실 분 · 보고서 온 분 · 운영팀: 전체(단계별) |
| 🎉 **등록식** `nf-ceremony` | `newfamily` | 후보 · 이번 명단 · 확정 · 엑셀 |
| 📊 **새가족 통계** `nf-stats` | `newfamily`·`nfteam`(pastor) | 기준 날짜 단추 셋 |
| 🧑‍🤝‍🧑 **함께 쓰는 분** `nf-staff` | `newfamily` | 섬김이 명단 · 들어오신 분 · 하는 일 |

- 카드 입력: 한 줄에 칸 하나 · 전화·생일은 숫자 자판 · 수료 대상은 예/아니오 가운데 하나를 골라야 저장.
  `draft` 저장은 이름·등록일·수료 대상·동의만 있으면 된다. 저장이 안 되면 쓴 것을 `localStorage` 에 두었다가 다시 보낸다(보낸 뒤 지운다 — 폰에 남기지 않는다).
- 섬김이: 새가족 카드 한 장에 「오늘 만났어요」 큰 단추 하나. 누르면 일자(오늘)·내용·비고. 네 줄이 차고 목사님 교육이 끝나면 「목사님께 보내기」.
- 목사님: 보고서를 연 화면에서 바로 교구 고르기. 옆에 인도자의 목장과 주소.
- 메뉴는 역할을 받은 분에게만 보인다 — **운영에 올려도 `newfamily`·`nfteam` 을 아무에게도 주지 않으면 아무도 못 본다**(이것이 게이트다).

## 7. 개인정보

- `privacy.html`(교회 어드민)에 더한다 — 새로 모으는 것(새가족의 이름·생일·전화·주소·차량번호·가족·세례·교육 기록·카드 사진·환영 사진), 쓰는 곳, 두는 기간(지워 달라 하실 때까지), 판독을 위해 카드 사진이 Google(Gemini)로 보내지는 것.
  ⚠️ 성경암송 앱의 `privacy/` 는 건드리지 않는다(플레이 심사 중 — 그리고 이 기능은 앱에 없다).
- 종이 카드의 동의 문구를 고칠 문안을 1단계에서 함께 낸다(받는 것 · 쓰는 곳 · 등록을 마치지 않아도 기록이 남는 것 · 판독 · 지워 달라고 할 곳 · 사진은 따로 선택).
- 개발 DB 에는 **지어낸 이름만**. 진짜 카드·명단·사진은 `C:\Projects\Data\새가족\` 에만(저장소 밖). 판독 시험도 저장소 밖에서.
- 지우기: 운영팀이 한 분(또는 카드 한 장)을 지우면 교육 줄·사진까지 함께 지운다(`nfPersonDelete` — 3단계에 넣는다 · 수료번호를 드린 분은 번호 칸만 남기고 나머지를 비운다).
