## 3. 표와 함수 — `church-admin/supabase/sql/013_ministry_stats.sql`

```sql
-- 글자 다듬기 — 사역 이력의 같은 줄 열쇠(history-match.ts nospace)와 같은 규칙: NFC · 띄어쓰기 없음
create or replace function public.mh_key(t text) returns text language sql immutable
  as $$ select regexp_replace(normalize(coalesce(t, ''), NFC), '\s+', '', 'g') $$;

-- 부서 이음표 — (부서, 팀) → 큰 분류 · 계열 · 중분류 · 표준 팀
create table if not exists ministry_dept_map (
  committee_key text not null,                 -- mh_key(부서 원문)
  team_key      text not null,                 -- mh_key(팀 원문)
  big_group     text not null check (big_group in ('찬양', '교회학교', '그 밖', '목양', '기관')),
  family        text not null,                 -- 계열
  mid           text not null default '',      -- 중분류(찬양 · 교회학교 · 부설기관만)
  team_std      text not null,                 -- 표준 팀
  note          text not null default '',
  source        text not null default 'seed' check (source in ('seed', 'admin')),   -- admin = 나중에 화면에서 고친 줄(씨앗이 덮지 않는다)
  updated_at    timestamptz not null default now(),
  primary key (committee_key, team_key)
);

-- 명단이 일부인 해 — scope: '*' = 그 해 전체 · 'g:교회학교' = 큰 분류 · 'f:재정' = 계열
create table if not exists ministry_list_gaps (
  year  int  not null check (year between 1950 and 2100),
  scope text not null,
  note  text not null default '',
  primary key (year, scope)
);
```

- 두 표 모두 `enable row level security` · 정책 없음 · `revoke all … from anon, authenticated`(서버만).
- **씨앗:** `tools/history/dept_lineage_draft.py --seed-sql` 이 이음표 2차 규칙에서 `ministry_dept_map` 줄을 SQL 로 낸다(`supabase/sql/013b_ministry_dept_map_seed.sql` — 부서·팀 이름뿐, 사람 정보 없음). `on conflict … do update … where source = 'seed'` 라 다시 돌려도 안전하고, 나중에 화면에서 고친 줄은 덮지 않는다.
- `ministry_list_gaps` 씨앗: `(2021, '*')` · `(2014 · 2023 · 2024, 'g:교회학교')` · `(2022~2026, 'f:재정')`. 사역 담당 확인(남은 확인 N02)이 오면 SQL 로 고친다.

## 4. 사람을 세는 열쇠 — 떠난 분을 따로 잡는다

교인명부는 지금 교적에 있는 분만 담는다. 못 이은 줄을 그냥 빼면 옛 해의 유지율이 실제보다 높게 나온다. 그래서 못 이은 줄도 사람으로 센다.

| 종류 | 어떤 줄 | 같은 사람으로 보는 열쇠 | 나이·성별 | 직분 |
|---|---|---|---|---|
| **m** 교인 | `person_id` 가 있다 | 교인ID | 교적 | 교적의 지금 직분 |
| **g** 떠난 분 | `person_id` 가 없고 — `link_how = 'none'`(담당자 「이분 아님」) 이거나, 못 이은 까닭이 「교인명부에 같은 이름이 없음」 · 「교인명부의 같은 이름은 …(다른 분으로 봄)」 · 「같은 목장·이름 줄을 담당자가 「이분 아님」으로 둠」 | `mh_key(이름)` — 그 이름이 지금 명부에 없거나 있어도 다른 분이므로 겹칠 상대는 떠난 분끼리뿐이다 | 모름 | 명단의 그때 직분(가장 늦은 해) |
| **u** 아직 못 정함 | 그 밖의 못 이은 줄(「누군지 못 가림」 · 「아직 맞추지 않음」) | `mh_key(이름) + mh_key(목장)` — 목장이 같을 때만 같은 분 | 모름 | 명단의 그때 직분 |

- 못 이은 까닭은 `history-match.ts` 의 상수 글자다. SQL 은 그 **앞머리 글자**로 가른다 — 상수가 바뀌면 SQL 도 바뀌어야 하므로, 시험이 TS 상수와 SQL 의 글자를 맞대어 지킨다(§9).
- 같은 이름의 떠난 분이 두 분이면 한 분으로 합쳐진다. 첫 판은 이대로 두고(수가 조금 적게 나온다), 손으로 나누는 화면은 나중이다. 교적 프로그램에서 이명·제적·별세 명단을 받을 수 있으면 그때 진짜 번호로 바꾼다(친구 확인 중).
- 사람 번호는 `dense_rank()` 로 매긴 **그 부름 안의 번호**다. 교인ID 도 이름도 함수 밖으로 나가지 않는다.

## 5. 세는 규칙 — `supabase/functions/church-admin/ministry-stats.ts`(순수 모듈 · Node 시험이 같은 파일을 읽는다)

### 5.1 단위

| 단위 | 뜻 |
|---|---|
| `all3` 전체 | 찬양 + 교회학교 + 그 밖(사역 자리). 목양·기관은 넣지 않는다 |
| `g:<큰 분류>` | 찬양 · 교회학교 · 그 밖 · 목양 · 기관 |
| `f:<계열>` | 계열 하나(찬양 · 교회학교 · 전도·중보기도 · 부설기관 …) |

수는 단위마다 따로 센다. 한 분이 찬양과 교회학교에서 봉사하면 두 단위 모두에서 한 분이다(전체에서는 한 분).

### 5.2 한 해의 수

- **자리** = 그 단위의 줄 수 · **봉사자** = 그 단위에 한 자리라도 있는 사람 수 · **두 자리 이상** = 그 단위에서 자리가 둘 이상인 사람 수.

### 5.3 흐름 — 올해 봉사자가 견준 해에도 했는가

해 `y` 의 봉사자 `P(y)` 를 **견준 해** `q`(§5.4)의 봉사자 `P(q)` 와 맞댄다.

| 이름 | 뜻 |
|---|---|
| 계속 | `P(y) ∩ P(q)` |
| 돌아옴 | `P(y) − P(q)` 가운데 `q` 보다 앞선 어느 해에 이 단위에 있던 분 |
| 처음 | `P(y) − P(q)` 가운데 이 단위가 처음인 분. 그 가운데 **사역이 처음**(다섯 분류 어디에도 `y` 앞에 없던 분)과 **다른 곳에서 옴**을 따로 센다 |
| 나감 | `P(q) − P(y)`. 올해 다른 단위에 있으면 **옮김**, 어디에도 없고 교인이면 **쉼**, 어디에도 없고 떠난 분이면 **떠남** |
| 유지율 | `계속 ÷ P(q)` (%) |

- 자료의 첫 해(2010)는 견줄 해가 없다. 앞쪽 해일수록 「처음」이 실제보다 많다(2009년에 하신 분을 모른다) — 화면 「세는 법」에 적는다.
- 예(어림): 전체 2026년 봉사자 659명 = 계속 537 + 돌아옴 73 + 처음 49, 유지율 87%(2025년 620명 가운데 537명).

### 5.4 명단이 일부인 해

`ministry_list_gaps` 에 든 해는 그 단위에서 **견주는 해로 쓰지 않는다.** `scope` 가 `'*'` 면 모든 단위, `'g:…'` 면 그 큰 분류와 그 안의 계열, `'f:…'` 면 그 계열에 걸린다.

- 견준 해 `q` = `y` 보다 앞선 해 가운데 자료가 있고 일부가 아닌 가장 늦은 해.
- 일부인 해 자신의 수도 내되 「명단 일부」 표시를 단다(화면에서 빗금).
- 건너뛰면 두 해 이상 전과 견주게 되어 유지율이 낮게 나온다 — 줄마다 「견준 해」를 함께 보인다.
- 왜 필요한가(어림): 2021년 명단은 부서 12곳만 실렸다. 건너뛰지 않으면 2022년에 「돌아옴 203명 · 유지율 58%」가 되고, 건너뛰면(2020년과 견줌) 「돌아옴 46명 · 유지율 47%」다. 앞의 것은 2021년에 안 실린 분들이 쉬었다 돌아온 것처럼 세어진 것이다.

### 5.5 작은 수

- 유지율은 견준 해 봉사자가 **5명 이상**일 때만 낸다. 그보다 적으면 「—」.
- 「올해 유지율」처럼 한 칸으로 요약할 때는 올해가 「명단 일부」면 「—」.

### 5.6 나이 · 성별 · 직분

- **나이** = 그 해 − 태어난 해. 평균 나이와 나이대(39세까지 · 40대 · 50대 · 60대 · 70세부터 · 모름) 수. 떠난 분·못 정한 분은 「모름」.
- **성별** = 남 · 여 · 모름.
- **직분** = 장로 · 안수집사 · 권사 · 집사 · 그 밖 · 모름. 교인은 교적의 지금 직분, 떠난 분·못 정한 분은 명단의 그때 직분. 글자에 「장로」·「안수집사」·「권사」·「집사」가 든 차례로 가른다(은퇴·명예·협동·서리가 붙어도 같은 칸).
- ⚠ 「지금 직분으로 본 그 해 봉사자」다. 2012년에 집사였고 지금 권사인 분은 2012년에도 권사로 센다.
- **보이는 범위:** 전체와 큰 분류는 늘 보인다. 계열은 그 해 봉사자가 **30명 이상**일 때만 보인다. 1~4명인 칸은 수 대신 「5 미만」으로 적는다.

### 5.7 안쪽 나눔

찬양 · 교회학교 · 부설기관은 중분류와 표준 팀마다 해별 자리 수를 낸다(찬양대별 · 미취학·아동·청소년 · 도서관·시니어학교 …). 사람 수와 흐름은 내지 않는다(팀이 작아 수가 흔들린다).

### 5.8 이음표에 없는 줄

이음표에 없는 (부서, 팀) 쌍은 「그 밖 · 미정」으로 세고, 화면 「세는 법」에 「아직 안 이은 부서·팀 N가지 · M줄」과 그 이름을 보인다. 2027년 명단이 들어오면 새 이름이 여기에 뜬다.

## 8. 권한 · 개인정보

- 액션 `ministryStats` = 역할 `ministry`(사역신청 담당) + 총괄. 📜 사역 이력에서 이미 줄을 이름과 함께 보는 분들이다 — §12 물음 ①.
- 이 화면은 **이름을 싣지 않는다.** 새로 보이는 것은 교적에서 온 나이·성별·직분의 **묶음 숫자**뿐이고, §5.6 의 범위로 가린다 — §12 물음 ②.
- `ministry_stats_facts` 는 서버(service_role)만 부른다. 사람 번호·태어난 해가 든 재료는 Edge Function 안에서 숫자로 바뀐 뒤 버려진다.
- 새 표·함수는 `anon`·`authenticated` 에게 열지 않는다. 운영에 올린 뒤 `check-authenticated-exposure.sql` 이 0줄인지 본다.
- 두 저장소 모두 공개다. 씨앗 SQL 에는 부서·팀 이름만 있다(사람 이름 없음 — 초안 엑셀에서 이름 2,166가지와 맞대어 0건을 확인한 그 규칙).

## 10. 여는 순서

1. SQL 013(표·함수) — **개발 → 운영**.
2. 씨앗 013b — 개발 → 운영. 운영에서 「이음표에 없는 쌍」 수를 본다(0에 가까워야 한다 — 운영 줄은 통합 엑셀을 올린 것이다).
3. 함수 배포 — 개발 → 운영. 올리기 전에 배포된 함수를 내려받아 기대 커밋과 대조한다(다른 세션의 것이 딸려 나가지 않게).
4. 화면 — 푸시(= 배포). 함수가 먼저다.
5. 친구가 운영에서 수를 본다. 사역 담당께는 그 뒤에 알린다.

## 11. 함정

- **이름만 보고 잇지 말 것** — 이음표를 고칠 때는 팀까지 내려가 앞뒤 해 사람 흐름으로 확인한다(세 번 틀렸다).
- **명단 일부인 해를 「쉼」으로 세지 말 것** — §5.4. `ministry_list_gaps` 가 비면 2022년 「돌아옴」이 네 배가 된다.
- **못 이은 줄을 빼고 세지 말 것** — 옛 해 유지율이 높게 나온다(§4).
- **사람 수는 단위마다 다르다** — 큰 분류별 봉사자를 더하면 전체보다 많다(2026년 어림 128명이 두 분류 이상).
- **줄을 화면으로 가져와 세지 말 것** — 1,000줄 한도. 재료는 `ministry_stats_facts` 한 번으로.
- **상수 글자와 SQL 을 따로 고치지 말 것** — 못 이은 까닭(§4)은 두 곳에 있다. 시험이 지킨다.
- 운영 교인명부를 읽는 것은 서버 함수뿐이다. 설계·시험에서 Claude 가 운영 줄을 들여다보지 않는다(친구 허락 뒤 묶음 숫자만).
