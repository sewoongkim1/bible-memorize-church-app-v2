# 봉사 당번 — 자리 틀 · 지원 · 확정 · 전날 알림 (설계)

> **한 줄.** 담당자가 「주일 · 2부 · 설거지 · 2명」 같은 **자리 틀**을 만들면 날짜마다 자리가 생기고, 성도님이 성경암송 앱의 「🙋 봉사 당번」에서 빈 자리에 지원한다. 담당자가 그날을 확정하거나 **전날 저녁 7시가 되면** 그 뒤로는 담당자만 고친다.
> 작성 2026-10-06 · 친구 결정(§0)으로 범위를 정하고, 같은 날 다섯 관점 검토(동시성 · 보안 · 성도님 화면 · 담당자 운영 · 기존 코드)를 반영해 고쳐 썼다(§14 갱신 이력) · 첫 당번은 **식당 봉사(설거지)**, 김장 같은 **한 번짜리 모집도 같은 틀**.

## 0. 친구가 정한 것 (2026-10-06)

| 항목 | 결정 |
|---|---|
| 틀 | 「날짜 × 예배(조) × 일 × 정원」 자리에 성도님이 **지원**한다. 식당 설거지(예배별 2명)가 첫 당번이고 비슷한 사역이 같은 틀을 쓴다 |
| 한 번짜리 모집 | 김장 봉사 같은 **1회성 모집도 봉사 당번에서**(교육신청에 넣지 않는다) — 날짜를 골라 넣는 자리 틀 |
| 지원 자격 | 당번마다 정한다 — 「누구나」 또는 「그 사역팀에 임명된 분만」 → **이번에 만드는 것은 「누구나」와 「담당자가 넣는 당번」 둘**(§0-1 ①) |
| 이름 | 지원한 분의 **이름이 앱에 로그인한 분께 보인다** |
| 자리 만들기 | **반복 규칙으로 한꺼번에** — 쉬는 주·특별한 날만 손으로 |
| 날짜 더하기·빼기 | **날짜를 더할 수 있고**(성탄절 · 특별 예배) **쉬는 날로 뺄 수 있다**(여름 휴가처럼 여러 주는 기간으로 한 번에) |
| 취소 | 날짜 마감 규칙 대신 **담당자가 확정하면 신청자는 고치지 못하고**, 그 뒤 넣기·빼기·옮기기는 **담당자만** |
| 확정 단위 | **날짜 단위** — 「10월 18일 확정」 한 번에 그날 그 당번의 모든 자리가 굳는다 |
| 전날 확정 | **둔다**(친구 「전일 확정」) — 담당자가 확정하지 않아도 전날 저녁에는 저절로 굳는다 |
| 확정 풀기 | **둔다** — 풀면 본인 취소가 다시 열린다 |
| 확정 뒤 빈 자리 | **성도님 지원은 계속 받는다** — 지원하는 순간 바로 확정이라 취소할 수 없다고 **지원 전에** 알린다 |
| 알림 | **전날 알림**(본인에게) · 담당자가 확정한 순간에도 한 번 |
| 역할 | **둘로 나눠 각자 롤로** — 「당번 총괄」(모든 당번 · 만들기)과 「당번 담당」(맡은 당번만) |

### 0-1. 검토를 거쳐 내가 정한 것 (친구가 바꿀 수 있다)

| # | 정한 것 | 까닭 |
|---|---|---|
| ① | **「임명된 분만」 자격은 이번에 만들지 않는다.** 대신 당번 상태에 「지원 멈춤(담당자가 넣어요)」을 둔다 — 앱에서는 명단과 내 당번이 보이고, 넣는 것은 담당자만 | 로그인이 본인 확인이 아니라 임명된 분의 이름·소속으로 들어오면 그대로 통과한다. 그리고 자격을 묻는 답(된다/안 된다)이 「그 목장에 그 이름이 교적에 있고 그 팀에 임명됐다」를 일 년 내내 알려 주는 창구가 된다. 임명된 분끼리 도는 당번은 담당자가 넣는 편이 안전하다 |
| ② | **「확정됨」은 SQL 한 곳이 그때그때 셈한다** — 담당자가 확정했거나, 지금이 그날 전날 저녁 7시(한국)를 지났으면 잠긴 날 | 예약 작업(크론)이 하루 빠지거나 그 뒤에 자리가 생겨도 잠금이 지켜진다. 크론은 알림만 맡는다 |
| ③ | **전날 저녁 7시가 지나면 확정 풀기는 안 된다** — 그 뒤엔 담당자가 직접 빼기·옮기기 | 풀린 채 당일 아침 취소가 되면 전날 확정을 둔 뜻이 없어진다 |
| ④ | **쉬는 날은 「끄고 켜는 스위치」** — 이미 지원한 분의 줄을 지우지 않는다. 쉬는 동안 그 줄은 명단 수·알림에서 빠지고, 다시 열면 그대로 살아난다. 쉴 때와 다시 열 때 그분들께 알린다 | 폰에서 날짜를 잘못 눌러도 되돌릴 수 있다 |
| ⑤ | **담당자가 뺀 분은 그 자리에 스스로 다시 지원하지 못한다**(「담당자께 말씀해 주세요」) · 담당자는 다시 넣을 수 있다 | 확정 뒤 빈 자리는 지원 즉시 잠기므로, 안 그러면 빼도 한 번 눌러 되돌아온다(교육의 「반려 유지」와 같은 결) |
| ⑥ | **잠긴 뒤 못 가게 된 분은 「못 가게 됐어요」로 담당자께 알린다** — 줄은 그대로(빼는 것은 담당자) · 주별 명단에 표시 | 「바꾸려면 담당자께」만으로는 길이 없다 — 조용한 결석이 된다 |
| ⑦ | **문의처 한 줄**(60자 · 이름 + 직분 + 알려도 되는 번호) — 교육 강좌 「문의」와 같은 규칙 | 2026-10-06 교육에서 친구가 정한 규칙을 그대로 |
| ⑧ | **어린이 부서 계정**(보호자 확인 대상 — 영아~초등 · 사랑부 · 중등 1·2학년)은 앱에서 지원하지 못한다 — 담당자가 넣는다 | 이름과 있을 날짜·장소가 앱을 쓰는 누구에게나 보인다. 보호자 확인은 암송 앱을 쓰는 것까지 받은 것 |
| ⑨ | **한 분이 미리 잡아 둘 수 있는 자리 수**를 당번마다 둘 수 있다(비우면 제한 없음) | 계정이 공짜라 한 사람이 모든 자리를 채울 수 있다 · 두세 분이 몇 달 치를 먼저 잡는 것도 막는다 |
| ⑩ | **자리는 저절로 굴러간다** — 요일이 정해진 자리 틀은 「보이는 기간」만큼 늘 자리가 만들어져 있다. 「끝 날짜」는 선택(비우면 계속) | 「자리 만들기」를 잊어 앱의 당번표가 조용히 비는 일을 없앤다 |
| ⑪ | **담당이 자리 틀·날짜·쉬는 날·문의처를 직접 고친다.** 총괄은 당번 만들기 · 담당자 지정 · 이름·상태(준비/보관) | 식당 사정은 식당 담당이 가장 잘 안다 — 바뀔 때마다 총괄을 기다리지 않게 |
| ⑫ | 담당자가 넣은 분(앱을 안 쓰는 분 · 새가족)의 **이름도 당번표에 보인다** — 넣기 창에 그 안내 한 줄 | 벽에 붙이던 당번표와 같다. 방침 문구는 「지원하거나 담당자가 넣으면」으로 적는다(4단계) |

## 1. 범위

**한다:** 당번 만들기 · 자리 틀(매주 반복 / 날짜를 골라) · 자리가 저절로 생김 · 날짜 더하기 · 쉬는 날(하루·기간·자리 하나) · 앱 지원·취소 · 정원 · 겹침 막기 · 날짜 확정·풀기 · 전날 저녁 잠금 · 담당자 대신 넣기(교인명부에서 찾기 · 직접 입력)·빼기·옮기기·메모 · 「못 가게 됐어요」 · 주별 명단·엑셀 · 알림(확정 · 전날 · 담당자가 바꾼 것 · 쉬는 날) · 맡은 당번만 보는 담당자 · 게이트 · 기록 합치기.

**안 한다(이번):** 「임명된 분만」 자격(§0-1 ① · 만들 때의 조건은 §13) · 대기 줄 · 담당자 승인 뒤 확정 · 성도님끼리 바꿔 서기 · 두 분 맞바꾸기 단추(옮기기 두 번으로) · 자동 배정 · 섰는지 출석 체크 · 문자·알림톡 · 통계(누가 몇 번 섰나) · 가족 단위 지원 · 벽에 붙일 인쇄 판(엑셀 표로 대신) · 교인명부 「자세히」 창의 당번 탭 · 한꺼번에 빼기·계정 막기(§13).

## 2. 구조

```
성도님 ─ 성경암송 앱(gocheok.onlybible.kr) ─ api(Edge Function) ─────┐
                                                                     ├─ 같은 DB: duty_* 표 + SQL 함수(정원·겹침·잠금·쉼)
담당자 ─ 교회 어드민(admin.onlybible.kr) ─ church-admin 함수 ────────┘
```

| 어디에 | 무엇 |
|---|---|
| 성경암송 `supabase/duty.sql` | 표 `duty_boards`·`duty_lines`·`duty_days`·`duty_slots`·`duty_signups`·`duty_notify_log` + SQL 함수 전부 (교육의 `edu.sql` 과 같은 자리) |
| 성경암송 `supabase/member_merge.sql` | 기록 합치기가 `duty_signups` 를 안다(여덟 자리 · §5-7) — **같은 커밋** |
| 교회 어드민 `supabase/sql/015_duty_roles_staff.sql` | 역할 두 줄(`duty`·`dutylead`) + 담당 표 `duty_board_staff`(성경암송 `duty.sql` 이 먼저) |
| 성경암송 `api` | 성도님 액션 여섯 + 내부 액션 둘(알림) |
| 교회 어드민 함수 | 관리 액션 전부(`duty-rules.ts` 순수 · `duty-db.ts`) |

- 교육신청과 **표를 섞지 않는다**(강좌는 한 번 신청해 여러 주, 당번은 날마다 따로). 방식만 따른다.
- **`duty_*` 표의 상태·정원·쉼·지원 줄은 SQL 함수로만 쓴다** — 두 Edge Function 에서 직접 update 하지 않는다(메모 한 칸 `staff_note` 만 예외).
- **응답 모양도 SQL 이 만든다** — 성도님·담당자 화면이 읽는 명단은 jsonb 하나를 돌려주는 함수(`duty_board_view`·`duty_mine`·`duty_roster`)라 `user_id`·`ident_key` 가 처음부터 실리지 않고 1,000줄 함정도 없다.
- 교인명부와의 이음은 교육과 같다 — 명부에서 넣은 줄은 `ident_key = 'person|<교인ID>'`(서버 안에서만). `people_links` 는 쓰지 않는다.

### 네 겹

| 겹 | 표 | 예 |
|---|---|---|
| 당번 | `duty_boards` | 식당 봉사 |
| 자리 틀 | `duty_lines` | 주일 · 2부 · 설거지 · 11:30~12:30 · 2명 |
| 날짜 | `duty_days` | 10월 18일 — 확정됨 / 쉬는 날 / 한 줄 메모 |
| 자리 | `duty_slots` | (2부 설거지 틀) × 10월 18일 — 정원 2 |
| 지원 | `duty_signups` | 그 자리에 선 한 분 |

자리는 **자리 틀을 가리킨다** — 이름(예배·일)과 시각은 틀에서 읽는다. 틀의 이름·시각을 고치면 그 틀의 모든 자리에 곧바로 보인다(자리마다 따로 고칠 일이 없다). 정원만 자리마다 따로 둔다(이 날만 3명).

## 3. 역할과 권한

| 누구 | 어디 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|---|
| 성도님 | 성경암송 앱 | 보이는 당번의 자리·찬 수·선 분 이름 · 내 당번 | 지원 · **잠기기 전** 취소 · 잠긴 뒤 「못 가게 됐어요」 |
| 당번 총괄 (`duty`) | 교회 어드민 | 모든 당번 | 당번 만들기 · 이름·상태 · 담당자 지정 · 아래 전부 |
| 당번 담당 (`dutylead`) | 교회 어드민 | **맡은 당번만** | 자리 틀 · 날짜 더하기 · 쉬는 날 · 정원 · 문의처·설명·보이는 기간 · 지원 받기 켜고 끄기 · 확정·풀기 · 넣기·빼기·옮기기·메모 · 엑셀 |
| 총괄 (`super`) | 교회 어드민 | 전부 | 역할 주기 |

- 「맡은 당번만」은 **서버가 지킨다** — 교회 어드민 표 `duty_board_staff`(당번, 담당자). 줄을 받는 액션은 **그 줄에서 당번을 읽어** 확인한다(지원 → 자리 → 당번 · 몸통의 `board_id` 를 믿지 않는다). 아니면 `not-assigned`(아무것도 쓰지 않음).
- 옮기기는 **같은 당번 안에서만**(SQL 이 `wrong-board` 로 거절).
- 교인명부 찾기(`dutyPeopleLookup`)도 맡은 당번의 창에서만 — 역할만으로 명부를 이름으로 떠볼 수 없게.
- 총괄만 하는 일을 담당이 하려 하면 `forbidden` 이 아니라 **`chief-only`** 로 답한다(교회 어드민 화면은 `forbidden` 을 받으면 통째로 다시 부팅한다).
- 새 액션마다: `authz.ts` `ACTION_ROLES` · `index.ts` case · `tests/server.dev.test.mjs` `PROBE` · `tests/authz.test.mjs`(역할 목록 · 배열 액션 거르기) · 쓰기면 `js/menus/system/audit.js` 이름표 + `tests/audit.test.mjs`.
- 담당자 화면에는 이름·소속만 — 연락처·교적 상세는 주지 않는다.

## 4. 자료 모양

모든 표: 만든 자리에서 **RLS 켜고 `public`·`anon`·`authenticated` revoke** · 시퀀스도 revoke.
모든 함수: `security definer set search_path = public` · **`revoke all on function … from public, anon, authenticated` + `grant execute … to service_role`**(안쪽 전용은 `service_role` 도 뺀다) · `p_staff := coalesce(p_staff, false)`.
파일 끝 확인 질의에 「`duty_%` 표·함수의 anon/authenticated/PUBLIC 권한 0」을 넣는다 — `check-authenticated-exposure.sql` 은 둘 다 열린 함수를 못 잡는다(보조 확인).

**`duty_boards`** — 당번
- `id uuid pk` · `title`(1~40) · `description`(~1000) · `place`(~40) · `contact_note`(~60 · 문의처)
- `open_days int default 56`(7~370 · 오늘부터 며칠 앞 자리까지 앱에 보이나) · `until_date date null`(이 날 뒤로는 자리를 만들지 않는다 · 비우면 계속) · `max_ahead int null`(한 분이 이 당번에 미리 잡아 둘 수 있는 자리 수)
- `status` — 아래 표

| 상태 | 앱 | 지원 | 알림·잠금 | 담당자 일 |
|---|---|---|---|---|
| `draft` 준비 | 안 보임 | — | 없음 | 된다(종이 당번표를 미리 옮겨 적는다) |
| `open` 받는 중 | 보임 | 받는다 | 돈다 | 된다 |
| `closed` 지원 멈춤 | 보임(명단 · 내 당번) | **새 지원만 막는다**(담당자가 넣는 당번도 이 상태) | 돈다 | 된다 |
| `archived` 보관 | 안 보임 | — | 없음 | 쓰기 거절(지우는 길은 없다 — 시험 당번은 보관으로) |

**`duty_lines`** — 자리 틀
- `id` · `board_id` · `sort int` · `service`(1~12 · 예 「2부」·「오전조」) · `task`(~20 · 예 「설거지」 · 비워도 됨) · `start_time`·`end_time`(**둘 다 꼭** · `start < end`) · `capacity`(1~200) · `weekday`(0=주일 … 6=토 · **null = 날짜를 골라 넣는 줄**) · `active`
- 글자는 NFC·앞뒤 빈칸 없이(CHECK) · 살아 있는 줄끼리 `unique(board_id, service, task)`
- 자정을 넘는 자리는 23:59 에서 끊어 적는다(§13)

**`duty_days`** — 날짜 하나의 상태: `pk(board_id, on_date)` · `off bool`(쉬는 날) · `note`(~60 · 성도님께 보이는 한 줄 — 「여름 휴가」) · `confirmed_at` · `confirmed_by`(담당자 id · FK 없음 · 응답에 안 싣는다)
- **자리가 있는 날짜에는 늘 줄이 있다**(자리가 FK 로 가리킨다) — 잠글 부모가 늘 있다. 자리가 없는 날짜도 미리 쉬는 날로 둘 수 있다.
- 「쉼」과 「확정」은 **서로 독립인 두 사실**이다(쉼을 풀어도 확정 여부는 그대로).

**`duty_slots`** — 자리: `id` · `board_id`·`on_date`(→ `duty_days`) · `line_id`(→ `duty_lines` · restrict) · `capacity` · `off bool`(이 자리만 쉼) · `unique(line_id, on_date)`

**`duty_signups`** — 지원 한 줄(자리·사람에 **한 줄** — 다시 지원하면 그 줄을 되살린다)
- `id` · `slot_id`(restrict) · `user_id uuid null → users on delete cascade`(대신 넣은 분은 null 가능) · `ident_key` · 신원 사진(`who_type`·`group_name`·`sub_name`·`name` — 지원 당시 값 · **서버가 users 줄에서 읽는다**)
- `status`(`active` · `cancelled` 본인 취소 · `removed` 담당자가 뺌) · `end_reason`(`self`·`staff`·`merge`) · `source`(`app`·`staff`) · `staff_note`(~500 · 담당자만)
- `ask_at`·`ask_why`(`cant` 못 가게 됐어요 · `mistake` 잘못 눌렀어요 · `notme` 제가 한 게 아니에요)
- `applied_at` · `ended_at` · 시각들
- `unique(slot_id, user_id) where user_id is not null` · `unique(slot_id, ident_key) where user_id is null` · `check(user_id is not null or ident_key <> '')`

**`duty_notify_log`** — `pk(signup_id, kind)` · kind `confirmed`·`remind` — 같은 지원에 같은 알림 한 번(보내기 **전에** 잡는다 · 잡은 번호는 `bigint[]` 하나로).

**교회 어드민 `duty_board_staff`** — `pk(board_id, member_id)` · 당번·담당자 cascade.

## 5. 규칙

### 5-1. 잠금
- **잠긴 날** = 담당자가 확정했거나, 지금이 그날 전날 19:00(한국)을 지났다. 크론이 쓰는 값이 아니라 SQL 이 부를 때마다 셈한다.
- 잠긴 날: 본인은 취소·변경을 못 한다. 빈 자리 지원은 받되 **서버가 「알고 누른 것」을 확인한다** — `ack_locked` 없이 오면 아무것도 쓰지 않고 `locked-day` 로 답하고, 앱이 그 자리에서 「취소할 수 없는 날이에요」 확인을 띄운 뒤 다시 보낸다(화면을 열어 둔 사이 잠긴 경우도 같다).
- 확정 풀기는 마감 전에만. 확정은 「채워졌다」가 아니라 「이제 담당자가 관리한다」는 뜻 — 빈 자리가 남은 채로도 확정한다.

### 5-2. 지원 (`duty_apply`)
잠금 차례는 늘 같다(교착 막기): **⓪ 전역 advisory(지원 줄을 쓰는 함수 모두 — 기록 합치기 트리거가 줄을 쓸 때 쥐는 그 잠금을 맨 먼저) → ① 사람 advisory(계정 → 명부 키) → ② 날짜 줄 `for update` → ③ 자리 줄 → ④ 지원 줄.** 날짜 줄·자리를 **만드는** 일(자리 만들기 · 틀 고치기·빼기 · 날짜 더하기 · 쉬는 기간 · 날짜 메모)은 당번 advisory 를 맨 먼저(§14 셋째 판).

검사 차례(모두 끝난 뒤에만 쓴다):
1. 신원 — 이름 1~40자 · 계정 없는 줄은 담당자 길 + 신원 키 필수
2. 당번 상태 — `archived` 거절 · 본인은 `open` 만(`closed` → `closed`)
3. 쉬는 날·쉬는 자리 → `off`
4. (본인) 지난 날 `past` · 오늘인데 시작 시각이 지남 `started` · 보이는 기간 밖 `not-yet`
5. **이미 이 자리에 내 줄** → 살아 있으면 `{ok, already:true}`(두 번 눌러도 한 줄) · (본인) 담당자가 뺀 줄이면 `removed-by-staff`
6. (본인) 잠긴 날인데 `ack_locked` 없음 → `locked-day`
7. 정원 → `full`(담당자는 확인 뒤 `force` 로 넘긴다)
8. 겹침 — 같은 분(계정 또는 신원 키)이 같은 날 **시각이 겹치는**(시작 포함·끝 제외 — 맞닿은 자리는 안 겹침) 다른 자리에 살아 있음 → `overlap`(무엇과 겹쳤는지 이름을 함께) · 담당자는 `force`
9. (본인) 미리 잡아 둔 수가 `max_ahead` 에 닿음 → `too-many`

api 가 SQL 앞에서 보는 것: 문(§7) · users 줄이 있는가 · 어린이 부서(`guardian`) · 이름이 당번표에 실을 만한가(`bad-name` — 20자 넘음 · 꺾쇠·따옴표 같은 글자 · 숫자 네 자리 이상).

### 5-3. 취소·빼기·옮기기
- 본인 취소: 잠기기 전 · 지난 날 아님 → `cancelled`.
- 담당자 빼기: 언제든(지난 날짜도 — 당일 안 온 분·대신 선 분을 다음 날 바로잡는다) → `removed`(`end_reason staff`).
- 담당자 옮기기: 같은 당번 안 · 정원·겹침은 확인 뒤 `force` · 날짜나 시각이 달라지면 전날 알림 기록을 지워 새 자리로 다시 가게 한다.
- 담당자 넣기: 교인명부에서 찾기(화면은 `{name, pick, check}` 만 보내고 서버가 같은 찾기를 다시 돌린다 — 교인ID 는 화면에 안 나간다 · 앱 계정이 정확히 하나로 맞으면 그 계정에) 또는 직접 입력(새가족).

### 5-4. 쉬는 날
- 날짜(하루·기간)와 자리 하나를 쉬게 할 수 있다. **지원 줄은 건드리지 않는다** — 쉬는 동안 그 줄은 찬 수·겹침·전날 알림에서 빠지고 앱에는 「이날은 쉬어요 · 안 나오셔도 돼요」로 보인다. 다시 열면 그대로 살아난다.
- 켜고 끌 때 이미 지원한 수를 보여 주고 확인받는다(그 사이 수가 바뀌면 다시 묻는다).

### 5-5. 자리 틀을 고칠 때
- 이름·시각: 그 틀의 모든 자리에 곧바로 보인다.
- 정원: 새로 생기는 자리부터. 「앞날 자리에도」를 고르면 옛 정원 그대로인 앞날 자리만 바꾼다.
- 요일을 바꾸거나 틀을 빼면: 앞날 자리 가운데 지원 줄이 하나도 없는 것만 지운다. 남긴 수를 알려 준다.

### 5-6. 시간
- 「오늘」은 한국 날짜 한 곳(`duty_today()`).
- 지난 날짜: 성도님은 읽기도 없다(앱 응답은 오늘부터) · 담당자는 고칠 수 있다(기록 `duty.*`).

### 5-7. 기록 합치기 (`member_merge.sql`)
- 여덟 자리(실행 순서 머리 · 트리거 목록 · 기록 수 · 충돌 검사 · FK 허용 · user_id 허용 · 정리·옮기기 · 주인 옮기기 목록)에 `duty_signups`.
- 두 계정이 **같은 자리**에 줄을 가지면: 남는 쪽이 살아 있으면 원본 줄을 지우고, 원본만 살아 있으면 남는 쪽의 끝난 줄을 지운 뒤 옮긴다(자리·사람에 한 줄).
- 두 계정이 **앞날의 같은 날 시각이 겹치는 서로 다른 자리**에 둘 다 살아 있으면 `merge-duty-conflict` 로 멈춘다(담당자가 한쪽을 뺀 뒤 다시).
- `duty.sql` 뒤에 `member_merge.sql` 을 다시 돌린다(표가 먼저 있어야 쓰기 연결 트리거가 붙는다).

## 6. 화면

### 성경암송 앱 — 첫 화면 「교회」 묶음의 「🙋 봉사 당번」
1. **당번 목록** — 보이는 당번 카드(이름 · 장소 · 「한 분 더 필요해요」가 있는 가까운 날) · 「내 당번」(다가오는 날짜 순 · 오늘 것은 그날 끝까지). 당번이 하나뿐이면 목록을 건너뛴다.
2. **당번 자세히** — 설명 · 장소 · 📞 문의 · 날짜마다: 머리(「10월 18일(일)」 · 잠긴 날이면 「확정됨 · 지원하면 앱에서 취소할 수 없어요」 · 쉬는 날이면 「쉬어요」와 메모) + 자리 줄(「2부 · 설거지 · 11:30」 · 선 분 이름 · 「한 분 더 필요해요」/「다 찼어요」) + 단추. 찬 자리에는 단추를 두지 않는다.
3. **지원** — 모든 지원에 확인 창 한 번(날짜·자리·시각·장소 굵게 · 누구 이름으로 들어가는지 · 「이 자리에 이름이 보여요」 · 언제까지 취소할 수 있는지). 잠긴 날은 다른 창(「⚠️ 취소할 수 없는 날이에요」 · 단추 「취소 못 해도 지원하기」).
4. **내 줄** — 잠기기 전: 「✅ 지원했어요 — 이대로 서시면 돼요 · ○월 ○일(토) 저녁 7시까지 취소할 수 있어요」 + 〔취소〕 / 잠긴 뒤: 「🔒 확정됐어요 — 바꾸려면 담당자께」 + 문의처 + 〔못 가게 됐어요〕 / 담당자가 뺀 줄: 그날이 지날 때까지 「담당자가 빼 드렸어요」(성도님 화면에 removed 같은 말은 쓰지 않는다).
- 서버가 판정을 준다(잠김 · 취소 마감 · 지원할 수 있나 · 왜 안 되나) — 앱은 말만 고른다(순수 함수 `dutySlotView`·`dutyMineView`·`dutyErrText` + 시험).
- 지원·취소 뒤에는 맨 위로 올리지 않고 그 날짜로 돌아온다. 화면이 다시 보이면(다른 앱에서 돌아옴) 자료를 다시 받는다.
- 요일 글자는 「(일)」(교육 화면과 같게).

### 교회 어드민 — 묶음 「봉사 당번」
1. **🧰 당번 관리**(총괄) — 당번 카드(상태 · 담당자 · 자리 틀 요약) · 만들기·고치기 · 담당자 지정 · 「받는 중」으로 바꾸는 저장에만 확인 한 번.
2. **📅 당번 명단**(총괄·담당) — 당번 고르기(하나면 건너뜀) → **날짜 칩 줄**(빈 자리가 있는 날 강조 · 확정·쉼 표시 · 처음엔 오늘 또는 다음 날짜) → 그날 판: 상태(「담당자 확정」/「전날 저녁 자동 확정」/「쉬는 날」)와 〔이 날 확정〕·〔확정 풀기〕·〔쉬는 날로〕 → 자리마다 선 분(이름 · 소속 · 앱/담당자 · 「앱 없음」 · 「못 온다고 알림」 · 「같은 분일 수 있어요」)과 〔넣기〕·〔빼기〕·〔옮기기〕·〔메모〕 · 빠진 분은 접어 둔다.
   위 줄: 〔자리 틀〕 〔날짜 더하기〕 〔쉬는 기간〕 〔당번 설정〕 〔엑셀〕.
- 엑셀: 시트 「당번표」(한 줄 = 날짜 · 칸 = 자리 틀 차례 · 값 = 이름들 · 빈 자리 표시 — **이름만**) + 시트 「명단」(한 분 한 줄 · 소속 · 넣은 곳 · 메모 — 담당자용).

## 7. 노출 게이트

- 앱: `dutyVisible() = !ministryHiddenOnPlay() && (dutyOpenCached() || ministryTesterCached())` — `app_config.dutyOpen`(세 값: 켜짐·꺼짐·모름) 또는 🧪 시험 참여자. 플레이 앱에서는 심사가 끝날 때까지 숨긴다(사역·교육과 같은 스위치). 키는 `PUBLIC_CONFIG_KEYS` 에.
- **서버는 읽기도 막는다**(교육과 다르다 — 이름이 나간다): `dutyGate(userId)` = users 에 그 줄이 **실제로 있고**(꼴만 보지 않는다) `dutyOpen === true` 이거나 시험 참여자. 못 지나면 `dutyList`·`dutyBoard`·`dutyMine` 은 `{ok:true, open:false}`(당번·이름·수 모두 없음), `dutyApply`·`dutyCancel`·`dutyAsk` 는 `not-open`.
- 알림도 `dutyOpen` 이 켜지기 전에는 시험 참여자에게만(보내는 한 곳에서 거른다 · 걸러진 줄은 잡지 않는다).
- 알림 주소(`/?duty=1`)와 열린 창 메시지는 `dutyVisible()` 일 때만 당번 화면을 연다.
- 당번 코드는 **운영 SQL·api 가 올라간 뒤에만 main 에 올린다**(가지 `duty-roster` — main 은 여러 세션이 함께 푸시하고, api 는 작업 트리를 통째로 배포한다).

## 8. 개인정보·보안

- **새로 모으는 것:** 당번 지원(당번·날짜·자리·지원 시각·상태) · 「못 가게 됐어요」 표시 · 담당자 메모. 휴대폰 번호는 받지 않는다.
- ⚠️ **이름 공개의 실제 범위(친구 결정 「로그인한 분께 보인다」).** 이 앱의 로그인은 이름·소속만 넣으면 계정이 생긴다. 그래서 「로그인한 분께 보인다」는 **앱을 쓰는 누구에게나 보인다**와 같은 말이고, 식당 벽에 붙이던 당번표 수준의 공개로 본다. 방침에도 그렇게 적는다 — 「봉사 당번에 지원하거나 담당자가 당번에 넣으면 이름이 앱을 쓰는 성도님께 보입니다」.
  - 응답에 싣는 것은 **이름 글자만**(가나다 차례) — 소속·`user_id`·`ident_key`·지원 시각은 싣지 않는다. 이름은 한 곳에서 다듬어 싣는다(NFC · 제어 글자 빼기 · 20자).
  - 화면은 이름·담당자 글을 모두 이스케이프해 넣는다.
- ⚠️ **확정은 「취소 장난」만 막는다 — 「넣기 장난」은 오히려 굳힌다.** 남의 이름·소속으로 들어오면 그분 계정이 되고, 잠긴 날에 넣은 지원은 본인이 지울 수 없다. 그래서:
  - 잠긴 날에 새로 들어간 줄(앱 지원 · 담당자 넣기·옮기기)은 **그 계정의 기기로 곧바로 알린다**(본인이 그날 안다).
  - 잠긴 줄의 본인은 〔못 가게 됐어요 / 제가 한 게 아니에요〕로 담당자에게 알린다.
  - 주별 명단은 넣은 곳(앱/담당자)과 「같은 분일 수 있어요」를 보여 주고, 담당자가 뺀 분은 스스로 되돌아오지 못한다.
  - 당번마다 한 분이 미리 잡을 수 있는 수를 둘 수 있고, 담당이 지원 받기를 바로 끌 수 있다.
- 어린이 부서 계정은 앱에서 지원하지 못한다(api `needsGuardian` 한 곳으로 판정).
- 「맡은 당번만」·명부 찾기는 §3.
- 계정을 지우면 그분 지원 줄도 지워진다(교육과 같다 — 주별 명단에는 빈 자리로 보인다).
- 개인정보 안내: 성경암송 세 곳(`privacy/index.html` · `renderPrivacyInfo` · `renderHelp` 🔒 — 같은 커밋 · `tests/store-review.test.cjs` `PRIVACY_ITEMS`) + 교회 어드민 `privacy.html`(당번 역할이 교인명부를 이름으로 찾는 것 포함) — **공개(4단계) 전에 · 플레이 심사 뒤.**
- 담당자 응답에 `auth_user_id`·`user_id`·`ident_key`·`confirmed_by` 없음 · 쓰기는 `admin_audit` `duty.*`(이름 없이 id·수만) · 명부 찾기는 `people.lookup` `from:"duty"`.
- 엑셀 「당번표」 시트에는 이름만(메모·넣은 곳·앱 여부 없음 — 벽에 붙는다).

## 10. 알림

보내는 길은 api 한 곳(`dutyNotifySend`) — 문(§7) · 한 번만(`duty_notify_claim`) · 기기(웹 푸시 + 아이폰) · `push_log` 한 줄. 교회 어드민은 **저장·기록이 끝난 뒤** 부탁만 한다(실패해도 저장은 성공 — 응답에 `notified`·`notifyError`).

| 언제 | 누구에게 | 글 |
|---|---|---|
| 담당자가 날짜를 확정 | 그날 살아 있는 분 | 「10월 18일(일) 식당 봉사 2부 설거지 당번이 확정됐어요. 이제 앱에서는 취소할 수 없어요 — 못 오시면 담당자께 알려 주세요」 |
| 전날 19:00 | 내일 당번인 분(한 분의 여러 자리는 한 통에) | 「내일 10월 18일(일) 당번이에요 — 식당 봉사 2부 설거지 11:30 · 식당」 |
| 잠긴 날에 앱 지원이 들어옴 | 그 계정 | 「10월 18일(일) 식당 봉사 2부 설거지에 지원하셨어요 — 확정된 날이라 앱에서 취소할 수 없어요」 |

| 쉬는 날로 / 다시 열기 | 그날 살아 있는 분 | 「10월 18일(일) 식당 봉사 당번은 쉬어요 — 안 나오셔도 돼요」 · 「… 당번을 다시 서요」 |

- 전날 저녁 저절로 잠긴 날은 확정 알림을 따로 보내지 않는다(전날 알림 한 통).

  - §6-4 「○월 ○일(토) 저녁 7시까지 취소할 수 있어요」 → **「확정 전까지 앱에서 취소할 수 있어요(늦어도 ○월 ○일(토) 저녁 7시에 확정돼요)」** — 잠김은 「담당자 확정 또는 전날 저녁」(§5-1)이라 그 시각은 「늦어도」다. 날짜 머리는 「늦어도 … 에 확정돼요 — 확정 뒤에는 앱에서 취소할 수 없어요」.
  - §0-1 ⑥ 「담당자께 알린다」는 **담당자 당번표의 표시**다(담당자 휴대폰으로 가는 알림은 없다 — §10 의 알림은 모두 성도님께 간다). 화면은 「알렸어요」가 아니라 「담당자 당번표에 표시했어요 · 급하시면 담당자께 직접 연락해 주세요」라 말하고, 스스로 못 빼는 줄의 「내 당번」 카드에 문의처를 둔다(§6-4 「+ 문의처」).
  - 담당자가 넣는 당번(지원 멈춤)의 날짜 머리에는 지원·취소 말을 쓰지 않는다 · 빈 자리가 없는 당번 카드는 「지금은 지원할 수 있는 자리가 없어요」 · 자리만 쉬면 「이 자리는 쉬어요」(`duty_mine` `dayOff`).
  - 「서버가 판정을 준다」에 **계정 단위 판정**이 더해졌다 — 읽기 응답 `me.why`(어린이·청소년 부서 · 당번표에 실을 수 없는 이름). 그런 계정에는 「지원하기」 단추를 두지 않는다.
  - 보관한 당번은 성도님 길에서 「없는 당번」(`not-found`)이다 · 계정 번호를 못 받은 동안에는 서버를 부르지 않고 단추도 두지 않는다 · 늦게 온 응답은 떠난 화면을 덮지 않는다.
  - 교회 어드민: 넣기 창에 「넣은 분의 이름이 앱 당번표에 보여요 · 못 가게 됐어요는 명단의 표시(따로 알림이 오지 않아요)」(§0-1 ⑫) · 문이 닫힌 동안 「선 분의 이름이 시험 참여자 앱에 보여요 — 진짜 명단은 준비 중에」(§11 ⚠️).
