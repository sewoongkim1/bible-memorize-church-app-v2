## 0. 정한 것과 까닭

| 물음 | 정한 것 | 까닭 |

## 1. 데이터

### 표 (운영 DB · 새로 · 만든 자리에서 RLS 켜고 `anon`·`authenticated` revoke)

**`church_people`** — 교인 한 분 = 한 줄. 열쇠는 **교인ID**(dimode 번호, 원본 `RigthPerosonModify('45458')` 의 숫자).

| 칸 | 원본(엑셀 정리본 칸) |
|---|---|
| `person_id` (int, PK) | 교인ID |
| `name`, `position`, `position_detail`, `gender` | 이름 · 직분 · 직분상세 · 성별 |
| `birth` (text), `birth_date` (date, 날짜로 읽히는 것만), `lunar`, `age` | 생년월일 · 양음력 · 나이(명단 기준일의 나이) |
| `spouse`, `spouse_position` | 배우자 · 배우자직분 |
| `household_head`, `household_rel` | 신앙세대주 · 세대주관계 |
| `kind1`, `kind2`, `kind3` | 교인구분 1~3 (교인 / 장년·청년·교회학교 / 출석교인·관리교인…) |
| `registered` (text), `registered_date` (date), `reg_type` | 등록일 · 등록구분 |
| `phone1`, `phone2` | 연락처1 · 연락처2 |
| `guide`, `email` | 인도자 · 이메일 |
| `mok_path`, `mok1`, `mok2`, `mok3`, `mok_leader` | 목장(전체) · 목장1(교구) · 목장2 · 목장3 · 목장리더 |
| `school_path`, `school_dept`, `teacher` | 교회학교(전체) · 교회학교부서 · 교사 |
| `youth_path`, `mission` | 청년(전체) · 선교회 |
| `address`, `address_jibun` | 주소 · 지번주소 |
| `has_photo` (bool), `photo_hash` | 사진파일이 「사진없음」이 아니면 true · 사진의 md5(다시 올릴 때 바뀐 사진만 올리려고) |
| `name_key` | 이름을 NFC 로, 띄어쓰기 없이 — 찾기·맞대기용 |
| `phone_digits` (text) | 연락처1·2 에서 숫자만, 띄어쓰기로 이음(`01012345678 026861234`) — 전화 뒷자리 찾기(`ilike`)·맞대기용 |
| `updated_at` | 이 줄이 마지막으로 바뀐 때 |

- 칸 이름·풀이 규칙은 2026-09-29 변환(원본 대조: 낱말 210,899개 중 빠짐 0)을 그대로 따른다. 거기서 정한 두 가지를 이어받는다:
  교회학교 소속이 없는 분의 「교사」는 비운다(내보내기 기본값) · 전부 빈 칸이던 「청년 리더」는 없다.

**`church_people_imports`** — 올린 기록 한 번 = 한 줄: `id` · `imported_at` · `source_date`(명단 기준일) · `total` · `added` · `changed` · `removed` · `photos`.
화면의 「명부 기준일」은 이 표의 마지막 줄에서 읽는다.

### 사진 — 비공개 Storage 칸 `church-people-photos`
- `public = false`, 정책 없음 → 서버(service role)만 연다. 파일 이름 `<교인ID>.jpg`.
- 실제 사진만 올린다(2026-09-29 기준 4,645장 · 238MB). 기본 그림(회색 바탕 흰 사람 모양, 같은 그림 4,027장)은 올리지 않고 `has_photo = false`.

### 개발 DB 에는 진짜 명부를 넣지 않는다
- 개발(`ktpwthwqzgcqcrmsafdo`)에는 스크립트가 만든 **가짜 교인 100명**(가짜 이름·번호·주소, 사진 몇 장은 단색 그림)을 넣는다.
- 진짜 8,672명은 **운영에만**. 사본이 하나 적을수록 샐 곳도 하나 적다.

## 2. 서버 (`supabase/functions/church-admin`)

### 역할
- `admin_roles` 에 `('directory', '교인명부', '교인 찾기 · 현황 · 내려받기')` 한 줄. 역할의 원본은 그 표다(코드·CHECK 에 박지 않는다).
- `super` 는 지금처럼 전부 본다(`canCall` 그대로).

### 액션 (모두 `directory`) — 규칙대로 `authz.ts` `ACTION_ROLES` + `index.ts` case + `tests/server.dev.test.mjs` PROBE 셋에 한 줄씩

| 액션 | 받는 것 | 돌려주는 것 |
|---|---|---|
| `peopleSearch` | 검색어(이름 또는 전화 뒷자리 4개) · 거르기(교구 `mok1` · `kind2` · `kind3` · 직분 · 사진 없음) · 쪽(50명씩) | 목록 칸(교인ID·이름·직분·성별·나이·소속·연락처1·사진 여부) + 그 쪽 사람들의 **사진 주소(10분)** + 전체 수 + 명부 기준일 |
| `peoplePerson` | 교인ID | 담은 칸 전부 + 사진 주소(10분) |
| `peopleStats` | 없음 | 숫자만 — 교구별(목장 수·인원) · kind2 · kind3 · 직분 · 교회학교 부서 · 연령대×성별 · 사진 없는 분 수 · 명부 기준일 |
| `peopleExport` | `peopleSearch` 와 같은 거르기(없으면 전체) | 칸 전부(사진 빼고) — 화면이 CSV 로 저장(임명현황 `csvText` 와 같은 방식) |

- 사진 주소는 `createSignedUrls(paths, 600)` — 만료 10분. 목록은 그 쪽 50명 것만 만든다.
- 1,000행 넘는 읽기는 쪽 넘기기(`.range()`)로 — PostgREST `max_rows` 에 잘리지 않게(3단계에서 한 번 겪었다).

### 사역신청과 맞대기 — 사역 담당자에게는 **표시 하나**만
`ministryList`(신청 현황)와 `ministryPaperCheck`(종이 명단 살펴보기)의 줄마다 `church: { state, reason }` 을 더한다.

| state | 언제 | reason 예 |
|---|---|---|
| `맞음` | 이름 + 소속이 같은 분이 **정확히 한 분** | — |
| `확인 필요` | 이름 + 소속이 같은 분이 여럿 · 또는 이름은 같고 소속이 다름(전화가 같으면 「소속 다름」, 아니면 「같은 이름 N명」) | `소속 다름` · `같은 이름 2명` |
| `없음` | 교적에 같은 이름(`name_key`)이 없음 | — |

- 「소속이 같다」: 교구 신청은 교구(`mok1`) 같고 목장 번호 같음(명부 `기쁨-12목장` → 12, 앱 `12`·`12목장` → 12).
  교회학교 신청은 부서가 `school_dept` 또는 `mok1`(청년부)와 같음. 새가족 교구는 교구만 본다.
- 전화 비교는 사역신청·종이 명단에 남은 전화와 `phone_digits`.
- ⚠️ **교적의 값(연락처·주소·생년월일·직분)은 사역 쪽 응답에 싣지 않는다.** 시험이 그 칸이 없는 것을 확인한다.
- 맞대기 규칙은 **순수 함수 모듈**(`people-match.ts`)에, 찾기 조건 풀기·현황 세기는 `people-query.ts` 에 두고 Node 시험이 같은 파일을 읽는다(`authz.ts` 와 같은 방식).

### 열람 기록 — 본 일도 남긴다
지금 `admin_audit` 는 바꾼 일만 남긴다. 명부는 **읽은 일도** 남긴다(개인정보 처리 시스템의 접속 기록).

| action | target | detail |
|---|---|---|
| `people.search` | — | 검색어 · 거르기 · 결과 수 |
| `people.view` | 교인ID | 이름 |
| `people.export` | — | 거르기 · 명수 |
| `people.import` | import id | 기준일 · 새로/바뀜/빠짐 수 (스크립트가 남긴다) |

- 기록은 지우지 않는다. 「바꾼 기록」 화면에 **「명부 열람」 거르기 단추**를 더한다.
- 응답에 `auth_user_id` 를 싣지 않는다(지금 규칙 그대로).

## 3. 화면 (`js/menus/people/*` · `registry.js` 에 두 줄)

### 🔎 교인 찾기 (`role: "directory"`)
- 위: 검색창(이름 · 전화 뒷자리) + 거르기 단추(교구 · 장년/청년/교회학교 · 출석 구분 · 직분 · 사진 없음).
- 결과: 폰은 카드, PC(≥1024px)는 표 — 작은 사진 · 이름(직분) · 성별·나이 · 소속 · 연락처(`tel:` 로 바로 걸기).
- 한 분을 누르면 자세히(큰 사진 + 담은 칸 전부).
- **⬇️ 내려받기** → `dialog` 로 먼저 묻는다: 「지금 걸러 낸 N명을 받습니다. 받은 기록이 남아요.」 → 확인해야 CSV 저장.
- 사진 주소는 10분 뒤 만료된다 — 목록 사진은 **바로 불러오고**(`loading=eager`), 못 불러오면 이름 첫 글자로 바꾼다. 자세히 보기는 열 때마다 서버가 새 주소를 준다.

### 📊 교인 현황 (`role: "directory"`)
- 숫자 표: 교구별(목장 수·인원) · 장년/청년/교회학교 · 출석 구분 · 직분 · 교회학교 부서 · 연령대×성별.
- **사진 없는 분 N명**을 누르면 교인 찾기로 넘어가 「사진 없음」으로 걸러 보여 준다.

### 두 화면 공통
- 맨 위 한 줄: **「명부 기준일 2026-09-29 · 8,672명」**. 기준일이 **90일**을 넘기면 「명부가 오래됐어요 — 새 명단을 올려 주세요」로 바뀐다.

- **신청 현황 · 종이 명단 올리기**: 이름 옆 표시 — 초록 `교적 ✓` · 주황 `교적 확인` · 회색 `교적 없음`. reason 은 표시 안에 작은 글씨로(누를 필요 없이 폰에서도 보인다). 화면 위에 뜻풀이 한 줄.
- **바꾼 기록**: 「명부 열람」 거르기.
- **`privacy.html`**: 「교인 정보」 절 — 어디서 온 것(교회 교적 프로그램) · 담는 칸 · 누가 보나(교인명부 역할을 받은 담당자) · 본 일을 기록함 · 새 명단이 오면 갈아 끼우고 빠진 분은 지움 · 삭제 요청처(지금 안내의 요청처 그대로).

## 4. 올리기와 안전장치

### 올리기 스크립트 (`tools/people/` · 코드만 커밋)
새 명단이 오면 친구가 `.xls` 를 `C:\Projects\` 에 두고 차례로 돌린다. 작업 폴더는 **저장소 밖**(`C:\Projects\교인명부_작업\<기준일>\`).
1. **풀기** — 2026-09-29 변환 그대로 → `people.json`. 원본 낱말 대조(빠짐 0)를 매번 돌리고, 빠짐이 있으면 멈춘다.
2. **사진 받기** — 동시에 3장, 이어 받기, 기본 그림은 같은 그림(해시)이 100장 넘게 나오는 것으로 골라낸다.
3. **살펴보기** — DB 를 바꾸지 않고 「새로 N · 바뀜 N · 빠짐 N · 사진 바뀜 N」만 보인다.
   ⚠️ **빠짐이 지금 인원의 5%를 넘으면 멈춘다** — dimode 에서 한 교구만 내려받은 파일로 나머지가 통째로 지워지는 사고를 막는다.
   (정말 그만큼 빠진 것이면 친구가 확인하고 `--allow-drop` 으로 넘긴다.)
4. **넣기** — 바뀐 줄만 upsert · 빠진 분은 줄과 사진을 지움 · 사진은 해시가 달라진 것만 올림 · `church_people_imports` 한 줄 + `people.import` 기록.
- 대상은 늘 **`--dev`(가짜 100명) 먼저, 그다음 `--prod`**.
- 키: 개발은 지금 있는 `~/.church-admin/dev.env`. 운영은 **넣을 때만** `~/.church-admin/prod.env`(PROD_URL · PROD_SERVICE_KEY)를 두고 쓴다 —
  저장소 밖이며, 다 넣은 뒤 지울지는 친구가 정한다(서비스 키는 모든 표를 여는 열쇠다).
- 가짜 명부 만들기: `tools/people/fake.py`(개발 전용 · `--prod` 에 넣으려 하면 거절).

### 공개 저장소에 새지 않게
- `.gitignore`: `교인*` · `*.xls` · `people*.json` · `교인명부_작업/`.
- `tools/preflight.py` 에 검사 하나: **커밋된 파일에 전화번호 꼴(`01\d-?\d{3,4}-?\d{4}`)이 20개 넘게 든 파일이 있으면 배포를 멈춘다** — 이름 규칙을 피해 들어간 명단도 잡는다(시험 자료는 가짜 번호 꼴 `010-0000-00xx` 를 쓰고 이 검사에서 뺀다).
- 노출 점검 `check-authenticated-exposure.sql` 에 ⑦을 더한다: **사진 칸 `church-people-photos` 가 `public = true` 면** 잡는다(정책이 없어도 공개 칸은 누구나 연다).
  같은 프로젝트의 다른 앱이 일부러 공개로 둔 칸은 이 점검의 대상이 아니라 칸 이름을 박는다. 새 표 둘은 ①~④가 이미 본다. 개발·운영 모두 **0행**.

### 배포 순서 — 새 표에 새 액션이라 **표가 먼저**

## 5. 오류 처리
- 명부가 한 번도 안 올라온 상태: 두 화면이 「아직 명부가 없어요」를 보이고, 사역 화면의 교적 표시는 **아예 그리지 않는다**(전부 「교적 없음」으로 보이면 사실이 아닌 말이 된다).
- 사진 주소 만들기 실패: 그 사람은 사진 자리에 이름 첫 글자만. 목록 전체를 실패로 만들지 않는다.
- 내려받기가 큰 경우(8,672명 · 약 4MB): 한 번에 받는다(쪽 넘기기는 서버 안에서). 실패하면 `toast` 로 알리고 기록은 남기지 않는다(기록은 응답을 돌려주기 직전에).
