## ① 왜 — 복습은 지금 작동하지 않는다

2026-09-23 운영 DB 실측(`docs/analysis/2026-09-23-usage-analysis.md`):

| 항목 | 값 |
|---|---:|
| 복습이 차지하는 반복 | **0.6%** (755회 / 123,776회) |
| 복습 대상 | 174명 |
| **한 번도 복습 안 한 사람** | **122명 (70.1%)** |
| 복습 대기 | 2,841건 |
| 그중 기한 지남 | 2,383건 (83.9%) |
| 7일 이상 밀림 | 2,099건 (73.9%) |
| 30일 이상 밀림 | 456건 |
| 한 사람 평균 밀린 건 | 13.9건 (중위 6건, 최대 43건) |

2026-09-02 개편으로 복습을 **첫 화면 맨 위 단추**로 올렸는데도 이 숫자다.
**자리를 옮겨서 해결되는 문제가 아니다.** 원인 후보 둘을 함께 친다.

### 원인 ① 카드 모드가 없다

| 화면 | 카드 | 자판 | 음성 | 총 반복 |
|---|---:|---:|---:|---:|
| 암송 | **59.6%** | 39.7% | 0.7% | 81,736회 |
| 도전 | **77.5%** | 22.5% | 0.0% | 41,285회 |
| **복습** | **0%** | **99.9%** | 0.1% | 755회 |

카드가 전체 반복의 65.2%를 먹었는데 복습만 자판뿐이다.

이 구멍은 `docs/notes/metrics.md` 에 **2026-09-02에 이미 적혀 있었다.**

### 원인 ② 적체 자체가 벽이다

밀린 양이 **쌍봉**이다 — 171명 중 39명은 1건만 밀렸는데,
**52명은 21~40건**이 밀려 있고 그 52명이 전체 적체의 **73.6%**(1,755건)를 쥐고 있다.

그런데 실제로 복습을 한 날 **그날 복습한 구절의 중위값이 3구절**이다(평균 4.7, 최대 28):

| 그날 복습한 구절 | 횟수(사람×날) | 비중 |
|---|---:|---:|
| 1구절 | 52 | 32% |
| 2~3구절 | 44 | 27% |
| 4~5구절 | 19 | 12% |
| 6~10구절 | 29 | 18% |
| 11구절+ | 17 | 11% |

**3은 실제 행동의 중위값이다.** 1~3건만 밀린 67명(39%)에게는 아무 변화가 없고,
21건 이상 밀린 54명에게만 벽이 사라진다. 정확히 겨냥한 대상이다.

⚠️ 다만 **상위 29%는 6구절 이상** 한다 — **막으면 안 된다**(→ ② 결정 3).

## ③ 범위

### 하는 것
1. 복습 화면에 **카드 모드** (토글 단추 + 쟁반)
2. 복습 큐를 **3구절씩** 나눠 보여 주기 + **밀린 순 정렬**
3. 그에 맞춘 **문구** 수정 (첫 화면 · 진행 · 완료 화면)
4. `review-typing-card` 를 위한 **DB CHECK 확장 · 서버 폴백 확장**
5. 낡게 되는 **주석·문서** 정리

### 안 하는 것 — 그리고 왜

| 안 하는 것 | 왜 |
|---|---|
| **하루 카운터(진짜 상한)** | 결정 3. 저장 위치·하루 경계·공용 기기 문제를 전부 떠안는데, 실측상 막을 이유가 없다 |
| **첫 화면 「오늘 할 일」 점유 풀기** | `dueCount>0` 이면 암송·도전이 영영 큰 단추가 못 된다(app.js:2000-2007). **진짜 문제지만 별건이다** — 첫 화면 우선순위를 바꾸는 일이라 이번 변경과 섞으면 무엇이 효과인지 못 가른다 |
| **서버 `ymd()` 의 UTC 버그** | index.ts:120 이 UTC라 KST 09시 이전 복습은 간격이 7일이 아니라 **6일**로 저장된다. 아침 알림이 KST 05~08시라 **푸시 보고 들어온 분은 항상 이 창에 든다**. 별건으로 잡을 것 |
| **암송 화면 재완료를 복습으로 쳐 주기** | 지금은 같은 구절을 암송 화면에서 다시 마쳐도 복습 빚이 **1건도 안 줄어든다**(advanceReview 를 부르는 길이 복습 화면 하나뿐). 고치면 「반복해서 쓰기」를 켠 분이 하루에도 여러 번 다음 박스로 밀려 간격의 뜻이 무너진다 — 하루 1회 묶음이 함께 필요해 별건 |

| **밀린 것 일괄 재분배 / Leitner 박스 내리기** | 되돌릴 수 없고 간격(3·7·14·30·60)의 뜻이 달라진다 |
| **`3` 을 `app_config` 로 빼기** | 프런트 전용이라 `getConfig` 캐시를 첫 화면 렌더 전에 넣어야 한다. 복잡도 대비 이득이 낮다 — 코드 상수로 두고, 조정이 필요해지면 그때 뺀다 |

## ④ 설계

### 4.1 복습 카드 모드

복습은 **이미 공용 `setupChallengeTyping` 을 쓰고 있다**(app.js:7575).
카드 입력 로직은 그 함수 안에 있고 `#card-tray` 가 있는 화면에서만 쟁반을 만든다(app.js:7733-7734).
**복습에 카드가 없는 이유는 템플릿에 div 한 줄이 없어서다.**

| # | 자리 | 무엇을 |
|---|---|---|
| 1 | `renderReview` 템플릿 (app.js:7520 아래) | `<div id="card-tray" class="card-tray"></div>` 한 줄 |
| 2 | 같은 템플릿 btn-row (app.js:7508-7512) | `#rv-mode-toggle` 토글 단추 — 암송 `#mode-toggle`(5334)·도전 `#ch-mode-toggle`(7390)과 같은 꼴 |
| 3 | 토글 클릭 핸들러 | `stopSpeaking(); setCardMode(!isCardMode()); renderReview(queue, idx);` |
| 4 | `onDone` (app.js:7571) | mode 매핑 (아래) |
| 5 | **`startReview`** (app.js:7462-7478) | `setCardMode(isCardStart());` |

**mode 매핑 — 음성을 먼저 가른다:**

```js
const m = mode === "voice" ? "review-voice"
        : (isCardMode() ? "review-typing-card" : "review-typing");
postChallenge(verse, m);
```

⚠️ **도전(app.js:7446)을 그대로 베끼면 안 된다.** 복습은 타자·음성이 **같은 onDone 을 공유**한다
(app.js:7575·7576). 도전은 7447 에서 voice 를 따로 박아 이 충돌을 피해 뒀다.
`cardUsed` 를 먼저 보면 카드를 누르다 🎤로 마친 기록이 `review-typing-card` 로 남는다.

⚠️ **`"review-" + mode` 로 이어 붙이면 안 된다.** `review-card` 가 나오는데,
이름에 `typing` 이 없어 순위·통계의 `%typing%` 집계에서 **조용히 빠진다.**

⚠️ **5번은 반드시 `startReview`, `renderReview` 가 아니다.** 토글이 `renderReview` 를 다시 그리는
방식이라, 리셋을 `renderReview` 안에 넣으면 **토글을 누르는 순간 설정값으로 되돌아가 단추가 안 먹는다.**
시편이 피한 방식 그대로다(`js/psalm.js:435` 리셋 vs `:380` 재렌더).

**CSS는 손댈 것이 없다.** `.card-tray`·`.wcard` 는 전역이고(style.css:456-475),
`.test-card .btn-row` 가 `flex-wrap: wrap`(style.css:3138-3145)이라 단추 넷도 줄바꿈으로 받는다.

### 4.2 3구절씩 나눠 보기 + 밀린 순 정렬

**자르는 자리는 `dueReviewNos()`(app.js:1171-1187) 한 곳뿐이다.**
호출처가 `renderSummary`(1991)와 `startReview`(7464) 둘뿐이라, 거기서 자르면
**첫 화면 숫자 · 큐 길이 · 완료 화면 숫자가 저절로 같은 수가 된다.**
반대로 `startReview` 안에서만 `slice` 하면 단추 숫자만 옛 수로 남아 화면이 자기모순에 빠진다.

상수는 `REVIEW_INTERVALS`(app.js:1140) 바로 옆에 둔다 — 복습 정책이 한자리에 모인다.

```js
const REVIEW_BATCH = 3;   // 한 번에 보여 줄 복습 구절 수 (상한이 아니라 묶음)

function dueReviewNos() {
  // ...(기존 시편 제거 · verses 에 없는 no 제거 부수효과는 그대로 둔다)
  return nos
    .sort((a, b) => (r[a].next < r[b].next ? -1 : r[a].next > r[b].next ? 1 : a - b))
    .slice(0, REVIEW_BATCH);
}
```

- 정렬 첫째 열쇠는 `next`(기한) 오름차순 = **가장 오래 밀린 것부터**. 동률이면 구절 번호.
- ⚠️ **`.sort()` 를 명시적으로 넣는다.** 지금은 `Object.keys` 의 정수 키 순회에 **암묵적으로 기대고** 있다.
- ⚠️ `startReview`(7465)의 `verses.filter(...)` 는 **순서를 `verses` 배열 순으로 덮어쓴다.**
  큐를 만들 때 `dueNos` 순서를 살려야 한다 — `dueNos.map(no => verses.find(v => v.no === no)).filter(Boolean)` 꼴로 바꾼다.
- ⚠️ **`isPsalmNo` 방어(app.js:1176-1180)를 걷어내지 말 것.** 「어차피 `verses` 가 막아 준다」는
  `getVerses` 의 옛-DB 폴백(index.ts:1197-1200, track 필터 없음)에서 깨진다 — 2026-09-13 사고(no=1005)가 되살아난다.

**총수는 필요 없다.** 완료 화면에서 `dueReviewNos().length > 0` 을 다시 물으면
「남은 것이 있나」를 알 수 있다(→ ⑤ 함정 1 덕분에 그다음 묶음이 곧바로 기한이 된다).

### 4.3 문구 — 「오늘」을 뺀다

묶음이므로 「오늘」이라고 말하면 거짓이 된다(다시 누르면 또 나온다).

| 자리 | 지금 | 바꿀 것 |
|---|---|---|
| 첫 화면 큰 단추 (app.js:2002) | `오늘 복습 ${dueCount}구절` | `복습 ${dueCount}구절` (밑줄 「잊기 전에 다시 한 번」은 그대로) |
| 첫 화면 작은 줄 (app.js:2011) | `복습 ${dueCount}구절` | 그대로 |
| 복습 진행 (app.js:7519) | `복습 ${idx+1} / ${queue.length}` | 그대로 (「복습 1 / 3」이 된다) |
| 완료 화면 (app.js:7592) | `오늘 복습 ${count}구절을 마쳤어요` | `복습 ${count}구절을 마쳤어요` |
| 완료 화면 (app.js:7593) | `다음 복습은 자동으로 안내됩니다.` | 남은 것이 있으면 **「3구절 더 하기」 단추**, 없으면 지금 문구 그대로 |

「더 하기」 단추는 **완료 화면 안**에 둔다 — 첫 화면을 건드리는 것보다 훨씬 싸다
(`startReview` 호출처가 app.js:2172 하나뿐이라 첫 화면 쪽은 `dueCount>0` 분기까지 얽힌다).
동작은 **`startReview()` 를 다시 부르는 것**이 전부다 — 새 큐를 만들어 `renderReview(queue, 0)` 로 간다.
`renderReviewDone` 안에서 `dueReviewNos().length` 를 한 번 읽어 0 이면 단추를 아예 안 그린다.

⚠️ **밀린 총수를 화면에 쓰지 않는다.** 「적체가 벽」이라는 가설과 정면으로 부딪친다.
쓰게 된다면 **「밀린 137구절 중 오늘 3구절」 꼴은 금지**다(`docs/notes/home-screen.md` — 단위를 두 번 쓰는 함정).

⚠️ **색을 새로 만들지 않는다.** 복습은 이미 청록을 갖고 있다(style.css:1688·2913).
「밀린 게 많다」를 경고색으로 표현하려는 유혹이 「색은 네 단계뿐」 규칙에 걸린다.

⚠️ **NEW 배지를 쓰지 않는다.** 화면에 하나뿐이라(app.js:1388-1396) 지금 NEW 를 단
「쉴만한 물가」·「이벤트」에서 배지를 빼앗는다. 그리고 이것은 새 기능이 아니라 기존 기능의 조정이다.

### 4.4 서버 · DB

**DB** — `challenge_log.mode` CHECK 에 `'review-typing-card'` 가 없다(migrate_modes_card.sql:40-43).
새 파일 `supabase/migrate_modes_review_card.sql` 로 그 멱등 패턴을 그대로 베낀다.
낡은 `supabase/schema.sql:53` 목록도 함께 갱신한다.

⚠️ 제약 재생성 SQL 의 `do $$` 루프는 `contype='c'` 인 제약을 **이름 불문 전부** 지운다.
지금 `challenge_log` 의 CHECK 는 mode 하나뿐이라 안전하지만(schema.sql:49-56 확인),
돌리기 전에 `select conname, pg_get_constraintdef(oid) from pg_constraint where conrelid='public.challenge_log'::regclass and contype='c';` 로 확인한다.

**서버** — 폴백(index.ts:2101)이 `m === "typing-card"` **정확 일치**라 복습 값에는 안 걸린다.
**접두사를 보존하도록** 넓힌다:

```
review-*  →  review-typing
learn-*   →  learn-typing
그 밖      →  typing
```

⚠️ **전부 `"typing"` 으로 통일하면 안 된다.** `app.js:454 logPassageActivity` 가 `challenge` 액션으로
이미 완성된 `learn-*` 를 보내고 있어, 복습·긴 본문이 **「도전」으로 둔갑해 전환율이 부풀어 오른다**
(`challenge_funnel.sql` 의 도전 판정이 `mode not like 'learn%' and mode not like 'review%'`).
2026-09-02 이전에 겪은 그 사고를 다시 만드는 것이다.

`advanceReview`(index.ts:2131-2143)는 mode 를 아예 안 읽는다 — **손댈 것이 없다.**

### 4.5 배포 순서 — SQL 먼저

```
① SQL (개발 → 확인 → 운영)      CHECK 에 review-typing-card 추가
② Edge Function (개발 → 운영)    폴백 접두사 보존
③ 프런트 (bump → push)           카드 모드 · 자르기 · 문구
```

⚠️ **뒤집으면 복습 기록이 통째로 사라진다.** 제약에 없는 값은 폴백 없이 throw → 500 →
`postChallenge` 의 catch(app.js:7798)가 삼킨다. 더 나쁜 것은 바로 다음 줄
`advanceReview(verse.no)`(app.js:7572)가 **그래도 돌아간다**는 점이다 —
**기록은 안 남고 복습 일정만 다음 박스(며칠~몇 주 뒤)로 밀려난다.** 재시도 대기열도 없다.

⚠️ `supabase functions deploy` 는 git 이 아니라 **작업 트리를 올린다.**
배포 전에 `git status` 로 남의 커밋 안 된 코드가 섞이지 않았는지 본다.

## ⑤ 함정 — 실사에서 나온 것

1. **★ 자르기만 하면 「하루 제한」이 아니라 「굴러가는 3구절 창」이 된다.**
   `advanceReview` 가 구절마다 즉시 `next` 를 3일 뒤로 밀므로(app.js:1188-1192),
   3구절을 마친 직후 `dueReviewNos()` 는 **그다음 3구절**을 돌려준다.
   → **그래서 「더 하기」를 따로 만들 필요가 없다.** 대신 「오늘」이라는 말을 쓰면 안 된다(4.3).

2. **복습 순서는 지금 「밀린 순」이 아니다.** `dueReviewNos`(1181)에 `.sort()` 가 없고
   `startReview`(7465)가 `verses` 순서로 덮는다. `next` 는 **필터에만** 쓰이고 정렬에 안 쓰인다.

3. **`mergeServerReviews` 는 병합이 아니라 통째 교체다**(app.js:666-674).
   「오늘 고른 3개」 같은 상태를 `r[no]` 안에 심으면 다음 `syncProgress()` 에 조용히 사라진다.
   ⚠️ **그런데 `syncProgress` 는 복습을 마친 뒤에는 안 돈다**(호출처는 앱 진입 521·재시도 870 둘뿐).
   그 세션 안에서는 멀쩡히 살아 있고 **앱을 껐다 켠 다음에만** 사라진다 — 새로고침 없이 테스트하면 절대 못 본다.
   → 이번 설계는 상태를 아예 안 심으므로 해당 없다. **나중에 상태를 심고 싶어지면 이 함정을 먼저 읽을 것.**

4. **로컬 `advanceReview` 는 서버 실패를 삼킨다**(app.js:1194 `.catch(() => {})`).
   서버가 실패하면 로컬만 앞으로 가고, 다음 동기화의 통째 교체로 **옛 `due_at` 으로 되돌아간다** —
   성도님께는 「분명히 복습했는데 또 떠 있다」가 된다. 적체 일부가 이걸로 설명될 수 있다(추측).

5. **`tests/event-input.py` 가 공용 함수를 못 박고 있다.** 카드 두 장을 눌러 완료했을 때
   `window.__done` 이 정확히 `"typing"` 인지 검사한다(100-160줄). 공용 `setupChallengeTyping` 의
   `onComplete("typing")`(app.js:7674)을 건드리면 **여기서 걸린다** — 안전망이자 반드시 돌려야 할 시험이다.

6. **공용 경로에서 mode 를 바꾸지 말 것.** `setupChallengeTyping` 은 본문 마디(app.js:4332)·
   본문 전체(4429)도 쓰는데, 그쪽 onDone 은 `mode === "typing"` 을 **문자열로 직접 비교**한다(4316).
   공용 onComplete 에 `"typing-card"` 를 흘리면 그 화면의 단계 진행이 조용히 멈춘다.

7. **잠복 버그가 덤으로 고쳐진다.** 지금 「👆 카드」를 켜 두신 분이 복습에 들어오면
   쟁반은 없는데 `isCardMode()` 가 true 라 **첫 칸 자동 포커스가 안 된다**(app.js:7768).
   입력칸이 잠기지는 않으므로(잠그는 코드가 쟁반 블록 안에만 있다) 직접 누르면 쓸 수 있지만 불편하다.
   쟁반이 생기면 함께 풀린다.

8. **관리자 통계 「그중 카드」 열의 뜻이 넓어진다.** `%card` 로 세므로(stats-rpc-card.sql:35,78)
   `review-typing-card` 가 합산된다. 복습이 전체의 0.6%라 티는 안 나지만,
   `docs/analysis/2026-09-23-usage-analysis.md` 와 앞뒤를 견줄 때는 기준이 달라진 것을 알고 봐야 한다.

9. **`supabase/stats-rpc.sql` 을 다시 돌리지 말 것.** 32-33·73-74줄이 `%typing`(뒤 와일드카드 없음)이라
   card 로 끝나는 값이 타이핑·음성 어디에도 안 들어가 **타이핑+음성 ≠ 총횟수**가 된다.
   새 개발 DB 를 세울 때는 `stats-rpc.sql` **다음에 반드시** `stats-rpc-card.sql` 을 돌린다.

10. **⚠️ 측정 오염 — 알고 받아들인다.** 카드와 자르기를 같은 판에 내면
    「복습 참여가 늘었다」의 원인을 둘로 못 가른다. 다만 **카드 쪽은 `review-typing-card` 로 갈리므로
    카드 사용률은 따로 잴 수 있다** — 섞이는 것은 자르기 효과뿐이다.

## ⑧ 위험과 되돌리기

| 위험 | 되돌리는 법 |
|---|---|
| 카드가 복습에서 이상하게 동작 | 프런트만 되돌린다(SQL·서버는 넓히기만 해서 그대로 둬도 무해) |
| 3구절 자르기가 오히려 나쁘다 | `REVIEW_BATCH` 를 큰 수(예 999)로 바꾸면 **자르기가 무효가 된다** — 상수 하나다(정렬은 아래 줄에서 따로 되돌린다) |
| 정렬이 문제 | `.sort()` 한 줄과 `startReview` 의 큐 만드는 줄을 되돌리면 이전 동작(번호순) |
| 기록이 안 남는다 | 배포 순서를 지키면 안 생긴다. 생기면 SQL 부터 확인 |

**노출 게이트는 두지 않는다** — `REVIEW_BATCH` 상수 자체가 게이트 노릇을 한다(999면 무효).
카드 모드도 기존 설정(`card-start`)을 따를 뿐 새 노출 면이 없다.
