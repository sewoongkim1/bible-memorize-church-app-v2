# 이번주 말씀 위젯 머리말 — 「🐑 3일째」 (설계)

2026-10-13 · 친구 「위젯을 스마트하게 — 다른 앱에서 구현해 놓은 것 중 적용할 만한 것」에서 시작.
고른 것: 다른 앱 아이디어 가운데 **① 이 말씀 며칠째 + ③ 구절마다 이모지 하나**, 그리고 **머리말을 서버가 만든다**.

## 까닭
- 위젯은 로그인 없이 공개 정보만 받는다(`user_id` 없음). 그 안에서 할 수 있는 「알아채는 위젯」이 이 둘이다.
  개인 기록(오늘 횟수·단계)은 아이폰은 App Group 이 필요하고 안드로이드(크롬 TWA)는 위젯이 앱 기록을 읽을 길이 없어 뺐다.
- 위젯 코드를 고치면 스토어 판이 하나 나가야 한다. **머리말 글자를 서버가 통째로 내려 주면** 이번 한 번만 판을 내고,
  그 뒤의 문구·모양은 `api` 만 고쳐 바꿀 수 있다(옛 판 위젯은 모르는 칸을 무시한다).

## 친구 결정(2026-10-13)
- 이모지는 **AI 가 정해진 목록 안에서** 고른다. 지금 있는 주간 구절 41개는 이번에 골라 친구가 보고 넣는다.
- 머리줄 모양은 **「이모지 + 며칠째」** — `🐑 3일째`, 첫날은 `🐑 새 말씀`. 점(●○)은 쓰지 않는다.

## ① 무엇이 보이나
- **이번주 말씀 위젯의 홈 「중간」·「크게」**(아이폰 `TodayVerseWidget` · 안드로이드 `VerseWidget`)에서
  머리줄 「(교회 마크) 이번주 말씀」 **오른쪽 끝**에 한 줄. 머리줄과 같은 글씨 크기·회색(secondary)·한 줄(넘치면 끝을 `…`).
- **새 줄을 만들지 않는다.** 가장 긴 구절(69자 · 삼상 26:24)이 중간 크기에서 이미 5줄을 채운다 — 줄을 더하면 잘린다.
- 넣지 않는 곳:
  - 잠금 화면(네모·한 줄): 시스템이 한 색으로 칠한다(교회 마크를 뺀 것과 같은 까닭).
  - 돌려 보기 위젯: 오른쪽 위에 이미 날짜·시각이 있다.
  - 묵상·기도문 위젯: 이번 범위 밖.

## ② 서버 — `getWeeklyVerse` 응답에 두 칸
```
{ no, ref, text, prev,            // 지금 그대로
  badge: "🐑 3일째",              // 새로 — 없으면 칸째 뺀다
  badgeDate: "2026-10-13" }       // 새로 — badge 를 셈한 한국 날짜(widgetYmd(b))
```
- **며칠째** = 이 구절의 `date`(한국 날짜)부터 오늘까지 + 1. 1이면 「새 말씀」, 아니면 「N일째」(7을 넘어도 그대로 — 운영 구절은 7~10일 간다).
  - 운영 구절 시작일은 목·금·토로 들쭉날쭉하다(2026-07~10 · 14개 확인). 그래서 「일~토 요일 칸」이 아니라 **이 말씀 며칠째**로 센다.
  - `date` 가 없는 구절(`weeklyVerseKst` 가 「오늘」로 보는 것)·아직 시작 전인 구절(앱의 「곧 시작할 말씀」)은 **며칠째를 쓰지 않는다** — 이모지만.
- **이모지** = `verses.emoji` 가 아래 목록 안에 있을 때만. 없으면 며칠째만.
- 둘 다 없으면 `badge` 칸을 보내지 않는다(위젯은 지금 모양 그대로).
- `prev` 는 지금 모양 그대로 둔다(새 칸을 싣지 않는다).
- ⚠️ `weeklyVerseKst` 가 `emoji` 칸을 읽게 되므로 **SQL(칸 추가)이 api 보다 먼저**다 — 칸이 없는 DB 에서 select 가 실패하면
  지금의 폴백(track 없는 DB)도 같은 칸을 읽어 함께 실패한다. 개발 → 운영 모두 SQL 먼저.
- **끄는 법:** `badge` 를 보내지 않게 api 만 고쳐 올리면 모든 위젯이 지금 모양으로 돌아간다(스토어 판 필요 없음).

## ③ 이모지 — `verses.emoji` 칸 · 정해진 목록 · AI 가 채움
**칸:** `alter table public.verses add column if not exists emoji text;` — 공개 정보(구절 본문과 같은 급)라 RLS·노출 문제 없음.

**목록(40개 · 서버 상수 하나):** 안드로이드 7.0(minSdk 24)에서도 네모 칸(□)으로 안 나오게 **유니코드 7.0 이하**만 둔다.
사람 모양은 피부색이 갈리지 않는 🙏 👣 만.
```
🐑 🕊️ 🙏 ❤️ ✝️ 📖 🌱 🌿 🍃 🌳 🌾 🌸 🌻 🍇 🍞 🐟 💧 🌊 ☀️ 🌅
🌙 ⭐ ✨ 💡 🔥 🌈 ⛰️ 🏠 🚪 👣 🛡️ ⚓ 👑 🗝️ ⚖️ ⏳ 🕯️ 🎁 🎶 🌍
```
- 견줄 때는 이체 선택자(U+FE0F)를 떼고 견주고, 저장·응답은 **목록에 적힌 꼴 그대로** 쓴다.

**지금 있는 것(주간 구절 41개):** 이번에 Claude 가 골라 표로 친구께 보이고, 확인 뒤 SQL 로 넣는다
(`update … set emoji = … where no = … and emoji is null` — 이미 채운 것은 건드리지 않는다).

**앞으로 들어올 구절 — 위젯이 처음 부를 때 서버가 채운다(게으른 채움):**
- 조건: 요청에 `date` 입력이 **없고**(실제 오늘), 이번 구절의 `emoji` 가 비었거나 목록 밖일 때만.
  `date` 를 받는 길(시험판)로는 채우지 않는다 — 인증 없는 호출로 앞날 구절의 AI 호출을 부르지 못하게.
- **응답을 기다리게 하지 않는다** — 이번 응답은 이모지 없이 나가고(`🐑` 없이 「새 말씀」), 채우는 일은 `EdgeRuntime.waitUntil` 로
  응답 뒤에 돈다(지금 `eduAfterResponse` 와 같은 꼴). 몇 초 뒤부터 부르는 위젯은 이모지를 받는다.
- Claude 에게 구절 이름·본문과 목록을 주고 **목록 안 하나만** 답하게 한다. 답이 목록 밖이면 버린다(저장 안 함).
  모델은 환경 변수로 바꿀 수 있게(`VERSE_EMOJI_MODEL` · 기본은 작은 모델 — 구현 때 claude-api 스킬로 이름 확인).
- 저장: `update verses set emoji = $1 where no = $2 and emoji is null` — 여럿이 함께 채워도 처음 것 하나만 남는다.
- 실패가 이어질 때 매 요청마다 AI 를 부르지 않게, 같은 구절은 **한 isolate 안에서 10분에 한 번**만 시도한다.
- `ANTHROPIC_API_KEY` 가 없으면 조용히 건너뛴다(머리말은 며칠째만).
- 사람이 고치고 싶으면 SQL 한 줄(`update verses set emoji = '🕊️' where no = 42`) — 관리 화면은 만들지 않는다
  (관리 기능은 교회 어드민으로 옮기는 중이라 앱 관리자 화면에 새 기능 금지 · `docs/backlog.md` 4-5).

## ④ 위젯 — 지난 날의 머리말을 보이지 않게
위젯은 받은 것을 적어 두었다가(받기 실패·비행기 모드) 그것으로 그린다. 그대로 두면 어제 받은 「3일째」가 오늘도 남는다 —
**사실이 아닌 말**이 된다. 그래서:
- **그릴 때 `badgeDate` 가 오늘(한국 날짜)과 같을 때만** badge 를 보인다. 다르거나 없으면 머리줄은 지금 모양.
- **아이폰:** 타임라인에 장을 둘 깐다 — 지금 장, 그리고 **다음 한국 자정에 같은 내용의 장**(그 장은 날짜가 달라 badge 가 숨는다).
  정책은 지금처럼 `.after(다음 자정 또는 30분 뒤)`. 시스템이 새로 받기를 몇 분 미뤄도 자정을 넘긴 「어제 머리말」은 안 보인다.
- **안드로이드:** `render` 에서 지금 시각으로 오늘을 셈해 견준다(`WidgetLogic` 의 순수 함수 · JVM 시험). 다시 받기 알람은
  지금처럼 정확하지 않은 `RTC`(SCHEDULE_EXACT_ALARM 권한 없이) — 자정 직후 알람이 늦게 오는 동안은 어제 머리말이 남을 수 있으나,
  폰이 깨어 있으면 곧 다시 받는다(받기 실패면 적어 둔 것의 `badgeDate` 가 어제라 숨는다).
- 아이폰 머리글 `WidgetHeader` 는 묵상·기도문 위젯도 쓴다 — **기본값이 있는 칸 하나**(`trailing: String? = nil`)를 더해 다른 위젯은 손대지 않는다.
- 안드로이드 머리줄(`widget_verse_medium.xml`·`widget_verse_large.xml`)은 너비를 `match_parent` 로 넓히고 오른쪽에
  `widget_badge`(없으면 `gone`)를 둔다. 가장 좁은 위젯 너비 250dp 에서 「(교회 마크) 이번주 말씀」 + 「🐑 10일째」가 한 줄에 들어간다.
- ⚠️ 아이폰 위젯 코드는 **두 벌**(`ios-app/native/TodayVerseWidget/` · `ios-app/ios/App/TodayVerseWidget/`)이고 지금까지 늘 같은 커밋에서
  같이 고쳤다 — 이번에도 둘 다. 새 파일은 만들지 않는다(위젯 타겟 파일 목록이 `project.pbxproj` 에 손으로 등록돼 있다).
- ⚠️ 위젯 kind(`TodayVerseWidget`)·클래스 이름(`VerseWidget`)은 바꾸지 않는다 — 놓아 둔 위젯이 그 이름으로 이어진다.

## ⑤ 차례
1. **SQL** `supabase/verse_emoji.sql`(칸 추가 + 41개 채움) — 개발 → 확인 → 운영 · `tools/sql-applied.py record`.
   41개 표는 SQL 을 넣기 **전에** 친구 확인.
2. **api** — 개발(`deploy-fn.py api --dev`) → `getWeeklyVerse` 를 `date` 넣어 불러 badge 확인 → 운영(`--prod`) → 운영 스모크.
   이때부터 응답에 badge 가 실리지만 지금 판 위젯은 무시한다.
3. **위젯** — 안드로이드(시험 · `bundleProdRelease`) · 아이폰(두 벌 · 맥이 없어 Codemagic 빌드로 컴파일 확인).
4. **스토어 판** — 아이폰 **1.1.2**(`MARKETING_VERSION` 네 곳) · 안드로이드 **versionCode 6 / 1.1.2**. 업로드·제출은 친구(스킬 `store-release`).
5. 웹(`app.js`)은 고치지 않는다 — bump 없음. 설명서의 위젯 장 문구도 그대로(머리말은 설명이 필요 없는 크기).
