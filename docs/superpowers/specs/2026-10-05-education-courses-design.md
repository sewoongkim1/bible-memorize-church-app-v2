# 교육신청 — 강좌 개설 · 신청 · 출석 · 수료증 (설계)

> **한 줄.** 성도님은 성경암송 앱의 「🎓 교육」에서 강좌를 보고 신청하고 「내 강좌」에서 출석·수료를 보며 수료증을 받는다.
> 교육 담당자와 강사는 교회 어드민(admin.onlybible.kr)의 「🎓 교육」 메뉴에서 강좌를 열고, 신청을 확정하고, 출석을 체크하고, 수료를 정해 수료증을 찍는다.
> 작성 2026-10-05 · 친구 결정으로 범위를 정함(아래 §0) · 처음 쓰는 때 **2027년 상반기(1~3월)**.

## 0. 친구가 정한 것 (2026-10-05)

| 방식 | **지금 있는 두 앱 위에 얹는다**(성경암송 앱 + 교회 어드민 · 같은 DB) — 별도 사이트·외부 서비스(구글 폼·LMS)는 쓰지 않는다 |

## 1. 범위

**한다:** 강좌(과정·학기·회차) 만들기 · 앱 신청·취소 · 선착순/승인 · 정원·대기·대기 올림 · 담당자 대리 등록(교인명부에서 찾기 · 새가족 직접 입력) · 신청 현황·엑셀 · 강사 출석부 · 출석 현황 · 수료 판정·확정 · 수료번호 · 수료증(앱 저장·일괄 인쇄) · 진위 확인 · 교인명부 「🎓 교육 이력」 탭 · 통계 · (4단계) 알림·사역신청 선수 조건.

**안 한다(이번):** 결제 · 과제 제출·시험·동영상 강의(LMS 의 학습 기능) · 문자·알림톡 발송 · 어린이·청소년 부모 대리 신청 · QR 자가 출석 · 외부(교인 아닌 분) 공개 신청.

|---|---|---|

| 대리 등록 | 직원이 대신 넣기 · 가족 등록 | 담당자 대리 등록(교인명부·직접 입력) · 가족 등록은 안 함 |

| 증명서 | PDF · 일련번호 · 발급일 · 서명/직인 · 진위 확인 URL | 같다(수료번호 · 진위 확인 페이지) |
| 이력 | 교인 기록의 교육 이력 · 직분/사역 조건 | 교인명부 「🎓 교육 이력」 탭 · (4단계) 사역신청 선수 조건 |
| 알림 | 메일·문자·앱 알림 | (4단계) 앱 알림만 — 신청 확정·대기 올림·개강 전날·수료 |
| 결제 | 온라인 결제 | 안내만 + 납부 체크 |

## 3. 구조

```
성도님 ─ 성경암송 앱(gocheok.onlybible.kr) ─ api(Edge Function) ─┐
                                                                 ├─ Supabase 같은 DB: edu_* 표 + SQL 함수(정원·대기·번호)
담당자·강사 ─ 교회 어드민(admin.onlybible.kr) ─ church-admin 함수 ─┘      └─ people_links(kind 'edu') ─ church_people(교인명부)
```

- 정원·대기·수료번호처럼 **두 함수가 함께 부딪히는 규칙은 SQL 함수 한 곳**에 둔다(`edu_apply`·`edu_cancel`·`edu_issue_certs`) — 성도님 신청과 담당자 확정이 동시에 와도 정원을 넘지 않게(강좌 줄 `for update`).
- 성경암송 `api` 는 **성도님 액션만**(목록·상세·신청·취소·내 강좌·수료증 자료·진위 확인). 관리 액션은 모두 교회 어드민(사역신청을 옮기며 정한 방향과 같다 · v2 에 담당자용 액션을 새로 만들지 않는다).
- 순수 규칙(상태 전이·출석률·수료 판정·번호 꼴)은 **양쪽이 같은 글자로 쓰는 작은 모듈**로 — 교회 어드민 `edu-rules.ts`(Node 시험이 읽는다) · v2 는 필요한 판정만 서버 응답으로 받는다(앱이 다시 계산하지 않는다).

## 4. 역할과 권한

| 누구 | 어디 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|---|
| 성도님 | 성경암송 앱 | 열린 강좌 · 내 신청·출석·수료 | 신청 · 개강 전날까지 취소 · 수료증 저장 |
| 교육 담당자 (역할 `education`) | 교회 어드민 | 모든 강좌·신청·출석·수료 · 통계 | 강좌 만들기·고치기·복사 · 확정/반려/대기 · 대리 등록 · 출석 고치기 · 수료 확정·취소 · 수료증 인쇄 · 엑셀 |
| 강사 (역할 `teacher`) | 교회 어드민 | **맡은 강좌의** 명단(이름·소속·상태)·회차·출석 | 출석 체크·고치기(맡은 강좌만) |
| 총괄 (`super`) | 교회 어드민 | 전부 | 역할 주기 · 강사 배정 |

- 역할은 교회 어드민 `admin_roles` 표 한 곳(코드·CHECK 에 박지 않는다 — 교회 어드민 함정). 새 액션마다 `authz.ts` `ACTION_ROLES` + `index.ts` case + `tests/server.dev.test.mjs` `PROBE` 셋을 함께.
- **강사의 「맡은 강좌만」은 서버가 지킨다** — 액션 권한(`teacher`)과 별도로 `edu_course_teachers` 에 (강좌, 담당자) 줄이 있어야 한다. 화면에서 숨기는 것만으로 끝내지 않는다.
- 강사에게는 연락처·교적 상세를 주지 않는다(이름·소속·상태·출석만).

## 5. 자료 모양 (SQL · 개발 먼저)

모든 표: 만든 자리에서 **RLS 켜고 `anon`·`authenticated` revoke**(서버만 읽는다 · 「TO authenticated 로 열지 말 것」 — 카카오 로그인 뒤로 authenticated = 누구나).

**`edu_courses`** — 학기마다 여는 강좌 하나
- `id uuid pk` · `track text`(과정 키 · 예 `discipleship-1` — 선수 조건·이력 묶음) · `title` · `kind`(`regular`·`lecture`·`training`) · `term text`(예 `2027-1`)
- `description` · `teacher_label`(화면에 보일 강사 이름 — 계정과 별개) · `place` · `fee_note`(안내 글)
- `capacity int null`(null = 제한 없음) · `mode`(`auto` 선착순 · `approve` 승인) · `waitlist bool`
- `apply_from date` · `apply_to date` · `target text`(안내 글 · 예 「교회학교 교사」) · `prereq_tracks text[]`
- `attend_pct int default 80` · `check_label text null`(담당자가 확인할 것 · 예 「과제」 — null 이면 출석률만)
- `status`(`draft` 준비 · `open` 모집 · `closed` 모집 끝 · `running` 진행 · `done` 끝 · `archived`) · `created_by` · 시각들

**`edu_sessions`** — 회차: `id` · `course_id fk cascade` · `no int` · `on_date date` · `start_time` · `end_time` · `topic` · `place null`(강좌와 다르면) · `unique(course_id,no)`

**`edu_enrollments`** — 한 분의 한 강좌 신청(한 줄에 수료까지)
- `id bigserial` · `course_id fk` · `user_id uuid null`(앱 계정 · 대리 등록은 null 가능) · `ident_key` · 신원 사진(`who_type`·`group_name`·`sub_name`·`name` — 신청 당시 값)
- `status`(`applied` 신청 · `confirmed` 확정 · `waitlisted` 대기 · `cancelled` 취소 · `declined` 반려) · `source`(`app`·`staff`) · `waitlist_at`(대기 순서) · `applied_at` · `decided_at` · `cancelled_at`
- `fee_paid bool` · `staff_note`(담당자만) · `check_done bool`(강좌의 확인 항목)
- `completed bool` · `completed_at` · `cert_no text unique null` · `cert_revoked bool`
- `unique(course_id, user_id) where user_id is not null`(같은 강좌에 한 계정 한 줄 · 취소 뒤 다시 신청은 그 줄을 되살린다)

**`edu_attendance`** — `pk(enrollment_id, session_id)` · `state`(`present` 출석 · `late` 지각 · `absent` 결석 · `excused` 공결) · `marked_by`(담당자 id · 응답엔 안 싣는다) · `marked_at`

**`edu_course_teachers`** — `pk(course_id, member_id)`(교회 어드민 담당자) — 강사 배정

**`edu_cert_seq`** — `year pk` · `last int` — 수료번호 차례(되쓰지 않는다)

**교인명부 잇기:** `people_links` 에 kind **`edu`**(row_id = `edu_enrollments.id`) — 기존 규칙 그대로(`manual`·`none` 은 자동이 덮지 않는다 · 앱 표엔 칸을 더하지 않는다).

### SQL 함수 (두 함수가 같이 부른다)
- **`edu_apply(course, user, 신원…, by_staff bool)`** — 강좌 줄 `for update` → 이미 있는 줄이면 되살림 → `approve` 면 `applied` · `auto` 면 확정 수 < 정원이면 `confirmed`, 아니면 `waitlist` 가 켜져 있으면 `waitlisted`(순서 시각) 아니면 `full` 오류. 신청 창·선수 조건·status 검사도 여기서(담당자 대리 등록은 창·선수 조건을 건너뛸 수 있다 · `by_staff`).
- **`edu_cancel(enrollment, by)`** — `cancelled` + 시각 → 그 줄이 `confirmed` 였고 강좌가 `auto` 면 **대기 첫 분을 `confirmed` 로 올린다**(같은 트랜잭션). `approve` 강좌는 올리지 않고 담당자가 고른다.
- **`edu_issue_certs(course, enrollment_ids[])`** — 수료 확정 + 수료번호를 차례대로(`고척-YYYY-NNNN` · 해는 수료일 해) · 이미 번호가 있으면 그대로 · 수료 취소는 `cert_revoked`(번호는 다시 쓰지 않는다).

## 6. 흐름의 규칙

**상태 전이(신청 한 줄)**
```
(신청) ─ auto·자리 있음 ─▶ confirmed
      ─ auto·자리 없음·대기 켜짐 ─▶ waitlisted ─(앞사람 취소)─▶ confirmed
      ─ approve ─▶ applied ─(담당자)─▶ confirmed | waitlisted | declined
confirmed·waitlisted·applied ─(성도님: 개강 전날까지 · 담당자: 언제든)─▶ cancelled ─(다시 신청)─▶ 처음부터
```
- 담당자 확정은 정원을 넘길 수 있다(「정원을 넘깁니다」 확인 한 번) — 사람이 정한 예외.
- 성도님 취소 마감 = **첫 회차 전날**. 그 뒤엔 「담당자에게 말씀해 주세요」.

**출석률과 수료**
- 출석으로 치는 것: `present`·`late`. 공결(`excused`)은 **분모에서 뺀다**. 출석률 = (출석+지각) ÷ (전체 회차 − 공결). 체크 안 한 회차는 아직 안 한 것으로(끝난 뒤엔 결석으로 본다).
- 수료 후보 = 출석률 ≥ `attend_pct` **그리고** (`check_label` 이 있으면) `check_done`. 화면이 후보를 미리 고르고, **담당자가 확정**해야 수료(자동 확정 없음).
- 순수 함수: `attendRate(rows, sessions)` · `completionCandidate(enrollment, course, rate)` · `nextStatusOnApply`·`nextOnCancel` — 시험으로 지킨다.

**대리 등록** — 교회 어드민에서 ① 교인명부로 찾아 넣기(앱 계정이 있으면 그 계정에 · 없으면 `user_id` null + `people_links` 로 교인 잇기) ② 직접 입력(새가족 — 이름·연락 메모 없이 이름·소속 글만). 앱 계정이 나중에 생기면 담당자가 「앱 계정과 잇기」.

**수료증**
- 한 장의 템플릿(HTML · A4 가로): 교회 로고 · 「수료증」 · 이름 · 과정·학기 · 기간 · 수료번호 · 발급일 · 담임목사 이름과 서명/직인 이미지(담당자가 올림 · 비공개 저장소 칸).
- **교회 어드민:** 강좌의 수료자 전원을 한 번에 인쇄(브라우저 인쇄 · 한 장에 한 분).
- **앱:** 「내 강좌 → 수료증」 같은 템플릿을 그려 저장·공유. ⚠️ **네이티브 앱(아이폰 WKWebView · 플레이 TWA)에서 파일 저장이 되는지 3단계 첫 일로 확인**한다 — 지금 앱엔 파일 내려받기가 없다(공유는 `navigator.share` 한 곳). 기본안: 이미지로 그려 공유 시트(`navigator.share({files})`) · 안 되는 곳은 「길게 눌러 저장」 안내.
- **진위 확인:** `gocheok.onlybible.kr/cert/?no=고척-2027-0001` — 번호가 맞으면 과정·학기·수료일·**가린 이름**(김*웅)만. `user_id`·소속은 안 보인다. 번호를 정확히 넣어야만 답한다(목록·검색 없음).

5. 수료증 — 템플릿 · 저장/공유

**교회 어드민 「🎓 교육」 메뉴 묶음**

3. ✅ 출석부 — 회차를 고르면 명단 · 한 번 누르기로 출석/지각/결석/공결 · 폰 우선 · 강사는 맡은 강좌만

5. 📊 교육 통계 — 학기·강좌별 신청·확정·출석률·수료 · 교구별

- 고르기·날짜·시각은 `js/core/picker.js` 만(교회 어드민 함정) · 확인은 `dialog` · 저장 중 `busy()`.

## 9. 노출 게이트

- 앱의 「🎓 교육」은 `app_config` **`eduOpen`** 이 켜졌거나 🧪 시험 참여자(교회 어드민 ⚙️ 시스템 → 🧪 — 사역신청과 같은 명단)일 때만 — 사역신청 `ministryVisible` 과 같은 결(세 값: 켜짐·꺼짐·모름).
- 강좌 하나하나는 `status` 와 신청 창으로 — `draft` 는 담당자에게만.
- ⚠️ **플레이 심사 중에는 방침·공지를 바꾸지 않는다**(2026-10-03 친구) — 게이트를 켜기 전에 개인정보 안내를 보완한다(§10).

## 10. 개인정보·보안

- **새로 모으는 것:** 교육 신청(강좌·신청 시각·상태)·출석·수료(번호·날짜)·담당자 메모·납부 체크. **휴대폰 번호는 받지 않는다**(알림은 앱으로).
- 개인정보 안내 **세 곳**(성경암송 `privacy/` · 앱 안 개인정보 화면 · 교회 어드민 `privacy.html`)을 1단계 공개 전에 같은 커밋으로 — 누가 보나(담당자·강사는 맡은 강좌만) · 얼마나 두나(수료 기록은 교육 이력이라 계속 · 출석 세부와 메모는 정할 것 §13).
- 앱은 비밀번호가 없다(`user_id` 를 믿는다) — 신청·취소는 사역신청과 같은 수준. 수료증은 「내 줄」만 · 진위는 번호로.
- 진위 확인은 가린 이름만 · 번호를 정확히 알아야만 답한다.
- 강사·담당자 화면 응답에 `auth_user_id`·`user_id`·`ident_key`·`marked_by` 를 싣지 않는다.
