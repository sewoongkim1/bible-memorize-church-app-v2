# 「내게 주시는 말씀」 에이전트 — 설계 (2026-11-20)

> 친구 결정(2026-11-20 대화): 성도님이 **AI 에이전트를 경험할 만한 기능**으로 「내게 주시는 말씀」을 에이전트로 바꾼다.
> 할 일 둘(① 맞는 암송 구절 → 바로 외워 보기 · ② 맞는 설교 → 3분 요약 듣기) · 되묻기는 **단추로 2번까지** ·
> AI가 하는 일을 **실제로 하는 그때 한 줄씩** 보여 준다 · 속은 **AI가 도구를 골라 쓰는 진짜 에이전트**(길 1).

## 0. 목표와 범위

**목표** — 고민이나 궁금한 것을 적으면, AI가 스스로 찾을 말을 정해 설교와 앱의 암송 구절을 찾아 보고,
답과 함께 「이렇게 해 보세요」(외울 구절 · 들을 설교)를 내민다. 성도님은 **AI가 무엇을 하는지 화면에서 본다.**

**이번에 하는 것**
- 답 + 출처(지금과 같음) + 📖 외워 볼 말씀 1~2장(바로 외워 보기) + 🎧 들어 볼 설교 1장(3분 요약 듣기 · 영상)
- AI가 고른 되묻기 단추 2~3개 — 한 질문에 2번까지
- 단계 줄을 실시간으로(스트리밍) — 끝나면 「AI가 한 일 N가지 ▾」로 접힘

**하지 않는 것**(YAGNI — 필요해지면 따로 설계)
- 카드 만들기 · 기도문 쓰기 · 알림 예약 · 글로 이어 묻기
- 성도님의 암송 기록 · 이름 · 소속을 AI에 보내는 것(개인 맞춤은 다음 단계 「암송 코치」의 몫)

## 1. 화면

자리는 지금의 「💬 내게 주시는 말씀」 화면 그대로. 문(§3)이 열린 분만 새 방식, 나머지는 지금과 똑같다.
화면 코드는 **새 파일 `js/sc-agent.js`**(지연 로드 — `docs/notes/lazy-load.md` 꼴)에 두고, `app.js` 의 `scAsk` 는 문을 보고 갈래만 나눈다.

1. **단계 줄** — 서버가 보내는 step 줄을 받는 대로 쌓는다.
   ```
   🔎 설교에서 「염려와 평안」 찾는 중…   → ✓ 설교 3편을 찾았어요
   📖 「두려워 말라」 구절 찾는 중…        → ✓ 외울 만한 구절 2개
   ✍️ 답을 쓰는 중…
   ```
   - 「」 안은 **AI가 도구를 부를 때 실제로 넘긴 찾을 말**이다. 정해 둔 문구를 시간 맞춰 띄우지 않는다(사실이 아닌 말이 된다).
   - 실패한 도구는 그 줄을 「⚠ 찾지 못했어요」로 바꾸고 계속한다.
   - 답이 오면 줄들은 「AI가 한 일 N가지 ▾」로 접힌다(눌러 펼침).
   - 저장된 답이면 단계 줄 대신 「📚 전에 같은 질문으로 찾은 답이에요」 한 줄.
2. **답** — 지금과 같은 2~4문단 · **굵게** · 출처 설교 목록(`scOpenSermon` 그대로).
3. **「이렇게 해 보세요」 카드**
   - 📖 **외워 볼 말씀**(1~2장): 장절 · 본문 두 줄 · AI가 고른 까닭 한 줄 · **[바로 외워 보기]** → `startTest(그 구절)`.
     암송 화면에서 뒤로 오면 이 화면과 답이 그대로 있어야 한다(답 상태를 들고 있다가 다시 그린다).
   - 🎧 **들어 볼 설교**(1장): 제목 · 날짜 · 까닭 한 줄 · **[3분 요약 듣기]** → 지금의 설교 요약 화면(`renderSermonSummary`) · **[영상]**.
4. **되묻기 단추** — AI가 고른 2~3개(예: 🔁 다른 구절로 · ✂️ 더 짧은 구절로 · 👨‍👩‍👧 아이와 함께 외울 말씀).
   누르면 아래로 이어서 1~3을 한 번 더. 2번 쓰면 단추를 걷고 「새로 물어보기」만 남긴다.
5. 🚩 **이 답 알리기** 그대로 — 알릴 때 추천 구절 · 설교도 함께 남긴다.
6. **통째로 실패**(서버 오류 · `fallback` 줄 · 네트워크)하면 지금 방식(`sermonChat`)으로 한 번 더 — 빈 화면을 보이지 않는다.
7. 흘려받기를 못 하는 기기는 응답을 끝까지 받은 뒤 줄을 한꺼번에 푼다(단계 줄만 늦게 뜨고 답은 같다).

## 2. 서버 — 새 액션 `sermonAgent`(Edge Function `api`)

`sermonChat` 은 **손대지 않는다**(문이 닫힌 분 · 되돌림 길). 새 액션은 `json()` 대신 흘려보내는 응답을 돌려주므로
라우터의 `switch` 앞에서 따로 받는다(CORS 머리 같게).

### 2-1. 흘려보내는 줄(NDJSON · `content-type: application/x-ndjson`)

| 줄 | 꼴 |
|---|---|
| 단계 | `{"t":"step","id":1,"kind":"sermon"\|"verse"\|"write"\|"cache","q":"염려와 평안","state":"start"\|"done"\|"fail","n":3}` |
| 답 | `{"t":"answer","answer":"…","sources":[…지금과 같은 꼴],"verses":[{"no":2014,"ref":"…","text":"…","why":"…"}],"sermon":{…sources 한 칸 꼴,"why":"…"}\|null,"chips":["🔁 다른 구절로",…],"turn":0}` |
| 되돌림 | `{"t":"fallback","reason":"…"}` — 화면이 `sermonChat` 으로 다시 묻는다 |
| 한도 | `{"t":"answer","limited":true,"answer":"오늘은 질문을 많이 하셨어요…"}` — 지금 문구 그대로 |

### 2-2. 도구 셋

1. `search_sermons({query})` — 지금의 설교 검색 그대로: Voyage 임베딩 → `match_sermon_chunks`(5개) → 유사도 0.4 이상만.
   돌려주는 것: 발췌마다 `sermon_id` · 제목 · 날짜 · 본문 장절 · 내용.
2. `find_verses({topic})` — 앱의 암송 구절을 뜻으로 찾는다.
   - 새 표 `verse_embed` 의 임베딩과 견준다(새 RPC `match_verse_embed`). 상위 6개.
   - **그 성도님께 보이는 묶음만**: 주간 구절(지난 것 포함) 늘 · 주제별 성경암송은 app_config `naviPublic` · 쉴만한 물가는 `psalmPublic` 이 켜졌을 때.
     (화면의 `naviVisible` · `psalmVisible` 과 같은 판정을 서버에서 다시 한다 — 앱이 보낸 값은 믿지 않는다.)
   - 임베딩이 없거나 본문이 바뀐 구절(본문 해시가 다름)은 **찾기 직전에 그것만** Voyage 로 만들어 채운다 — 새 주간 구절이 들어온 첫 질문만 조금 느리다.
   - 돌려주는 것: 구절 번호 · 장절 · 본문.
3. `give_answer({answer, verses:[{no,why}], sermon:{sermon_id,why}|null, chips:[…]})` — 마지막에 한 번.
   서버 검증(순수 함수로 빼서 시험):
   - `verses` 의 번호는 **이번 대화에서 `find_verses` 가 실제로 돌려준 것**만 남긴다(최대 2) · `sermon_id` 도 `search_sermons` 가 돌려준 것만.
   - `chips` 는 최대 3개 · 각 30자 · 빈 것 버림.
   - `why` 는 각 60자.
   - `answer` 가 비면 되돌림(`fallback`).

### 2-3. 돌림

- 지시문: 지금 `sermonChat` 의 지킴이 문장(설교 발췌에만 근거 · 지어내지 않기 · 출처 밝히기 · 목사인 척하지 않기 · 2~4문단 · 굵게는 문단마다 한두 곳)을
  그대로 옮기고, 도구 쓰는 법(먼저 설교를 찾고 · 외울 구절을 찾고 · 끝에 `give_answer` 한 번)을 덧붙인다.
- 모델: 지금처럼 `SERMON_CHAT_MODEL`(없으면 지금 기본값). ⚠️ 구현 때 모델 이름 · 도구 사용 API 꼴은 스킬 `claude-api` 로 확인한다.
- **상한**: 도구 부름 4번 · AI 부름 5번 · 40초. 넘으면 「지금까지 찾은 것으로 `give_answer` 하라」를 한 번 더 보내고, 그래도 없으면 `fallback`.
- 단계 줄은 도구를 부르기 **직전**(start)과 결과를 받은 **직후**(done · n)에 보낸다. 「답을 쓰는 중」은 마지막 AI 부름 직전.
- 성도님의 질문 · 단추 글은 **믿지 않는 입력**이다(지시를 바꾸라는 글이 와도 지시문이 앞선다). 도구 결과(설교 · 구절)는 교회 자료.

### 2-4. 되묻기

- 화면이 보내는 것: `{message: 첫 질문, follow: {chip: "누른 단추 글", prev_verses: [번호…], prev_sermon: sermon_id, turn: 1|2}}`.
- 앞의 답 글은 보내지 않는다 — 서버가 `prev_*` 번호로 구절 본문 · 설교 제목을 다시 꺼내 「앞에서 이것을 권했다」로 넣는다.
  화면이 보낸 글을 「AI가 했던 말」로 믿는 일이 없게.
- `turn` 은 화면이 세지만, 속여도 하루 한도(§2-5)에 걸린다.

### 2-5. 저장 · 셈 · 알림

- **저장**: 첫 질문의 결과만 `sermon_ai_cache`(`kind: "agent"` · 열쇠는 `sermonQuestionKey(message)` — 지금과 같은 열쇠 함수).
  돌려줄 때 구절은 **지금 보이는 묶음으로 다시 거른다**(그사이 문이 바뀌었을 수 있다). 되묻기는 저장하지 않는다.
- **셈**: 질문 · 되묻기 모두 `sermon_chat_log` 에 한 줄씩(지금 `sermonChat` 과 같은 칸 — 되묻기는 `question` 에 「↪ 다른 구절로」꼴) → 지금의 하루 한도(한 분 20 · 모두 300)가 그대로 센다.
- **🚩 AI 답 알림**: `sermonAnswerReport` 가 캐시를 찾을 때 `kind` `"chat"` 과 `"agent"` 를 함께 본다(관리자 「답 지우기」도 둘 다).

### 2-6. 새로 만드는 것(SQL — 개발 먼저 · 스킬 `new-table` · `sql-migrate`)

- 표 `verse_embed(track text, no int, text_hash text, embedding vector(1024), updated_at)` — 기본 열쇠 `(track, no)` · 임베딩은 설교와 같은 `voyage-3-large` · 1024 차원(`embedVoyage`) · 꼴은 `supabase/sermon_chunks.sql` 을 따른다.
- 표 `sermon_agent_run(id, created_at, turn int, tool_calls int, ai_calls int, in_tokens int, out_tokens int, ms int, outcome text)` — **이름 · `user_id` 없음** · 90일 뒤 지움.
- RPC `match_verse_embed(query_embedding, tracks text[], match_count int)` — `match_sermon_chunks` 와 같은 꼴.
- 셋 다 그 자리에서 RLS 켜기 · `anon` · `authenticated` revoke · `TO authenticated` 금지 · 공개 키로 행이 안 오는지 확인.

## 3. 지킴이

**문(세 값)** — app_config `scAgent`: 비어 있음 = 닫힘 · `"test"` = 🧪 시험 참여자(`ministryTesters` 명단 — 화면 `ministryTesterCached` · 서버 `ministryIsTester`) · `"on"` = 모두.
화면과 서버가 같은 문을 본다(서버는 문이 닫혔으면 `fallback`). 공개 설정 키 목록(`PUBLIC_CONFIG_KEYS`)에 더한다. 모두에게 열 때 `FEAT_SINCE` 에 날짜.

**어린 부서** — 지금 「내게 주시는 말씀」이 모두에게 열려 있으므로 같게 둔다. 새로 모으거나 AI에 보내는 개인 정보가 없다.

**개인정보** — AI(Anthropic)에 가는 것: 질문 글 · 누른 단추 글 · 설교 발췌 · 구절 본문. 이름 · 소속 · 암송 기록은 안 간다.
방침의 Anthropic 줄(「입력한 질문 글」)은 그대로 사실. **Voyage 줄만** 「설교 검색용」 → 「설교 · 구절 검색용」으로 —
세 자리(`privacy/` · 앱 안 `renderPrivacyInfo` · `renderHelp`)를 같은 커밋에(스킬 `copy-truth`) · 스토어 심사 중이 아닐 때.

**비용** — §2-3 상한 + 하루 한도 그대로 + `sermon_agent_run` 으로 「한 질문에 얼마」를 본다. 시험 호출 전에 친구께 호출 수를 미리 알린다(2026-10-16 사용 한도 일).

## 4. 시험

1. **순수 함수**(`tests/*.cjs` 꼴 · 서버 것은 Deno 시험 또는 같은 함수를 꺼내 node 로): `give_answer` 검증 · 화면의 NDJSON 줄 풀기(조각난 줄 · 빈 줄 · 깨진 줄).
2. **개발 DB 스모크**: `verse_embed` 채우기 → 정해 둔 질문 10개 — 단계 줄 · 카드 · 되묻기 2번 · 저장된 답(📚 줄) · 한도 · 문 닫힘(`fallback`) · 도구 실패 · 통째 실패 되돌림.
3. **실기기**: 아이폰 앱 · 플레이 앱 · 크롬 — 단계 줄이 **실시간**으로 뜨는지(흘려받기), 바로 외워 보기 → 뒤로 → 답이 남는지.
4. **운영**: 문 `"test"` 로 1~2주 — 비용(`sermon_agent_run`) · 🚩 알림 · 시험 참여자 말씀을 보고 `"on"`.

## 5. 내는 차례

새 표에 새 액션만 얹는 일이라 **표가 먼저**(빈 표는 아무도 안 읽는다), 코드는 **문이 닫힌 채**로 나간다.

1. SQL(표 둘 · RPC) — 개발 → 확인 → 운영 · `tools/sql-applied.py record`
2. `api` — `tools/deploy-fn.py api --dev` → 스모크 → `--prod`
3. 화면(`js/sc-agent.js` · `app.js` 갈래 · `style.css`) — 문 닫힌 채 release
4. 개인정보 세 자리(심사 중이 아닐 때)
5. 문 `"test"` → 지켜보기 → `"on"` + `FEAT_SINCE`
6. 기능 문서 `docs/notes/sermon-agent.md` + `CLAUDE.md` 표에 한 줄
