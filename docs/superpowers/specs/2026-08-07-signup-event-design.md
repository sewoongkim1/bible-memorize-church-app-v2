# 말씀 이벤트(가입 이벤트) 설계

## 배경 및 목적

오프라인 광고와 연계해 성도들의 앱 참여를 유도하는 이벤트. 1회차는 **2026-09-30까지, 성경암송 앞 12개 구절(1~12번)**로 진행하며, 이후에도 관리자가 회차(기간·구절 범위)만 바꿔 계속 운영한다. 참여자는 12개 구절의 빈칸 1개씩을 맞히면 **응모 완료**되고, 관리자는 응모자 명단으로 오프라인 추첨·시상을 진행한다.

- 참여 대상: **로그인한 성도** (기존 식별자 로그인 그대로, 별도 가입 절차 없음)
- 참여 기록은 기존 암송 통계·랭킹에 **반영하지 않음** (별도 기록)

## 사용자 흐름

1. 이벤트 기간 중 로그인하면 **첫 화면(기록 화면)에 이벤트 버튼** 노출
   - 미응모: `🎉 말씀 이벤트 참여하기`
   - 응모 완료: `✅ 이벤트 응모 완료` (누르면 재도전 가능 — 연습용, 응모는 최초 1회만 기록)
   - 기간이 아니면 버튼 자체가 보이지 않음
2. 버튼을 누르면 이벤트 화면 진입:
   - 대상 12개 구절이 **매번 무작위 순서**로 출제
   - 구절마다 **빈칸 1개** — 빈칸 단어도 **입장할 때마다 무작위**로 선정
     (공백 기준 토큰 중 **2글자 이상**인 단어에서만 골라, 조사 한 글자가 빈칸이 되는 어색함 방지.
     2글자 이상 토큰이 하나도 없는 예외 상황에서는 가장 긴 토큰을 사용)
   - 구절 아래에 기존 설교 아카이브의 **AI 풀이(easyExplain)**를 함께 표시(있는 구절만)
   - 정답을 맞히면 자동으로 다음 구절로(기존 도전 화면과 같은 타이핑 채점 — 오답이면 흔들림 후 재입력)
   - 상단에 진행 표시 `3 / 12`
   - **중간에 나가면 저장 없음** — 다음 입장 시 처음부터(순서·빈칸 모두 새로 뽑힘)
3. 12개를 모두 맞히면:
   - 서버에 **응모 기록** 저장 (최초 1회만; 이미 응모했으면 저장 생략)
   - **"이벤트 응모가 완료되었습니다"** 축하 화면 표시 + `말씀 도전으로 이어가기` 버튼(지속 참여 연결)

## 데이터 설계

### 이벤트 설정 — `app_config` (key: `event`)

관리자가 배포 없이 회차를 만들고 수정한다. 값 예시:

```json
{
  "id": "2026-1",
  "name": "성경암송 가입 이벤트",
  "start": "2026-08-11",
  "end": "2026-09-30",
  "fromNo": 1,
  "toNo": 12
}
```

- `id`: 회차 식별자(응모 기록이 이 값으로 묶임). 다음 회차는 새 id로 저장
- 기간 판정은 **KST 기준, 종료일 당일 포함**(end 23:59까지)
- `getConfig`의 공개 키 화이트리스트(`PUBLIC_CONFIG_KEYS`)에 `event` 추가 (읽기는 공개, 쓰기는 기존 `saveConfig`의 관리자 검증 그대로)

### 응모 기록 — 새 테이블 `event_entries`

```sql
create table event_entries (
  event_id  text not null,
  user_id   text not null,
  entered_at timestamptz not null default now(),
  primary key (event_id, user_id)   -- 회차당 1인 1응모
);
```

- challenge_log와 분리해 기존 통계·랭킹에 영향 없음
- PK 충돌 시 무시(upsert ignore) → 재도전해도 최초 응모 시각 유지

### 백엔드 액션 (Edge Function `api`)

| 액션 | 권한 | 동작 |
|---|---|---|
| `getConfig(key=event)` | 공개 | 이벤트 설정 반환(기존 액션에 키만 추가) |
| `eventEnter` | 로그인 사용자 | `{event_id, user_id}` 응모 기록(중복이면 기존 유지). 응답에 `entered_at` 포함 |
| `eventStatus` | 로그인 사용자 | `{event_id, user_id}` → 응모 여부·시각 반환 (기기 변경 시 버튼 상태 복원용) |
| `eventEntrants` | 관리자 | 회차별 응모자 명단: users 조인으로 교구·목장·이름 + 응모일시, 응모순 정렬 |

## 화면 설계

### 첫 화면 버튼 (app.js `renderSummary`)

- 로그인 후 `getConfig("event")` 로드(기존 dailyMessage 로드 흐름에 편승) → 기간 중이면 버튼 표시
- 응모 여부는 `eventStatus` 결과를 localStorage에 캐시해 즉시 표시, 백그라운드로 서버 확인

### 이벤트 화면 (app.js 신규)

- 기존 도전 화면(`renderChallenge`)의 골격 재사용: 상단 요절 고정 배너, 타이핑 채점(`setupChallengeTyping` 방식)
- 차이점: 빈칸 1개 고정, 진행 `n/12` 표시, 다음 구절 자동 진행, 풀이 항상 펼침 표시, 힌트·음성·보기 버튼 없음(단순하게)
- 뒤로가기 → 확인 없이 종료(저장 없음, 재입장 시 처음부터)

### 응모 완료 화면

- `🎉 이벤트 응모가 완료되었습니다` + 이름·응모일시 표시
- `🔥 말씀 도전으로 이어가기` / `기록 화면으로` 버튼

### 관리자 (admin-stats.html)

- **이벤트 관리** 섹션 추가:
  - 설정 편집: 이름·기간·구절 범위·회차 id (app_config `event` 저장)
  - 응모자 명단: 회차 선택 → 표(순번·교구·목장·이름·응모일시), 인원수 합계 표시

## 범위 밖

- 앱 내 자동 추첨·상품 관리 (오프라인 진행)
- 미로그인 체험 모드 (이벤트는 로그인 후 참여)
- 이벤트 전용 푸시 알림 (필요 시 기존 sendPush로 수동 발송)
