# 성도 기록 병합 안내

이 문서는 이름이나 교구·목장이 바뀐 뒤 성도님이 새 소속으로 이미 앱을 사용하여 기록이 두 사용자로 나뉜 경우의 처리 방법을 설명합니다.

예시는 다음과 같습니다.

| 구분 | 사용자 번호 | 정보 |
| --- | --- | --- |
| 이전 사용자 | `A` | 사랑교구 1목장 김세웅 |
| 현재 사용자 | `B` | 화평교구 20목장 김세웅 |

관리자가 두 정보가 **동일인**임을 확인하고 기록 합치기를 실행하면, 새 소속에서 사용 중인 `B`를 남기고 `A`에 연결된 기록을 `B`로 옮깁니다.

```mermaid
flowchart LR
  A["이전 사용자 A\n사랑교구 1목장 김세웅"] -->|"기록과 연결 정보 이전"| B["현재 사용자 B\n화평교구 20목장 김세웅"]
  A -. "이전 번호·이전 소속\nB로 연결" .-> B
  B --> R["계속 사용하는 하나의 기록"]
```

## DB에서 일어나는 일

1. `users` 테이블에서는 `B` 행을 유지합니다.
2. `A`에 연결된 기록의 `user_id`를 `B`로 변경하거나, 키가 겹치는 기록은 아래 기준으로 병합합니다.
3. 이전 식별 정보(예: `교구|사랑|1|||김세웅`)는 `B`의 로그인 별칭으로 저장합니다.
4. `users` 테이블의 `A` 행은 삭제합니다.
5. `user_merges` 테이블에는 `A → B`, 병합 시점, 병합 당시의 두 프로필, 사유를 남깁니다.

따라서 병합 후 `users` 테이블에는 `B`만 남습니다. 다만 이전 기기에서 `A`를 보내거나 이전 소속으로 로그인해도 서버는 `user_merges`와 로그인 별칭을 통해 `B`로 해석합니다.

## 기록별 병합 기준

| 기록 | 처리 방식 |
| --- | --- |
| 암송·도전 로그 | 모든 행과 기록 시각을 유지하고 `B`의 기록으로 이전합니다. 횟수를 합산합니다. |
| 한글·영어 진도 | 같은 구절·언어가 겹치면 더 높은 단계를 유지합니다. 어느 한쪽에서 ‘마음에 둠’을 체크했다면 유지합니다. |
| 복습 일정 | 마지막 복습일이 더 최근인 쪽의 상자·예정일을 유지합니다. 같은 날이면 현재 사용자 `B` 쪽을 유지합니다. |
| 긴 본문 암송 | 완료한 마디 번호를 합치고, 한쪽이라도 전체 완료면 완료 상태를 유지합니다. |
| 축복 기도문 조회 | 같은 날짜·기도문은 조회 횟수를 합산합니다. |
| 게시글·답글 | 원래 작성 행을 보존하고 작성자 `user_id`만 `B`로 변경합니다. 과거 표시 이름·소속 문자열은 작성 당시 값으로 남습니다. |
| 게시판 공감·이벤트 참여·순위 응원 | 같은 반응·참여가 겹치면 한 건만 남깁니다. 병합 뒤 자기 자신에게 한 순위 응원은 제거합니다. |
| 필사 신청·푸시 알림 기기 | 원래 신청·구독 행을 보존하고 `B`로 이전합니다. |
| 사역 신청·상세 이벤트 신청 | 서로 다른 신청은 이전합니다. 같은 사역팀 또는 같은 회차 신청이 양쪽에 모두 있으면 자동 합치지 않고 중단합니다. |

암송·도전 로그를 기준으로 다시 일별 활동 집계를 만들기 때문에, 병합 뒤 순위·참여 횟수가 빠지거나 이중 집계되지 않습니다.

## 관리자 화면에서 하는 방법

1. 관리자 허브에서 **성도 정보 관리**를 엽니다.
2. 이전 소속으로 등록된 성도를 검색해 선택합니다.
3. 이름·소속을 현재 사용 중인 정보로 입력하고 변경 사유를 적습니다.
4. 변경 내용 확인에서 저장을 누릅니다.
5. 같은 이름·소속의 현재 사용자가 이미 있으면, 양쪽 소속과 기록 수가 표시됩니다.
6. 두 정보가 동일인임을 확인한 뒤 체크하고 **같은 성도 확인 후 기록 합치기**를 누릅니다.

병합을 실행하기 전에는 어느 기록도 바뀌지 않습니다.

## 안전장치와 주의 사항

- 이름이 같다는 이유만으로 자동 병합하지 않습니다. 관리자 확인 체크가 반드시 필요합니다.
- 병합은 하나의 DB 트랜잭션으로 실행됩니다. 중간에 오류가 나면 기록 이전, 별칭 저장, 사용자 삭제가 모두 취소됩니다.
- 새 기능의 알 수 없는 기록이 이전 사용자에 연결되어 있으면 자동으로 지우지 않고 병합을 중단합니다.
- 동일 사역팀이나 동일 상세 이벤트의 신청이 양쪽에 있으면 답변·상태가 유실될 수 있으므로 병합을 중단합니다. 중복 신청을 먼저 확인·정리한 후 다시 시도해야 합니다.
- 관리자 화면에는 두 사용자로 되돌리는 기능이 없습니다. 동일인 확인이 확실할 때만 실행합니다.
- 병합 실행 뒤에도 이전 소속 정보는 다른 신규 사용자에게 재사용할 수 없습니다. 이전 기기와 구버전 앱이 계속 같은 성도님의 기록으로 연결되도록 예약되어 있기 때문입니다.

## 확인 방법

병합 직후 이전 소속과 현재 소속으로 각각 앱에 접속해도 같은 진도·복습 기록이 보이는지 확인합니다. 관리자 화면에서 현재 소속으로 다시 검색하면 한 명만 표시됩니다.

`user_merges`와 `user_profile_changes`는 관리자용 감사 기록입니다. 성도 화면이나 공개 API에는 노출되지 않습니다.
